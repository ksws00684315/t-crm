# ADR-006 许可证白名单增加 Apache-1.1 并要求第三方许可声明

- 状态：已接受（2026-10-05）
- 决策人：项目负责人

## 背景

任务 02 第二次续做时，Codex 核对依赖 JAR 包内的许可证原文，发现 `org.aspectj:aspectjweaver:1.9.25.1`（由 `spring-boot-starter-aspectj` 引入，后台操作日志切面使用）的 POM 只写 EPL-2.0，但包内附带的许可证为 `EPL-2.0 AND BSD-3-Clause AND Apache-1.1`：其中打包的修改版 Apache BCEL 采用 Apache-1.1。Apache-1.1 不在规范 07 白名单内，且"AND"组合不能只取其中一项。

为避免逐个依赖反复中止，项目负责人一侧对后台与跳转服务的全部依赖（含迁移 PostgreSQL 后新增的依赖，约 180 个包）做了基于 POM 元数据的许可证普查：除 AspectJ 外，所有含 GPL/LGPL 字样的依赖均为"任选其一"且另一选项在白名单内，PostgreSQL 相关依赖均为 BSD-2-Clause、MIT 或 Apache-2.0。

## 决定

1. 许可证白名单增加 `Apache-1.1`。
2. 明确"AND"组合许可的每一项都必须在白名单内；许可证以包内原文为准，不以元数据为准。
3. 新增交付要求：每个工程自动生成并提交 `THIRD-PARTY-NOTICES`，交付物中必须包含。

## 理由

- Apache-1.1 是 OSI 认可的宽松许可证，无传染性，允许商用与闭源；义务为保留版权声明、在产品文档中致谢、不得以 Apache 名义为产品背书，均可通过第三方许可声明满足。
- BSD、EPL、Apache-2.0 同样有随附声明的义务，此前规范只约束"能否使用"，未约束"交付时随附什么"，借此补齐。

## 备选方案及放弃原因

| 方案 | 放弃原因 |
|---|---|
| 移除 AspectJ，改用 Spring 拦截器实现操作日志 | 拦截器难以获取反序列化后的方法参数，需要额外的请求体处理，为一个宽松许可证改变实现方式不划算 |
| 为 AspectJ 单独登记例外而不扩充白名单 | 例外机制用于漏洞豁免；许可证是长期属性，应在白名单层面明确 |

## 影响

- 任务 02 新增后台与跳转服务的第三方许可声明生成；任务 03 新增两个前端的生成。
- 以后若再出现白名单外的宽松许可证，仍须按规范修改白名单并记录 ADR。
