# ADR-023：达人编号格式改为 KOL-字母+序号，推广状态由商务手动维护

- 状态：已接受（2026-10-18）
- 决策人：项目负责人
- 相关：[ADR-012](ADR-012-跳转服务不回源后台.md)、[ADR-018](ADR-018-管理端改为超级管理员加可配置权限的子账号.md)、[1017 确认事项与变更清单](../00-需求/客户补充资料-1017/1017确认事项与变更清单.md) R1～R9、设计 §4.2、§5.2、§8.2

## 背景

客户 2026-10-17 确认（功能评估表 03.01～04.03、会议纪要）：

- 达人编号要有辨识度，按注册顺序递增；
- 达人有业务状态，商务按状态逐步完成审核和推广配置；
- 推广配置要保留修改记录。

现状：编号为 `KOL` + 4～8 位数字（`KOL0001`）；达人只有启用 / 停用和账号激活两种状态；推广相关字段散在达人资料中，没有修改记录。

## 决定

1. **编号格式**：`KOL-` + 3 位随机大写字母 + 序号，例如 `KOL-ASD001`。
   - 序号沿用全局序列 `crm_kol_code_seq`，至少 3 位，不足补零，超过 999 自然变成 4 位及以上；
   - 编号会出现在中转链接中（`/t/{kolCode}/…`，ADR-012），跳转服务和链接索引按编号建键，所以编号必须**全局唯一**；全局序列保证这一点，代价是同一公司的序号可能不连续；
   - 校验正则 `^KOL-[A-Z]{3}[0-9]{3,8}$`，后台、跳转服务、两个前端统一；
   - 创建后不可修改，唯一约束覆盖已逻辑删除的记录，永不复用；
   - 系统未上线，不迁移旧编号；测试数据随新规则重建。
2. **推广状态** `promotion_status`（与账号启用状态、激活状态分开）：

   | 值 | 含义 | 进入方式 |
   |---|---|---|
   | `PENDING_REVIEW` 待审核 | 注册后的初始状态 | 系统设置 |
   | `PENDING_PROMOTION` 待推广 | 商务已审核资料 | 商务手动 |
   | `PROMOTING` 推广中 | 推广配置已完成 | 商务手动，要求推广配置必填项齐全 |
   | `ENDED` 合作结束 | 不再合作 | 商务手动 |

   - 状态之间的切换**全部由商务手动操作**（负责人 2026-10-18）。系统只校验「改为推广中时推广配置齐全」，不因上传推广表、订单等事件自动改状态；
   - 「**待更新**」不是存储的状态：达人没有绑定在职商务时，界面和接口的显示状态为「待更新」，期间业绩归管理员（公司，见设计 §4.13）；重新绑定后显示回存储的状态；
   - 每次状态变更写入修改记录。
3. **推广配置**（商务在「待推广」时填写，之后可改）：
   - 佣金比例、代购平台（多选，选项来自本公司维护的代购平台模板 `crm_link_template`）、达人专属落地页地址、达人邀请码、备注；推广表格地址选填；
   - 每次保存生成一条配置记录（谁、何时、改前改后），供审核追溯；
   - 佣金比例的生效时点与佣金计算的关系，在佣金任务中按 R15 定稿。
4. **商务的达人范围**：
   - 列表只显示已绑定本人的达人；
   - 未绑定任何在职商务的达人，商务可以按达人编号或邮箱**精确**搜索后认领，认领即绑定本人；不支持模糊搜索与浏览未绑定达人。
5. **清理配置**（运营维护）：设置「X 天未出单」的达人自动清理。清理为**逻辑删除**达人，并逻辑结束其商品对应关系；订单、佣金历史保留；不调用微店接口。默认关闭。

## 后果

- 后台、跳转服务、管理端、达人端的编号校验同时修改；跳转服务需要与后台一起发布。
- 达人表增加推广状态、落地页地址；新增达人与代购平台的多对多表、推广配置记录表、清理配置。
- 达人列表、详情的状态展示与跳转（待审核 → 审核页，待推广 → 推广配置页，推广中、合作结束 → 推广数据）随之调整。
- 原设计「达人编号 `KOL` + 4～8 位数字」被替代。
