# ADR-040：2026-11-10 全量审查后的规范修正

- 状态：已接受（2026-11-10）。负责人 2026-11-10 对任务 145 分诊问题 Q-3、Q-5、Q-8 回复「全部按建议」
- 决策人：项目负责人
- 相关：《全量审查问题清单（2026-11-10）》M-09、M-16～M-20、M-22、C-04、D-02；任务 145 执行报告；[ADR-035](ADR-035-表格视觉采用方案A.md)、[ADR-039](ADR-039-sys_config为平台级表.md)

## 背景

全量审查发现若干规范条款与项目现状长期不一致，代理按条款执行会做错事，或者干脆无从执行：

1. 规范 03 §8 和规范 08 完成标准要求用 OpenAPI 3（springdoc）描述接口，项目从未引入，原规范 09 的 I6 也一直记为「未整改」（M-09）。
2. 规范 02 要求金额舍入一律 `HALF_UP`；代码中按业务不应有余数的换算用 `UNNECESSARY`，余数一出现就抛异常暴露问题。代码的做法更稳妥（M-20）。
3. 规范没有任务编号的分配规则（索引里有，规范里没有），任务 144 曾被两处同时占用；也没有类的行数上限、状态值用枚举的约定（M-22）。
4. 规范 08 §8 写「上线首个版本为 `1.0.0`」，正式环境实际从 `v0.1.0` 起；四个工程的版本号一直是 `0.1.0`，镜像版本来自 git 标签（C-04）。
5. 规范 05 必测清单还写着「一笔订单多位达人」「结算单」「看板指标」（M-16）；规范 06 导入上限 20MB 没有写推广表格 300MB 的例外（M-18）；规范 11 的看板条款对应暂缓的功能（M-19）；规范 10 保留了一张旧字号表，容易被当成现行规则（D-02）；规范 09 是已完成的整改清单（M-17）。

## 决定

1. **不引入 OpenAPI**：接口以设计说明书的接口清单为准，改接口时同步更新清单。规范 03 §8、规范 08 完成标准、PR 模板同步修改。
2. **舍入方式**：需要舍入的位置用 `HALF_UP`；按业务应当没有余数的换算用 `UNNECESSARY`（规范 02 §6）。
3. **任务编号**：编号由负责人先在任务索引登记再派发；代理开工前核对编号未被占用，冲突时停下报告（规范 08 §6）。
4. **类行数与枚举**：只写成【推荐】，类不超过约 500 行，有限取值用枚举（规范 02 §1）。不加自动检查。
5. **版本号**：镜像与交付包的版本只以发布标签为准，工程版本号是开发版本，发布时不改（规范 08 §8）。
6. **其余条款按现状修正**：规范 05 必测清单改为现行口径；规范 06 写明 300MB 例外；规范 11 看板小节加暂缓说明，条款不删；规范 10 删除旧字号表，改为指向规范 13；规范 09 移到 `docs/99-过程稿/`。
7. 两端共享代码的机制（M-22 第三项）不在本 ADR 内，随审查 S-04 另开任务。

## 备选方案及放弃原因

- **引入 springdoc**：需要新增依赖，还要给全部接口补注解；单人加 AI 开发，接口清单已经在设计说明书里维护。放弃。
- **统一改成 `HALF_UP`**：会把本应暴露的数据错误静默舍入掉。放弃。
- **类行数上限设为【强制】并接入 Checkstyle**：现有大类较多，强制会立刻阻断 CI，需要先单独规划拆分。放弃。
- **每次发版前改四个工程的版本号**：要多维护一个步骤，镜像标签已经能唯一标识版本。放弃。

## 影响

- 规范 README 升到 V1.5；规范清单去掉 09。
- 历史执行报告中的规范 09 路径和 OpenAPI 表述不回改。
- 之后审查 PR 时，「接口变更已同步设计说明书接口清单」取代原 OpenAPI 检查项。
