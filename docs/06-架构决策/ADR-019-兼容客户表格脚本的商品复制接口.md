# ADR-019：提供与客户表格脚本兼容的商品复制接口，并按复制商品 ID 中转跳转

- 状态：已接受（2026-10-16）；第 4 条复制实现于 2026-10-18 由负责人定稿（目标店铺、失败处理、额度、加价）；2026-10-17 修订第 2 条（复制令牌的保存、数量、额度与管理页，沿用原系统「TOKEN管理」）
- 决策人：项目负责人
- 相关：[ADR-012](ADR-012-跳转服务不回源后台.md)、[ADR-013](ADR-013-链接索引采用事务内登记与后台同步.md)、[ADR-016](ADR-016-微店店铺授权与凭证加密.md)、设计说明书 §4.3、§4.4、§6.5、§7.4

## 背景

客户 2026-10-15 提供了现用的 Google 表格脚本（Apps Script 3.0.5，`docs/00-需求/客户补充资料-1015/prod5(2).zip`）。2026-10-14 会议确认了推广链接的生成方式：

1. **准备表格**：运营准备一张商品表，每行一个商品，链接列是微店商品链接或代购平台链接。
2. **跑脚本**：每来一位新达人，在表格里运行一次脚本，填入该达人的令牌（Token）和邀请码，并选择一个**链接模板**。
3. **发起复制**：脚本把各行的来源商品 ID 发给后端的复制接口，后端为该达人在微店复制商品，返回复制后的商品 ID。
4. **写回链接**：脚本用「模板 + 邀请码 + 复制后的商品 ID」拼出新链接，写回单元格。

脚本调用的后端地址可以配置（脚本属性 `TALENT_CRM_API_BASE_URL`），默认指向旧系统，调用的是旧系统的 5 个外部接口：

| 接口 | 用途 |
|---|---|
| `GET /external/product-links/templates?channelCode=WEIDIAN` | 取链接模板列表：`id`、`templateCode`、`templateName`、`templateUrl`（含 `{PRODUCT_ID}`，可含 `{INVITE_CODE}`）、`channelCode`、`sortOrder` |
| `POST /external/product-links/convert` | 提交复制任务：`{token, callerPlatform, items:[{sourceChannelCode, sourceProductId, ruleId}]}`，返回 `{jobCode}` |
| `POST /external/product-links/jobs/{jobCode}/items/resolve` | **V2 主流程**：脚本每批最多 50 个单元格调用一次，请求 `{token, items:[{sourceChannelCode, sourceProductId}]}`（批内去重）。响应 `{jobCode, status, resultVersion, items}`：`status` 为 `ready` / `preparing` / `job_pending`，非 `ready` 时脚本稍后重试；`ready` 时 `resultVersion` 为非空字符串，`items` 与请求条数相同、每个来源恰好一条，每条 `status` 为 `success` / `failed` / `not_found` / `conflict` / `already_applied`，成功时带 `targetChannelCode`、`targetExternalProductId`、`targetStoreId`（均为字符串，商品 ID 为纯数字） |
| `GET /external/product-links/jobs/{jobCode}` | 旧路径，任务进度：`status`（`completed` / `failed` / `partial_failed` 表示结束）、`totalCount`、`successCount`、`failCount` |
| `GET /external/product-links/jobs/{jobCode}/items` | 旧路径，任务明细数组：`sourceChannelCode`、`sourceProductId`、`status`（`success` 为成功）、`targetChannelCode`、`targetExternalProductId`、`targetStoreId` |

脚本接受的响应是 JSON，`code` 为 0 或 200（或 `success` 不为 false）时取 `data`，与本系统 `{code:0, data}` 的统一信封兼容。

链接模板里约有 20 个代购平台（kakobuy、cnfans、mulebuy 等）。**最终链接由脚本自己拼接**，后端只返回复制后的商品 ID。因此若沿用代购平台模板，表格里的链接不经过跳转服务，也就没有点击统计；而客户 10-11 答复「中转链接、点击统计仍然需要」。

## 决定

1. **兼容旧接口**：后台按上表的路径、参数和响应字段实现这 5 个接口，统一挂在 `/admin-api/external/product-links/**`。客户只需把脚本属性 `TALENT_CRM_API_BASE_URL` 改为 `https://admin.域名/admin-api`，**脚本代码不改**。
   - 字段名和状态值严格照旧（`success`、`completed` 等小写字符串）。
   - 本系统新增的字段只能追加，不能改名。
   - 测试用脚本实际发出的请求和期望的响应做契约测试。
2. **认证**：
   - **复制令牌**：`convert` 用请求体里的 `token` 认证。令牌是为某位达人签发的**复制令牌**，由有 `kol:copy-token` 权限的账号在后台生成。认证时按 SHA-256 查找；明文另用 `SecretCipher` 加密保存，有权限的人可在「复制令牌」列表中再次复制，每次复制写操作日志（2026-10-17 负责人修订，原为「明文只显示一次」）。
   - **有效期与额度**：生成时填写额度和有效分钟数，默认取公司配置（如 1,000 个、1440 分钟），仿照旧系统的 Token。同一达人可以同时有多个有效令牌，各自计量，可单独作废（2026-10-17 负责人修订，原为「重新生成会作废旧令牌」）。
   - **管理页**：沿用旧系统「TOKEN管理」：列出全部令牌（脱敏），按令牌、达人、渠道、状态筛选，显示使用量、有效分钟、过期时间与状态（有效 / 已用尽 / 已过期 / 已作废）。
   - **令牌决定归属**：令牌决定公司和达人，请求里不接受公司或达人 ID。
   - **`items/resolve`**：请求体同样带 `token`，令牌须属于该任务的达人。
   - **其余三个接口**：脚本请求时不带令牌。模板只包含公开的代购平台地址，不算敏感信息；两个旧路径的任务编号是 128 位随机值，持有编号才能查询，查询结果只包含商品 ID。
   - **限流**：5 个接口都按来源 IP 限流，`convert` 与 `items/resolve` 另按令牌限流。
   - **`items/resolve` 的状态**：请求的各条都已处理完时返回 `ready`；否则返回 `job_pending`。`preparing` 不使用。每条明细的状态：
     - `success`：已复制，带复制商品 ID；
     - `failed`：复制失败；
     - `not_found`：该来源不在本任务中；
     - `conflict`：来源商品在本公司多个店铺中都能找到，无法确定；
     - `already_applied`：来源 ID 本身就是该达人已有的复制商品 ID，即这一格已经替换过，重复运行脚本时出现。
   - **`resultVersion`**：取任务最近一次更新的时间戳。
3. **链接模板**：
   - 模板表 `crm_link_template` 按公司维护代购平台模板，由超级管理员管理。
   - 列表中固定追加一个**「T-CRM 中转」模板**，`templateUrl = https://t.域名/i/{PRODUCT_ID}`。
   - 运营在脚本中选这个模板时，表格里写入的是中转链接：点击先经过跳转服务计数，再 302 到该达人的代购平台链接（达人档案中的代购平台模板 + 邀请码 + 复制商品 ID）。
   - 选其他模板时，链接直达代购平台，没有点击统计。由客户按场景选择；系统推荐中转模板。
4. **复制实现**（2026-10-18 负责人定稿）：`convert` 只建任务、立即返回任务编号，由后台工人逐条处理。每一条：
   1. 在本公司启用的店铺中找到来源商品，并登记或更新为原商品（`crm_product`）；
   2. 若该达人已有这件原商品的有效对应关系，直接返回已有的复制商品 ID，不重复复制；
   3. 否则调用微店接口复制到目标店铺：读取商品与详情，再新增商品并保存详情，即 09a 已定义的 `vdian.item.get`、`vdian.item.getItemDetail`、`vdian.item.add`、`vdian.item.saveItemDetail`；
   4. 写入对应关系 `crm_kol_item`，并登记链接索引（ADR-013）。

   - **目标店铺**：令牌指定了店铺时复制到该店铺；否则复制到本公司的**默认复制店铺**（超管在店铺管理中把一个店铺标为默认复制店铺，`crm_shop.copy_target`，每家公司最多一个）。目标店铺必须启用并已完成微店授权。既没有指定也没有默认店铺时，`convert` 直接拒绝。
   - **失败处理**：某一条复制失败时，该条状态为 `failed` 并带原因，**系统不做业务层重试**；微店接口的临时网络错误仍由接口网关（09a）自动重试。商务重新运行脚本即发起新的请求，已复制成功的直接返回已有结果，失败的会再次尝试。
   - **额度**：每次真正调用微店复制前扣减 1 个额度（`CopyTokenApi.consume`）；已有对应关系、`already_applied` 不扣；额度不足时该条为 `failed`（原因「额度不足」）。
   - **加价**：不加价，照原价复制；脚本传来的加价参数（`markUp` 等）忽略。
5. **按复制商品 ID 跳转**：跳转服务新增 `GET /i/{weidianItemId}`。
   - Redis 新增 `HASH linkitem:{末两位}`（按商品 ID 末两位分 100 个桶），field 为复制商品 ID，value 与现有链接索引同为 JSON：`{"kolItemId","targetUrl","status"}`。
   - 由 `link` 模块与 `link:{kolCode}` 在同一把达人锁内一起写入、一起重建。
   - 跳转服务仍只读 Redis、不回源后台（ADR-012）。现有 `/t/{kolCode}/{productCode}` 保留。
   - 微店商品 ID 全平台唯一，跳转服务不需要知道公司。
6. **跳转目标**：两种中转链接的 `targetUrl` 统一改为：
   - 达人设置了代购平台和邀请码：用该代购平台的模板，代入邀请码和复制商品 ID；
   - 否则：`https://weidian.com/item.html?itemID={复制商品 ID}`。

   达人的代购平台、邀请码或模板地址变化时，登记该达人的链接索引刷新（ADR-013 的 `KOL` 范围）。

## 影响

- 推广表格由客户的脚本在客户自己的 Google 账号里生成和维护，CRM 只记录表格地址（设计说明书 §4.4）。原计划由 CRM 调用 Google API 建表的任务 07 推迟，作为以后的可选功能保留。
- 链接索引的 Redis 内存约增加一倍：同一条复制商品写入两个 hash。按 200 万条复制商品估算，约多占 330MB，接近生产 `maxmemory 1280mb` 的一半。超过约 300 万条时需要调高 Redis 上限（设计说明书 §7.4）。
- 对外开放的接口多了 5 个，其中只有 `convert` 有写操作；`convert` 与 `items/resolve` 必须带有效的复制令牌。

## 备选方案及放弃原因

| 方案 | 放弃原因 |
|---|---|
| 重写表格脚本，或由 CRM 用 Google API 生成表格 | 客户已在用这套脚本；兼容接口改动最小，也不需要 CRM 持有客户 Google 账号的写权限 |
| 只提供代购平台模板，不做中转 | 失去点击统计，与客户「需要点击统计」的答复冲突 |
| 中转链接沿用 `/t/{kolCode}/{productCode}` | 脚本只能代入 `{INVITE_CODE}` 和 `{PRODUCT_ID}`，拿不到达人编号和原商品编码 |
| 中转链接用 `/t/{邀请码}/{商品 ID}` | 邀请码是代购平台的推广码，各平台之间可能重复，也可能变更，不能作为主键 |
| 模板与两个旧路径也要求令牌 | 脚本请求它们时不带令牌，要求令牌就得改脚本；这几个接口的数据不敏感 |
