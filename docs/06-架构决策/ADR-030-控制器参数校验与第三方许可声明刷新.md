# ADR-030：控制器参数校验与第三方许可声明刷新

- 状态：已接受
- 日期：2026-10-22
- 关联：规范 02、03、07；`AGENTS.md`；审查共性问题集中修复（#99）

## 背景

对开放 PR #92–#98 的审查中，归纳出三类跨任务共性问题：

1. 若干新/旧 Controller 为启用路径参数约束而加了类级 `@Validated`；在 Spring Framework 6.1+ / Boot 4 下，这会改走 AOP 方法校验，失败可能变成 `ConstraintViolationException` 并以 500 返回，而不是统一的 400 信封。
2. 管理端 `formatInstant` 等时间展示曾写死 `zh-CN`，英文界面日期排版仍像中文。
3. Dependabot 只改 `package.json` / 锁文件时，`THIRD-PARTY-NOTICES` 未同步刷新，本机 `notices:check` 失败。

规范修改须按规范 08 第 7 节记录 ADR。

## 决定

1. **Controller 不加类级 `@Validated`**：`@RestController` 禁止类级 `@Validated`。路径 / 查询参数上的 `@Min` / `@Max` / `@NotBlank` 等由 MVC 内建校验处理，失败走 `HandlerMethodValidationException` → `GlobalExceptionHandler` → 400 + `COMMON_VALIDATION_FAILED`。类级 `@Validated` 留给 `@Service` 等需要方法级校验的 Bean。ArchUnit 禁止 Controller 带类级 `@Validated`。
2. **时间按界面语言显示**：`formatInstant` / `formatInstantToMinute` 必须按当前界面语言调用 `Intl`（或等价 API），禁止写死 `zh-CN` / `en-US`。「名称（编码）」走 `common.nameWithCode` / `formatNameWithCode`：中文全角括号、英文半角括号。
3. **Dependabot / 锁文件变更后刷新 notices**：合并前必须刷新 `THIRD-PARTY-NOTICES`。本地执行仓库根目录 `scripts/refresh-notices.sh`（依次刷新 admin-ui、kol-portal、backend、redirect），把变更的 notices 与依赖变更一并提交。PR 模板与 Dependabot 配置同步提示该步骤。

## 备选方案及放弃原因

- **继续在 Controller 上使用类级 `@Validated`**：与 Boot 4 / MVC 内建校验冲突，切片测试易出现 500，放弃。
- **仅在 CI 自动改写 notices 并推回**：当前 GitHub Actions 额度不足且规范要求本机可验证；以本机脚本为准，放弃依赖 CI 自动改写。
- **时间格式继续固定中文区域**：违背 ADR-015 中英文切换目标，放弃。

## 影响

- 已有误加类级 `@Validated` 的 Controller（如任务 38/39）须在合入本 ADR 后的对应 PR 中去掉；路径参数 `@Min(1)` 保留。
- 订单等前端页硬编码全角括号的展示，后续 PR 改用 `formatNameWithCode`。
- 选择器全量列表与分页列表分开的接口约定见规范 03 第 6 节（本 ADR 不重复展开）。
