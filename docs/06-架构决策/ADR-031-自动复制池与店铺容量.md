# ADR-031：自动复制池与店铺容量

- 状态：已接受
- 日期：2026-10-22
- 取代：ADR-019 第 4 条中“未指定店铺时使用公司的默认复制店铺”规则

## 背景

任务 37 要求公司可以维护多个承接复制的微店，并按在售商品容量选择复制目标。单一 crm_shop.copy_target 标记无法表达池状态、源店铺和目标容量，也不能避免并发复制任务超卖。

## 决定

1. crm_shop 使用 is_source 与 copy_pool_status 表达源店铺和自动复制池成员关系；迁移时把旧 copy_target = true 转为 JOINED，其余转为 EXITED，随后删除旧列。
2. 复制目标必须属于当前公司、渠道相同、启用、授权有效、非源店铺、已加入复制池且有未预留容量。
3. 令牌未指定目标店铺时，在复制任务创建时选剩余容量最大的单店；不把一个任务拆分到多个店铺。
4. 创建任务时锁定候选店铺行，并将处理中任务的待处理明细计入容量预留；复制成功后原子增加 current_items。失败或成功状态变更在事务提交后释放预留。
5. 容量刷新仅在微店商品列表接口成功后覆盖商品数及刷新时间；失败保留上次成功值。
6. 店铺上限默认配置为每家公司 20 家。

## 考虑过的方案

- 保留单个默认目标店铺：实现简单，但不满足自动池与按容量分配需求。
- 按任务商品数拆分到多店：能利用零散容量，但违反单个复制任务只使用一个店铺的约束，也会增加脚本与任务结果复杂度。
- 只在复制成功后增加商品计数：并发任务创建时看不到未完成工作，存在多个任务同时使用同一空余容量的竞态。采用数据库行锁和待处理任务预留。

## 影响

- 产品模块拥有店铺编码、容量、复制池、分配与预留规则；kol 模块通过 CopyTargetShopApi 查询容量、校验指定店铺和分配目标。
- integration 模块通过公开 API 提供授权状态、商品容量刷新与三类接口探测。
- 商品列表接口使用在售商品总数字段、状态枚举和真实账号下的接口行为须在 M0 验证；自动化测试以模拟服务器覆盖请求/响应解析。
- 数据库新增 crm_shop 字段并移除 copy_target；迁移范围为任务 37 分配的版本段。
