# ADR-028：补全前端工程与需求验收规范

## 背景

工程规范 V1.0（2026-10-04）对后台写得很细，前端只有规范 01 第 6 节的目录结构和规范 02 第 7 节的十条编码规则。页面怎么搭、必须用哪些公共组件、未实现的功能怎么处理、做完怎么验收，都没有写，只能由架构负责人在每个任务提示词里临时补充。到 2026-10-21，这个缺口造成了以下问题：

- 任务 32 第一版按截图而不是进度表「功能说明」原文设计，列表列和弹窗字段与客户要求不符；
- 任务 36 的代理自行制定字体规则，合并、增删了《网页字体字号规范.xlsx》的条目；同一个视觉 PR 还附带了 1020 客户补充表的业务改动（后端接口、迁移脚本）；
- 任务 34 的代理两次把改动写进主目录，影响负责人的预览构建；
- 任务 34 在后台新增了必填环境变量，但 Compose 文件没有传给后台，单元测试和集成测试都没查出来，预览和生产都无法启动（#87 修复）。

「进度表是需求依据」「代理只在自己的工作树中写文件」「共享数据库的使用规则」等规则此前只写在任务提示词里，没有写进规范，也没有自动检查。

## 决定

1. 新增规范 11《前端工程规范》：页面目录、管理端公共组件（`ListSearch`、`DataTable`、`RowActions`、`CopyText`、`ImportDialog`）、列表与弹窗的标准写法、权限、接口与错误处理、国际化、状态管理、「开发中」占位、样式与前端测试。按两端现有代码写成。
2. 新增规范 12《需求与验收规范》：需求依据顺序（签约范围 → 进度表功能说明 → 已登记的客户补充表 → 负责人决定 → 设计说明书）、字体以 xlsx 为准、客户补充资料的登记流程、任务提示词内容、逐条复核表、浏览器验收矩阵、配置与部署变更必须实际启动、审查与合并。
3. 规范 08 新增第 9 节「本地环境与 AI 代理协作」：工作树隔离、子代理工作目录、共享中间件规则、共享库迁移校验和由架构负责人处理；第 4 节增加 GitHub Actions 暂停期间以本地复跑代替 CI 的临时条款；业务与视觉改动分开提 PR。
4. 规范 06 第 5 节：`application.yml` 中不带默认值的占位符必须在生产和预览 Compose 中传给对应服务并列入 `.env.example`；新增 `deploy/scripts/check-compose-env.py` 自动检查，部署工作流增加该步骤，并在 `application*.yml` 改动时触发。
5. `AGENTS.md` 同步摘要。
6. 行操作：规范 10 第 1 节按字体表要求「操作过多时收进『更多』」，管理端统一使用 `RowActions`（默认直接显示前 2 个）。**本条替代 ADR-026 中「不将六个操作收进『更多』」的取舍**；操作的顺序、权限和禁用规则仍按业务定义不变。**（本条已被 ADR-029 替代：行操作全部直接显示。）**

## 备选方案及放弃原因

- 继续只在任务提示词中写规则：每个提示词都要重复，代理之间各自理解，已经多次出错。
- 给 Claude Code 代理加钩子，禁止写入主目录：只对 Claude Code 生效，对 Codex 等代理无效；子代理的工作目录也可能就是主目录，钩子无法区分。暂不采用，以规范、提示词和审查前检查主目录 `git status` 为准，负责人另行决定是否增加。
- 引入 stylelint 拦截数值字号：需要新增依赖；改用现有 Vitest 扫描（任务 36 的 `tokens.spec.ts`）达到同样效果。

## 影响

- 新任务的提示词、执行报告和 PR 审查按规范 11、12 执行；执行报告必须包含逐条复核表。
- 抽查现有页面与规范 11 基本一致；差异登记在规范 09 第 9 节，在涉及该页面的任务提示词中写明后整改。
- 部署工作流的触发范围扩大到两个工程的 `application*.yml`。
