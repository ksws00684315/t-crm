# ADR-021：原商品以 Google 商品源表为主要来源，Excel 导入为兜底

- 状态：已接受（2026-10-16）
- 决策人：项目负责人
- 相关：[ADR-016](ADR-016-微店店铺授权与凭证加密.md)、[ADR-019](ADR-019-兼容客户表格脚本的商品复制接口.md)、设计说明书 §3.4、§4.3、§4.4、§5.2、§6.2、§7.2

## 背景

需求说明书第六章要求「后台批量导入微店原始商品链接库」，第七章要求对接 Google Sheets API。客户 1015 流程图中，CRM 一列的步骤是：

1. 商务配置完成；
2. 系统调取 Google 接口，读取**商品源表**中的链接；
3. 运行脚本复制商品；
4. CRM 关联达人与商品。

2026-10-16 修订设计时，推广表格改由客户脚本生成（ADR-019），系统「一期不调用 Google API」，原商品只能通过 Excel 导入。负责人 2026-10-16 明确：

- 优先读取 Google 在线表格；
- 手工导入只作为兜底；
- 由架构负责人亲自实现。

客户的商品源表是私有表格（打开需要登录 Google），每行一个商品：

- 链接列显示文字为「LINK」，实际地址以单元格内嵌链接保存，可能是微店链接，也可能是包着微店链接的代购平台链接；
- 另有名称、价格（美元，如 `$60`）、图片等列；
- 表头不在第 1 行（样表第 2 行是表头，第 3 行起是商品）。

后端部署在海外服务器，可以直连 Google（负责人 2026-10-16 确认）。

## 决定

1. **读取对象**：系统读取超管配置的**商品源表**，按商品链接新增或更新**原商品**。原商品 Excel 导入保留为兜底。
   - 达人的个人推广表格仍由客户脚本生成（ADR-019），本决定不建表、不写表；
   - 表格回写见设计 §4.4 第 5 条。
2. **认证**：每家公司一个 Google 服务账号。
   - 客户在自己的 Google Cloud 项目中创建服务账号、启用 Sheets API、下载 JSON 密钥；
   - 超管在管理端上传密钥，私钥用 `SecretCipher` 加密保存，只能写入、不能读出，界面只显示服务账号邮箱；
   - 客户把每张源表分享给该邮箱，「查看者」权限即可。
   - 权限范围只申请 `spreadsheets.readonly`。
3. **不引入 Google 官方 Java 客户端**：只用到「换取访问令牌」和「读取表格」两个 HTTP 接口。
   - 服务账号 JWT 用 JDK 的 `SHA256withRSA` 签名，换取 1 小时有效的访问令牌，内存缓存，到期前 5 分钟刷新；
   - 读取用 `spreadsheets.get`，参数 `includeGridData=true`，每个需要的列各请求一个范围，并用 `fields` 只取单元格的显示文字、链接、公式与文字片段链接；
   - 两个接口的地址可配置，供测试替换为本地桩。
   - 读取接口定义为 `product.api.SourceSheetReader`，由 `integration` 模块的 Google 客户端实现：`integration` 已依赖 `product.api`（微店集成读取店铺），`product` 再依赖 `integration` 会形成模块循环。
4. **源表配置**（超管）：
   - 名称、表格地址（解析出表格 ID）、页签名、表头所在行；
   - 列字母：链接、名称、价格必填，分类、图片可选；
   - 默认店铺：链接里没有店铺 ID 时使用；
   - 价格货币：ISO 4217，默认 `USD`。
5. **解析规则**，与客户脚本 3.0.5 保持一致：
   - **取链接**：单元格内嵌链接 → `=HYPERLINK("…")` 公式 → 以 `http` 开头的文字。
   - **识别平台**：URL 解码后包含 `taobao` 或 `1688` 的不是微店商品，跳过并报告。
   - **取商品 ID**：先取 `itemID=` 后的数字，再取 `/weidian/` 后的数字，最后取第一个独立的 10 位数字。
   - **取店铺**：取 `shop{数字}.v.weidian.com` 中的数字；取不到时用源表的默认店铺。
   - **短链接**：不跟随跳转，因为系统不向表格中的任意地址发请求；解析不出商品 ID 的行跳过并报告。
   - **图片**：只识别 `=IMAGE("https://…")` 公式。插入在单元格上方的图片无法通过接口读取，不处理。
   - **价格**：如果文字中有所配置货币的符号（`$`、`¥`、`€`、`£`），取紧跟该符号的数字，否则取第一个数字；去掉千分位。
   - **跳过空行**：链接列为空的行（例如分类标题行）直接跳过，只计数。
6. **处理方式与 Excel 导入相同**：
   - 读到的行转换为「原商品导入」的行，生成工作簿，提交同一种导入任务，复用同一套校验、进度与错误文件；
   - 新建的原商品编码自动生成、状态为在售；已有的按（店铺，微店商品 ID）更新名称、分类、图片、价格与货币，编码与状态不变。
   - 一次最多 50,000 行。
7. **源表中消失的商品不自动下架**（负责人 2026-10-16）：
   - 系统记录每次读取看到的（店铺，商品 ID）；
   - 列出「源表中已不存在」的原商品，由运营决定是否下架。
8. **只手动读取**（负责人 2026-10-16）：管理端「立即读取」，不设定时任务。同一源表读取期间持分布式锁，重复点击返回 409。
9. **价格货币**：
   - 原商品新增 `price_currency`，默认 `CNY`；
   - 源表读取写入源表配置的货币；
   - Excel 导入新建时为 `CNY`，更新时不改货币；
   - 佣金按订单实付计算，与展示价无关。
10. **权限**：
    - 服务账号与源表配置：超管专属；
    - 「立即读取」、查看读取结果与「已不存在」列表：`product:edit`；
    - 源表列表：`product:view`。

## 后果

- 运营维护商品的主要方式变为「在源表里改，然后点立即读取」。Excel 导入仍可用，规则与源表读取完全相同。
- 新增两张表（源表配置、源表商品快照）和一张凭证表；原商品增加货币字段。
- 客户需要自行创建 Google 服务账号，并把源表分享给它。这一步写进部署说明。
- 被替代的说法：设计 §4.4 第 4 条「本系统一期不调用 Google API」、§7.2「一期不接入」。推广表格仍不由系统生成。
