# ADR-012 跳转服务不回源后台

- 状态：已接受（2026-10-06）
- 决策人：项目负责人（任务 06 提示词 §4.4）

## 背景

设计说明书 §4.5 原写"跳转服务只读 Redis；Redis 未命中时调用 `crm-admin` 内部接口回源并回填缓存"，任务 01 据此在 `RedirectService` 留下 `TODO(task-01)`，等待"内部链接接口"。

任务 06 实现了链接索引的写入方：`crm-admin` 在对应关系、达人、商品、店铺变更提交后增量更新 `HASH link:{达人编号}`，并每天 04:30（UTC）及超管手动触发时全量重建（设计说明书 §7.4、§9）。在此前提下需要决定未命中时是否仍回源。

## 决定

1. 跳转服务**不回源**：`HGET` 未命中、值无法解析或 `status` 为 0 时，一律 302 到回退地址（`TCRM_REDIRECT_FALLBACK_URL`），不调用后台、不写点击事件。
2. 不新增后台内部链接接口，也不为跳转服务与后台之间引入共享密钥。
3. 索引完整性由写入方负责：事务提交后的增量更新 + 每日全量重建（修复漏更新、删除多余 key）；增量更新失败只记 `ERROR` 日志，由当天的全量重建修复。
4. 删除 `TODO(task-01)`，改为注释说明"未命中即链接不存在，跳回退地址"。跳转服务行为不变。

## 备选方案及放弃原因

| 方案 | 放弃原因 |
|---|---|
| 未命中时回源后台并回填缓存（原设计） | 任意随机路径都会穿透到后台数据库，恶意扫描可以放大为数据库压力；需要新增内部接口、鉴权与共享密钥，增加一个跨服务的故障点；且索引已由写入方保证完整，回源只能查到"不存在" |
| 回源 + 空值缓存（防穿透） | 仍需内部接口与密钥；空值缓存会在新链接生效时造成短暂"不可用"，与增量更新互相干扰 |
| 跳转服务直连数据库 | 违反规范 01（跳转服务只依赖 Redis，与后台不共享代码与数据访问），并扩大数据库暴露面 |

## 影响

- 增量更新与全量重建之间若出现遗漏（例如提交后 Redis 短暂不可用），最长到下一次全量重建（当天 04:30 UTC）或超管手动重建前，对应链接会跳到回退地址；不会产生错误点击记录。
- 索引遗漏或陈旧由 ADR-013 的机制保证在数秒到数分钟内修正，不再依赖每日重建。
- Redis 数据丢失（无持久化或重建实例）后，需要超管在管理端点击"重建链接索引"立即恢复；否则等到下一次定时重建。部署说明中写明该操作。
- 跳转服务的可用性只依赖 Redis，与后台、数据库的故障隔离。
