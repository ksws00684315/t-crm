# ADR-033：看板图表组件与 ECharts 使用规则

- 状态：已接受（2026-10-27）
- 决策人：项目负责人
- 补充：ADR-010（ECharts 依赖链许可证）、ADR-028（前端工程规范）

## 背景

任务 42 要为「经营分析」看板（任务 48～51）建立公共底座，管理端第一次引入图表。负责人已于 2026-10-21 同意引入 Apache ECharts；达人端 `package.json` 中已有 `echarts 6.1.0`（ADR-010），但还没有页面使用。

规范 11 只规定了列表和弹窗的公共组件，图表怎么引入、看板页由哪些组件组成，此前只写在任务 42 的提示词里。四个看板模块会在任务 42 合并后并行开发，如果这些规则不写进规范，每个代理都可能各自封装一套图表、各自格式化数值，结果又会出现列表页那种不一致（见 #107）。

## 决定

在规范 11 第 2 节新增「看板与图表」小节：

1. 图表只用 Apache ECharts，两端版本一致且写死（当前 6.1.0）；不引入其他图表库或 ECharts 的 Vue 封装包。
2. 按需引入，注册代码集中在一个文件里。
3. 看板页必须使用 `DashboardFilter`、`QuerySummary`、`MetricCard`、`ChartPanel` 四个公共组件，页面不直接创建 ECharts 实例，并按固定顺序排列。
4. 金额、比例和空值的格式统一；图表的颜色和字号从令牌读取。
5. 单元测试 mock 图表注册文件，实际渲染在浏览器验收中确认。

## 理由

- 只允许一个封装（`ChartPanel`）创建实例，自适应、销毁、深色模式、四种状态和语言切换才能一处实现、一处测试。
- 不引入 Vue 封装包：`ChartPanel` 本身就是这层封装，再加一个依赖没有收益（规范 07：新增依赖须说明理由）。
- 按需引入能控制管理端的包体积，也只需要为实际注册的图表类型做浏览器验收。
- 组件的名称和职责沿用任务 42 提示词第 4 节的约定，不另起名字。

## 影响

- 任务 42 按本节实现四个组件。任务 48～51 只复用这些组件，不另写图表封装。
- 达人端如需图表（例如任务 50 的达人本人视图），同样遵守版本与按需引入的规则；组件是否移植到达人端，由该任务提示词决定。
- 修改规范 11 的版本号为 V1.2。
