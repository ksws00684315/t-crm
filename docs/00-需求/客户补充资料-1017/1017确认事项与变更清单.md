## 1. 已确认的规则

### 1.1 达人身份与状态

| 编号 | 规则 | 来源 |
|---|---|---|
| R1 | 达人编号：`KOL-` + 3 位随机大写字母 + 按公司注册顺序递增的数字（至少 3 位，不足补零，超过 999 自然变成 4 位），例如 `KOL-ASD001`。系统未上线，直接改生成规则，不迁移旧编号 | 表 03.01；负责人 |
| R2 | 达人只能通过商务的邀请链接注册，注册后自动归入该商务 | 表 01.01；纪要 |
| R3 | 注册表单必填：邮箱（即账号，6 位验证码）、WhatsApp、核心社媒平台、核心社媒 ID、密码。「对接商务名称」暂时忽略 | 表 02.01；负责人 |
| R4 | 五种状态：待审核（注册后）、待推广、推广中、合作结束、待更新。**全部由商务手动修改**；上传推广表不自动改状态 | 表 03.01、04.01；负责人 |
| R5 | 「待更新」：达人没有绑定在职商务时，系统**自动显示**为待更新，期间业绩归管理员；重新绑定后恢复原状态 | 表 04.02；纪要；架构设计取舍 |
| R6 | 商务的达人列表只显示已绑定的达人；未绑定的达人只能按 ID 或邮箱精确搜索后认领 | 表 03.02 |
| R7 | 审核页：商务可编辑除邮箱和达人编号以外的信息 | 表 04.02 |
| R8 | 推广配置（「待推广」时填写）：佣金比例、代购平台（多选，平台清单可维护）、达人专属落地页地址、达人邀请码、备注；推广表格地址选填。所有填写与修改留存记录 | 表 04.03；纪要 |
| R9 | 清理配置：运营设定「X 天未出单」的达人自动清理。**逻辑删除**，关联的达人商品对应关系一并逻辑删除；微店侧不处理 | 表 04.01；负责人 |

### 1.2 推广链接与销售追踪

| 编号 | 规则 | 来源 |
|---|---|---|
| R10 | 第一版：商务在谷歌表格中用现有脚本完成链接替换，再把推广表**上传到系统**，系统按表中的微店链接把商品 ID 关联到达人。暂不由系统自动生成或写入谷歌表格（ADR-021 不变；表 12.x 为后续评估项） | 纪要「关键决策」；表 08.01、08.02 |
| R11 | 销售追踪：订单按「微店商品 ID → 达人」归属，数据全部来自微店接口；链接中不需要嵌入系统的达人编码 | 纪要 |
| R12 | 原需求推广表中的 4 个 sheet 不再保留；商品、订单、成交数据在系统内展示（达人端「我的商品」「我的订单」） | 纪要 |
| R13 | 复制令牌沿用原系统「TOKEN管理」（任务 17a）。脚本的接口地址可配置（`TALENT_CRM_API_BASE_URL`），对外复制接口（17b）完成后切换到本系统 | 表 07.01；脚本 3.0.5 |

### 1.3 订单与佣金

| 编号 | 规则 | 来源 |
|---|---|---|
| R14 | 订单兜底导入的字段以微店接口文档为准（任务 18 的模板已按接口字段设计） | 表 16.03；负责人 |
| R15 | 佣金 = 微店回传的**可提现金额** × 达人佣金比例；可提现金额从微店接口取得。暂不设固定结算周期，按微店的待结算、可提现字段调整 | 表 18.01；纪要；负责人 |
| R16 | 最低提现额可在后台配置，初期 200 元人民币 | 表 18.03；纪要 |
| R17 | 达人看到预估、可提现、申请中、已付金额，明细可追溯到订单 | 表 18.02 |
| R18 | PayPal 收款账户增加币种 | 表 19.01 |
| R19 | 系统不实际打款：审核通过后由管理员在系统外付款，再登记结果并上传凭证，可查询和导出 | 表 20.01；权限表 |
| R20 | 不设独立财务角色；财务操作只由管理员执行。预付、结算审批暂不开通 | 权限表 |
| R21 | 商务离职后的归属调整放在二期（任务 16、16b 已实现基础能力，不受影响） | 纪要 |
