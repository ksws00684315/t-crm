# 04 数据库规范

> 数据库：**PostgreSQL 17**（见 ADR-005）。命名、索引、建表约束参考《阿里巴巴 Java 开发手册》数据库章节，类型与语法按 PostgreSQL 调整。

## 1. 建表

【强制】表名、字段名使用小写字母、数字、下划线，不以数字开头；单数名词；不使用 PostgreSQL 保留字；不使用需要双引号包裹的标识符。
【强制】表名前缀表示归属：`sys_` 系统、`crm_` 业务、`agg_` 汇总。
【强制】数据库编码 `UTF8`；业务表建在 `public` schema，由应用账号拥有。
【强制】每张表、每个字段都用 `COMMENT ON TABLE` / `COMMENT ON COLUMN` 写注释；枚举类字段在注释中列出全部取值及含义。
【强制】必备字段（日志、点击、汇总等只追加的表可省略修改类字段与逻辑删除，须在表注释中说明）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `BIGINT NOT NULL` | 主键，雪花算法生成（不使用自增序列，避免 ID 可猜测）；用 `CHECK (id > 0)` 约束 |
| `create_by` | `BIGINT NULL` | 创建人，系统操作为空 |
| `create_time` | `TIMESTAMPTZ(3) NOT NULL` | 创建时间 |
| `update_by` | `BIGINT NULL` | 修改人 |
| `update_time` | `TIMESTAMPTZ(3) NOT NULL` | 修改时间 |
| `is_deleted` | `BOOLEAN NOT NULL DEFAULT FALSE` | 逻辑删除 |

【强制】业务表（`sys_`、`crm_`、`agg_`）必须有 `tenant_id BIGINT NOT NULL`（所属公司），子表也直接带，不靠关联主表判断；例外只限设计说明书 §3.4 所列（`sys_tenant`、`crm_link_index_outbox`，以及 `sys_user`、`sys_oper_log` 的平台级记录可为空）。新增例外须写 ADR（任务 06c 起执行，见 ADR-014）。
【强制】禁止外键约束和级联操作（批量导入、分区表、按需重算均不受外键约束牵制）；关联完整性由应用层保证并有测试覆盖。
【强制】禁止在存储过程、触发器、视图中写业务逻辑（`update_time` 等由应用填充，不用触发器）。
【推荐】使用 `CHECK` 约束限定枚举与状态取值。

## 2. 字段类型

| 数据 | 类型 |
|---|---|
| 金额 | `NUMERIC(14,2)`；禁止 `REAL`、`DOUBLE PRECISION`、`MONEY` |
| 比例 | `NUMERIC(6,4)` |
| 时间点 | `TIMESTAMPTZ(3)`；禁止不带时区的 `TIMESTAMP` |
| 日期（统计日） | `DATE`，在注释中写明所用时区 |
| 布尔 | `BOOLEAN`，字段名 `is_xxx`；Java 字段不带 `is` 前缀 |
| 枚举 | `VARCHAR(n)` + `CHECK`，存枚举名称；不使用 PostgreSQL `ENUM` 类型（修改取值需要 DDL） |
| 外部平台 ID | `VARCHAR`（如微店商品 ID），不用数值类型 |
| 结构化扩展信息 | `JSONB`，仅用于不参与常规查询条件的数据 |
| 字符串 | `VARCHAR(n)` 按业务上限定义；长文本才用 `TEXT` |

【强制】可为空的字段须在设计时说明为空的含义；能给默认值的不允许为空。

## 3. 索引

【强制】主键约束 `pk_{表名}`，唯一约束或唯一索引 `uk_{表名}_{字段}`，普通索引 `idx_{表名}_{字段}`，检查约束 `ck_{表名}_{含义}`。
【强制】业务上唯一的字段组合必须建唯一约束（不能只靠应用层判断）；需要"只在有效记录中唯一"时使用部分唯一索引（`WHERE is_deleted = FALSE` 或 `WHERE valid_to IS NULL`）。
【强制】每个查询条件都要能命中索引；新增查询时在 PR 中附 `EXPLAIN` 结果或说明使用的索引。
【强制】业务上的唯一性默认在公司内判断（唯一索引包含 `tenant_id`）；只有出现在对外链接中或用于识别公司的标识（达人编号、微店店铺 ID、管理员用户名）全系统唯一（任务 06c 起执行）。
【强制】按公司列表、排序的索引以 `tenant_id` 开头；以达人、店铺、原商品等只属于一家公司的 ID 为条件的索引不必加（任务 06c 起执行）。
【强制】单表索引不超过 6 个；联合索引遵循最左前缀，区分度高的字段放前面。
【推荐】大表（点击日志、订单明细、佣金明细）的列表查询使用游标分页（按 `id` 或时间），避免深分页。
【推荐】点击日志等按时间增长的大表使用声明式分区（`PARTITION BY RANGE`），按月分区。

## 4. 迁移脚本（Flyway）

【强制】所有结构与基础数据变更只通过 Flyway 迁移脚本完成，禁止手工改库。
【强制】脚本位于 `backend/src/main/resources/db/migration`，命名：`V{yyyyMMddHHmm}__{snake_case_描述}.sql`，例如 `V202610041200__init_system.sql`。使用时间戳是为了避免多个分支同时新增脚本时版本号冲突。
【强制】**已合并到 `main` 的脚本不得修改**；需要调整时新增脚本。
【强制】一个脚本只做一件事（一个功能点的建表或改表）；结构变更与数据修正分开写。
【强制】大表加字段、加索引须评估锁表影响，在 PR 中说明；在线创建索引使用 `CREATE INDEX CONCURRENTLY`（该脚本须单独、且不在事务中执行）。
【强制】脚本中不得包含密码、令牌等敏感数据，不得包含测试数据。

## 5. SQL 编写

【强制】使用 MyBatis-Plus 的 Lambda 条件构造器（`LambdaQueryWrapper`）或 XML 中的 `#{}` 参数绑定；禁止字符串拼接 SQL，禁止 `${}`（排序字段等确需动态的，必须经过白名单校验）。
【强制】禁止 `SELECT *`，查询只取需要的字段（Mapper 默认方法除外）。
【强制】分页查询必须带排序字段，且排序结果确定（最后加 `id` 兜底）。
【强制】批量写入使用批处理，单批不超过 1,000 行；幂等写入使用 `INSERT ... ON CONFLICT`。
【强制】`UPDATE`、`DELETE` 必须带条件，禁止全表更新。
【强制】只使用 PostgreSQL 标准语法与官方内置函数，不依赖第三方扩展（除非经 ADR 批准）。
【推荐】统计类复杂查询写在 XML 中，并配集成测试。
