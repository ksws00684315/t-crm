# 03 接口规范

## 1. 路径

【强制】路径前缀：管理端 `/admin-api`，达人端 `/kol-api`，内部接口 `/internal`，跳转 `/t`。
【强制】格式：`/{前缀}/{模块}/{资源}`。资源名使用**复数名词**、**kebab-case**：

| 正确 | 错误 |
|---|---|
| `/admin-api/system/users` | `/admin-api/system/user`、`/admin-api/system/getUsers` |
| `/admin-api/system/oper-logs` | `/admin-api/system/operLog` |
| `/admin-api/order/order-items/{id}/attribution` | `/admin-api/order/updateAttribution` |

【强制】非增删改查的操作，表达为资源的子资源或状态：`PUT /users/{id}/status`、`POST /settlements/{id}/confirm`。
【强制】查询参数使用 lowerCamelCase。

## 2. HTTP 方法与状态码

| 方法 | 用途 | 成功状态码 |
|---|---|---|
| GET | 查询，不改变状态 | 200 |
| POST | 新增、触发动作 | 200（返回新资源）或 202（异步任务） |
| PUT | 整体修改或修改某个状态 | 200 |
| DELETE | 删除 | 200 |

【强制】HTTP 状态码表达错误类别，响应体 `errorCode` 表达具体原因：

| 状态码 | 场景 |
|---|---|
| 400 | 参数校验失败、请求格式错误 |
| 401 | 未登录、令牌失效 |
| 403 | 已登录但无权限、越权访问 |
| 404 | 资源不存在、路径不存在 |
| 405 | 方法不支持 |
| 409 | 状态冲突、唯一键冲突、并发修改冲突 |
| 422 | 参数合法但违反业务规则 |
| 429 | 频率限制、账号锁定 |
| 500 | 未预期的服务器错误 |
| 502 / 503 | 外部服务（微店、Google）不可用 |

## 3. 响应格式

【强制】所有 JSON 接口使用统一信封：

```json
{
  "code": 0,
  "msg": "Success",
  "data": { },
  "errorCode": null,
  "traceId": "8f3c1a..."
}
```

| 字段 | 说明 |
|---|---|
| `code` | 成功为 `0`；失败与 HTTP 状态码相同 |
| `msg` | 英文、面向开发者的说明；前端不直接展示 |
| `data` | 业务数据；失败时为 `null` |
| `errorCode` | 失败时必填，见第 4 节；成功时为 `null` |
| `traceId` | 与响应头 `X-Trace-Id` 相同，便于排查 |

说明：业界较新的标准是 RFC 9457（Problem Details）。本项目选择统一信封，是因为两个前端模板与国内后台生态普遍采用该形式；字段语义（状态码表达类别、错误码表达原因、带追踪号）与 RFC 9457 保持一致，后续如需对外开放接口再评估切换。

## 4. 错误码

【强制】`errorCode` 为 UPPER_SNAKE_CASE 字符串，格式 `{模块}_{原因}`，在 `shared` 的 `ErrorCode` 枚举中统一登记，每项包含 HTTP 状态码与英文说明。示例：

| errorCode | HTTP | 含义 |
|---|---|---|
| `COMMON_VALIDATION_FAILED` | 400 | 参数校验失败 |
| `COMMON_NOT_FOUND` | 404 | 资源或路径不存在 |
| `AUTH_UNAUTHORIZED` | 401 | 未登录或令牌失效 |
| `AUTH_FORBIDDEN` | 403 | 无权限 |
| `AUTH_INVALID_CREDENTIALS` | 401 | 用户名或密码错误 |
| `AUTH_ACCOUNT_LOCKED` | 429 | 账号已锁定 |
| `USER_USERNAME_EXISTS` | 409 | 用户名已存在 |
| `USER_CANNOT_DISABLE_SELF` | 422 | 不能停用自己 |

【强制】新增错误码须同时更新前端的错误文案映射。
【强制】参数校验失败时，`data` 返回字段级错误列表：`[{"field": "username", "message": "..."}]`。

## 5. 分页与列表

【强制】请求参数：`page`（从 1 开始）、`size`（默认 20，最大 100）、`sort`（可选，格式 `field,asc|desc`，只允许白名单字段）。
【强制】分页响应：

```json
{ "items": [ ], "total": "1024", "page": 1, "size": 20 }
```

【强制】看板等大区间查询限制时间跨度（最大 90 天），超出返回 400。

## 6. 数据格式

【强制】JSON 字段名 lowerCamelCase。
【强制】`Long` 类型 ID 序列化为字符串。
【强制】金额以字符串返回，保留 2 位小数（如 `"128.50"`）；比例以字符串返回，保留 4 位小数。
【强制】时间以 ISO 8601 UTC 返回（如 `"2026-10-04T14:41:49.617Z"`）；按日期统计的字段使用 `"2026-10-04"`，并在接口文档中注明所用时区。
【强制】枚举以字符串名称传输（如 `"SUPER_ADMIN"`），不使用序号。
【强制】空集合返回 `[]`，不返回 `null`。
【强制】前端每个请求带 `Accept-Language`（`zh-CN` 或 `en-US`）；后端据此生成参数校验提示、导入模板与错误文件的文字，缺失或其他语言按英文处理。信封中的 `msg` 始终为英文（任务 06d 起执行，见 ADR-015）。
【强制】接口不接受公司 ID 参数，当前公司只从登录态取；仅平台管理接口（`/admin-api/platform/**`）以路径中的公司 ID 指定被管理的公司（任务 06c 起执行，见 ADR-014）。

## 7. 接口文档

【强制】使用 OpenAPI 3 描述接口，由代码注解生成（springdoc）；仅在开发与测试环境开放文档页面，生产关闭。
【强制】每个接口注明：用途、所需角色或权限码、请求与响应示例、可能的 `errorCode`。

## 8. 兼容与幂等

【强制】已发布接口的字段只增不删；需要删除或改语义时新增接口并标记旧接口弃用。
【强制】可能被重复提交的写操作（导入、生成结算单、触发同步）必须幂等：用业务唯一键或请求令牌去重。
