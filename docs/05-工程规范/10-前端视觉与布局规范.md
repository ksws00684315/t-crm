# 前端视觉与布局规范

适用范围：`admin-ui` 管理端和 `kol-portal` 达人端的所有页面、公共组件、Element Plus 控件及弹层。本文是当前可执行的视觉标准，双方样式变量必须保持一致。原引用的《网页字体字号规范.xlsx》目前未入库；若后续补入，须先与本文及已确认的视觉决策核对，不能直接覆盖本文。业务设计有特殊要求时，新增例外须在任务说明中写明原因。

## 1. 字体与文字层级

两端使用同一份视觉令牌：颜色、圆角、阴影、间距与版式全部定义在 `admin-ui/src/style/tokens.css`，`kol-portal/src/style/tokens.css` 与之逐字节一致（负责人 2026-10-24，任务 58）。达人端与管理端视觉一致：页头与侧栏、卡片、列表（`ListSearch`、`DataTable`、`CopyText`、`RowActions`）、按钮与登录页的配色、圆角和间距相同，差异只来自两端的业务结构。

字号与行高单位均为 CSS px。该表为桌面端后台规范，未在表中列出的位置按最接近的文字角色处理；新增文字角色时先补充本表，再实现页面。

**负责人决定（2026-10-27，ADR-034）**：表格采用方案 A；已确认细则集中在 [规范 13《前端视觉与交互规范（曼曼版）》附录 A](13-前端视觉与交互规范-曼曼版.md)。规范 13 第 2 章也已确认部分页面文字与统一主色。规范 13 目前仍是草案，定稿后再统一用于前端落地；此前本表继续作为现行页面的实施基线。定稿后的差异以规范 13 已确认内容为准，其余视觉仍执行本文。

### 1.2 实施与验收要求

- **字体统一**：避免混入宋体或衬线字体。ID、邮箱、日期与正文同字体；金额可设置 font-variant-numeric: tabular-nums。
- **字重定义**：400=常规，500=中等，600=半粗。字重统一由公共样式或组件主题配置。
- **密度切换**：默认／紧凑／宽松仅调整行高与间距，字号不随密度变化。
- **表头与长内容**：优先调整列宽，避免词语生硬断行；长邮箱、账号统一省略显示，悬停可查看完整内容。
- **显示验收**：浏览器100%缩放验收。同类文字字号一致，选中前后不跳动，无文字裁切、重叠。
- 规范依据：参考 [Ant Design 字体规范](https://ant.design/docs/spec/font/) 的层级原则；表格 15／24px 是负责人选定的项目规格，并非 Ant Design 默认值。

两端以 `tokens.css` 的 CSS 变量承载上表数值（`--tcrm-font-size-*`、`--tcrm-line-height-*`、`--tcrm-font-sans`）；表格使用规范 13 的独立变量，不通过全局正文变量放大非表格内容。页面与组件样式不得出现字号数值写法，视觉契约测试负责扫描并保证两端变量一致。表格文字颜色角色见规范 13 附录 A，已确认的非表格文字与主色见规范 13 第 2 章；其他颜色继续沿用现行规则，待逐项确认。

## 2. 布局、间距与控件

- 间距变量仅使用 4、8、12、16、24、32px；圆角沿用既有颜色与组件主题，不在页面另建尺寸体系。
- 内容区外边距：视口宽度大于等于 1280px 为 24px，768～1279px 为 16px，小于 768px 为 12px。
- 卡片默认内边距 16px，相邻内容区间距 16px，主要区块之间 24px。筛选项横向间距 16px、纵向间距 12px；按钮之间 8px。
- 桌面普通输入和按钮高度 32px。小于 768px 时交互目标至少 44px，字号保持不变。
- 页面使用 `min-width: 0`、可收缩的 flex/grid 轨道及内容区内滚动适应窄视口；避免视口级横向溢出。长邮箱、账号、链接按需省略，并提供完整内容的可访问提示。
- 侧栏子菜单的展开箭头固定 14px，贴在标题右侧内边距内并垂直居中；不随标题宽度拉伸，长词条在标签内省略，不得与箭头或左侧图标重叠（实现细节见 `SideMenu` 组件注释）。

## 3. 表格与表单

- 表格的字体、密度、行高与列对齐执行规范 13；列宽优先保证可读表头，不通过缩小字号或任意拆断文字适配宽度。
- 管理端列表继续使用 `ListSearch`、`DataTable` 和 `CopyText`。不在页面手写另一套列表分页；筛选标签置于输入框上方，查询和重置与输入框底部对齐，主要新增操作靠右，空间不足时自然换行。
- 常规列表的表头、数据行、分隔线与悬停色执行规范 13；操作文字同排优先，不为压缩行高缩小字号。
- 列表卡片高度贴合内容：行数少时卡片随内容收缩，"共 N 条"与分页紧跟最后一行，不在视口底部留下大块空白；行数多时表格在卡片内部滚动，"共 N 条"与分页始终可见。实现方式是用容器可用高度作为表格 `max-height` 上界，不用固定视口减法。
- 列较多时允许表格容器横向滚动，固定需要持续定位的首列和操作列；页面本身不得因此横向滚动。横向溢出时固定列必须有左侧投影、横向滚动条保持可见（不依赖悬停），否则被裁的列会被误读为渲染错误。业务定义的列序、操作入口、权限和禁用状态保持不变。
- 列宽按规范 13 的表格文字实测确定：表头优先完整不换行，长邮箱、电话、社媒 ID 等长值省略并悬停显示全文。中文与英文标签长度差异大时，允许按语言给出不同列宽，但同一语言内同类页面保持一致。列宽下限保证表头文字完整显示，不满足时必须让相邻可省略列（邮箱、备注等）让出像素（表头内边距与下限的换算见 `DataTable` 组件注释）。
- 列宽是下限不是定值：`DataTable` 把数据列按设计宽度渲染成 `min-width`，宽屏时剩余空间按比例分配给各列，卡片右侧不留空白带；列宽下限之和超过容器时才横向滚动。操作列保持定宽并贴住卡片右边缘，不参与拉伸。因此页面只声明设计宽度，不要自己写死 `width` 去适配某个分辨率；1900～3500 宽的屏幕上表格必须铺满卡片。
- 行内操作（链接按钮）挤在一行时，按规范 13 的间距和表格正文行高排布；不要沿用 Element Plus 默认按钮外边距，避免多操作行折成两三行。列宽实在不够时，先压缩只显示短文案的列（如“13 项”“仅本人”），不要缩小字号。
- 单元格里的 `el-button.is-link` 默认盒子可能高于表格正文；`DataTable` 应统一其盒子与表格文字的行高，页面内的链接按钮不要再单独设高度。
- 表格 `max-height` 上界按实际各行高度取到最后一个完整行：行数溢出时，最后一行不得只露出半个行高；多行内容允许自然增高，分页条要紧贴一个完整行（行数未溢出时保持贴合内容的高度）。
- 表单标签使用统一正文规格并保持同一对齐方式；错误、帮助文字使用辅助规格。提交和校验状态不得造成控件文字跳动或裁切。
- 非表格类列表（如站内消息）同样套用筛选／列表卡片：卡片撑满内容区，空态在卡片内居中，不允许把列表或“暂无数据”直接铺在页面底纹上。

## 4. 响应式与验收

- 达人端桌面表格在小于等于 767px 时使用已有卡片布局；长值允许换行。管理端列表在表格容器内横滚，搜索项与分页允许换行，工具区不覆盖内容。
- 手机端（小于等于 767px）的完整视觉设计在后续阶段处理。本期（任务 58）达人端手机宽度只要求页面不报错、能正常使用，沿用现有卡片布局。
- 浏览器缩放 100%，至少验收 1440×900、1280×800、390×844 和 375×812；另需在 2560 宽（或更宽的外接屏）上确认列表铺满卡片、右侧无空白带。两种语言均检查导航、页面标题、筛选表单、表格、分页、弹窗、抽屉、空状态和错误提示。
- 列表页另验三条：行数少于半屏时卡片不撑满视口；行数超过一屏时分页仍在视口内；横向溢出时能看到滚动条和固定列投影。
- 不是列表的页面，要在内容超过一屏的状态下验证能滚动到底部；页头、侧边栏和页签栏保持固定，页面本身不出现横向滚动。
- 逐页抽查登录、首页、主要列表、详情和所有复用浮层；验证有数据、空数据、长内容和校验提示状态。核对计算后的字体、字号、行高、字重、密度与响应式控件高度，无文字裁切、重叠、异常断行或页面横向滚动。
- 表格的专项视觉验收按规范 13 附录 A.5 执行，覆盖中英文、长值、金额、横滚、固定列及行操作。
- 两端使用 CSS 变量表达本规范的类型和间距值；`admin-ui` 的视觉契约测试负责比较两端 token，改动任一端时必须同步更新另一端。
