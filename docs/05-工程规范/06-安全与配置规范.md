# 06 安全与配置规范

> 安全目标：满足 OWASP ASVS 5.0 **第 2 级**的相关要求（本系统处理达人个人信息与佣金资金数据）。下列条款为本项目必须落实的部分。

## 1. 认证

【强制】密码使用 BCrypt（强度 ≥ 12）存储；长度 10～72 个字符；禁止明文、可逆加密或弱哈希。
【强制】登录失败按"用户名 + 来源 IP"（5 次）、"来源 IP"（20 次）、"用户名全部 IP"（50 次）三个范围在 15 分钟窗口内计数，任一范围达到上限锁定该范围 15 分钟，锁定期间返回 429；不得仅按用户名锁定（见 ADR-008）。
【强制】管理端每次登录都必须校验图形验证码，验证码只能使用一次（校验即删除，无论对错）、有效期不超过 5 分钟；验证码错误不计入登录失败次数；生产环境不得关闭 `crm.auth.captcha.enabled`（见 ADR-017）。
【强制】用户不存在、账号停用与密码错误的响应内容和耗时不得可区分：三种情况都执行一次 BCrypt 比较。
【强制】登录失败的提示不区分"用户不存在"和"密码错误"。
【强制】令牌有过期时间；修改密码、重置密码、停用账号后，该账号所有令牌立即失效。
【强制】管理员与达人使用两套独立的令牌体系，互不通用。
【强制】邀请、重置密码链接中的令牌一次性有效、有过期时间（≤ 72 小时），数据库只存其哈希。
【强制】初始账号通过环境变量创建；代码、SQL、文档中不得出现默认密码。

## 2. 鉴权与数据隔离

【强制】默认拒绝：每个接口必须显式声明所需角色；未声明的接口不得上线（ArchUnit 检查 controller 方法或类上存在角色注解，公开接口须显式标注为公开）。
【强制】达人端接口的达人 ID 只从登录态获取，不接受前端传入。
【强制】商务数据范围在 service 层查询时强制过滤，不依赖前端隐藏。
【强制】按 ID 访问资源时，必须校验该资源属于当前用户的可访问范围（防止越权读取他人数据）。
【强制】每个需要隔离的接口都有越权测试（见 05）。
【强制】公司隔离（任务 06c 起执行，见 ADR-014）：当前公司只从登录态取；数据访问由多租户插件自动追加 `tenant_id` 条件，取不到当前公司时报错，不得退化为不过滤。绕开自动过滤（后台跨公司维护、平台管理接口）必须显式声明并在代码中写明原因，PR 中列出每一处。
【强制】平台管理员只能访问平台管理接口，所有业务接口拒绝平台管理员。

## 3. 输入与输出

【强制】所有外部输入（请求参数、导入文件、第三方接口返回）都要校验：类型、长度、格式、取值范围。
【强制】导入文件：限制大小（≤ 20MB）和行数，只接受约定的扩展名与内容类型；解析时防范公式注入（导出 Excel 时，以 `=`、`+`、`-`、`@` 开头的单元格内容加前缀转义）。
【强制】SQL 只使用参数绑定（见 04）。
【强制】前端不使用 `v-html` 渲染来自后端或用户输入的内容。
【强制】跳转服务只允许跳转到登记的目标地址（来自 Redis 索引），不接受请求参数中的跳转地址（防开放重定向）。
【强制】响应头：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`；管理端和达人端设置 `Content-Security-Policy`；全站 HTTPS 并启用 HSTS（在 Nginx 或 Cloudflare 层）。
【强制】跨域只允许配置中列出的前端域名。
【强制】客户端 IP 只在 TCP 对端属于 `TCRM_TRUSTED_PROXIES` 时才从转发头读取，默认不信任任何代理（见 ADR-009）；审计、点击哈希、登录限流使用同一解析结果。

## 4. 敏感数据

【强制】不存储买家姓名、电话、地址等个人信息；必须保存的标识（如买家 ID）存哈希。
【强制】消费者与达人侧采集的 IP（如跳转点击）只存加盐哈希。
【强制】管理员操作审计日志（`sys_oper_log`）可保存原始 IP，用于安全取证；保留期限 180 天，到期由定时任务清理；只有超级管理员可查看。
【强制】第三方凭证（微店密钥与令牌、Google 服务账号密钥）按公司用 AES-256-GCM 加密入库，主密钥来自环境变量 `TCRM_SECRET_KEY`，密文带密钥版本号；接口只写不读，任何接口都不返回明文；不入日志。
【强制】操作日志中的请求参数对密码、令牌等字段脱敏。
【强制】接口返回中不包含密码哈希、令牌哈希、第三方密钥。

## 5. 配置

【强制】遵循十二要素应用原则：环境相关配置全部来自环境变量，变量名以 `TCRM_` 开头。
【强制】仓库只提交 `.env.example`（所有变量列全、值留空或为示例）；`.env` 与任何真实密钥不得提交。
【强制】配置分环境：`dev`（本地）、`test`（CI 与测试环境）、`prod`；生产关闭接口文档与调试端点，Actuator 只暴露 `health`。
【强制】必填配置缺失时应用启动失败并明确报错，不使用不安全的默认值。
【强制】系统中不存在可用的超级管理员、且未提供初始化账号的环境变量时，后台启动失败并提示需要设置哪些变量；已存在超级管理员时不受影响。任务 06c 起检查和创建的对象改为平台管理员；各公司的超级管理员由平台管理员创建。

## 6. 依赖与漏洞

【强制】CI 中使用 **OSV-Scanner** 扫描全仓库依赖（Maven `pom.xml` 与 `pnpm-lock.yaml`），同时检查漏洞与许可证：
- 发现已知漏洞即阻断合并；
- 许可证只允许规范 07 第 3 节列出的白名单；
- 有修复版本的漏洞必须升级修复（Spring Boot 管理的依赖按规范 07 第 1 节"安全修复例外"处理）；
- 确实无法立即修复的漏洞，在仓库根目录 `osv-scanner.toml` 中登记豁免，必须写明原因（`reason`）和到期日（`ignoreUntil`，不超过 90 天），到期后自动恢复阻断；
- 许可证的声明规则见规范 07 第 3 节。

【强制】前端另运行 `pnpm audit --audit-level high`。
【强制】开启仓库的 Dependabot 漏洞告警，作为扫描的补充。
【强制】不使用 GitHub 依赖审查（dependency-review-action）与代码扫描 SARIF 上传：私有仓库需要 GitHub Advanced Security 授权，见 ADR-004。
