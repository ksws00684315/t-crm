# 05 测试规范

## 1. 测试分层

| 层级 | 测什么 | 工具 | 命名 | 何时运行 |
|---|---|---|---|---|
| 单元测试 | service 业务规则、工具类、计算逻辑 | JUnit 5、Mockito、AssertJ | `*Test` | 本地每次构建、CI |
| 接口切片测试 | controller 参数校验、权限、序列化、错误处理 | MockMvc（模拟 service） | `*ControllerTest` | 本地、CI |
| 架构测试 | 第 01 章的分层与模块依赖规则 | ArchUnit | `ArchitectureTest` | 本地、CI |
| 集成测试 | SQL、迁移、Redis、完整业务流程 | Testcontainers（PostgreSQL、Redis） | `*IT`，标注 `@Tag("docker")` | CI；本地有 Docker 时 `mvn verify -Pdocker-it` |
| 前端单元测试 | 工具函数、store、路由守卫、权限判断 | Vitest | `*.spec.ts` | 本地、CI |

【强制】测试代码与被测代码使用**相同的包路径**（`src/test/java` 下镜像 `src/main/java`）。
【强制】集成测试不依赖本机环境（固定端口、本地数据库、外部网络），全部由 Testcontainers 提供，外部 HTTP 服务（微店、Google）使用模拟服务器。
【强制】测试之间相互独立，不依赖执行顺序；每个集成测试自行准备并清理数据。

## 2. 测试写法

【强制】测试方法名描述行为：`should{结果}_when{条件}`，如 `shouldLockAccount_whenFiveFailuresWithin15Minutes`。
【强制】一个测试方法只验证一个行为；按"准备 → 执行 → 断言"三段组织。
【强制】断言使用 AssertJ；断言具体值，不只断言"不为空"。
【强制】禁止为了通过测试修改被测逻辑的预期，禁止 `@Disabled` 跳过失败测试（确需暂时跳过须注明原因与任务编号）。
【强制】**修复缺陷必须先写能复现缺陷的测试**，确认失败后再修复。

## 3. 必测清单

【强制】以下逻辑必须有单元测试，且覆盖正常、边界、异常三类情况：

| 领域 | 必测内容 |
|---|---|
| 权限 | 每个接口的角色限制；达人只能访问自己的数据；商务（`OWN`）只能访问负责的达人；越权返回 403 |
| 认证 | 登录成功与失败、锁定、令牌失效、停用用户 |
| 归因 | 专属商品命中、未命中进入人工池、一笔订单多位达人、映射生效区间、重复导入幂等 |
| 计佣 | 比例优先级、比例快照、四舍五入、部分退款冲减、跨期扣回、人工改归属、不重复计佣 |
| 结算 | 结算单金额、负数结转、冻结达人排除、作废回滚 |
| 统计 | 每个看板指标的口径（与设计说明书 §8.6 一一对应）、跨日期区间去重、时区边界 |
| 跳转 | 有效、未命中、停用、非法参数、写点击失败仍跳转 |
| 导入 | 合法数据、每类非法数据、部分成功时的错误文件 |

【强制】涉及资金和统计口径的测试，用例数据写明计算过程（注释中列出手算结果）。

## 4. 覆盖率门槛

由 JaCoCo 统计，CI 中低于门槛即失败：

| 范围 | 行覆盖率 | 分支覆盖率 |
|---|---|---|
| 后台整体 | ≥ 70% | ≥ 60% |
| `commission`、`order`（归因）、`stats`、`security` 模块 | ≥ 85% | ≥ 80% |
| 跳转服务 | ≥ 80% | ≥ 70% |

【强制】覆盖率统计排除：启动类、配置类、`*DO`、`*VO`、`*Request` 等纯数据类。
【强制】覆盖率只降不升的 PR 须在描述中说明原因。

## 5. 测试数据

【强制】测试中的账号密码在测试内随机生成或使用明显的测试值，不得使用任何真实账号。
【强制】不在仓库中提交从生产导出的数据；需要样例时手工构造并脱敏。
