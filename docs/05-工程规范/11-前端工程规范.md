# 11 前端工程规范

适用：`admin-ui` 管理端、`kol-portal` 达人端。本章规定**页面怎么搭**：目录、公共组件、列表与弹窗的标准写法、权限、接口、国际化、未实现功能与测试。与其他章节的分工：

| 内容 | 位置 |
|---|---|
| 目录结构、`api/` 规则 | 01 第 6 节 |
| TypeScript、Vue 风格、语言包、令牌存放 | 02 第 7 节 |
| 全站字体、字号、间距、响应式 | 10 |
| 前端视觉与交互框架（曼曼版）；已确认的表格细则见附录 A | 13 |
| 需求依据、逐条复核、浏览器验收 | 12 |

本章以两端现有代码为准写成。现有代码与本章不一致时，按规范总则改代码；确实需要例外的，在任务提示词中写明原因。

## 1. 目录与文件

【强制】页面放在 `views/{模块}/{页面}/`，入口为 `index.vue`；只属于该页面的弹窗、抽屉、标签页组件放在同一目录，文件名 PascalCase 且以用途结尾（`CommissionDialog.vue`、`KolDetailDrawer.vue`、`KolManageTab.vue`）；该页面的测试放在同目录的 `__tests__/`。
【强制】两个及以上页面复用的组件才放进 `components/`；两个及以上页面复用的有状态逻辑放进 `composables/`（`use` 开头）；无状态的纯函数放进 `utils/`。
【强制】新增公共组件、组合式函数或 store 时，在任务提示词或 PR 描述中写明复用的页面。只有一个页面用的，不提取。
【强制】页面组件声明 `defineOptions({ name: "…Page" })`，名称与路由 `meta.componentName` 一致（多标签页缓存依赖它，`component-names.spec.ts` 校验）。
【强制】页面模板只能有一个根元素：根级不得出现多个同级元素、根级 `<template>` 或纯文本。管理端用 `<Transition mode="out-in">` 包裹路由页面，根节点是 Fragment（多根）时 Vue 取不到参与过渡的元素，离场钩子不会结束，过渡停在离场状态，此后任何页面切换都只剩占位注释（白屏），必须刷新整个浏览器页面才恢复；`page-single-root.spec.ts` 校验全部路由页面。根级的 `v-if` / `v-else` 分支链可以，编译器会合成一个条件元素。

## 2. 管理端公共组件

【强制】管理端列表页必须使用以下组件，不得在页面里另写一套：

| 组件 | 用途 | 要点 |
|---|---|---|
| `ListSearch` | 筛选区 | 输入项放在默认插槽，`search` / `reset` 事件触发查询；已筛选条件通过 `chips` 显示，可单个移除 |
| `DataTable` | 列表、分页、工具栏（密度、列设置、导出、全屏） | 列定义用 `DataColumn`；`tableId` 全局唯一（列设置按它保存）；不分页的列表设 `paged=false`；弹窗或抽屉里的表格设 `plain` |
| `RowActions` | 行操作 | 按业务顺序声明全部操作，**全部直接显示，不使用「更多」**（负责人 2026-10-21，ADR-029）；可见性用 `hidden`，不可用用 `disabled` 加 `tooltip`；操作列宽度按全部操作的实测宽度（文字宽度之和 + 操作间距 8px + 单元格左右内边距 20px）设定，中英文分别给出 |
| `CopyText` | ID、邮箱、链接等可复制的值 | 不在页面里自己调用剪贴板 |
| `ImportDialog` | Excel 导入 | 模板下载、上传、导入任务进度统一由它处理 |

【例外】非表格形式的列表（例如站内消息）可以使用 `el-pagination`，但仍须套用筛选区与列表卡片，空态在卡片内显示（规范 10 第 3 节）。
【强制】列宽只声明设计宽度（`width` 或 `minWidth`），由 `DataTable` 换算为最小宽度并在宽屏铺满；不得为某个分辨率写死像素。中英文表头长度差异大时，可以按语言给出两组宽度（见 10 第 3 节）。
【强制】`DataTable` 的列对齐、金额数字排版、自定义插槽和操作组布局按规范 13《前端视觉与交互规范（曼曼版）》附录 A.2、A.4 落地；两端共享同一契约。长文本列仍须提供完整内容提示，不得用等宽字体显示 ID、邮箱、日期。规范 13 定稿前不依据其待确认章节修改页面。

### 看板与图表

适用于「经营分析」各看板和工作台总览（任务 42 实现公共组件，任务 48～51 复用），见 ADR-033。

【强制】图表统一使用 Apache ECharts（负责人 2026-10-21 同意，Apache-2.0；依赖链许可证见 ADR-010），不得引入其他图表库，也不得引入 ECharts 的 Vue 封装包。两端的版本保持一致且写死，当前为 `echarts 6.1.0`，与达人端已有依赖相同。
【强制】按需引入：从 `echarts/core` 只注册实际用到的图表类型、组件和 `CanvasRenderer`，注册代码集中在一个文件里（例如 `utils/echarts.ts`）。不得整包引入（`import * as echarts from "echarts"`）。
【强制】页面不得直接调用 `echarts.init`。独立「经营分析」看板页使用以下公共组件，放在 `admin-ui/src/components/dashboard/`；工作台总览按任务 42 只使用实际需要的指标卡，不为复用组件而添加筛选区或图表：

| 组件 | 用途 | 要点 |
|---|---|---|
| `DashboardFilter` | 看板筛选区 | 时间快捷项：今日、昨日、近 7 天（默认）、近 30 天、本月；自定义区间最长 90 天，边界按北京时间。店铺、渠道、达人、邀请人等页面专有的筛选放在插槽里。提供查询、重置、手动刷新，可选每 5 分钟自动刷新 |
| `QuerySummary` | 结果说明 | 显示接口返回的 `meta`：生效的筛选条件、统计起止日期（北京时间）、权限范围（全部 / 本人名下）、最近更新时间 |
| `MetricCard` | 指标卡 | 指标值、环比（上升 / 下降；上期为 0 时显示「-」）、辅助指标。字段在 `unavailable` 中时显示「开发中」。指标名旁用提示说明口径（SPU、订单、件数、金额的区别） |
| `ChartPanel` | 图表容器 | 唯一创建 ECharts 实例的地方：宽度随容器自适应，卸载时销毁实例，跟随深色模式。分别显示加载中、无记录、无权限、加载失败四种状态。图表文字随当前语言切换 |

【强制】独立「经营分析」看板页自上而下依次为：`DashboardFilter`、`QuerySummary`、`MetricCard`、`ChartPanel`、列表。列表部分仍按本节前面和第 3 节的要求使用 `DataTable`，列对齐执行规范 13 附录 A.2。工作台总览是任务 42 的指标卡入口，本期不展示 `ChartPanel`、趋势图或列表；其指标卡排布见规范 13 第 3.6 节。
【强制】看板数值格式：
- 金额：`¥` 加两位小数；
- 比例：百分比，保留一位小数；
- 零分母或无数据（`null`）：显示「-」，不得用 0 代替。

格式化函数放在 `utils/format.ts`，图表的坐标轴和提示框也使用同一组函数。
【强制】图表的颜色和字号从 `tokens.css` 的变量读取，由 `ChartPanel` 统一转换后传给 ECharts。页面的图表配置里不写颜色值和字号数值（第 10 节、规范 10）。
【强制】ECharts 在 jsdom 中无法渲染。单元测试对注册文件（`utils/echarts.ts`）做 mock，断言两件事：传给图表的配置（系列、数据、格式化）正确，四种状态正确显示。实际的图表渲染在浏览器验收中截图确认（规范 12）。

## 3. 列表页标准写法

【强制】一个列表页由「筛选区 + 列表卡片」组成，查询逻辑按以下顺序：

1. 筛选条件放在一个 `reactive` 对象里，分页参数 `page`、`size` 单独保存；
2. `load()` 设置 `loading`，调用 `api/` 下的函数，取回 `{ items, total }`，写入 `rows` 与 `total`；
3. 失败时调用 `notifyError(error)`，不自行拼接错误文字；
4. 查询从第 1 页开始；重置条件后也回到第 1 页；
5. 新增、编辑、状态变更成功后重新加载当前页。

【强制】列定义写成 `computed`，表头文字通过 `t()` 读取，切换语言后立即更新。
【强制】空数据由 `DataTable` 显示统一空态；不在页面上另画「暂无数据」。
【强制】行的可见、可点、禁用规则写成具名函数（例如 `rowOwned(row)`、`reviewClickable(row)`），在模板里调用，便于单元测试。

## 4. 弹窗与抽屉标准写法

【强制】编辑类弹窗使用 `el-form` 加 `rules`：

- 校验函数优先复用 `utils/validation.ts` 和各模块的校验工具（例如 `kol-validation.ts`），错误文字来自语言包；
- 后端返回的字段错误用 `serverFieldErrors()` 映射到对应表单项，同时 `notifyError()`；
- 提交中按钮显示加载状态，禁止重复提交；
- 成功后提示，`emit("saved")` 并关闭；打开时根据传入数据重置表单并清除校验状态。

【强制】弹窗的打开状态用 `v-model`（`modelValue`）控制；弹窗不直接修改父页面的列表数据，由父页面在 `saved` 后重新加载。
【强制】删除、冻结、清理、转移等不可逆或影响范围大的操作，必须二次确认；需要原因的，原因必填。

## 5. 权限

【强制】路由访问由 `meta` 声明：`permission`（权限码）、`superAdmin`、`platformAdmin`、`companyAccount`、`hideForOwn`；判断统一走 `utils/permission.ts` 的 `canAccessRoute()`，不在页面里自己判断角色字符串。
【强制】页面内按钮的显示与禁用，通过 `accessOf(user)` 或各模块的能力函数（例如 `kolAbilities()`）计算，规则与后端权限码一致。
【强制】前端隐藏或禁用只是提示，不能代替后端校验；每个新按钮对应的接口必须在后端声明权限码（规范 06、ADR-018）。
【强制】权限相关的显示规则必须有测试：至少覆盖「有权限可用」「无权限隐藏或禁用」两种情况，以及商务（`OWN`）只能操作自己负责的数据。

## 6. 接口调用与错误处理

【强制】请求函数放在 `api/{模块}/*.ts`，类型与后端 `*Request`、`*VO` 字段一一对应；ID 和金额按字符串处理（规范 03）。
【强制】页面只调用 `api/` 中的函数，不直接使用 `http` 或 axios。
【强制】所有接口错误最终交给 `notifyError()` 显示：它按 `errorCode` 从语言包取文案，401 已由请求拦截器处理时不重复提示。新增错误码时同步更新两端的错误码映射，`error-codes.spec.ts` 会检查。
【强制】需要在页面上特殊处理的错误，用 `error instanceof ApiError && error.errorCode === "…"` 判断，不比较错误文字。
【推荐】同时发起、互不依赖的请求用 `Promise.all`；辅助数据（例如倒计时、角标）请求失败时降级显示，不阻断主列表。

## 7. 国际化与格式

【强制】界面文字只从语言包读取，两种语言的键必须一致（`messages.spec.ts` 检查）；不在模板或脚本中写死中文或英文。
【强制】日期时间统一用 `utils/format.ts` 的格式化函数（例如 `formatInstant`、`formatInstantToMinute`），按浏览器时区显示；金额、比例用对应的格式化函数，前端不做金额的浮点运算。
【强制】名称以客户确认的文字为准（进度表与补充表的原文，例如「社媒平台/ID」「指定商务全部达人」）；英文由任务提示词给出或沿用已有译名，不自行改名。

## 8. 状态管理

【强制】只有跨页面共享的状态放进 Pinia：登录用户、语言、站点配置、标签页等。页面自己的列表、筛选、弹窗状态留在页面内。
【强制】从后端取得的运行时配置（站点名称、上传地址等）通过 `stores/site-config.ts` 读取，不使用构建时变量，也不写死（任务 34）。

## 9. 未实现的功能

【强制】需求中有、但当前还不能实现的部分（等待客户确认、依赖后续任务），在界面上显示「开发中」：整页用 `views/common/ComingSoon.vue`，单个字段或按钮用 `common.developing` 文案并禁用。不得用假数据或假的成功提示代替。
【强制】在执行报告的复核表中，把这些项标为「开发中」并写明原因（见 12）。

## 10. 样式

【强制】字号、行高、间距只使用 `style/tokens.css` 中的变量；页面和组件样式中不得出现字号数值（`tokens.spec.ts` 扫描两端）。
【强制】页面样式使用 `<style scoped>`；需要改 Element Plus 默认样式的，全站统一的写在 `style/index.css`，只影响本组件的用 `:deep()`，不得在页面里覆盖全站规则。
【推荐】避免 `!important`；确需使用时，在旁边注释原因。
【强制】表格专用视觉令牌及两端一致性执行规范 13 附录 A.3、A.4。

## 11. 测试

【强制】测试使用 Vitest 和 `@vue/test-utils`，选择元素一律用 `data-test` 属性，不依赖 CSS 类名或文字内容。
【强制】每个新页面或新弹窗至少测试：

| 测什么 | 例子 |
|---|---|
| 渲染 | 列与表头齐全；中英文切换后表头随之变化 |
| 权限 | 有权限可用、无权限隐藏或禁用、商务只能操作自己的数据 |
| 提交 | 调用的 `api` 函数和参数正确；必填校验拦截 |
| 错误 | 接口失败时调用 `notifyError`，页面不卡在加载中 |

【强制】工具函数、组合式函数和 store 有单元测试（规范 05）。
【强制】修改公共组件（`DataTable`、`ListSearch`、`RowActions` 等）时，同时跑完整测试，并在 PR 描述中列出受影响的页面。
【强制】表格的对齐、视觉令牌、组件测试与真实浏览器验收执行规范 13 附录 A.5；实际前端落地安排在规范 13 定稿后。

## 12. 达人端差异

- 默认英文；页面结构同样遵守第 1、6～11 节。
- 视口小于等于 767px 时，表格改用卡片布局，交互目标不小于 44px（10 第 2、4 节）。
- 提交与加载状态统一使用 `utils/useSubmission.ts`。
- 达人端只显示达人本人的数据，达人 ID 只从登录态获取，接口不接收前端传入的达人 ID（规范 06）。
- 达人端列表使用与管理端相同的 `ListSearch`、`DataTable`、`CopyText`、`RowActions`（位于 `kol-portal/src/components/`，任务 58 移植）。修改任一端的这些组件时，两端同步修改，并在 PR 描述中写明。达人端的 `DataTable` 比管理端多一个可选的 `empty` 插槽，用于显示达人端的空态文案（文件头注释有说明）。
- 达人端的页头、左侧菜单、卡片和登录页与管理端使用同一套令牌和样式（规范 10 第 1 节）；菜单项为 `RouterLink`，保留 `href` 与 `aria-current` 语义，样式与管理端 `SideMenu` 一致。
