# 02 编码规范

## 1. Java 通用

【强制】格式遵循 Google Java Style，由 Spotless（google-java-format）自动格式化并在 CI 校验；格式不符构建失败。
【强制】禁止通配符导入（`import x.y.*`）；禁止未使用的导入。由 Checkstyle 检查。
【强制】代码、注释、标识符使用英文；文档使用中文。
【强制】JDK 21；可使用 `record`、`switch` 模式匹配、文本块、`var`（仅在右侧类型显而易见时）。
【强制】依赖注入使用构造器注入，字段 `private final`；禁止字段注入（`@Autowired` 写在字段上）。
【强制】`*DO` 等可变对象字段一律 `private`，通过 getter/setter 访问；禁止 `public` 实例字段。
【强制】`pom.xml` 按标准多行格式书写，依赖按"框架 → 数据 → 工具 → 测试"分组。

## 2. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 类 | UpperCamelCase；按分层使用固定后缀 | `UserController`、`UserService`、`SysUserMapper`、`SysUserDO`、`CreateUserRequest`、`UserVO` |
| 方法 | lowerCamelCase，动词开头 | `createUser`、`listUsers`、`resetPassword` |
| 常量 | UPPER_SNAKE_CASE | `MAX_PAGE_SIZE` |
| 布尔字段 | 不加 `is` 前缀（数据库字段可用 `is_`） | `deleted`，对应列 `is_deleted` |
| 枚举 | 类名 UpperCamelCase，值 UPPER_SNAKE_CASE | `Role.SUPER_ADMIN` |
| 测试类 | 单元测试 `*Test`，集成测试 `*IT` | `UserServiceTest`、`UserApiIT` |

【强制】service 方法命名前缀：查询单个 `get`、查询多个 `list`、分页 `page`、统计 `count`、新增 `create`、修改 `update`、删除 `delete`。

## 3. 异常

【强制】业务规则不满足时抛出 `BusinessException(ErrorCode)`，由全局异常处理器统一转换为响应；controller 中不写 `try-catch` 吞异常。
【强制】捕获异常后要么处理、要么带上下文重新抛出；禁止空 `catch`、禁止只打印不处理。
【强制】不向前端返回堆栈、SQL、类名等内部信息。
【强制】外部调用（微店、Google、邮件）的异常在 `integration` 层转换为本项目定义的异常类型，不把第三方异常类型泄漏到业务模块。

## 4. 日志

【强制】使用 SLF4J；禁止 `System.out`、`printStackTrace`。
【强制】日志级别：`ERROR` 需要人工处理的故障；`WARN` 可自动恢复的异常情况；`INFO` 关键业务节点（任务开始结束、同步结果、状态变更）；`DEBUG` 排查细节。
【强制】每个请求生成 `traceId`，写入日志上下文（MDC），并通过响应头 `X-Trace-Id` 返回。
【强制】禁止在日志中输出：密码、令牌、密钥、完整手机号、邮箱、收货地址、明文 IP。
【强制】使用占位符 `log.info("synced {} orders", n)`，禁止字符串拼接。
【推荐】生产环境输出 JSON 格式日志。

## 5. 注释

【强制】公开接口（`api` 包内的类与方法）写 Javadoc，说明用途、参数约束、异常。
【强制】复杂业务规则（归因、计佣、结算、指标口径）在代码处注释规则来源，引用设计说明书章节，如 `// See design §8.3`。
【强制】不写复述代码的注释；不保留被注释掉的代码。
【强制】`TODO` 必须写明原因与跟踪方式：`// TODO(#issue 或 任务编号): 说明`。

## 6. 并发、事务与时间

【强制】写多张表的 service 方法使用 `@Transactional`，并显式指定 `rollbackFor = Exception.class`；事务内禁止调用外部 HTTP 接口。
【强制】定时任务必须通过 `shared` 中的分布式锁执行，防止多实例重复运行。
【强制】时间统一使用 `java.time`：存储与传输用 `Instant`（UTC）；按业务时区统计时用 `ZonedDateTime` 并显式指定时区。禁止 `java.util.Date`。
【强制】金额统一使用 `BigDecimal`，构造用字符串或 `valueOf`，舍入方式显式指定 `RoundingMode.HALF_UP`；禁止 `double`、`float` 表示金额。

## 7. 前端（Vue 3 + TypeScript）

【强制】组件使用 `<script setup lang="ts">` 组合式 API。
【强制】`tsconfig` 开启 `strict`；禁止 `any`（ESLint 设为错误），确需时使用 `unknown` 并收窄。
【强制】遵守 Vue 官方风格指南"必要"级规则：组件名多单词、`v-for` 必须带 `key`、`v-if` 与 `v-for` 不写在同一元素、Props 必须声明类型。
【强制】组件文件名 PascalCase（`UserForm.vue`），页面入口 `index.vue`；组合式函数以 `use` 开头（`useUserList.ts`）。
【强制】ESLint + Prettier 由 CI 校验；类型检查（`vue-tsc --noEmit`）由 CI 校验。
【强制】界面文字：两端都支持中英文（`zh-CN` / `en-US`，管理端默认中文、达人端默认英文；任务 06d 起执行，见 ADR-015）；界面文字全部从语言包读取，组件和脚本中不写死文字；两种语言的键必须一致。后端错误按 `errorCode` 映射为界面文案，不直接展示后端 `msg`。
【强制】时间展示（如 `formatInstant`）必须按**当前界面语言**调用 `Intl`（或等价 API），禁止写死 `zh-CN` / `en-US`。
【强制】「名称（编码）」一类拼接展示走语言包键（如 `common.nameWithCode` / `common.codeWithName`）或 `formatNameWithCode` / `formatCodeWithName`：中文用全角括号、英文用半角括号；组件模板中禁止写死 `（）` / `()`。
【强制】令牌只存放在内存与 `localStorage` 之一（统一由 store 管理），不得写入 URL。
【推荐】数值金额由后端以字符串返回，前端展示时只做格式化，不做浮点运算。

页面的搭建方式（公共组件、列表与弹窗、权限、错误处理、测试）见规范 11；字体与布局见规范 10。
