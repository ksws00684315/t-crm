# 微店 API 风险调研报告（最终版）

> 调研日期：2026-09-30 ｜ 调研方式：微店开放平台官方 API 文档实地核查（open.weidian.com/#/api/overview，无需登录可直接浏览）+ 公开资料交叉验证
> 本版结论已覆盖前两轮基于公开资料的推断，冲突之处以本版官方文档核查结果为准。

---

## 一、总体结论（先看这个）

| # | 关键问题 | 最终结论 | 风险等级 |
|---|---|---|---|
| 1 | 订单同步 API 是否可用 | ✅ 可用，接口齐全 | 🟢 低 |
| 2 | 订单能否返回"归属达人"数据 | ✅ **能！** `vdian.order.get` 返回 `fans1_id`（推广员 ID）+ `fans1_money_total`（该单佣金） | 🟢 低（有前提） |
| 3 | 达人身份映射 API | ✅ `fxmall.fans.list/get` 返回推广员（sharerUid）与粉丝绑定关系 | 🟡 中（高级型权限+商城版） |
| 4 | 优惠券/优惠码 API | ✅ 优惠券全套 API 存在（创建/买家领券明细/使用报表），专属券归因可行 | 🟢 低 |
| 5 | 外部浏览器（Ins/WhatsApp）锁关系是否生效 | ⚠️ **官方文档未覆盖，唯一剩余的核心待实测项** | 🔴 待实测 |

**一句话结论：客户说的"微店能看到订单关联哪个达人"是真实的、且 API 直接返回——前提是店铺开通商城版推广员功能、达人注册为推广员。归因主引擎可以用微店官方的 `fans1_id`，自有中转点击日志退居辅助校验。项目最大技术不确定性从"归因无解"变为"外部浏览器锁关系实测"，风险大幅下降。**

## 二、决定性发现详解

### 2.1 订单详情接口直接返回推广员归因（`vdian.order.get`，2.0 版）

返回示例中的关键字段（官方文档原文）：

```json
{
  "fans1_id": "1389137237",        // 一级推广员（达人）ID —— 归因核心字段
  "fans1_money_total": 0,          // 一级推广员本单佣金（微店已自动算好）
  "fans2_id": "1500361957",        // 二级推广员（邀请人）ID
  "fans2_money_total": 0,          // 二级推广员佣金
  "order_id": "819338716369577",
  "status": "pay", "status_desc": "待发货",
  "pay_time": "...", "total": "...", "items": [...],
  "refund_info": {...},            // 退款状态（佣金扣回依据）
  "external_order_channel": "",    // 外部订单渠道字段
  "is_out_order": 0
}
```

注意事项：
- **加密接口**：买家姓名/电话/地址为 AES 加密返回（示例可见密文），需按官方指引申请接口调用权限并处理解密（文档：open.weidian.com/#/guide/143）
- **订单列表（`vdian.order.list.get`）不返回 fans 字段**——批量同步需"列表取单号 → 逐单调详情"。自用型 QPS 5/秒下，日均 1000 单约 3 分钟拉完，量级完全可控

### 2.2 推广员身份与关系映射（`fxmall.*` 系列，高级型权限）

- `fxmall.fans.list` 查询粉丝列表：返回 `sharerUid/sharerNick/sharerPhone`（推广员）+ `fansUid/fansNick`（绑定粉丝）+ `bindTime`（绑定时间）
- `fxmall.fans.get` 粉丝信息、`fxmall.fans.audit.list` 粉丝审核、`fxmall.black.fans` 黑名单
- `fxmall.relation.get` **查询关系链**（买家→推广员绑定链路）
- ⚠️ 官方原文："如果未打开推广员的推广开关，则此接口不返回明细数据"——**前提是商城版推广员功能已开通**

### 2.3 佣金配置 API（分销工具分类）

- `vdian.batch.get.item.commissionRate` 批量查询商品级佣金配置
- `vdian.save.item.commissionRate` 保存商品级佣金配置
- 配合订单的 `fans1_money_total`，**微店侧已形成"配置佣金比例 → 自动归因 → 自动算佣"闭环**，CRM 可直接采信或按自有规则重算

### 2.4 优惠券全套 API 存活（营销工具分类）

`create.shop.coupon`（创建）、`delete.coupon`、`get.shop.coupon.list/detail`、**`get.buyer.fetch.coupon.list`（买家已领券明细）**、`get.shop.coupon.report`（领取/使用报表）、`coupon.takeByPhone`（手机号发券）、`coupon.verify.use.coupon`（核销）。
→ "达人一人一张专属券 + 领券/用券报表反查归因"技术上完全可行，可作为归因的第二通道。

### 2.5 CPS 渠道对接（另一条可选通道）

- `vdian.cps.popularize.getTunnel` **获取推广位**、`vdian.cps.popularize.query/getCpsItems/getItemByUrl` CPS 商品查询
- `channel.getOrderList` **渠道订单列表（T+1）**——类淘宝联盟模式：推广位链接 → 归因订单 → T+1 拉取
- 若推广员路线实测不顺，CPS 是备选架构

### 2.6 唯一剩余核心风险：外部浏览器锁关系

推广员的锁关系机制为微信生态分享设计。达人链接在 Instagram/WhatsApp 中点击后于**外部浏览器打开微店 H5**，`fans1_id` 归因是否依然成立，官方文档未覆盖，**必须实测**（实测方法已极其简单：测试推广员链接发 Ins → 外部浏览器走一单 → 调 `vdian.order.get` 看 `fans1_id` 是否非空）。
缓解预案：若外部浏览器锁关系失效，退回"中转点击日志 + 时间窗口匹配"方案（原 PRD 四级归因），或测试中转链接透传推广员参数能否激活绑定。

## 四、对 CRM 方案的最终修订

| 模块 | 修订后方案 |
|---|---|
| 归因引擎 | **主引擎 = 微店 `fans1_id`（官方归因，准确率最高）**；辅 = 自有中转点击日志（点击量统计、转化率、交叉校验）；兜底 = 人工修正池。原 PRD 五级归因中的"优惠码兜底"可升级为"专属优惠券 API"方案 |
| 佣金结算 | 微店 `fans1_money_total` 为参考基准，CRM 按 `(净销售额 × 配置比例)` 重算并对账，差异进人工池 |
| 达人注册 | 达人在微店侧注册为店铺**推广员**（获得 sharerUid），CRM 用 `fxmall.fans.list` 拉取映射到 KOL ID，或注册流程引导同步 |
| 商品库 | `vdian.item.list.get` / `weidian.get.items` 自动同步，替代 Excel 导入 |
| 退款扣回 | 逆向系列接口（退款列表/详情）+ 订单 `refund_info` |
| 订单同步 | 列表 → 逐单详情（取 fans1_id），日增量可控；加密字段按需解密 |

**前置条件（客户必须完成）**：①开通微店商城版（付费）并打开推广员开关；②达人注册为推广员；③开放平台创建自用型应用，申请订单（基础型）+ 推广员/优惠券（高级型）+ 加密接口权限。

## 五、签约前最终实测清单（收缩为 3 项）

1. **外部浏览器锁关系实测**（唯一核心风险）：测试推广员链接发到 Ins/WhatsApp → 外部浏览器完成一单 → `vdian.order.get` 检查 `fans1_id` 是否非空。通过 → 全方案成立；不通过 → 评估中转链接透传参数 / 切 CPS 通道 / 退回点击匹配方案
2. **权限申请验证**：自用型应用创建后，确认订单详情（加密）、fxmall 系列、优惠券系列权限能否获批及审批时长
3. **海外达人注册推广员流程走通**：达人无微信/国内手机号情况下能否完成推广员注册与绑卡（涉及佣金支付）

## 六、前两轮调研结论的修正记录

- ~~"归因数据不对 API 开放"~~ → **修正**：`fans1_id`/`fans1_money_total` 直接在订单详情返回
- ~~"微店无优惠券 API（仅老版 v1 存在）"~~ → **修正**：优惠券全套 API 在现行平台存活
- ~~"专属分销链接生成 API 不存在"~~ → **部分修正**：推广员体系归因不依赖链接参数（锁关系绑定），无需"复制专属链接"；CPS 通道另有"获取推广位"接口
- 维持不变：订单列表不带归因字段（需逐单详情）；商城版推广开关为前提；外部浏览器场景待实测
