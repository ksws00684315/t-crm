## 一、需求理解与功能范围评估

### 1.1 项目一句话概括

为 100 名海外社媒达人生成唯一推广 ID，以「一人一独立 Google Spreadsheet + 双层中转追踪链接 + 五级订单归因 + 自动佣金结算 + 严格数据隔离」的方式，打通 **达人注册 → 链接分发 → 流量追踪 → 订单归因 → 销售统计 → 佣金结算** 的全链路分销管理闭环。

### 1.2 功能范围清单（13 个模块）

| 分类 | 模块 | 范围要点 |
|---|---|---|
| 达人域 | 达人注册管理 | 自主注册（姓名/邮箱/国家/社媒账号）、自动生成终身唯一 KOL ID（KOL0001 递增） |
| 达人域 | 达人审核管理 | 人工审核、启用/禁用、资料编辑、密码重置 |
| 商品域 | 商品链接管理 | 微店原始链接批量导入、商品基础信息统一维护 |
| 链路域 | 专属链接生成 | 批量生成 100 人 × 2 万条 = 200 万条双层追踪链接（中转链接 + 溯源微店链接） |
| 链路域 | Google Sheet 自动分发 | 自动创建独立表格、批量写入 2 万条链接、Drive 权限定向分享、同步调微店接口复制达人专属链接 |
| 链路域 | 中转跳转 + 点击追踪 | `/t/{KOL}/{Product}` 302 跳转、点击全量记录、异常恶意点击识别、转化率统计 |
| 订单域 | 微店订单同步 | API 实时同步 + Excel/CSV 离线导入双模式 |
| 订单域 | 智能订单匹配 | 五级优先级归因 + 人工匹配池 |
| 数据域 | 销售数据统计 | 点击/订单/交易额/退款/净销售额，按日/周/月报表 |
| 财务域 | 佣金结算管理 | 自动核算、待结算/已结算/冻结/解冻、退款扣回、结算单导出 |
| 前台 | 达人前台看板 | 仅见自身链接、流量、订单、销售、结算五大视图（数据隔离） |
| 后台 | 后台全域管理 | 全域数据、销售排行榜、异常监控、异常订单人工修正 |
| 平台 | 权限 + 审计 | 超管/运营/财务/达人四级 RBAC；链接导入、订单匹配、人工修正、结算、账号变更全链路日志 |

另含需求文档第五节的 Google 表格 4-Sheet 规范（Links / Orders / Summary / Settlement，共 11+12 个固定字段）与数据定时回写。

### 1.3 规模量级判断

| 维度 | 量级 | 说明 |
|---|---|---|
| 用户规模 | 小 | 100 达人 + 少量管理角色（后台并发极低） |
| 链接数据 | 中 | 200 万条链接记录；100 份谷歌表格 × 2 万行 × 11 字段 ≈ 2200 万单元格总写入量 |
| 点击流量 | 中（待澄清） | 参考截图日访问 1.7 万 PV；跳转服务需按峰值设计，异步化采集 |
| 外部集成 | **3 个，高复杂度** | 微店开放 API（订单 + 链接复制 + 优惠码）、Google Sheets API、Google Drive API |
| 财务准确度 | 高 | 佣金核算涉及真金白银，需幂等、对账、审计 |
| 页面端 | 2 个 | 管理后台（中文）+ 达人前台（参考截图为英文，多语言待澄清） |

**总体判断：中等规模 B 端业务系统，业务逻辑不复杂但外部集成多、数据链路长、财务准确性要求高；工作量重心在「链接引擎 + 三方 API 集成 + 归因结算」而非页面数量。**

## 二、技术复杂度与关键实现难点

### 2.1 难度分级

| 模块 | 复杂度 | 核心难点 |
|---|---|---|
| Google Sheets/Drive 集成 | ★★★★★ | 见 2.2-R1 |
| 微店 API 对接 | ★★★★★ | 见 2.2-R2（**全项目最大不确定性**） |
| 五级归因引擎 | ★★★★ | 见 2.2-R3 |
| 佣金结算 | ★★★★ | 见 2.2-R4 |
| 链接生成 + 跳转追踪 | ★★★ | 200 万链接批量任务编排；跳转低延迟高可用；点击异步采集 |
| 权限隔离 + 审计 | ★★★ | 达人端防越权（IDOR）；全操作留痕 |
| 达人看板 / 后台 / 注册审核 | ★★ | 常规 CRUD + 报表 |

### 2.2 六大关键难点与应对

**R1 · 谷歌 API 的网络可达性与限流（已实测风险）**
- 国内服务器无法访问谷歌全系 API —— 系统必须部署海外节点（香港/新加坡）或配置稳定海外代理；这同时影响架构、运维和数据链路（订单数据经海外中转，需客户确认无出境合规顾虑）。
- 2 万条链接 × 100 人的批量写入和 Links/Orders/Summary/Settlement 的定时回写，受 Sheets API 配额限制（项目级 300 请求/分钟等），必须做：异步任务队列、分块批量写入（values.batchUpdate）、限速器、断点续传、失败重试、配额监控告警。单个达人表格初始化预计 30–60 分钟，100 人全量铺量需以「小时级后台任务」设计而非同步请求。

**R2 · 微店 API 能力不确定（最大报价风险）**
- 需求文档自认两项事实：微店原生链接直接访问报「商品不存在」；原生链接参数溯源不稳定。因此系统设计为中转链接 + 后端拼接溯源参数跳转，属可控方案。
- 但文档要求「同步调起微店接口、用微店的复制工具为每人生成专属链接」——**微店开放平台是否提供"分销链接复制"的官方 API 尚未证实**；若无官方 API，需退化为半自动（运营在微店后台批量操作 + 系统导入校验）或 RPA 方案，工作量与稳定性差异显著（±15~25 人天）。
- 优惠码同理：文档将「达人专属唯一优惠码」定为一期最高优先级兜底归因手段，但优惠码由微店侧还是本系统侧生成、微店订单数据能否回传优惠码字段，直接决定归因方案能否成立。**签约前必须完成微店开放平台的接口调研与账号申请。**

**R3 · 五级归因引擎的工程化**
- 归因不是简单匹配，而是一个可重放的数据管道：订单到达 → 按优先级 1（达人 ID）→ 2（优惠码）→ 3（track_id）→ 4（时间窗口模糊匹配，二期）逐级裁决 → 未命中进人工池 → 人工修正后要能触发下游统计与佣金的**级联重算**。需要幂等设计、归因结果版本化、修正操作留痕，且统计口径（点击转化率、净销售额）与归因结果强一致。

**R4 · 佣金结算的财务准确性**
- 退款扣回（已结算订单发生退款怎么办）、冻结/解冻、结算单状态机、防重复结算的幂等控制、结算明细可逐笔追溯到订单与归因记录。这是资金相关模块，测试深度应高于其他模块。

**R5 · 数据隔离与安全**
- 达人端必须做到接口级鉴权（不能只靠前端隐藏）：任何查询强制注入当前达人 ID 过滤；链接、订单、结算表按达人隔离；跳转服务防恶意刷量。全链路操作审计日志（导入、匹配、修正、结算、账号变更）。

**R6 · 双端体验与时区**
- 达人在海外（参考界面为英文系统）：达人前台需英文（或多语言）、移动端适配；订单时间、统计周期需明确时区基准（建议 UTC 存储 + 按用户时区展示）；国内运营访问海外部署的后台需评估加速能。

### 2.3 建议技术栈（供参考，以架构设计阶段评审为准）

- 前端：Vue3 / React + Ant Design（管理后台）；达人前台响应式 H5，i18n 多语言
- 后端：Node.js (NestJS) 或 Java (Spring Boot) 单体分层 + 领域模块化；MySQL 8 + Redis
- 异步任务：BullMQ / RabbitMQ（链接生成、谷歌写入、订单同步、回写同步全部队列化）
- 跳转服务：独立无状态轻量服务（Node/Go），302 跳转 + 点击日志异步落库（削峰）
- 部署：海外云主机（香港/新加坡）+ HTTPS + CDN；日志监控告警（Prometheus/Grafana 或云监控）
- 三方凭据：Google 服务账号（Domain-wide Delegation）、微店开放平台应用凭据

## 四、报价方案

1. **工作量依据**：第三节功能模块分解估算（WBS 自底向上 + 类比同类 CRM/分销系统项目校准）。
2. **单价依据**（2026 年国内软件外包市场行情，一线/强二线城市，可按团队实际资质调整）：

| 角色 | 级别 | 人天单价（元） |
|---|---|---:|
| 架构师 / 高级后端 | 5 年+ | 2,600 |
| 中级后端 / 前端 | 3 年+ | 1,800 |
| UI/UX 设计 | 3 年+ | 1,400 |
| 测试工程师 | 3 年+ | 1,200 |
| 项目经理 | 5 年+ | 2,200 |
| **加权平均** | | **≈ 1,800–1,900** |

3. **风险依据**：三个外部 API 依赖中有两个（微店、谷歌网络环境）存在文档明示的实测风险；报价已按「接口可用」的基准假设计算，微店不利情形另列风险预留。

### 4.2 方案一：固定总价（推荐）

| 项目 | 人天 | 报价 |
|---|---:|---:|
| 一期（全链路核心功能 + 上线试运行） | 325 | **¥585,000**（≈ 58.5 万） |

- 风险预留 30 人天（¥5.4 万）不计入合同价，仅在微店 API 调研结论不利（需 RPA/半自动方案）时经双方确认后追加。

### 4.3 方案二：精简一期（降低首期投入，需客户接受范围调整）

在方案一基础上：一期先以 **Excel/CSV 导入 + 优惠码归因** 跑通全链路闭环，微店 API 实时同步移至二期；性能测试从简、看板报表保留核心视图。

| 项目 | 人天 | 报价 |
|---|---:|---:|
| 精简一期 | 约 220 | **¥396,000（≈ 39.6 万）** |
| 二期（微店 API 实时同步 + 全部增强项） | 约 105 | ¥189,000 |

> 适合预算敏感、希望先用最小成本验证业务的客户；与现行 PRD 的"双模式同步"要求有出入，需客户书面确认。

### 4.4 方案三：时间材料制（T&M）

- 按人月计费：**¥38,000/人月/人**（综合人月，21.75 人天/月），按月结算。
- 预估总量与方案一相同（约 17.5 人月），总价预期一致，但需求变更风险由双方共担，适合需求预计持续演进的场景。

### 5.3 关键路径与依赖提示

1. **第三方账号申请必须第 1 周启动**：微店开放平台审核、Google Workspace 开通与服务账号配置、海外服务器采购均有外部等待期（1–3 周不等），任一延迟直接顺延 P2。

## 六、需进一步澄清的问题清单（签约前必须确认）

### A. 决定报价与架构（高优先级）

1. **微店开放平台**：是否已有店铺与开放平台账号？"为指定达人复制专属分销链接"是否有官方 API？优惠码功能是否开放、由谁生成（一达人一码 or 一达人一商品一码）？订单接口能否回传 kol_id/track_id/优惠码字段？有无沙箱环境？
2. **归因兜底优先级确认**：若微店既不回传链接参数、又无优惠码能力，归因只能依赖点击记录 + 人工修正，可接受的归因准确率验收线是多少（建议 ≥95%）？
3. **谷歌资产与部署**：Google Workspace 企业账号是否已有？100 份表格挂在企业域名下还是达人个人 Gmail？系统整体部署海外（香港/新加坡）是否可接受？国内运营后台的访问加速方案与预算？订单/达人数据经海外节点处理是否有出境合规顾虑？
4. **点击量级预估**：100 名达人的粉丝量级与日均点击预估（决定跳转服务与点击日志存储的规格）。

### B. 影响业务规则与工作量（中优先级）

5. **佣金规则**：比例是全局统一、按达人分层还是按商品设置？结算周期（月结/半月结）？起结金额与币种？海外达人佣金通过什么渠道支付（PayPal/银行转账，系统是否需要记录打款凭证）？退款发生在已结算之后的扣回规则细节？
6. **商品与链接维护**：2 万条商品是否所有达人全量一致？商品库更新频率？商品下架/换链后已生成的达人链接与已分发的谷歌表格如何处理（全量刷新 or 增量追加）？
7. **达人注册**：完全自主注册还是运营代建？邮箱验证即可还是需要海外手机号验证？达人端语言（纯英文 or 中英双语）与时区基准？
8. **历史数据迁移**：现有 100 份人工维护的谷歌表格中，历史订单/点击数据是否需要迁移入新系统并纳入结算？
9. **二期范围界定**：时间窗口模糊匹配、恶意点击分析是否确认纳入本合同二期（影响总价），还是验收后另议？

### C. 商务与交付（低优先级，签约时明确即可）

10. 验收标准与试运行时长（建议试运行 2 周 + 归因准确率达标）；质保期时长与响应 SLA；源码交付与知识产权归属；是否需要后续运维托管服务。

## 七、结论摘要

- **定性**：中等规模、集成密集型分销 CRM；页面不重、链路重，财务准确性要求高。
- **报价**：推荐方案一固定总价 **¥58.5 万（一期）/ ¥68.4 万（含二期）**，可谈区间 58–68 万；预算敏感可选方案二精简一期 ¥39.6 万；付款推荐 30/20/30/15/5 里程碑制。
- **排期**：**约 5 个月（21 周）**完成一期 + 二期；一期上线在第 17 周末；7 个里程碑各有明确交付物。
- **最大风险**：微店开放平台的链接复制与优惠码 API 能力未证实 —— 建议合同中约定 W3 前完成接口调研，若结论不利按风险预留条款（30 人天 / ¥5.4 万）或半自动降级方案处理。
- **立即行动项**：签约当周即启动微店开放平台申请、Google Workspace 配置、海外服务器采购，否则整体排期顺延。
