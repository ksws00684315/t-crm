# 海外达人分销CRM单人AI交付报价与排期方案

编制日期：2026年9月30日

交付模式：一名熟悉全栈开发的工程师，使用成熟管理系统框架、代码生成器及多个AI工具，负责设计、实现、联调、测试和上线。

建议客户报价：20,000元。基准投入：26—30个实际工作日。开发排期：约5—6个工作周，接口授权及客户反馈等待时间另计。金额的开票及税费口径须在签约时确认；如果客户预算为含税20,000元，应在该总额内核算收入。

## 一 重新评估结论

本系统以达人、商品、链接、订单、佣金的业务管理为主体。登录、菜单、角色、列表、导入导出、操作日志和基础图表均可复用，常规页面由代码生成器和AI完成初稿，工程师负责业务规则、代码审查和交付验证。按这个模式，原先采用多角色外包团队得出的数百人天估算不适用于本项目。

20,000元可以作为有明确范围的一期报价目标。该判断以使用熟悉的框架、复用模板界面、规则简明、外部接口开放且文档完整为前提，是工程估算，并非已经验证的交付承诺。不能仅因AI能生成调用代码，就假设第三方提供所需接口或订单归属字段。

文档中的100名达人、2万商品、200万条推广关系需要批处理、索引、增量同步及失败重试，但这一规模本身不要求微服务、专门的大数据平台或多名全职工程师。点击峰值和订单增速仍需确认。

## 三 功能范围和实现方式

### 一期覆盖范围

| 功能 | 交付口径 |
|---|---|
| 达人注册及审核 | 姓名、邮箱、国家、社媒资料；审核、启停、密码重置；唯一固定达人ID |
| 角色与数据权限 | 超级管理员、运营、财务、达人；服务端限制达人只能查询自身订单、统计和佣金；导出接口同样隔离 |
| 商品管理 | 商品、SKU及微店商品链接维护；一套固定Excel/CSV模板的批量导入、校验及导出 |
| 专属链接 | 达人、商品、track_id绑定；稳定中转链接；批量初始化与增量更新；任务进度和失败重试 |
| 点击采集 | 中转跳转、点击记录、按达人和商品统计；基础机器人过滤，明确统计口径 |
| Google表格 | 标准模板创建或复制、链接写入、对应达人授权、订单及汇总定时回写、失败重试 |
| 微店订单 | 一家店铺的一套官方订单接口，增量同步支付和退款；另提供固定模板Excel/CSV导入 |
| 订单归因 | 按文档实现达人或渠道标识、唯一优惠码、track_id、人工修正四项能力；记录证据、命中规则和修改历史 |
| 优惠码绑定 | 维护达人与可被微店识别的优惠码关系；创建方式取决于微店可用能力，不能把CRM自行生成的字符串当成微店有效优惠码 |
| 佣金结算 | 单币种、达人固定佣金比例；待结算、已结算、冻结和解冻；退款扣回；导出结算单；记录线下付款状态 |
| 看板及报表 | 达人自身和管理端全域的点击、订单、销售、退款、净销售、佣金指标；日、周、月筛选及简单排行 |
| 日志及系统配置 | 复用框架日志，补充归因修改、佣金和冻结操作记录；同步任务配置及失败列表 |

一期使用一套成熟后台界面，达人端复用同一技术体系，通过角色、菜单和数据权限呈现个人界面；提供固定英文界面文本，不含多语言管理平台和独立品牌视觉设计。

### 需要确认的文档冲突

**表格推广和财务保密。** 正文要求达人转发表格推广，同时要求同一文件含Orders、Summary、Settlement且仅该达人可查看。建议保留每达人一份私有四页管理表，另生成只含推广商品及中转链接的公开目录文件。这个方案增加一份公开文件，需要客户确认；不能用隐藏工作表代替访问隔离。[Google官方保护与隐藏说明](https://support.google.com/docs/answer/1218656?hl=en-gb)明确说明隐藏和保护不能作为保密措施。

**物理隔离含义。** 基准实现为CRM同一数据库的严格逻辑隔离，Google文件按达人独立。如果文档的“物理隔离”指每达人独立数据库、实例或服务器，需要重新确定方案，不能默认等同于按达人ID过滤。

**归因顺序。** 表格列出的顺序是原生达人标识、优惠码、track_id、模糊匹配、人工修正；另一段又称优惠码应成为最高优先级。签约附件需确认顺序及多凭证冲突处理。基准沿用归因表的顺序；冲突订单保留证据供复核，不静默覆盖。

**达人ID生成时点。** 正文分别出现注册生成和审核通过生成。基准在注册时创建内部用户ID，审核通过后分配终身固定KOL编号。

### 本期不纳入的截图扩展功能

店铺装修、模板市场、我的小店、子域名、合作视频费用支付、实际自动打款、达人提现申请、多级邀请分佣、商务部门业绩及高级事件分析。这些功能需要客户明确是否采购，不能把参考截图所有菜单默认纳入20,000元。

时间窗口模糊归因按原文放二期。新增规则、多店铺、多币种、历史数据清洗迁移及第三方接口未提供情况下的浏览器自动化另行评估。

## 四 技术复杂度和真正的难点

| 内容 | 判断 | 一期措施 |
|---|---|---|
| 常规后台页面 | 低至中，适合模板和AI | 复用账号、角色、表单、列表、导入导出及图表；不单独重建框架 |
| 200万推广关系 | 中，主要是初始化和变更 | 商品只存一份；维护达人商品映射；稳定链接按需解析；批量任务分块、断点续跑 |
| Google写入及权限 | 中，官方接口明确，但有配额和账号限制 | 按实际载荷分批，增量回写，指数退避，任务可恢复；先验证文件归属及授权 |
| 微店分销链接与订单凭证 | 最高不确定性 | 用实际账户验证生成链接、真实下单和订单返回值；不能只测“API返回200” |
| 佣金、退款和人工修正 | 中，关键是金额一致性 | 金额使用十进制定点；订单明细及费率快照；已结算后的退款形成扣回记录；重复同步不重复计佣 |
| 达人隔离 | 中，必须验证 | 从登录身份取达人ID，查询、明细、统计、导出统一限制；修改URL或请求参数不能越权 |

**中转链接只能证明点击来源。** 它不能自动让微店在订单中保留kol_id、优惠码或track_id，也不能保证解决所有“商品不存在”错误。优先确认微店原生推广员标识或可回传优惠码；都没有时，应在签约前和客户确定人工归属的可接受程度。此时系统仍能管理点击、订单和结算，但不能宣称完成自动精准归因。

微店[官方分销介绍](https://www.weidian.com/fxGuide/)说明存在分销和推广员能力，但不能据此认定当前商家账户有批量生成200万专属链接的开放接口，或订单接口提供需求中的全部字段。

Google Sheets默认读写配额分别为每项目每分钟300次、每用户每项目每分钟60次，建议单次载荷控制在2MB以内，不能只按每项目配额计算吞吐。[Google Sheets官方限制](https://developers.google.com/workspace/sheets/api/limits?hl=zh-CN)。Drive是另一个服务，要根据实际项目配额单独配置。[Google Drive官方限制](https://developers.google.com/workspace/drive/api/guides/limits)。服务账号不能拥有文件，应验证共享云端硬盘或代表用户的OAuth方案。[Google共享云端硬盘说明](https://developers.google.com/workspace/drive/api/guides/about-shareddrives)。

## 五 单人AI模式工作量

这些是工程师实际投入的工作日，包含指导AI、代码审查、必要沟通和联调，不是AI运行时间，也不是把原有人天统一打折。要求工程师熟悉所选框架，商品模板和接口资料可及时获得。

| 工作包 | 工作日 | 估算依据 |
|---|---:|---|
| 范围确认、数据模型、框架初始化 | 2 | 复用成熟脚手架，不重新开发登录和权限框架 |
| 达人注册、审核及角色菜单 | 1—2 | 生成基础页面，补充状态和达人ID规则 |
| 商品导入、专属链接、中转与点击统计 | 3 | 通用导入与列表复用，重点开发批量任务和跳转 |
| 订单导入、确定性归因及人工修正 | 3 | 固定模板、四项规则、证据留存及重复导入处理 |
| 佣金、退款、冻结和结算导出 | 3 | 单币种、固定费率，验证部分退款及结算后扣回 |
| 达人端及管理端基础看板 | 2 | 复用图表组件，统一统计查询，不做复杂BI |
| Google模板、分发、权限及回写 | 3—4 | 使用官方SDK，按标准模板实现任务队列及重试 |
| 微店官方链接与订单接口 | 2—4 | 限文档完整、账号具备权限、可用接口覆盖需求的常规对接 |
| 全流程测试、必要修复、部署及交付说明 | 4 | 重点验证越权、金额、重复同步、退款、批量初始化 |
| 已知范围内的返工缓冲 | 3 | 处理已约定功能的联调与反馈，不覆盖外部平台缺失能力 |
| **合计** | **26—30** | **核心管理部分21—22日；两个外部集成合计5—8日** |

这一估算仍需用最初2—3天的实际开发速度校准。首次使用陌生框架、接口无法试用或客户要求多次改版，会超出基准；不能以AI数量推算线性提速。

### 内部收益核算

20,000元除以26—30日，相当于每天约667—769元的项目收入，尚未扣除税费、AI工具、模板和售后时间。这是单人劳动收入核算，不等同于净利润或员工工资。

例如将本项目分摊的AI和模板费用暂设为1,000元，按28日交付，扣除该项后为约679元/日；再有5日售后投入，则约576元/日。1,000元仅为可替换的预算假设，不是已查询的软件套餐价格。实际应以你的订阅账单、模板授权及税费替换。

接单收益取决于能否在约一个月工作量内完成并控制修改轮次。客户已收到的40,000元报价可用来对照交付范围，没有必要仅因竞争报价翻倍就假设对方利润或实施成本。

### 费用边界及维护

20,000元覆盖约定功能、一次标准生产部署、源码、数据库脚本、部署及使用说明、一次远程培训，以及验收后30日内约定功能的缺陷修复。第三方账户、服务器、域名和订阅由客户持有并另行支付；新需求、平台政策变化或API版本迁移单独评估。

如果客户要求20,000元全包服务器或更长售后，应从总额内先预留对应费用，再核算可投入时间。维护期内不应把实现缺陷当作新需求收费。

约5—6个工作周为人员可连续投入、客户及时反馈的基准。外部授权等待、不可用接口或需求变更会影响日期，应记录实际阻塞和调整后的计划；双方确定开工日期、节假日和反馈时限后再给出日历里程碑。

## 八 付款方式

推荐40%—40%—20%：签约并确认范围后支付8,000元；M2核心业务闭环验收后支付8,000元；M5全量验收、上线及交付后支付4,000元。

备选30%—40%—30%：签约6,000元，M2验收8,000元，M5验收6,000元。30日缺陷修复义务不因尾款结清而取消。

接口能力验证应尽量在固定范围合同签署前完成；如需要先采购小规模验证，应另列其成果和费用，并明确是否抵扣20,000元总价，不能重复收费。

## 九 关键验收用例

1. 达人A修改请求中的达人ID、订单ID或导出参数，无法取得达人B的私有数据；Google私有表访问同样受到限制。
2. 同一订单通过API和CSV重复进入系统，不重复计订单、销售额和佣金；支付及退款状态可更新。
3. 同时存在达人字段、优惠码及track_id时，按已确认顺序处理并保留证据；无有效凭证进入人工池。
4. 部分退款、重复退款通知、结算前退款及结算后退款，佣金计算和扣回金额正确；人工改归属后不会重复向两个达人计佣。
5. 100名达人和2万商品的推广关系生成后无重复、无漏写、无串号；Google批量写入失败可恢复，重新执行不会重复创建全部文件。
6. 公开推广文件仅有允许公开的内容，订单及佣金不出现在公开文件中；以双方确认的文件分拆方案为准。
7. 使用真实订单验证至少一项可用的强归因凭证。接口缺失时，验收采用签约前确认的替代流程，不能用模拟数据宣称第三方能力已打通。

跳转峰值、初始化完成时限及表格同步延迟需在验证后定数值。基准方案采用分钟级订单同步和定时表格回写；文档中的“实时”如果指秒级全部表格更新，应重新评估配额及工作量。
