**Google 表格内容范围（三选一，待确认）**

达人会把表格转发到社媒，表格对所有人公开可见。Google 的页签隐藏和保护功能不能起到权限隔离作用，因此订单、佣金数据不能放在公开表格的隐藏页签里。

| 方案 | 内容 | 是否在本期报价内 |
|---|---|---|
| 方案一（推荐） | 公开表格只放商品链接；订单、佣金、结算只在系统达人端查看 | 是 |
| 方案二 | 公开表格放商品链接；另为每位达人建一份仅本人可见的私有表格，放订单和佣金 | 否，需另行评估 |
| 方案三 | 只建私有表格（含全部页签），不作为公开推广页 | 是 |

**不在本期范围内**

- 商务佣金、奖金、绩效考核规则（已报价的团队销售汇总和达人排行榜包含在内）
- 商品流量、成本、利润等额外分析（已报价的商品销售、退款及达人下钻包含在内）
- 外部机器人通知（系统内高退预警包含在内）
- 合作支付、达人提现、邀请/多级分销、达人等级、店铺装修、模板市场、我的小店、子域名
- 在微店中复制专属商品、修改微店副本的价格、库存和上下架
- 超过 3 个微店店铺或更换订单数据来源

### 2.2 可选增值项（另行计费）

| 增值项 | 解决的问题 | 开发费用 | 增加的运行成本 |
|---|---|---:|---:|
| **双机热备** | 降低单台服务器故障的影响。增加备用服务器、数据库主从同步和健康检查，主服务器故障时切换到备用服务器，切换期间可能短暂不可用。自动切换覆盖的故障类型和恢复时间以上线前演练结果为准。主从同步会同步误删操作，不能代替备份 | ¥3,000 | 约 ¥290～350/月（同配置备用服务器 + Cloudflare 负载均衡约 US$5/月） |
| **分钟级数据恢复** | 基础方案每天备份一次，最多可能丢失 1 天数据。增加数据库变更日志的异地归档后，目标最多丢失 5 分钟数据，可恢复到指定时间点，以恢复演练结果为准。归档约占 1～2GB 存储，不需要更换服务器硬盘。数据库回退后，Google 表格和已线下支付的佣金不会自动回退，需要人工核对 | ¥1,000 | 约 ¥0～10/月（归档存储） |

## 三、技术方案

### 3.1 部署与保障

| 项目 | 方案 |
|---|---|
| 界面语言 | 管理后台为中文，达人端为英文 |
| 部署 | 部署在美国西部云服务器（美国源站，不使用中国大陆 CDN，按规定通常无需 ICP 备案），可直接访问 Google 接口 |
| 基础保障 | 每日数据库异地备份、宕机监控告警、全站 HTTPS |

### 3.2 运行成本

以下费用由贵方以自己的名义开通，直接支付给服务商，我方不加价。汇率按 1 美元 ≈ 7.1 元估算，以实际账单为准。

**服务器（二选一）**

| | 方案 A：国内大厂云（推荐） | 方案 B：海外大厂云 |
|---|---|---|
| 服务商与配置 | 腾讯云轻量应用服务器，美国硅谷机房，4 核 8G、180GB SSD、35Mbps 带宽、每月 5TB 流量 | AWS Lightsail，美国俄勒冈机房，2 核 8G、160GB SSD、每月 5TB 流量 |
| 月费 | 约 ¥256（参考价 US$36，以腾讯云国内站下单价为准） | 约 ¥312（US$44） |
| 优势 | 通过腾讯云国内站开通：中文控制台和客服；支持支付宝、微信付款，可开国内发票；快照、防火墙、监控集中在一个控制台 | 美国本土云平台，配套服务齐全（负载均衡、托管数据库、邮件服务等）；不需要中国实名认证 |
| 劣势 | 需要中国大陆实名认证；海外机房可选配置比国内少；下单前需确认续费价格 | 控制台和客服以英文为主；需要国际信用卡付款，无国内发票 |

**推荐方案 A。** 本系统的管理后台主要由国内运营、财务使用，选择中文服务和国内付款更方便。两种方案的网络表现在 M0 阶段从国内和美国分别实测后再最终确定。贵方此前考虑的 UCloud（美国洛杉矶）也可以作为候选，一并实测。

### 3.3 技术风险点

以下风险在 M0 阶段（10/02～10/05）基于贵方已提供的账号和样例进行验证，并给出"通过 / 待验证 / 不通过"的结论。第三方审批（如微店接口权限）的时间由平台决定，不保证在 M0 内完成；未获批的项目标为待验证，并约定后续验证时间。**若核心前提验证不通过（如专属商品 ID 在真实订单中不保留），双方复核范围和报价后再继续。**

| 风险点 | 影响 | 应对措施 |
|---|---|---|
| 专属商品 ID 在真实订单中是否保留 | 代购平台可能转换商品链接，或采购时改用原商品，导致订单无法自动归因 | 用一笔完整测试订单核对：用户点击的链接、平台采购链接、最终订单商品 ID。只对保留专属商品 ID 的订单自动归因，其余进入人工匹配池 |
| 达人专属商品的标识规则 | 系统需要知道每个专属商品属于哪位达人、对应哪个原商品 | 约定标识规则（按达人编号建商品分类，或商家编码写成"原商品编码-达人编号"），在接口或导出文件确实返回该标识时，系统自动读取；否则由运营导出对应关系 Excel 后导入 |
| 微店订单接口权限 | 订单接口属于微店"加密接口"，需要向微店申请开通 | 签约后立即提交申请；开通前用订单 Excel 导入。Excel 导入期间，订单数据不是自动实时同步，看板显示"最近一次同步时间" |
| 专属商品的数量 | 100 位达人 × 2 万个商品 = 200 万个微店商品副本，可能超过微店单店上限，或被判定为重复铺货；复制与校验需要大量运营投入 | 贵方向微店确认上限与规则，并用实际复制工具测试速度；必要时分店铺存放（本期最多 3 个店铺） |
| Google 账号与存储 | 服务账号没有 Google 云端存储空间，不能直接持有表格 | 推荐使用 Google Workspace 共享云端硬盘；M0 实测建表、公开只读分享等权限 |
| Google 内容审核 | 表格有被 Google 限制访问的可能 | 全部链接和数据以系统数据库为准，可重新生成表格。重建不能保证解除平台限制；新表格的地址会变化，需要通知达人更新社媒中的链接 |
| "商品不存在"报错 | 部分链接直接打开时报错 | M0 阶段复现，区分链接格式、商品下架、权限、地区限制等原因；系统可控制的问题在中转跳转中处理，商品下架等情况给出明确提示，不承诺绕过平台限制 |
| 微店全店 UV、PV 数据来源 | 微店开放平台公开的接口文档中未找到店铺访客、浏览量接口 | M0 阶段向微店确认；无接口时，从微店后台导出后导入（需确认后台可导出）；仍无法获取时，改为"推广链接 UV、PV"，不展示转化率 |
| 代购下单时的"下单人数" | 代购平台用少数几个采购账号下单，按买家去重的"下单人数"会偏少，"下单客单价"会偏高 | 在看板上标注口径；需要时改为按订单数计算客单价 |
| 看板刷新频率 | 需求要求每 5 分钟刷新 | 订单接口开通后，每 5 分钟增量同步订单并更新当天统计；历史数据按天汇总，发生退款或人工改归属时重算受影响的日期 |

## 五、验收与变更

### 5.1 验收方式

验收以 M0 阶段签认的《需求确认书》为依据，至少覆盖以下场景：

| 类别 | 验收场景 |
|---|---|
| 订单归因 | 真实购买链路的订单正确归属；一笔订单含多位达人商品时按明细归属；重复导入同一订单不重复计算 |
| 佣金结算 | 部分退款和跨月退款的扣回；结算后人工修改归属的处理；不重复计佣 |
| 权限 | 达人只能看到自己的数据；商务只能看到自己负责的达人；越权访问被拒绝 |
| Google 表格 | 公开表格只读、私有表格不对外可见（按选定方案）；批量建表失败后可重试 |
| 数据完整性 | 已复制达人的专属商品对应关系完整；看板数据与订单明细一致 |
| 数据安全 | 完成一次备份恢复演练 |

### 5.2 验收流程

- 我方交付测试环境完整版本后，贵方在 **5 个工作日内**反馈问题。
- 问题分为两类：**阻断性问题**（主流程无法完成、数据计算错误）和**一般问题**（显示、文案、操作体验）。阻断性问题修复后复验；一般问题可在质保期内修复，不影响验收签认。
- 验收签认之日为上线日，质保期从签认日起算。
- 验收期间提出的新需求不属于验收问题，按变更流程处理。

### 5.3 变更流程

贵方书面提出变更 → 我方评估工作量和对排期的影响 → 双方书面确认后执行，费用按 ¥1,000/人天计算。

### 5.4 源代码与账号交付

- 交付本项目源代码、数据库脚本、部署步骤和必要的配置说明。
- 使用的开源组件保留其原有许可证。
- 账号密码、接口密钥不写入源代码，单独移交给贵方。
