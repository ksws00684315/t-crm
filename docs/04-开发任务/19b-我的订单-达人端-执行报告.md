# 19b 我的订单（达人端）执行报告

## 实现内容

- 新增只读接口 `GET /kol-api/orders`，要求达人登录态；达人 ID 和公司上下文只取自登录态。
- 查询范围限定当前达人且 `attribution_status = ATTRIBUTED` 的订单；支付时间 `payFrom` 含、`payTo` 不含，按支付时间倒序分页。状态仅接受七种标准状态，`size` 超过 50 由参数校验拒绝（400）。
- 返回分页 `{items,total,page,size}`。行字段为脱敏 `orderNo`、`payTime`、`orderStatus`、本人明细实付合计 `payAmount`、本人明细已完成退款合计 `refundAmount`、明细名称/SKU/数量/金额。响应不包含订单 ID、买家信息、店铺、商务、归因细节、商品 ID。
- 脱敏规则：订单号长度大于 8 时仅展示前 4 位、`****`、后 4 位；长度不大于 8 时仅展示末 2 位。金额只汇总归属于当前达人的订单明细，不含运费。
- 达人端增加 `/orders` 页面、首页入口与导航项；默认最近 30 天，支持 7/30/90 天和自定义日期区间（浏览器本地时间转换为 UTC）、状态筛选。宽屏表格可展开明细，小于 768px 显示订单卡片；金额按人民币两位小数展示，七种状态与界面文案均有中英文语言包。
- 更新系统设计说明书 §6.3 和 `backend/openapi-order.yaml`。没有新增依赖或数据库迁移。

## 接口示例

请求：

```http
GET /kol-api/orders?payFrom=2026-09-16T00:00:00Z&payTo=2026-10-16T00:00:00Z&orderStatus=COMPLETED&page=1&size=20
X-Kol-Token: <达人登录令牌>
```

响应（金额和 ID 按统一接口约定序列化为字符串；本接口不返回订单 ID）：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "items": [
      {
        "orderNo": "1234****5678",
        "payTime": "2026-10-10T08:30:00Z",
        "orderStatus": "COMPLETED",
```

## 偏离与遗留

架构审查提出脱敏订单号可能重复，不能作为卡片 key 或展开状态标识。已改用当前页列表位置作为卡片 key/展开标识，订单列表刷新时清空展开状态；桌面表格移除了同样不唯一的 `row-key`。新增回归测试先复现两张卡片同时展开，再验证仅展开被点击卡片。定向页面测试 5 项、Portal lint 和 typecheck 通过；更新推送后由 PR CI 再次验证。
