# 管理端登录图形验证码执行报告

> 分支 `feat/login-captcha`（基于 main `7a081fc`）。本任务没有提示词文件：需求来自项目负责人在对话中的选择——"图形验证码，自己生成，每次登录都要"。设计决定见 [ADR-017](../06-架构决策/ADR-017-管理端每次登录需要图形验证码.md)。

## 执行结论

管理端登录页与登录过期弹窗都要输入图形验证码，后端在校验密码之前先校验并作废验证码。达人端未改（其登录仍是本地占位实现）。本地后端 `mvn -B verify -Pdocker-it`、管理端 lint / typecheck / test / build / notices:check 全部通过。

## 设计决定落实位置

| 决定（ADR-017） | 位置 |
|---|---|
| 签发接口、`no-store`、公开 | `AuthController#captcha`（`@PublicEndpoint`）、`SecurityConfiguration` 两个拦截器的排除列表 |
| 纯 JDK 生成 PNG（4 字符、去易混字符、`SecureRandom`） | `security.service.CaptchaImageGenerator` |
| Redis `auth:captcha:{id}`，3 分钟，GETDEL 一次性，不区分大小写 | `security.service.CaptchaService#issue/verify` |
| 签发限速：每 IP 每分钟 30 张，429 `AUTH_CAPTCHA_RATE_LIMITED` | `CaptchaService#issue`（Lua 固定窗口，IP 取 SHA-256）；Nginx `tcrm_captcha` 区 |
| 先验证码、再锁定检查、再密码；错误 400 `AUTH_CAPTCHA_INVALID`，不计入失败 | `AuthService#login` |
| 开关 `crm.auth.captcha.enabled`（默认 true） | `application.yml`；关闭时签发返回 `enabled=false`，前端隐藏输入框 |
| 登录页、重新登录弹窗；点击换图；任何失败后自动换图；回车提交 | `components/CaptchaInput.vue`、`views/login/index.vue`、`layout/ReauthDialog.vue` |
| 中文 / 英文错误提示 | `locales/*.ts` 的 `errors.AUTH_CAPTCHA_*`、`captcha.*`、`validation.captchaRequired` |

交互细节：

- 验证码错误时**保留已输入的密码**（只是验证码错了），其他失败照旧清空密码。重新登录弹窗中验证码错误显示在验证码输入框下方。
- 弹窗只在第一次打开时拉取验证码，之后每次重新打开都换一张；页面加载不会请求验证码。
- 验证码图片自带浅色底，深色主题下用 `--el-fill-color-light` 底色和边框框住，输入框随主题变化。

| 项目 | 结果 |

| 生产 JRE 镜像出图 | 在 `eclipse-temurin:21.0.12.1_1-jre` 中用编译好的生成器出图成功（headless，镜像自带 DejaVu 字体），目测可读 |
| 跳转服务 | 未改动，未运行 |

新增 / 修改的测试：

- `CaptchaImageGeneratorTest`：字符集与长度、PNG 尺寸与大小、随机性、相同种子出图一致。
- `CaptchaServiceTest`：3 分钟 TTL、不区分大小写、错误也作废、重复使用、过期、缺失或格式错误的 ID 不查 Redis、签发限速键不含明文 IP、关闭开关。
- `AuthServiceTest`：校验顺序（验证码 → 锁定 → 密码）；验证码错误时不计失败、不查账号、不做 BCrypt。
- `AuthControllerTest`：签发接口返回字段与 `Cache-Control: no-store`。
- `CaptchaLoginIT`（开启状态，真实 Redis）：公开签发、PNG 可解码、Redis TTL；正确（大小写均可）登录成功；缺失、错误、过期、重复使用都返回 400；错误验证码连续 8 次后不锁定、正确登录成功；验证码正确但密码错误第 5 次仍 429，锁定期间不带验证码仍先返回 400；签发第 31 次 429、换 IP 正常。
- 现有登录辅助方法（`CompanySessions.login`、`SystemIT`、`TenantIsolationIT`、`KolIT`）改用新的 `Captchas` 测试辅助类：先签发、从 Redis 读答案，并清掉签发计数，避免整套 IT 在 127.0.0.1 上触发限速。
- 前端 `login.spec.ts`：显示图片、点击换图并清空输入、必填、失败后换图且下次带新 ID、验证码错误保留密码、回车提交、关闭开关时隐藏并不发送；`reauth.spec.ts`：带验证码登录、必填、`AUTH_CAPTCHA_INVALID` 后换图并保留密码与会话。

## 偏离与遗留事项

- **分支名**：规范 08 要求 `task/{编号}-{名称}`，本任务没有编号，使用 `feat/login-captcha`；如需编号请负责人指定，任务索引 `README.md` 由负责人维护，本次未改。
- **答案明文存 Redis**：见 ADR-017 决定 2。
- **达人端**未加验证码（无后端登录接口）。
- **未验证**：生产 Nginx `tcrm_captcha` 限速区未在真实 Nginx 中加载测试（只改了模板）；浏览器中的实际外观（浅色 / 深色）待负责人在本机或验证机复验。
