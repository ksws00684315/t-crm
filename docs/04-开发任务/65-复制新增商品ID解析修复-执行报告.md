# 65 复制新增商品 ID 解析修复 —— 执行报告

分支 `task/65-item-add-parse`，只改后端与任务文档；无迁移、无新依赖、无新错误码、无前端改动。

## 1. 缺陷

2026-10-24 M0 实测：表格脚本复制商品时，`vdian.item.add`（1.5）微店返回 `status_code=0`，商品已在微店创建（只读核对确认店内多出一件新商品）。系统却把该条记为「微店接口调用失败」，后续详情保存、达人商品对应关系、链接索引登记均未执行，额度已扣。

## 2. 原因

- `WeidianBusinessApiParser.addItem` 只读取 `result.item_id`。微店实际返回的商品 ID 字段名为 `itemid`（M0 实测），解析结果为 `null`。
- `WeidianItemCopyService.copy` 在 `itemId == null` 时抛出无自定义信息的 `WEIDIAN_API_FAILED`，因此显示为「微店接口调用失败」。

## 3. 修复

| 文件 | 改动 |
|---|---|
| `WeidianBusinessApiParser.java` | `addItem` 按 `itemid`、`item_id`、`itemId` 顺序识别商品 ID；数值或数字字符串均可；都没有则为 `null`。`add_sku_ids` 读取不变。 |
| `WeidianItemCopyService.java` | `vdian.item.add` 调用成功但解析不到 ID 时，抛出 `WEIDIAN_API_FAILED` 并附中文原因 `ITEM_ID_MISSING`：「微店已返回成功但未识别新商品 ID，商品可能已在微店创建，请在微店后台核对」；同时打 WARN 日志，内容为店铺 ID 与 `result` 的字段名列表，不含任何值。 |
| `WeidianBusinessApiParserTest.java` | 新增 `itemid` 数字、`itemid` 数字字符串、无已知 ID 字段三类用例；原 `item_id` 用例保留。 |
| `WeidianItemCopyServiceTest.java` | 新增：`itemid` 返回时复制成功并继续保存详情；成功但无 ID 时抛出明确错误、不保存详情，日志仅含字段名、不含值。 |
| `ADR-016` 后续核实 | 补一条 `vdian.item.add` 1.5 商品 ID 字段按 M0 实测为 `itemid` 的说明。 |

错误码沿用 `WEIDIAN_API_FAILED`（已有 `CopyJobWorker.failMessage` 对自定义中文消息的透传路径），未新增错误码，因此未改 `admin-ui` 语言包。

## 5. 第 4 条核对：`tmp_detail_id`

结论：**不改**。

- `WeidianBusinessApiParser.saveItemDetail` 解析 `tmp_detail_id`，但 `WeidianItemCopyService.copy` 完全不读取该返回值。
- 详情保存是否成功只由调用是否抛异常决定（异常时记 `DETAIL_SAVE_WARNING`，复制仍成功）。因此字段名不同不会造成误判失败。
- 该字段在整个后端只有解析和一个测试夹具引用，没有业务分支依赖它。

## 7. 与任务前提的偏差

1. **`docs/04-开发任务/55-微店接口连通性-实测结果.md` 不支持 `itemid` 结论。** 该实测报告中 `vdian.item.list.get` 返回 0 条、字段未检查；`vdian.item.get` 与 `vdian.item.getItemDetail` 标注为「跳过：无商品」。因此 ADR 补注只写「按 2026-10-24 M0 只读实测」，并注明任务 55 未覆盖该字段，没有引用 55 作为证据。`itemid` 在代码中的既有依据是官方示例夹具（`item-10552-v1.1.json`，`vdian.item.get` 1.1）及解析器既有的 `item()` / `itemList()`。
2. ADR 补注中的「M0 只读实测」来源是任务单所述的缺陷记录，仓库内没有对应的原始实测文件。

## 8. 遗留（不在本任务范围）

- **已创建商品未入账**：修复后仍会对「微店已成功但无 ID」的情况报错，复制任务项标记为失败，额度已扣，且微店上已存在的商品不会写入达人商品对应关系或链接索引。需人工在微店后台核对并补登记。建议后续另立任务：在该情况下记录微店侧商品标识以便对账，或提供补登记入口。
- 若微店真实返回的 ID 字段名不是上述三种之一，修复后会得到明确错误，且 WARN 日志中的字段名可直接用于定位。
