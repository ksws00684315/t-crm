## 1. 背景

任务 16 已实现商务转移的后端：

- 立即转移，或预约在将来某个时刻生效；
- 按约定的生效时间写归属历史；
- 商务停用后，名下达人自动改为「未分配」，即归公司。

管理端目前只有达人行上的「更换商务」，它调用旧接口 `PUT /bd-user` 做单个达人的立即更换。客户的场景是商务离职：超管把他名下的达人整批转给别人，并且可以预设生效时间（设计 §4.13）。

## 4. 已定的设计决定（不要自行改变）

### 4.1 后端补充（只限以下两项）

1. **转移记录补显示字段**：`GET /admin-api/kol/bd-transfers` 每行增加 `kolCode`、`kolName`、`fromBdUserName`、`toBdUserName`（昵称优先，没有昵称用用户名；为空表示未分配）。按页批量查询，不逐行查。
2. **保存转移原因**：现在 `reason` 只写进操作日志，记录页看不到。
   - 新增迁移，给 `crm_kol_bd_transfer` 加 `reason VARCHAR(255) NULL`（带中文注释），发起转移时写入，列表返回；
   - 迁移脚本 `V202610172100__add_bd_transfer_reason.sql`；
   - `PUT /bd-user` 发起的转移没有原因，保持为空。

两项都写单元测试，并补集成测试。不改转移规则。

### 4.2 转移对话框（一个组件，三处入口）

**字段**：

- **转移对象**：只读显示「已选 N 位达人」，或「商务 X 名下全部达人（当前 N 位）」；
- **新商务**：下拉，选项来自 `GET /admin-api/system/bd-users`，另加一项「未分配（归公司）」；按商务转移时，下拉中排除来源商务本人；
- **生效时间**：单选「立即」或「指定时间」。
  - 指定时间用日期时间选择器，按浏览器本地时区显示，旁边注明时区（例如「北京时间 UTC+8」），提交时转成 ISO UTC；
  - 只能选择当前时间之后、一年以内的时刻。
- **原因**：可选，≤ 255。

**提交**：调用 `POST /admin-api/kol/bd-transfers`。

- 成功时提示「立即完成 X 位，预约 Y 位，跳过 Z 位（已属于新商务）」；
- 409 `KOL_TRANSFER_EXISTS` 时，提示「以下达人已有预约转移，请先取消：」，并列出响应 `data` 中的达人编号；
- 422 `KOL_INVALID_BD_USER` 时显示对应文案。

**三处入口**（都只对超管显示）：

1. **达人列表工具栏**「转移商务」：勾选达人后可用，最多 500 位（超出时提示），请求 `kolIds`。
2. **达人行上的「更换商务」**：改为打开同一个对话框，只有这一位达人，请求 `kolIds: [id]`，不再调用 `PUT /bd-user`。后端旧接口保留不动。
3. **用户管理中商务账号行**的「转移名下达人」（仅子账号且数据范围为「本人」的行）：请求 `fromBdUserId`。
   - 名下人数通过 `GET /admin-api/kol/kols?bdUserId=…&size=1` 的 `total` 取得；
   - 为 0 时按钮置灰并提示「名下没有达人」。

### 4.3 停用商务的确认

用户管理中停用子账号时，确认框说明后果：「停用后，其名下 N 位达人将立即转为未分配（归公司），转给他的预约转移将被取消。」

- N 的取法同上；
- 名下为 0 时不显示这句话；
- 其他账号的停用确认不变。

### 4.4 转移记录页

1. 路由 `/kol/bd-transfers`，`meta.superAdmin: true`，菜单名「转移记录」，放在「达人管理」之后。
2. **筛选**：状态（预约中 / 已完成 / 已取消）、达人编号、来源商务、目标商务。
3. **列**：
   - 达人（编号 + 姓名）、来源商务、目标商务（空显示「未分配」）；
   - 约定生效时间、状态、实际执行时间；
   - 原因、取消原因、创建时间、操作。
4. **操作**：状态为预约中的记录有「取消预约」，二次确认后调用 `DELETE /admin-api/kol/bd-transfers/{id}`；409 `KOL_TRANSFER_NOT_SCHEDULED` 时提示对应文案并刷新。
5. 时间按浏览器本地时区显示。

### 4.5 与站内消息（20）的约定

转移记录页支持查询参数 `?status=` 与 `?kolCode=`：打开页面时用它们作为初始筛选条件。
