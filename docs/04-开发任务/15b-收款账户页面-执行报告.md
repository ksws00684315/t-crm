## 4. 偏离与说明

1. **`meta.permission` 扩展为数组任一满足**：按提示词 §4.2.1 实现，`canAccessRoute` 单码路径行为不变，补了专门用例；这是既有测试文件（`permission.spec` / `guard.spec` / `component-names.spec`）清单更新的原因。
2. **达人端二维码上传必须显式 `Content-Type: multipart/form-data`**：kol-portal 的 axios 实例默认 `application/json`，axios 1.20 的 `transformRequest` 在 JSON Content-Type 下会把 FormData 序列化成 JSON。已用 API 契约测试锁死「FormData + multipart 头」，防回归。这是浏览器验证发现的真实缺陷，不是测试环境问题。管理端存在同样的问题（Excel 导入），已由 #66 在 `utils/http` 拦截器层统一修复并合入 `main`；达人端保留调用点显式设头的做法（审查已认可）。
3. **`component-names.spec` 超时 5s→20s**：页面模块从 10 个增至 11 个，逐个动态 import 略超默认超时；断言本身未变，仅放宽时间预算。
4. **停用检查只做取消路径的浏览器验证**：确认路径已有单元测试覆盖，浏览器里不真停用（不可恢复）以免破坏后续验证数据。
5. **达人端账号长度下限取 3**：提示词只给上限，与后端 `@Size(min=3)` 对齐，避免提交后才被 400 拒绝。
6. **语言包预置 `nav.orders`**：19b 尚未合并，按 §4.3 要求三项键中英文都已备好，`NAV_ITEMS` 只放本任务两项。
7. **菜单徽标方案**：在 `MenuItem`/`SideMenu` 上加 `badge` 渲染实现（当前布局原本无徽标支持），未使用「页面标题旁显示」的降级方案。

## 5. 审查修复（PR #61 评论，2026-10-17）

架构审查通过，两处不阻塞的小问题已修复并补测试：

1. **`?id=` 关闭后同一链接无法再打开**：原实现只 `watch(route.query.id)`，关闭抽屉后 URL 仍带 `?id=`，再点同一条消息是对相同 URL 的 push、不产生导航，watch 不触发。现在关闭抽屉时清掉 `detailId` 并 `router.replace` 去掉 `?id=`（保留其他参数），使下一次点击成为真实的查询变化。新增两个用例：关闭后 URL 无 `id`、再次 push 同一链接重新打开且 `accountId` 正确；去掉 `id` 时保留其他查询参数。
2. **`ReviewDrawer` 409 分支多余的 try/catch**：`load()` 自身已捕获并提示错误、关闭抽屉，外层 try/catch 删除；既有 409 用例（提示 + 自动重载 + 触发 `reviewed`）仍通过。

按审查要求已把最新 `main`（含 #66 与 21a/21b 提示词）以 **merge** 方式合入本分支，无冲突；与 #57（`nav.ts`、达人端布局/首页/语言包）及 #59/#62/#63（管理端语言包、`component-names.spec.ts`）的并列冲突由后合并的一方保留双方条目。
