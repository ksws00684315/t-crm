# 任务 151：复制链接转换回溯原始商品 — 执行报告

## 1. 结论

convert 的来源商品 ID 命中登记过的达人专属商品（`crm_kol_item` 当前有效行）且属于其他达人时，从「直接失败（该商品是其他达人的专属商品）」改为回溯 `product_id` 指向的原始商品再走既有复制流程；同达人幂等返回已有 ID 的行为不变；无法回溯（推广表上传映射无原商品、原商品已删除）的失败并提示改用原始链接。负责人 2026-11-13 确认口径变更（ADR-019 修订、偏离清单 D-29）。

## 2. 背景与问题

脚本把复制后的链接写回表格单元格（SparkTrack 脚本「按商品 ID 替换」），下一位达人跑同一张表时提交的来源 ID 就是上一位达人的复制件 ID。ID 提取逻辑无法区分原始链接和复制件链接。原实现按「来源总是原始链接」设计（ADR-019 第 4 条、`CopyJobWorker` 内注释），复制件 ID 一律拒绝，导致该主流程整批失败。

## 3. 主要改动

### 3.1 后端（`product` 模块）

- `CopyJobWorker.processOne`：
  - 同达人专属 ID 分支原样保留（幂等返回该 ID，不复制不扣额度）；
  - 其他达人的专属 ID：新增 `resolveExclusiveSource` 回溯原始商品（`product_id` 为空或商品已删除返回 null），`shopUnavailable` 校验原商品店铺启用（与 `findSource` 对已登记原商品的停用店铺同规则，报 `SOURCE_NOT_IN_SHOPS`）；可回溯的走新提取的 `copyFor`（shop-item 锁 → 已有映射短路 → 扣额度 → 微店复制 → 登记对应关系 → 容量计数 → 链接索引事件 → 成功落库），不可回溯的失败落库新文案 `EXCLUSIVE_UNTRACEABLE`；
  - `copyFor` 为原 222-267 行的纯移动提取，findSource 路径与回溯路径共用。
- `ProductLinkMessages`：新增 `EXCLUSIVE_UNTRACEABLE`，删除 `OTHER_KOL_EXCLUSIVE`（唯一引用点已随分支删除）。
- 不改：convert 入口校验、日额度与令牌额度语义、resolve 状态映射、probe 路径、租户隔离、admin-ui（失败文案由后端落库透传）。

### 3.2 测试

- `CopyJobWorkerTest`：新增回溯成功（U1）、回溯后已有映射幂等（U2）、`product_id` 空（U3）、原商品已删（U4）、原店铺停用（U5）、回溯路径持锁（U6）；重写原拒绝用例；`verifyFailedMessage` 从「仅验非空」增强为经 `LambdaUpdateWrapper.getParamNameValuePairs()` 断言实际落库文案；既有同达人幂等、已有映射复用、probe/冲突/额度等用例全部原样保留作为回归。
- `ProductLinkIT`：新增 5 个端到端用例——B 达人转换 A 达人复制件回溯复制成功（断言 copy 收到原商品参数、`crm_kol_item` 登记在 B 名下、`source_shop_id` 为原商品店铺、扣额度）、二次转换幂等不复制、同达人转换自己的复制件不复制、无 `product_id` 的映射失败带新文案、三达人并发转换同一复制件（两人各自获得复制）。种子复用既有 helper。

## 7. 子代理审查（2026-11-13，code-reviewer 深度审查）

结论：**可合并**，无 P0/P1，5 条 P2。防误清理清单 4 项逐项核对完好：同达人幂等分支逐字保留、已有映射短路随 `copyFor` 提取后仍在 shop-item 锁之后、resolve `already_applied` 零改动、其余失败路径原位。

已按审查建议在合并前处理 2 条：

- `ProductLinkIT` 并发用例的精确配对断言（kolB→90002、kolC→90003）受 worker 线程调度影响可能反转，改为集合断言 `containsExactlyInAnyOrder("90002", "90003")`；
- ADR-019 修订第 4 条原写「失败不扣每日额度与令牌额度」与实际不符（微店复制发起前的预扣失败不返还），改为准确表述。

登记遗留 2 条（既有问题，本次不修）：L-171（已关闭映射的复制件 ID 可经 probe 登记为原商品，绕过「不复制复制件」口径）、L-172（`findCurrentByWeidianItem` `LIMIT 1` 无排序，异常数据下回溯目标不确定）。

其余核实结论：`copyFor` 提取逐行等价（sourceShopId、扣额度时点、锁范围、事件发布、MappingPersistException 路径均一致）；回溯链恒为一跳（`crm_kol_item.product_id` 三个写入方都只指向 `crm_product`，结构上不可能多跳）；advisory lock 同事务重入无害、并发无死锁；租户拦截覆盖回溯全部查询、天然限定本公司；SparkTrack 脚本按 source ID 配对写回，新失败文案经 `failed` 行透传兼容；`EXCLUSIVE_UNTRACEABLE`、`OTHER_KOL_EXCLUSIVE` 引用面与预期一致。

## 10. 遗留

- 未登记复制件的复制（系统外的复制件经 probe 登记为原商品）维持现状，本次不改：系统无法识别这类来源，且属既有行为。
- 已关闭映射的复制件经 probe 绕过口径（L-171）、`findCurrentByWeidianItem` 无排序（L-172）：既有问题，经审查登记遗留清单，不在本任务修。
- 失败文案为纯字符串（与既有失败文案一致，无错误码）；历史已落库的旧文案「该商品是其他达人的专属商品」原样保留，不做数据订正。
- 回溯路径复制的是专属映射 `product_id` 钉住的 `crm_product` 行；同一微店商品 ID 在多家店铺登记时，回溯来源与直连提交（报 SOURCE_CONFLICT）行为不对称，但确定性更强（审查认定不算缺陷，备查）。
