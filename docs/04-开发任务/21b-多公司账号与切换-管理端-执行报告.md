## 1. 页面与交互

### 1.1 页头切换公司（4.1）

| 情况 | 页头显示 |
|---|---|
| `companies` 多于一家 | 公司名变为下拉菜单（用户菜单左侧），列出本人的每家公司：当前公司打勾，并显示在该公司的角色（超级管理员 / 子账号） |
| 只有一家，或旧后端没有 `companies` | 与原来相同：公司名作为纯文字显示在用户名后 |
| 平台管理员 | 不显示下拉，仍显示「平台管理」 |

选择另一家公司：

1. `POST /admin-api/auth/company {tenantId}`，用返回的 `/me` 结构替换用户状态（公司、角色、权限码；菜单由权限码计算，自动变化）；
2. 关闭除首页外的所有标签页（`tabs.closeEveryTab()`，首页是固定标签）；
3. 跳到 `/home`；
4. 清空 keep-alive 缓存：页面区 `<KeepAlive>` 以当前公司 ID 为 `key`，跳转完成后更换 key，所有缓存页面卸载，首页也重新挂载；
5. 提示「已切换到 {公司}」；
6. 在 `BroadcastChannel("tcrm-admin-company")` 上发 `{type:"switched", tenantId}`。

失败为 403 `AUTH_COMPANY_NOT_MEMBER` 时提示对应文案，并重新获取 `/me`（公司列表随之更新）；其他错误按常规提示。切换进行中下拉禁用；选择当前公司不发请求。

第 2～5 步写在一个监听里（`composables/useCompanySync.ts`）：只要**同一账号**的「显示中的公司」变了就执行，不区分来源。所以以下情况走同一套刷新：本标签页切换、收到其他标签页的广播、409 后重新获取 `/me`、锁屏解锁或重新登录后后端选了另一家公司。登录、退出、换账号不触发（原有流程已处理）。

### 1.2 请求头核对（4.2）

- `utils/http` 增加 `getCompanyId`、`onCompanySwitched` 两个选项；请求拦截器在值非空时设置 `X-Company-Id`。下载请求同样带。
- 值来自**本标签页内存中的用户状态**（`api/setup.ts` 注册），而不是 `localStorage`。原因：同一浏览器的标签页共用 `localStorage` 中的会话，另一个标签页切换后 `localStorage` 已是新公司；若从那里读，旧标签页会带着新公司 ID 发请求，核对就失效了。
- 平台管理员、未登录时不带。
- 409 `AUTH_COMPANY_SWITCHED`：把错误标记为已处理（`notifyError` 不再弹普通错误），提示「当前公司已在其他标签页切换，页面将刷新」，重新获取 `/me`，之后按 1.1 刷新。用 `singleFlight` 合并：同时到达的多个 409 只提示一次、只请求一次 `/me`。
- 前端没有任何地方用这个头或其他参数选择公司；唯一改变公司的途径是 `POST /auth/company`。

### 1.3 与公司相关的本地状态（4.3）

| 状态 | 切换时 |
|---|---|
| 标签页（`sessionStorage`）与 keep-alive 缓存 | 清空，只留首页 |
| 列表筛选条件 | 都在页面组件内存里，随缓存卸载一起清空；`stores/` 中没有保存筛选的 store |
| 消息铃铛未读数 | 20 尚未合并，`main` 上还没有铃铛。合入 20 时把 `<NotificationBell>` 加上 `:key="company.cacheKey.value"`，切换后重新挂载、立即重新获取（见第 6 节） |
| 表格列设置、每页条数、主题、语言、侧栏折叠、锁屏时长 | 保留（测试中断言了主题与表格设置未被清除） |
| 锁屏状态 | 不动 |

水印与锁屏：当前代码中**两者都不显示公司名**（水印是「昵称 · 用户名 · 日期」，锁屏只显示用户名），所以 4.3 第 3 条没有需要改的地方；页头公司名随状态实时变化。本任务没有给水印或锁屏增加公司名，以免超出范围。若需要，请负责人决定后另行处理。

### 1.4 用户管理页（4.4）

- 用户名列：`companyCount > 1` 时显示「多公司」标签，悬停提示「该账号还属于其他公司；姓名、邮箱、密码只能由平台管理员修改」。
- 编辑对话框：多公司账号的昵称、邮箱输入框禁用，下方显示同一提示；提交时原样带回原值（不修改即不触发 422）。账号类型、岗位模板不受影响。
- 「重置密码」按钮：多公司账号禁用，外层包一层 `span` 让禁用按钮也能悬停出提示。
- 后端仍返回 422 `USER_MULTI_COMPANY_LOCKED` 时，显示错误码文案（与提示同义）。
- 新建时 409 `USER_USERNAME_EXISTS`：提示「用户名已存在。如需让其他公司的账号加入本公司，请联系平台管理员」。
- 权限设置、启停、批量启停、导出不变。16b 的转移与停用确认在 `main` 上还没有，合入时保持原样即可。

### 1.5 平台管理员：公司成员（4.5）

- 公司管理页每行的按钮与对话框标题由「超级管理员」改为「成员」。组件文件名 `TenantAdminsDialog.vue` 未改，以免与其他分支冲突。列表仍是 `GET /platform/tenants/{id}/admins`（4.6 没有列出全部成员的接口）。
- 原有「新建超级管理员」「重置密码」保留。
- 新增「加入已有账号」（`JoinMemberDialog.vue`）：
  - 输入完整用户名 → `GET /platform/users?username=`；返回 `null` 时显示「没有用户名为 X 的账号（只支持完整匹配）」；
  - 显示用户名、昵称、账号状态和已加入的公司（公司名 · 角色，停用的成员关系加「停用」标签）；
  - 已是本公司成员时显示提示，不显示加入表单，「加入」按钮禁用；
  - 角色：超级管理员，或子账号（岗位模板必选，数据范围可选，不选时请求不带 `dataScope`，由后端按模板默认）；
  - `POST /platform/tenants/{id}/members`：超管 `{userId, role:"SUPER_ADMIN"}`；子账号 `{userId, role:"STAFF", postTemplate, dataScope?}`；成功后刷新成员列表；409 `USER_ALREADY_MEMBER` 显示对应文案。
- 账号级操作（找到账号后）：
  - 修改姓名和邮箱 → `PUT /platform/users/{id} {nickname, email}`；
  - 重置密码 → 输入新密码后确认框「重置后，该账号在所有公司的登录都会失效。确定继续吗？」→ `PUT .../password {password}`；
  - 停用 / 启用账号 → 确认框说明影响所有公司 → `PUT .../status {status}`。
  - 操作后重新查询，刷新显示。
- 平台管理员界面没有新增任何业务数据。

## 2. 跨标签页处理

| 场景 | 处理 |
|---|---|
| 同浏览器另一个标签页切换 | 收到 `tcrm-admin-company` 广播 → `GET /auth/me` → 公司变了则按 1.1 刷新 |
| 浏览器不支持 `BroadcastChannel`，或广播没收到 | 下一次业务请求带旧的 `X-Company-Id` → 409 → 提示、重新获取 `/me`、刷新；该请求不执行业务（由后端保证） |
| 几个请求同时 409 | 只提示一次、只请求一次 `/me` |
| 布局卸载（退出登录） | 关闭频道 |

`/auth/me`、`/auth/company` 属于 `/admin-api/auth/**`，按 21a 4.5 第 4 条不核对请求头，所以刷新本身不会再触发 409。

## 5. 偏离与说明

1. **`PlatformUserVO.email`**：4.6 的查找结果只有 `id, username, nickname, status, companies`，没有 `email`，但 4.5 要求能修改姓名和邮箱。为了不改约定，前端把 `email` 声明为可选字段：后端返回就预填，不返回时邮箱输入框为空。这意味着在当前约定下，平台管理员只改姓名时如果没有重新填写邮箱，提交的 `email` 是 `null`——是否会清空邮箱取决于 21a 的实现。**建议 21a 在查找结果中带上 `email`，或明确 `PUT /platform/users/{id}` 中 `email` 为 `null` 的含义。** 这不算「接口实际字段与 4.6 不一致」（21a 还没有实际接口），所以没有按停止条件处理，记在这里请负责人确认。
2. **`PUT /platform/users/{id}` 等三个接口的请求体**：4.6 只写了路径。前端按现有同类接口推定为 `{nickname, email}`、`{password}`、`{status}`。21a 若不同，需要同步。
3. **切换时的过渡**：用户状态更新到跳转完成之间有一帧左右，旧页面会按新权限重绘一次（数据还是旧的），随后跳到首页。页面切换动画只有 150ms，实际不易察觉；没有为此加额外处理。
4. **水印、锁屏**：见 1.3，没有加公司名。
5. 弹窗组件文件名 `TenantAdminsDialog.vue` 未改，只改了显示文字。
