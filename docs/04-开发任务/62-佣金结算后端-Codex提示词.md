## 1. 范围（进度表 11.01、11.02、11.03、13.05、10.02）

- **数据模型**：按契约新增计佣相关的表，例如商品行计佣状态与修订记录。**只新增迁移，不修改已合并的迁移**，特别是预付的 `V202610221900`～`V202610231100`。
- **计佣来源快照**：订单和退款同步写入时（`order` 模块），通过 `commission` 模块的 `api` 登记商品行级来源快照，跨模块只经 `api` 包。有效金额等微店字段**未核实时不计提、不释放**（Q-1017-1/2），状态写明「待核实」。
- **计佣规则**：佣金 = 有效金额 × 佣金比例。比例取商品行支付时生效的推广配置，沿用已有的推广配置版本，见 ADR-032。退款冲减、归属修正后产生差额（10.02），差额不覆盖已付记录。规则写成纯函数，用单元测试覆盖。
- **冻结与释放**：按结算配置的渠道冻结天数，冻结到期后释放为可结算余额，计入已有的钱包与台账（`crm_commission_wallet` / `crm_commission_ledger`）。达人余额为负（有预付）时，按 #105 已有的先进先出逻辑冲抵。定时任务按现有方式加分布式锁。
- **结算配置**（11.03）：结算币种、最低提现金额（默认 200 元）、渠道冻结规则。读取需要权限，修改只限超管，并写审计。
- **管理端接口**：
  - 达人收入列表与详情（11.02）：汇总、付款流水；明细可追溯到订单、规则与凭证。商务按 `OWN` 范围只看自己的达人；
  - 结算明细与订单清算详情（13.05）：「已入账」与付款「已支付」分别记录，不能混用。
- **达人端接口**：佣金概览（预估总佣金、冻结、可提现、申请占用、已付）与资金流水。达人 ID 从登录态取得。申请占用由任务 63 写入，本任务先按契约返回 0，或读取任务 63 的表（视合并顺序而定）。
- **达人端订单的佣金字段**：按设计说明书 §6.3 `/kol-api/orders` 的契约，由本任务通过 commission 模块 `api` 提供商品行级的 `settlementStatus`、`rateSnapshot`、`commissionAmount`，以及订单级结算状态的取值规则；订单号、商品名等筛选由任务 64 实现。两个任务谁后合并，谁负责在 `KolOrderService` 中完成衔接。
- 可以参考 #116 分支（`origin/task/60-kol-portal`）中 `CommissionSettlementRules`、`CommissionSettlementService` 等实现，但必须满足：
  - 数据访问走 MyBatis-Plus Mapper，由公司插件隔离；
  - controller 不访问数据；
  - 跨模块只经 `api` 包；
  - 金额用 `BigDecimal`，时间用 `Instant`；
  - 错误码登记在 `shared.ErrorCode`；
  - ID 与金额序列化为字符串。
