## 1. 背景

#122 已把订单列表改成按订单分组、逐商品行展示，全系统的达人显示也统一为「名称在上、编号在下」（`NameCode` 组件）。目前列表接口的商品行没有图片和达人姓名，前端只能显示缺省状态；通知参数中只有达人编号，没有姓名。

## 2. 范围

### 2.1 契约（作为本 PR 的第一个提交）

在设计说明书 §6.2 订单列表接口和通知相关章节中，写明新增字段及其可空语义，并同步机读目录。

### 2.2 B05：订单列表商品行的图片与达人身份

- `GET /admin-api/order/orders` 返回的 `items[]` 每个商品行增加：
  - `imageUrl`：商品行图片地址，来源与订单详情一致；
  - `kolCode`、`kolName`：该行达人的业务编号与姓名。
  
  字段名与详情接口保持一致。
- **按商品行的真实归属取值**：多商品、多达人的订单，每行显示各自的达人，不能用主单达人代替全部行，也不能把数据库主键当作业务编号。
- **可空**：没有图片、未归属、引用已不存在时返回 `null`，不伪造。在契约中写明每种情况。
- **批量查询**：每页一次性取数，不得逐订单或逐行查询（不得出现 N+1）。跨模块只经对方的 `api` 包（`kol.api`、`product.api`）。
- 列表仍按订单分页，多商品行不改变订单数和 `total`。

### 2.3 B06：通知中的达人姓名

- 涉及达人的通知，在 `NotificationParams` 中增加 `kolName`，新产生的消息同时写入编号和姓名。
- **兼容历史消息**：已有消息只有 `kolCode`，前端仍要能正常显示（只显示编号）。不回填、不改写历史消息正文。
- 列出受影响的通知类型，写进执行报告。

### 2.4 前端（admin-ui，只改接线，不改 #122 的布局）

- 订单列表商品行接入 `imageUrl`、`kolName`、`kolCode`，替换现有的缺省显示；继续使用 `NameCode` 组件，图片缺失时沿用 #122 的缺图样式。
- 通知中有 `kolName` 时显示「名称在上、编号在下」，没有时只显示编号。
- 同步类型、中英文文案，补前端测试。
