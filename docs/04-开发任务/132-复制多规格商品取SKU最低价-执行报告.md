# 132 复制多规格商品取 SKU 最低价：执行报告

- 分支：`task/132-copy-multi-price`
- 日期：2026-11-08
- 类型：缺陷修复（后端，无迁移）

## 1. 背景

v0.1.7 发布后，crm-admin 重启，续跑了卡在「处理中」的复制任务 2119069735597068289（任务 131），随后任务失败。经负责人同意，在正式环境做了只读查询：

- 失败明细 2119069735605456898：源商品 7895688370，`error_message` 为「来源商品信息不完整」。
- 7895688370 还没登记到 `crm_product`；系统里只有 1 个启用店铺。
- crm-admin 日志（17:16:01Z～17:16:03Z）：先是 `Resuming copy job 2119069735597068289`，然后只有一次 `vdian.item.get`，`statusCode=0`，之后没有调用 `item.add`。

负责人在微店后台确认：这件商品是多规格商品，各规格价格不同。

**根因**：源商品没有登记时，`CopyJobWorker.findSource` 用 `probe`（`vdian.item.get`）查出名称和价格后再登记。价格只取商品级 `price`，而且必须能解析成单个数字。多规格商品各规格价格不同时，微店不返回单个商品价格，`price` 解析结果为 null，于是判为「来源商品信息不完整」。复制时的 `buildAdd` 也是同样的取法，所以即使商品已经登记，复制也会在同一处失败。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `backend/.../integration/service/WeidianItemCopyService.java` | 新增 `itemPrice`：先取商品级 `price`，取不到时取各 SKU `price` 中的最低价。`probe` 与 `buildAdd` 都改用它 |
| `backend/.../integration/service/WeidianItemCopyServiceTest.java` | 新增 `shouldProbeLowestSkuPrice_whenSkuPricesDiffer`（`price` 为区间，取 SKU 最低价）和 `shouldBuildAddWithLowestSkuPrice_whenItemPriceMissing`（商品级价格为空串，取 SKU 最低价，各 SKU 价格原样保留） |

| `backend/.../product/ProductLinkIT.java` | `@BeforeEach` 关闭 `LinkIndexSyncJob` 的定时同步。本 PR 的 CI 连续两次在 `shouldConvertProcessAndResolve_endToEnd` 失败，报「copy mapping should register a link-index refresh」。原因是该测试用 `@MockitoBean`，有独立的 Spring 上下文，定时同步每 2 秒处理一次 outbox，成功后删除对应行；如果在复制完成后、断言之前处理掉，断言就看不到这一行。其他集成测试（`BusinessChainIT`、`GuardChainIT` 等）都已关闭定时同步，这个测试后续本来也是手动调 `sync.drain()`。属于测试自身的竞态，与价格改动无关 |

`vdian.item.add` 1.5 的商品级 `price` 是选填，各 SKU 的价格另外分别传，所以复制后的商品各规格价格与源商品一致。

## 3. 影响范围

| 对象 | 影响 |
|---|---|
| 复制各规格价格不同的多规格商品 | 可以复制。系统登记的商品价格为最低规格价，目标店新商品的商品级价格也是最低规格价，各规格价格不变 |
| 单规格商品，或各规格同价的商品 | 商品级价格能取到时照旧，行为不变 |
| 接口、表结构 | 不变，无迁移 |

## 6. 偏离与遗留

- **`price` 原始值未用真实数据核对**：线上没有记录这次 `item.get` 的原始返回。商品级 `price` 是空串、区间还是缺字段都不知道，这几种情况都会走到 SKU 最低价。
- **失败的任务不会自动重跑**：任务 2119069735597068289 已是终态 `failed`，发版后需要通过表格脚本重新提交这件商品。
- **商品价格口径**：多规格商品在系统里登记的价格是最低规格价，属于「起售价」口径。如果需要别的口径，由负责人决定。
