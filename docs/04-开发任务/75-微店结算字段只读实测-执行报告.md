## 1. 结论摘要

| 问题（提示词第 1 节） | 结论 | 状态 |
|---|---|---|
| 1. 能否调用 `shop.order.trade.detail`；要不要 `ctx`；要不要申请权限 | 本店服务型应用不带 `ctx` 直接成功，无权限提示；文档的「企业门店 + 总店 token + `ctx`」场景不适用。**实测发现：整 3 个日历月跨度被拒（错误码 -1「查询时间跨度不能超过3个月」），窗口须 ≤ 约 89 天** | 已证实（对当前店铺与应用） |
| 2. `amount` 单位是分还是元 | 结算明细无样本无法比对；以订单详情 0.01 元订单返回 `total/price/last_income=0.01` 证实订单详情口径为元；结算明细 `amount` 按文档示例量级推断为元（**审查注**：此推断不成立，更可能是分，理由见实测结果「结论」问题 2 的审查注） | 待复测（推断，未证实） |
| 3. `tradeType`/`tradeSubType` 取值；`orderId` 格式与匹配；`tradeTime` 时点 | 近 12 个月 4 个窗口均 0 条，全部无样本；`PRE_SETTLE_REFUND` 可调用（根字段 `list,total`），当前无数据 | 待复测 |
| 4. `last_income` 各状态取值、与结算明细合计是否一致 | 两笔已关闭订单（全额退款）：`last_income=0.01`＝`total`＝`price`＝库内 `pay_amount`，**不因退款下调** → `last_income` 不是可提现金额，只能作结算前预估展示；与结算明细合计的一致性待有结算样本 | 部分已证实 |
