# 139 后端 CI 集成测试分片并行：执行报告

- 分支：`task/139-backend-ci-shards`
- 日期：2026-11-08
- 类型：CI 调整（无迁移，无代码改动）

## 1. 背景

负责人 2026-11-08 提出后端 CI 耗时太长。最近一次 PR 运行（Actions run 42476570343，任务 138）共用时 22 分钟，各步骤耗时如下：

| 步骤 | 耗时 |
|---|---|
| 依赖清单（notice）校验 | 0.2 min |
| `mvn verify`（2277 个单元测试、ArchUnit、覆盖率门槛） | 2.4 min |
| `mvn verify -Pdocker-it` | 18.9 min |

集成测试这一步慢，原因有两点：

1. `-Pdocker-it` 时 surefire 照常执行，2277 个单元测试又跑了一遍，约 2 分钟。
2. 43 个 `*IT` 类串行执行，各类耗时合计 996 秒。每个类自建 PostgreSQL、Redis 和 Spring 上下文，类之间互不依赖，适合拆到多个 job 并行。

仓库是公开仓库，GitHub 托管的标准 runner 不计费。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `.github/workflows/backend.yml` | 原来的单个 job 拆成两类：`verify`（notice 校验与 `mvn verify`，上传 JaCoCo 和 surefire 报告）和 `integration`（矩阵 4 个分片，与 `verify` 并行） |
| `docs/05-工程规范/08-Git与交付流程.md` | 第 4 节补充说明 backend 工作流的拆分方式 |
| `docs/04-开发任务/README.md` | 登记任务 139 |

分片规则：在 `src/test/java` 下找出 `*IT.java`，转成全限定类名后按 `LC_ALL=C` 排序，第 i 个类分到第 `(i-1) % 4` 片（取自 `strategy.job-index`/`job-total`），再通过 failsafe 的 `-Dit.test` 传入。新增的 IT 类会被自动分配，无须维护名单。

每个分片运行的命令：

```bash
mvn -B verify -Pdocker-it -Dit.test="$IT_CLASSES" \
  -Dtest=NONE -Dsurefire.failIfNoSpecifiedTests=false \
  -Djacoco.skip=true -Dspotless.check.skip=true -Dcheckstyle.skip=true
```

- `-Dtest=NONE` 加上 `-Dsurefire.failIfNoSpecifiedTests=false`：surefire 不执行任何测试，单元测试只在 `verify` 里跑一次。
- `-Djacoco.skip=true`：单个分片只覆盖部分代码，无法达到整体覆盖率门槛。门槛仍由 `verify` 判定，判定口径不变：原来第一步 `mvn verify` 就已经只按单元测试判定，第二步合并 IT 覆盖率后只会更高。
- 格式与静态检查已在 `verify` 做过，分片里跳过，避免同一个格式问题在 5 个 job 里重复报错。
- failsafe 的 `failIfNoSpecifiedTests` 保持默认值 `true`：分片选中的类如果一个都没执行，该分片会失败，不会被静默跳过。

## 3. 影响

| 对象 | 影响 |
|---|---|
| 门槛 | 单元测试、ArchUnit、Spotless、Checkstyle、JaCoCo 门槛、全部 43 个集成测试照常执行，不降低、不跳过 |
| 报告 | `backend-verification` 产物只包含单元测试覆盖率与 surefire 报告；集成测试报告按分片上传为 `backend-integration-1`～`4`。原来那份合并了单元测试和 IT 的覆盖率报告不再生成 |

预估：按 run 42476570343 的实测类耗时，4 个分片的测试时间分别约为 332、179、201、284 秒，再加上每片 2～3 分钟的编译与准备，墙钟时间预计从约 22 分钟降到约 8 分钟。实际耗时以本 PR 的 CI 为准，见第 5 节。
