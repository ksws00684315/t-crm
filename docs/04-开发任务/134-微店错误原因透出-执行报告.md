# 134 微店错误原因透出：执行报告

- 分支：`task/128-weidian-error-reason`
- 编号：原为任务 128，与 PR #223（实测「管理 / 财务」未完成项修复）重号，2026-11-08 改为 134；分支名保留原编号
- 日期：2026-11-07
- 类型：可诊断性改进（后端，无迁移）

## 1. 背景

任务 127 去掉 merchantCode 后，正式环境 2026-11-07 19:42 / 19:45（北京时间）的两次重试仍然
`vdian.item.add` 返回 `200056`，与修复前一致，说明编码不是唯一原因。

本地用生产微店应用凭证对测试店铺实测：同一套请求体（名称、价格、库存、一张图，无类目/重量/SKU）
可以成功建出商品（`7895761378`，已删除），说明请求结构本身没问题；线上失败更可能来自目标店铺
自身的限制。但微店返回的 `status_reason` 一直被丢掉，只剩数字码，无法判断真实原因。

负责人 2026-11-07 决定：先把原因与请求信息打出来，便于在本地复现，改完发布。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `backend/.../integration/service/WeidianClient.java` | 非 0 状态码时用 `WeidianResponseParser.statusReason()` 取微店原因：① 异常消息变为 `Weidian API error <码>：<原因>`（去换行、限 200 字符）；② 同时打 WARN，包含 `method`、`version`、`shopId`、`statusCode`、`reason` 与本次请求参数（限 2000 字符）。访问令牌在 public 表单里，不在参数中，日志不会出现 |
| `backend/.../integration/service/WeidianClientTest.java` | 既有权限错误用例改为断言带原因的消息；新增：原因进入异常消息、原因为空时保留裸错误码、失败时 WARN 含方法与参数且不含访问令牌 |

原因只做去空白与截断，不改写微店原文；任务明细最终仍受 `CopyJobWorker.failMessage` 的 200 字符限制。

## 3. 影响范围

| 对象 | 影响 |
|---|---|
| 复制任务明细 `error_message` | 从 `Weidian API error 200056` 变为 `Weidian API error 200056：<微店原话>`，客户在表格脚本里也能看到 |
| crm-admin 日志 | 微店调用失败时多一条 WARN，含请求参数；成功路径与现有 INFO 行不变 |
| 其它微店业务（订单、退款、商品同步） | 失败信息同样带上原因；行为不变 |
| 令牌与密钥 | 不进日志：令牌在表单 public 字段，参数只含业务字段 |
