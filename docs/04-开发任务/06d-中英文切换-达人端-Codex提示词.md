## 4. 已定的设计决定（不要自行改变）

### 4.1 依赖

- 新增**一个**运行时依赖：`vue-i18n`。
  - 选择当前最新的正式稳定版，版本号写死（规范 07）；
  - 许可证 MIT；
  - PR 中说明：用途、为什么不自己实现（见 ADR-015）、最近发布时间，以及传递依赖中的预发布版本（如有）。
- 不新增其他依赖，包括构建插件（例如 `@intlify/unplugin-vue-i18n`）。
- **CSP 要求**：生产 CSP 不允许 `unsafe-eval`。vue-i18n 默认的运行时消息编译必须在这个 CSP 下正常工作，不得为此放宽 CSP。按第 6 节验证。

### 4.2 语言与切换

| 项目 | 规则 |
|---|---|
| 支持的语言 | `en-US`、`zh-CN` |
| 默认语言 | `en-US`；回退语言（`fallbackLocale`）也是 `en-US` |
| 保存 | 用户的选择保存在 `localStorage`，键 `tcrm.kol.locale`。读写都要包 `try/catch`：存储不可用时退回默认语言，不报错。不读取浏览器语言，不存服务端 |
| 切换控件 | 登录页和页头各放一个。选项用各自语言的名称："English"、"中文" |
| 切换后立即生效 | 界面文字、Element Plus 组件语言包（`ElConfigProvider` 的 `locale`）、`<html lang>`、页面标题（路由 `afterEach` 设置的 `document.title`） |
| 请求语言 | `api/http.ts` 在每个请求上加 `Accept-Language`，值为当前语言（`en-US` 或 `zh-CN`）。后端目前忽略该请求头，06d 后端任务会使用 |

### 4.3 语言包与文字

1. **目录**：语言包放在 `src/locales/`，每种语言一个文件（例如 `en-US.ts`、`zh-CN.ts`），用 TypeScript 对象，不用 JSON。
   - 以 `en-US` 为基准，用 TypeScript 类型约束 `zh-CN` 必须有完全相同的键：缺键或多键都会导致 `pnpm typecheck` 失败；
   - 另外再写一个运行时测试，检查两份语言包的键一致。
2. **键名**：按"区域.含义"分层，例如：
   - `common.signOut`；
   - `login.title`、`login.account`；
   - `errors.AUTH_INVALID_CREDENTIALS`；
   - `route.notFound`。

   不要用中文或英文原句作为键。
3. **代码中不写死文字**：组件模板、脚本、路由 `meta.title` 中的界面文字全部改为语言包的键。
   - 路由 `meta.title` 存键名，显示时再翻译；
   - 品牌名 "T-CRM" 可以保留在语言包中，两种语言的值相同。
4. **错误文案**：`api/error-codes.ts` 改为按 `errorCode` 取语言包中的 `errors.*`。
   - 未知错误码、网络错误、字段错误的通用文案也放进语言包；
   - 现有的英文文案原样作为 `en-US` 的值，中文由你翻译。
   - 后端 `msg` 仍然不显示（规范 02）。
5. **中文翻译**：面向海外达人，用简洁、正式的简体中文。术语统一：
   - "Creator" 译作"达人"；
   - "Sign in" 译作"登录"，"Sign out" 译作"退出登录"。
6. **语言状态**：放在一个小模块里（组合式函数或 Pinia store，按现有 `stores/` 的写法），提供"当前语言"和"切换语言"两个能力，供组件、`http.ts`、路由共用。

### 4.4 不在本任务范围

- 管理端和后端的中英文切换：06d 的另外两份任务，在 06c 合并后执行；
- 达人端登录功能：后续任务；
- 日期、金额格式化：达人端目前没有这类数据，用到时再加，并沿用本任务的语言状态。

## 5. 执行步骤

1. 引入 vue-i18n，建立语言包、语言状态与切换控件；更新 `THIRD-PARTY-NOTICES`。
2. 把现有页面、页头、路由标题、错误码文案全部改为语言包。
3. 加上 `Accept-Language` 请求头，以及 `<html lang>`、页面标题的切换。
4. 测试（第 6 节）、CSP 验证、执行报告与 PR。

## 6. 测试要求

用 Vitest，至少覆盖以下场景：

| 场景 | 期望 |
|---|---|
| 默认语言 | 没有保存值时为 `en-US` |
| 切换为中文 | 登录页、页头的文字变为中文；`<html lang>` 为 `zh-CN`；`localStorage` 写入 `zh-CN` |
| 重新加载 | 刷新后读取保存的语言 |
| 存储不可用 | `localStorage` 抛异常时退回 `en-US`，不报错 |
| 保存值无效 | 例如 `fr-FR`：退回 `en-US` |
| 错误文案 | 同一错误码在两种语言下返回对应文案；未知错误码返回通用文案 |
| 请求头 | 请求带上当前语言的 `Accept-Language` |
| 语言包 | 两份语言包的键完全一致 |
| Element Plus | 切换后组件语言包随之切换（例如检查 `ElConfigProvider` 收到的 `locale`） |

现有测试全部通过，不得删除或弱化。

**CSP 验证**（结果写进执行报告）：

- `pnpm build` 后检查产物中没有 `new Function(` 和 `eval(`；
- 本机能运行 Docker 时，按 `deploy/README.md` 用生产模板启动，在浏览器中打开达人端并切换语言，确认控制台没有 CSP 报错；
- 不能运行 Docker 时，在报告中注明，由项目负责人验证。
