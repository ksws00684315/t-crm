### 第 2 步：批量任务框架（`c2c421b`）

**`task` 模块（`com.tcrm.admin.task`）**
- `task.api`：
  - `ImportTaskApi`：`submitImport`（类型、模板表头、文件、行处理器工厂）和 `template`；
  - `ImportRowProcessor`：逐行处理接口，返回中文原因列表，空列表表示成功；
  - `ImportFileDTO`、`TaskType`。
- `task` 不依赖任何业务模块，ArchUnit 通过。

**文件级校验（同步执行，失败返回 400）**
- 只接受 `.xlsx` 扩展名；MIME 为 xlsx 或 `application/octet-stream`。
- 大小 ≤ 20 MiB，同时配置 Spring multipart：`max-file-size` 20MB、`max-request-size` 21MB。
- ZIP 文件头 `PK\3\4`。
- 只读第一个工作表；表头与模板逐列一致。
- 数据行 1～2000（空行不计）。

**执行**
- 校验通过后保存原文件（`crm_task_file` INPUT），创建 `WAITING` 任务，返回 202 和任务 ID。
- 有界线程池：核心 2、队列 20，满时返回 429 `TASK_QUEUE_FULL`。
  - 没有注册成 `Executor` Bean，避免影响现有 `@Async` 审计写入器。
- 后台执行：
  - 任务置 `RUNNING`，从数据库重新读取原文件；
  - 逐行调用业务处理器，每 100 行和结束时写一次进度；
  - 处理器抛异常时，该行记为失败，原因为"系统错误，该行未导入"。
- 结束状态：全部成功 `SUCCESS`；部分失败 `PARTIAL`；全部失败或文件无法解析 `FAILED`。

**错误文件**
- 原始各列 + "错误原因"，多个原因用"；"分隔。
- 以 `= + - @` 开头的单元格加前缀 `'`。

**其他**
- 启动清理：`InterruptedTaskCleaner` 把 `WAITING` / `RUNNING` 任务置为 `FAILED`，`message` 为 `Interrupted by restart`。
- 接口：
  - `GET /admin-api/task/tasks/{id}`：任务进度；
  - `GET /admin-api/task/tasks/{id}/error-file`：错误文件附件；
  - 两个接口都只允许提交人或超管访问，其他人 403，不存在 404。
- 日志只记录异常类名，不记录单元格内容（避免个人信息进入日志）。
- 新错误码：`TASK_QUEUE_FULL`、`TASK_FILE_INVALID` / `TOO_LARGE` / `TOO_MANY_ROWS` / `HEADER_MISMATCH` / `EMPTY`。
- `GlobalExceptionHandler`：
  - 超过 multipart 上限 → `TASK_FILE_TOO_LARGE`；
  - 缺少文件部分 → `COMMON_VALIDATION_FAILED`。

### 第 3 步：达人管理（`5c83eba`）

**`kol` 模块：编号与写入**
- `KolCodeGenerator`：从序列取号，按 4 位补零，超过 9999 自动扩位；编号已被占用（导入的已有编号、已删除达人）时继续取下一个。
- `KolWriter`：
  - 同一事务内插入达人和首条归属历史（有商务时）；
  - 唯一索引冲突时：自动生成的编号换号重试，最多 3 次；邮箱冲突返回 `KOL_EMAIL_EXISTS`；指定编号冲突返回 `KOL_CODE_EXISTS`。

**`KolService`：权限与业务规则**
- 数据范围在 service 层强制执行：
  - `OPERATOR + OWN` 只看本人负责的达人，请求里的 `bdUserId` 被忽略；
  - 按 ID 访问他人达人返回 403；
  - `FINANCE` 写操作返回 403。
- 新建：
  - 商务本人新建时，`bd_user_id` 强制为本人；
  - 超管和运营 + ALL 指定的商务必须是可用商务或留空，否则返回 422 `KOL_INVALID_BD_USER`。
- 更换商务：
  - 商务本人更换返回 403；
  - 同一事务内 `SELECT … FOR UPDATE` 锁定达人行，关闭当前记录并新增一条（包括置空）；
  - 商务不变时不做任何操作。
- 关键字用 `ILIKE` 匹配编号、姓名、邮箱，并转义 `\ % _`。
- 排序：`create_time DESC, id DESC`。

**导入**
- `KolImportService` / `KolImportProcessor`：
  - 模板由 `KolImportColumn` 一处定义；
  - 每行独立事务，只新增；
  - 原因按列序给出；
  - 文件内重复（编号或邮箱）时，第二次及以后出现的行报错；
  - 已存在的编号或邮箱按"已存在"报错；
  - 商务本人导入时忽略"负责商务用户名"列，达人归属本人；
  - 提交人在请求线程中取得后传给后台线程。

**接口与门面**
- `system.api` 门面 `BdUserApi`：`getById`、`getByUsername`（不区分大小写）、`listByIds`、`listUsable`。
  - 返回的 DTO 只有 ID、用户名、昵称、是否可用。
  - 不使用 `AccountStore`；`kol` 不访问 `system` 的 service、mapper、model（ArchUnit 通过）。
- `GET /admin-api/system/bd-users`：超管和运营 + ALL 可调用，商务本人 403，财务 403。
- 达人接口（第 5 节）全部显式声明角色，写操作加 `@AuditLog`；上传接口返回 202 + `{taskId}`。
- 新错误码：`KOL_EMAIL_EXISTS`（409）、`KOL_CODE_EXISTS`（409）、`KOL_INVALID_BD_USER`（422）。

**对已有代码的两处修改**
- `AuditAspect` 的参数过滤增加 `MultipartFile`，避免把上传文件内容序列化进操作日志。
- `TcrmAdminApplication` 的 `@MapperScan` 增加 `task`、`kol` 两个包。
  - 原来只扫描 `system`；第 2 步的修复已并入 `c2c421b`。
  - 应用冒烟启动时发现这个问题；单元测试和切片测试都用 mock，发现不了。
  - 新增 `MapperScanTest` 防止以后再漏。

|---|---|

| 关键字（前导通配 `ILIKE`）、状态（只有两个取值） | 不能使用 B-tree，走 `idx_crm_kol_create_time` 加过滤。设计容量 500 人（导入上限 2000 行），可以接受；如需加速可用 `pg_trgm`，属于新扩展，需要 ADR，本任务不做 |

## 8. 偏离与遗留事项

**比提示词更细或多做的部分**

1. 文件级错误码比提示词的示例更细：`TASK_FILE_TOO_LARGE` / `TOO_MANY_ROWS` / `HEADER_MISMATCH` / `EMPTY`。
   - 空文件（只有表头）返回 400 `TASK_FILE_EMPTY`，不创建任务。
2. 文件 MIME 也接受 `application/octet-stream`：部分浏览器和操作系统上传 xlsx 时会用这个值。最终以 ZIP 文件头和解析结果为准。
3. 导入解析做了宽松处理：
   - 比例允许末尾带 `%`；
   - 粉丝数允许千分位逗号；
