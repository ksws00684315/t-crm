# 生产上线：负责人操作清单

代理没有真实账号，下列事项由负责人（或客户）在控制台完成。依据：[ADR-037](../06-架构决策/ADR-037-生产部署拓扑与AWS备份容灾.md)。从空白主机装机到上线的完整操作顺序见 [`deploy/RUNBOOK.md`](../../deploy/RUNBOOK.md)。各任务合并后才用得到的项，在「时机」列注明。

账号都用客户名下的（待确认清单第 32 项）。根账号开 MFA，日常不用根账号。

## 1. 需要决定

| 事项 | 建议 | 说明 |
|---|---|---|
| 主机 | **已定：EC2**（2026-11-03） | 4 核 8G 非突发机型（如 c7a.xlarge），下单前核对 us-west-2 的实际价格；报价单当时按 Lightsail 2 核 8G 估算，费用差额需告知客户 |
| 恢复目标 | **已定先行目标**：最多丢约 5 分钟数据，2 小时内恢复（2026-11-03） | 客户答复待确认清单第 35 项后如有变化再改；书面确认前不对外承诺 |
| `admin.` 是否走代理 | 默认走代理 | 服务器开通后从国内实测，慢就改灰云（`deploy/README.md` 写明了改法） |

## 2. AWS

| 操作 | 时机 |
|---|---|
| us-west-2 开主机，Ubuntu LTS，x86_64；系统盘 gp3，容量按 200GB 起，设置计费告警 | 任务 93 前可做 |
| 绑定固定公网 IP（Elastic IP） | 同上 |
| 安全组：入站只开 80、443；SSH 只放行固定 IP，EC2 优先用 Session Manager 不开 22 | 同上 |
| EC2：强制 IMDSv2，hop limit 设为 1，防止容器读取实例角色凭证（后台有短链解析这类服务端请求）；备份凭证由主机定时任务写入文件，不要为备份放宽 hop limit | 同上 |
| 建主备份桶（us-west-2）：禁止公开访问、开版本控制 | 任务 94 合并后 |
| 建副本桶（us-east-2）：开 Object Lock，默认保留 35 天；配置跨区域复制 | 同上 |
| 建 IAM 实例角色并挂到 EC2，策略参考 `deploy/backup/iam-policy.example.json`，另附加 AWS 托管策略 `AmazonSSMManagedInstanceCore`（Session Manager 登录需要，S3 策略示例不含它）；不创建长期访问密钥 | 同上 |
| 主机装 AWS CLI v2；建凭证目录 `install -d -m 755 /var/lib/tcrm/pgbackrest-creds`（**必须 755**，700 会让容器读不到凭证），`.env` 设 `TCRM_PGBACKREST_CREDS_DIR`；先跑一次 `deploy/backup/refresh-s3-credentials.sh` 再启动 postgres；root crontab 加 `*/15` 刷新任务（`deploy/README.md`「备份与恢复」） | 实例角色挂好后、首次启动前 |
| 配置 EBS 快照（Data Lifecycle Manager）每日一次，保留 7 天 | 主机就绪后 |
| 配置 S3 网关终端节点，备份流量不走公网 | 可选 |

## 5. 密钥保管

放密码管理器，不和备份放在一起：`TCRM_SECRET_KEY`、`TCRM_IP_HASH_SALT`、pgBackRest 加密口令、`pg_dump` 加密口令、数据库和 Redis 密码、`.env` 全文。

`TCRM_SECRET_KEY` 和备份口令丢失后无法找回，要有第二份保管。

## 6. 上线前演练

1. 在临时主机上按 `deploy/README.md` 从零部署，确认 S3 连通，pgBackRest 与 AWS S3 实测通过（本地只验证过 posix 仓库）。
2. 从 S3 恢复到临时主机，记录实际耗时，核对达人、订单、钱包余额、提现记录。
3. 用真实 `admin.`、`upload.` 证书从浏览器上传一次大表格。
4. 确认告警、心跳、证书续期能实际到达。
5. 演练用的主机用完释放，数据按真实数据对待。
6. 确认 `.env` 里已删除 `TCRM_BOOTSTRAP_ADMIN_PASSWORD`。
