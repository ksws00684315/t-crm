## 1. 迁移内容

`crm_kol` 新增列（全部带中文注释）：

| 列 | 类型与约束 |
|---|---|
| `whatsapp` | `VARCHAR(32) NULL`，`CHECK (whatsapp ~ '^\+[0-9]{8,15}$')` |
| `link_template_id` | `BIGINT NULL` |
| `invite_code` | `VARCHAR(64) NULL`，`CHECK (invite_code ~ '^[A-Za-z0-9_-]{1,64}$')` |
| `sheet_url` | `VARCHAR(512) NULL`，`CHECK (sheet_url LIKE 'https://docs.google.com/spreadsheets/%')` |
| `register_source` | `SMALLINT NOT NULL DEFAULT 1`，`CHECK (register_source IN (1, 2))` |

`country` 改为可空（`DROP NOT NULL`），原有两位大写字母 `CHECK` 保留（NULL 对 CHECK 天然放行），注释同步更新。

新表 `crm_link_template`：`id`、`tenant_id NOT NULL`、`template_code VARCHAR(32)`（`^[a-z0-9-]{2,32}$`）、`template_name VARCHAR(64)`、`template_url VARCHAR(512)`、`channel_code VARCHAR(16) NOT NULL DEFAULT 'WEIDIAN'`、`sort_order INT NOT NULL DEFAULT 0`、`status SMALLINT NOT NULL DEFAULT 1`，通用字段含 `is_deleted`；部分唯一索引 `(tenant_id, template_code) WHERE is_deleted = FALSE`；`CHECK`：`template_url` 以 `https://` 开头且包含 `{PRODUCT_ID}`、`status IN (0,1)`、`sort_order >= 0`。不设外键，与现有表一致。未加 `crm_kol.link_template_id` 上的索引：模板变更登记按页查询使用该列，但 `crm_kol` 设计容量为几百行（§1.2），顺序扫描足够；如后续达人量级显著增长再补。

## 2. 接口变化（供 11c 管理端任务使用）

### 2.1 达人档案（`/admin-api/kol/kols`）

新建 `POST`、编辑 `PUT /{id}` 请求新增可选字段（均可用 `null` 清空）：

| 字段 | 类型 | 校验 |
|---|---|---|
| `whatsapp` | string | `+` 加 8～15 位数字 |
| `linkTemplateId` | string(Long) | 必须是本公司**启用**的模板，否则 400 `LINK_TEMPLATE_INVALID` |
| `inviteCode` | string | 1～64 位 `A-Za-z0-9_-` |
| `sheetUrl` | string | 以 `https://docs.google.com/spreadsheets/` 开头，≤512 |
| `country` | string | 改为**可选**（两位 ISO 字母，传空即清空） |

社媒账号 `socialAccounts[]` 新增 `primary`（布尔，默认 `false`）：一位达人最多一个主阵地，多于一个返回 400 `KOL_MULTIPLE_PRIMARY`；后台录入不强制要求主阵地。

列表 / 详情响应（`KolVO`）在原有字段外新增：`whatsapp`、`linkTemplateId`（字符串）、`linkTemplateName`、`inviteCode`、`sheetUrl`、`registerSource`（1 后台录入 / 2 自助注册，本期恒为 1，由 12a 写入 2）；社媒账号项含 `primary`。达人列表的关键字搜索不扩展到新字段。

### 2.2 链接模板（`/admin-api/link/templates`，新控制器）

| 方法 | 路径 | 权限（当前写法，10a 合并后按 §4.6 改权限码） | 说明 |
|---|---|---|---|
| GET | `/admin-api/link/templates` | `SUPER_ADMIN`/`OPERATOR`（与达人编辑相同） | 本公司全部模板含停用，按 `sortOrder`、`id` 升序，不分页 |
| POST | `/admin-api/link/templates` | `SUPER_ADMIN` | 新建；409 `LINK_TEMPLATE_CODE_EXISTS` 编码重复 |
| PUT | `/{id}` | `SUPER_ADMIN` | 改名称、地址、排序；编码不可改；404 `LINK_TEMPLATE_NOT_FOUND` |
| PUT | `/{id}/status` | `SUPER_ADMIN` | 启用/停用；模板只能停用不能删除 |

请求体：`templateCode`（`^[a-z0-9-]{2,32}$`）、`templateName`（≤64）、`templateUrl`（https 且含 `{PRODUCT_ID}`，≤512）、`sortOrder`（0～9999）。响应字段：`id`（字符串）、`templateCode`、`templateName`、`templateUrl`、`channelCode`（恒 `WEIDIAN`，不接受入参）、`sortOrder`、`status`。

### 2.3 Excel 导入

- 模板末尾追加四列：`WhatsApp` / `代购平台编码` / `邀请码` / `推广表格地址`（英文 `WhatsApp` / `Agent Template Code` / `Invite Code` / `Promotion Sheet URL`），中英文表头均可。
- 旧模板（10 列）文件仍可导入：导入框架 `ImportTaskApi` 新增重载，接受额外的旧表头变体（`KolImportService` 传入前 10 列的键）。
- `代购平台编码` 按本公司**启用**模板的编码匹配，不存在或已停用为行错误 `import.kol.error.template-invalid`。
- 与 API 一致，导入的 `国家` 列改为可选（原 `import.kol.error.country-required` 删除，格式错误仍报）；编号、商务等原有规则不变。

## 3. 目标地址规则与 Redis 结构

**规则集中在 `LinkUrls.targetUrl(KolRefDTO, String)` 一处**（`LinkRules.indexValue` 与链接列表接口都调它）：

- 达人设置了**启用的**模板，且（模板不含 `{INVITE_CODE}`，或达人有邀请码）时：`{INVITE_CODE}` 替换为 URL 编码后的邀请码（`URLEncoder`，UTF-8），`{PRODUCT_ID}` 替换为专属商品 ID；
- 否则为 `https://weidian.com/item.html?itemID={专属商品 ID}`。

**`linkitem` 索引**：`HASH linkitem:{末两位}`（`LinkRules.itemBucket`，不足两位前补 0），field = 专属商品 ID，value 与 `link:{kolCode}` 对应字段**字节相同**的 JSON。`link:{kolCode}` 的 key 与 value 格式不变，只有 `targetUrl` 取值按上式变化。

增量写入（同一把达人锁内）：

- `refreshMapping`（MAPPING 范围）：写 `link` 的 productCode field；同时删除该达人+原商品**历史（含失效）映射**的专属商品 ID 在 `linkitem` 中的 field（当前映射除外，更换映射后旧 field 即被清掉），再写当前 field。映射失效且无新映射时两处都删除。
- `refreshKol`（KOL/PRODUCT/SHOP 范围）：先删除该达人**全部历史映射**专属商品 ID 的 `linkitem` field（数据库历史是旧 `link:{kolCode}` 出现过的 ID 的可靠超集——Redis JSON 中不含专属商品 ID，无法从旧值取），再写入当前值。

## 4. 全量重建

`link:{kolCode}` 做法不变（锁内 staging + RENAME、无映射删 key、孤儿 key 删除）。`linkitem` 按提示词 §4.4 第 3 条：

1. 逐个达人在锁内把当前字段**覆盖写**入桶（同时收集全部有效专属商品 ID）；
2. 全部达人处理完后扫描 100 个桶（HSCAN），删除不在集合中的 field；
3. 每个待删 field（按 500 一批）**回查数据库**（`KolItemApi.filterCurrentItemIds`，`valid_to IS NULL` 且走 `idx_crm_kol_item_item_shop_from` 前缀），确认无有效映射才删——重建期间新增的映射不会被误删。

`RebuildResult` 新增 `itemFields`（写入的 item field 数）与 `orphanItemFields`（删除的孤儿数），重建日志一并输出。

## 5. 刷新登记（ADR-013 outbox）

- 达人 `link_template_id` 或 `invite_code` 变化：`KolService.update` 在同一事务内发布 `kol.api.KolLinkTargetChangedEvent`，`LinkIndexListener` 登记 `KOL` 范围。
- 模板地址或状态变化：`LinkTemplateService` 在同一事务内发布 `kol.api.LinkTemplateChangedEvent`，监听器按页（每页 200，`KolApi.pageKolIdsWithTemplate`）查使用该模板的达人，逐个登记 `KOL` 范围。名称、排序变化不发事件。
- 新事件定义在发布方 `kol.api` 包；`link` 模块经 `KolRefDTO` 扩展字段（`inviteCode`、`linkTemplateUrl`、`linkTemplateEnabled`）获取已解析的模板，不直接访问模板表。

**模块归属说明（与设计 §2.2 的偏差）**：`crm_link_template` 的表、校验与管理服务放在 `kol` 模块，控制器映射 `/admin-api/link/templates`。原因：达人档案的创建/编辑要同步校验模板（400），若表归 `link` 模块则 `kol` 需依赖 `link.api`，与既有的 `link → kol`（链接索引读达人）构成模块循环，被 `ArchitectureTest` 的无环规则禁止。此取舍已在报告中记录，§2.2 的职责表未改动。

## 7. 内存实测

`LinkIndexMemoryIT`（docker profile，Testcontainers Redis 7.4.5）按合同规模写入 200 万条映射（100 位达人 × 20,000 商品），value 为设计 §7.4 的格式（微店直链目标）：

| 哈希族 | field 数 | 实测内存（used_memory 增量） |
|---|---|---|
| `link:{kolCode}`（100 个 key） | 2,000,000 | 327.1 MiB |
| `linkitem:{nn}`（100 个桶） | 2,000,000 | 327.4 MiB |
| 合计 | 4,000,000 | 654.6 MiB |

与设计 §7.4 记录的任务 06 复核值（200 万 field ≈ 327MiB）一致；`linkitem` 索引使内存约翻倍，也在 ADR-019 预估的「约多占 330MB」范围内。生产 `maxmemory 1280mb` 下两类哈希合计约占 51%，容量结论（约 350 万条专属商品）不变。运行 `mvn verify -Pdocker-it -Dit.test=LinkIndexMemoryIT` 可复现（日志行 `Link index memory at 2000000 mappings`）。代购平台目标地址更长，内存随模板 URL 长度线性增加。

Redis 内存监控（70% WARN / 85% ERROR）未改动。

## 9. 偏离与遗留

1. **模块归属**：模板表归 `kol` 模块而非设计 §2.2 的 `link` 模块（见第 5 节说明）；`link` 模块经 `kol.api` 读取解析结果，方向与既有依赖一致。
2. **refreshMapping 的删除范围**：提示词写「只改对应的一个 field」；实现为「删除该对历史 item field（当前除外）再写当前 field」，否则更换映射后旧 item field 会残留到下一次全量重建。与「映射失效且无新映射时，两处都删除」的意图一致。
3. **refreshKol 的删除数据源**：提示词写「旧 `link:{kolCode}` 中出现过的专属商品 ID」；Redis 值 JSON 不含专属商品 ID（禁止改格式），实现改用数据库中该达人全部历史映射的 ID（超集）。理论上可能删掉已被其他达人复用的同 ID field（同店铺 + 映射关闭后复用才会出现），由该达人的下一次刷新或每日重建修复；全量重建阶段无此问题（有 DB 回查）。
4. **导入国家列改可选**：提示词 §4.3.1 将新建/编辑的国家改为可选，导入按同一规则处理（原 `country-required` 行错误删除）；「编号、商务等原有规则不变」未涉及国家列。
5. **遗留**：
   - 10a 合并后按 §4.6 rebase：读取模板改 `@SaCheckPermission("kol:edit")`、写入改 `@SaCheckRole("SUPER_ADMIN")`、达人接口沿用 10a 结果；新错误码的前端映射由 11c 补。
   - `/i/{id}` 路由在跳转服务（任务 11b）；达人自助注册写 `register_source = 2`（任务 12a）；对外复制接口的「T-CRM 中转」固定模板（任务 17）。
   - 本机验证注意：Spotless（google-java-format 1.28）在 JDK 25 上会报 `jvm-version` 错误，需用 JDK 21 执行（CI 亦为 JDK 21）。
