## 修改与逐项复核

| 复审要求 | 本轮处理 |
|---|---|
| 运营、财务两阶段本人申请不显示审批入口 | 列表 `processMode` 同时检查申请人和当前用户，自己的申请只提供“查看”；其他有对应阶段权限的人仍提供“审批”。 |
| 详情弹窗同一规则 | `canApprove` 增加申请人判断，同时隐藏通过、驳回及相关提交入口；保留处理方法中的权限判断，旧入口或直接详情链接不会开放自审。 |
| 测试覆盖本人和其他审核人 | 列表两阶段分别覆盖本人、其他人及错误阶段权限；详情增加六组身份与权限组合，检查通过、驳回均按规则显示。原审核冲突用例明确改为其他申请人的单据。 |
| 合并最新 main | 保留 main 的达人端导航图标，同时为预付结果入口加上 `Coin` 图标；布局测试继续检查所有入口均有图标及中英文预付入口。 |
| Windows 检查兼容 | 样式测试在匹配明确允许定义原始颜色的 `tokens.css` 路径前，将 Windows 分隔符转成 `/`。没有扩大白名单或删除颜色、间距、字体检查。 |
| 接口契约 | 本轮不改接口、语言文案、数据库结构和依赖。完整管理端测试通过 `TCRM_BACKEND_SOURCE_ROOT` 读取配套后端工作树实际枚举。 |
