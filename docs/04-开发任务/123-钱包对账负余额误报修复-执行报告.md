# 123 钱包对账负余额误报修复：执行报告

- 分支：`task/123-wallet-reconcile-negative-balance`
- 日期：2026-11-07
- 类型：线上告警缺陷修复（后端，无迁移）

## 1. 问题

正式环境 2026-11-07 02:30 UTC（北京时间 10:30）告警：

```
ERROR c.t.a.c.j.CommissionWalletReconcileJob : withdrawal occupation exceeds wallet balance:
      tenant 1, kol 2118602579211653122, balance -500.00, funding occupation 0
ERROR c.t.a.c.j.CommissionWalletReconcileJob : wallet reconciliation found 1 mismatched creators
```

查生产数据：该达人（`KOL-ZDK002`）钱包 `-500.00`，台账合计同为 `-500.00`（一致），
只有一条 `2026-11-05 16:00Z PREPAY_DEDUCT -500.00`；预付单 `PP20261106000001`
（500 元，约定从佣金抵扣）已审核并付款；**没有提现记录**（占用 0）。

即：预付抵扣让尚无佣金的达人余额为负，属于预期状态（后续佣金补平）。任务 113 与
《金额名词与口径定义》已确认余额可为负；任务 63 的对账要求原文是「在途+已付申请金额合计
不得超过钱包余额（**负余额 + 在途提现**需人工介入）」。原实现按
`balance - funding < 0` 判断，余额为负、占用为 0 时也成立，于是把合法的负余额当成异常，
每天重复报 ERROR。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `backend/.../commission/job/CommissionWalletReconcileJob.java` | 占用比对改为 `funding.signum() > 0 && funding.compareTo(balance) > 0`：只有存在提现占用且占用超过余额时才记 ERROR；注释说明负余额本身合法（任务 113） |
| `backend/.../commission/job/CommissionWalletReconcileJobTest.java` | 新增日志捕获（`ListAppender`）与三个用例：负余额无占用保持安静、负余额有占用报错、占用超余额报错（补日志断言） |

## 3. 复现与验证

| 场景 | 余额 | 占用 | 期望 |
|---|---|---|---|
