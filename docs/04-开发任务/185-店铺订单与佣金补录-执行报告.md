## 8. 偏离与影响（相对既有行为）

### 8.1 链路核实状态：由「默认已核实」改为「每行都要有计佣快照」

`OrderChainCommissionService.chainOfOrder` 的 `allVerified` 原实现只要求「订单存在」，其余一律视为已核实；本次改为对每个商品行逐一要求存在计佣快照行（`crm_commission_item_state`），且该行 `verified` 为真。

**对已有数据的影响**：历史上未被计佣引擎处理过的订单行（例如任务上线前的存量订单、无达人归属的订单）不会有快照行，因此**这些订单在链路页会从「已核实」变为「待核实」**，该行的佣金金额、比例快照显示为「—」，整单佣金合计只累加有快照的行。

**判定依据**：这与设计「存在未核实行即待核实」一致，属于预期修正而非回归。已补单测 `OrderChainCommissionServiceTest#shouldReportUnverifiedWhenLineHasNoSnapshot`，覆盖「一行有快照、一行无快照」时返回 `UNVERIFIED` 且缺失行不贡献金额。

### 8.2 补录审计表归属与结构（按审查意见调整）

| 项 | 调整前 | 调整后 | 原因 |
|---|---|---|---|
| 表名 | `crm_order_rate_supplement` | `crm_commission_rate_supplement` | 该表只由 commission 模块的 Mapper 读写，按模块归属命名 |
| `previous_rate` | 存在，被 `CHECK (previous_rate IS NULL)` 固定为 NULL | **删除该列及约束** | 永远不会有值的列，且迁移尚未合并，删除成本最低 |

| 迁移版本号 | `V202611021900` / `V202611021901` | `V202611041100` / `V202611041101` | 原版本号早于 main 已执行的 `V202611031000`、`V202611041000`，Flyway 未开乱序执行会导致已有库启动校验失败 |

### 8.4 `historical_unit_price` 目前没有写入方（需产品确认）

同步与导入都不写该列，因此**所有订单**的单价、商品金额都会显示「缺失历史售价」。

**订单总额不在此列**：审查指出微店返回的 `total` 本身是可靠值，不该因为行单价缺失就整单隐藏。已按产品确认改为 `OrderDetailDTO.totalAmount` 直接取 `crm_order.total_amount`（源订单原值），只有单价与商品金额按缺失规则处理。改动点：`OrderService.detail` 原先把 `itemAmount` 同时当作 `totalAmount` 返回，现在两项分离；相应单测与 IT 断言一并调整（`OrderServiceTest`、`OrderQueryIT`）。

### 8.5 补录比例在链路页标注「补录」（按产品确认新增）

补录写入后，计佣修订（`crm_commission_item_revision`）只保留比例数值，不记录比例来源，因此单看修订无法区分「当时规则」与「超管授权」。按产品确认，链路页对补录行加标记，便于对账时判断口径。

| 项 | 实现 |
|---|---|
| 判定 | `OrderChainCommissionService` 批量查 `crm_commission_rate_supplement`（按 `tenant_id + order_item_id`），仅当**当前快照比例与该补录记录比例相等**时标记为补录 |
| 为何不用 `config_version` 为 NULL 判定 | 早于版本化的促销记录本身就没有 `config_version`（见 `PayTimeRuleRow` 注释），会把正常比例误标成补录 |
| 为何要求比例相等 | 补录后又换达人归属的行，快照比例来自新达人的配置，此时不应再声称是补录 |
| 接口 | `LineCommissionDTO.rateSupplemented`（`OrderChainCommissionApi` 与 `OrderChainDTO` 各加一个 `boolean`） |
| 展示 | 链路页「比例」列与链路明细「比例快照」处显示「补录」标记（中英文语言包 `order.chain.rateSupplemented`） |
| 容错 | 解析不到租户时退化为不标记，不让一个展示标记使整页查询失败 |

已补单测 `OrderChainCommissionServiceTest#shouldMarkRateAsSupplementedOnlyWhileItStillMatchesTheSupplement`（补录命中 / 换达人后不命中）与管理端 `chain-page.spec.ts` 的「补录标记同时出现在汇总行与链路明细」用例。
