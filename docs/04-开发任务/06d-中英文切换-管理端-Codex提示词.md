## 4. 已定的设计决定（不要自行改变）

### 4.1 依赖与结构

1. 新增依赖 `vue-i18n`，**版本与 `kol-portal` 完全相同**（11.4.14），不新增其他依赖。
2. 目录结构、语言状态、错误码写法、路由标题、类型约束、测试写法，全部照搬达人端报告第 2 节。与达人端的差异只有以下几处：

| 项目 | 管理端 |
|---|---|
| 默认语言与回退语言 | `zh-CN` |
| 基准语言包 | `zh-CN.ts`（`export type MessageSchema = typeof zhCN`）；`en-US.ts` 受该类型约束 |
| `localStorage` 键 | `tcrm.admin.locale` |
| Element Plus 默认语言包 | 中文 |
| 品牌名 | `T-CRM 管理端` / `T-CRM Admin` |

3. 切换控件放在登录页和页头（用户名旁），选项为"中文"和"English"。
4. 每个请求带 `Accept-Language`（当前语言）。

### 4.2 翻译范围

**以下全部改为语言包**，代码中不得再写死界面文字：

- 页面、对话框、表格列、按钮、占位符、空状态；
- 确认框与消息提示（`ElMessage`、`ElMessageBox`）；
- 菜单与路由标题；
- 角色名称（`ROLE_LABELS`）、数据范围、各类状态与枚举的显示名称；
- `utils/validation.ts` 中的表单校验提示；
- 错误码文案（`api/error-codes.ts` 改为按语言包取文案）；
- 页面标题后缀。

**不翻译**：

- 业务数据：达人姓名、商品名称、店铺名、公司名、备注等；
- 后端返回的字段级校验提示：后端已按 `Accept-Language` 生成，原样显示。

**日期与时间格式**：两种语言都保持现在的数字格式，不按语言改变。

### 4.4 顺带处理

删除 `utils/permission.ts` 中未使用的 `ALL_ROLES`（#27 遗留，见任务索引）。

## 5. 执行步骤

1. 引入 vue-i18n，建立语言包、语言状态、切换控件、`Accept-Language`、Element Plus 语言包与页面标题联动，照搬达人端。
2. 逐个模块迁移文字：布局与路由 → 登录与账号 → 用户与操作日志 → 公司管理 → 达人 → 店铺、原商品、对应关系、链接 → 任务与导入 → 错误码与校验提示。
3. 现有测试：原来断言中文文字的测试，在测试准备阶段固定为 `zh-CN`，断言保持不变；再为关键页面补英文断言。
4. 第 6 节的测试、CSP 检查、执行报告与 PR。

## 6. 测试要求

| 场景 | 期望 |
|---|---|
| 默认语言 | 没有保存值时为中文 |
| 切换到英文 | 菜单、页头、页面标题、`<html lang>` 变为英文，并写入 `localStorage`；刷新后保持英文 |
| 存储不可用 | 读写 `localStorage` 抛异常时退回中文，不报错 |
| 保存值无效 | 退回中文 |
| 语言包 | 两份语言包的键完全一致（类型约束加运行时测试）；每个路由 `meta.title` 键都存在 |
| 错误码 | 后端 `ErrorCode` 中的每个码在语言包中都有文案（用测试列出全部错误码名称做比对；后端新增错误码时，这个测试应当提醒补充） |
| 请求头 | 请求带当前语言的 `Accept-Language` |
| 关键页面 | 登录、达人列表、公司管理、用户管理，至少各有一条英文渲染断言 |
| 残留检查 | 加一个测试：扫描 `src/**/*.vue` 与 `src/**/*.ts`（排除 `locales/` 和 `__tests__/`），确认不含中文字符。确有必要保留的写进白名单，并注明原因 |

现有测试只允许按第 5 节第 3 条调整，不得删除或弱化。

**CSP 检查**：`pnpm build` 后，确认产物中没有 `new Function(` 和 `eval(`。
