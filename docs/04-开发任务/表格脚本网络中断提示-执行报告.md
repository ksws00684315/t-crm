# 表格脚本网络中断提示与自动重试：执行报告

- 分支：`agent/trace-error-origin-ce1be6c09d56`
- 日期：2026-11-10
- 类型：交付脚本可用性改进（`deploy/sheet-script/`），无后端与数据库改动

## 1. 问题

客户在「一键替换链接(V2)」弹窗里点「开始替换」，弹窗底部显示：

```
错误: NetworkError: 连接失败, 原因如下: HTTP 0
```

排查结论（已在飞书原线程答复）：这不是后台接口返回的，而是浏览器与谷歌 Apps Script 服务端之间
（`google.script.run`）这一跳断开的传输层错误。`HTTP 0` 表示浏览器没有拿到任何 HTTP 响应；
后台如果报错会带统一信封和状态码，脚本会显示「接口请求失败(状态码)：消息，请求编码…」。
生产只读日志佐证：出错时段谷歌脚本服务端调 `/admin-api/external/*` 全部 200，且报错窗口内没有
`convert` 请求，说明那次点击没有到达脚本服务端，更没有到达后台。

原实现把 `err.message` 原样显示，客户看到英文 `NetworkError` 与 `HTTP 0`，既无法判断责任方，
也不知道该重试还是该找谁。本次在脚本侧改进这块交互。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `deploy/sheet-script/submitFrom.html` | 区分传输层中断与后台业务错误；接续类调用（检查、继续替换、按批写入）自动重试 3 次（3s / 6s / 9s）；创建任务不自动重试，改为可操作提示；选区/模板读取失败也给出可读提示 |
| `deploy/sheet-script/README.md` | 更新「与原件差异」：`submitFrom.html` 不再逐字节一致，新增第 6 节说明改动与生效方式 |
| `docs/04-开发任务/sheet-script-network-error/` | 改动前后的浏览器截图（同一弹窗、同一场景、780×1080） |

新增函数：`isReplaceTransportError`、`isReplaceBusyError`、`replaceConnectionMessage`、
`replaceCreateConnectionMessage`、`formatRunError`；`handleReplaceFailure` 增加重试分支，
`clearReplaceAutoPoll` 同时清理重试定时器，`beginReplaceRequest` / `handleReplaceResult` 重置重试计数。

### 为什么自动重试是安全的

- 只有接续类调用重试：它们按任务编号 + 文档属性里的持久化游标推进；
- `.gs` 的 `applyProductLinkReplacementBatch` 在文档锁内重读游标，并对单元格当前内容与目标链接做
  比对，已写入的单元格计为「已应用」，不会重复替换或重复计数；
- 「开始替换」（`processFormSubmission`，创建任务）**不重试**，避免建出重复任务；只提示客户用任务编号
  点「继续替换」接续。

Node 用例覆盖的断言：创建失败不安排重试且提示含「不要反复点『开始替换』」；继续替换失败重试 3 次、
退避依次 3000/6000/9000ms、用尽后提示含「继续替换」且不再出现 `NetworkError`、按钮解锁；后台 500
不重试；锁冲突（「另一个链接转换正在写入」）按瞬时错误重试；成功后重试计数清零。

  分支；真实环境的下一次断连可直接观察新提示。
