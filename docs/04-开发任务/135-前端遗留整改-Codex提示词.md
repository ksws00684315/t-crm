## 2. 要求

### 2.1 L-123 达人端资金记录状态列显示键名（优先）

- 现象（任务 120 浏览器验收，2026-11-06）：`kol-portal/src/views/funds/index.vue` 的状态列显示 `funds.status.undefined`。
- 架构负责人看代码的情况：前端读 `row.publicStatus`，后端 `/kol-api/fund-records`（`KolCommissionController.FundRecordVO`）也返回 `publicStatus`。显示 `undefined`，说明当时的响应里这一项缺失。可能是验收时用了缺字段的模拟数据，也可能是佣金提现记录的状态取值有问题。还有一种情况：状态值存在但语言包里没有对应的键，这时页面会显示原始值，同样不对。
- 要做的：
  1. 用 `t135_` 真实数据（佣金提现记录、预付记录各至少一条，覆盖审核中、待付款、已付款、已驳回）复现，抓 `/kol-api/fund-records` 的响应。
  2. 根因在前端（字段名、语言键缺失、没有兜底）的，在前端修复：后端可能返回的每个状态值都要有中英文文案；遇到未知值或空值时，显示一个中性的「未知」文案，不显示键名，也不显示 `undefined`。
  3. 根因在后端（`publicStatus` 为空，或取值不在 §6.3 公开口径里）的，**停下来报告**，不改后端。
- 补单元测试：已知状态值都显示文案；未知值或空值显示中性文案，不出现 `funds.status.`。

### 2.2 L-122 管理端筛选下拉宽度统一

- 现象：筛选下拉的触发器宽度混用 120/140/160/180/220px 和 `filter-w-sm`/`filter-w-md` 两种写法，同一个筛选区里同类下拉宽度不一致。涉及 `views/system/import-task`、`views/system/user`、`views/product/kol-item`、`views/fund/prepay` 等页面。
- 要做的：
  1. 先盘点管理端所有 `ListSearch` 里的下拉触发器宽度，列一张表写进报告（页面、字段、现宽度、写法）。
  2. 按规范 13 统一。规范 13 有明确宽度的，照规范；没有的，按字段内容归为两三档（例如状态类、名称类），都用 class 写法，不再写行内像素。
  3. 统一后，中英文 1440 下文字都不能被截断。
