## 接口（与 25b 共用约定）

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT | `/admin-api/kol/kols/{id}/promotion-status` | 任意状态互转；改 `PROMOTING` 时配置不齐 → 422 `KOL_PROMOTION_CONFIG_INCOMPLETE` |
| GET/PUT | `/admin-api/kol/kols/{id}/promotion-config` | 佣金比例、多选平台、落地页、邀请码、表格 URL、本次备注 |
| GET | `/admin-api/kol/kols/{id}/promotion-records` | 分页修改记录 |
| GET | `/admin-api/kol/claimable?keyword=` | 编号/邮箱精确匹配；找不到或已绑定可用商务 → `null` |
| POST | `/admin-api/kol/kols/{id}/claim` | 可用商务认领；并发 → 409 `KOL_ALREADY_CLAIMED` |
| GET/PUT | `/admin-api/kol/cleanup-config` | `{enabled, idleDays}`；非「全部」数据范围 → 403 |
| GET | `/admin-api/kol/cleanup-preview` | 预览将被清理的达人 |
| 列表/详情 | 现有 KOL 接口 | 增 `promotionStatus`、`displayStatus`（可含 `PENDING_UPDATE`）、`landingUrl`、`platformTemplateIds` |
| 收款账户 | 达人端/管理端 | PayPal 增加 `currency`（ISO 4217）；USDT 不填 |

权限：状态/配置/记录 `kol:edit`（OWN 仅名下）；认领须可用商务；清理配置/预览须「全部」范围。写操作带 `@AuditLog`。

**偏离**：提示词写「→ 204」，本仓库管理端惯例为 `R.ok(null)`（HTTP 200 + 空 data），与现有 `status` / `invite` 等一致，未单独改为 204，以免 25b 客户端歧义。

## 清理任务判定

- 定时：每日 03:00 `Asia/Shanghai`（`KolCleanupJob` + 分布式锁）。
- 仅 `enabled=true` 的公司；仅 `promotion_status=PROMOTING` 且绑定商务的达人。
- 空闲起点：有归因支付订单取最近 `pay_time`；否则取改为 `PROMOTING` 的最近推广记录时间；再否则用达人 `update_time` 兜底。
- 执行：逻辑删除达人 + 结束有效商品对应（`KolMapper.closeItemMappings`，避免 kol→product.api 环）+ 系统操作日志；不调微店；订单/佣金不动。
- 预览与执行共用同一筛选。

## 模块边界

- `KolCleanupService` / `KolMapper` 用 SQL 结束 `crm_kol_item`、查最近归因支付时间，**不**依赖 `product.api` / `order.api`（ArchUnit）。
- `KolCodeGenerator` 公共构造加 `@Autowired`，避免 Spring Boot 4 多构造无默认构造报错。
