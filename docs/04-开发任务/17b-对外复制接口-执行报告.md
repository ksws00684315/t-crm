## 复制流程

1. `convert`：认证令牌 → 解析目标店铺（令牌指定 / 默认复制店铺）→ 校验启用且已授权 → 去重写入任务与明细 → 立即返回 `jobCode` → 提交有界线程池。
2. 工人（公司作用域、任务内顺序）：先查专属商品（本达人同 ID 成功 / 他达人失败）→ 查原商品（库中或对各启用店铺 `item.get` 探测并登记；缺名称/价格失败）→ 已有对应关系则直接成功不扣额度 → 否则 `consume` → 微店 get/detail/add/saveItemDetail（原价；详情失败仍成功带警告）→ 写 `crm_kol_item` + 链接索引事件。
3. 重启：`CopyJobWorker` 作为 `ApplicationRunner` **继续处理**仍为 `processing` 且明细 `pending` 的任务。

## 审查修订（PR #74 架构审查）

按审查意见已改（本机重跑 spotless / verify / docker-it；CI 暂停未等）：

1. **缺名称/价格**：`WeidianItemCopyService.buildAdd` / `ensureProduct` 不再用 `ZERO` / `copied-item`；缺项该条 `failed`「来源商品信息不完整」，不调用 `vdian.item.add`。
2. **详情保存失败**：`addItem` 成功后 `saveItemDetail` 失败仍记 `success`、写对应关系、返回新 ID，`errorMessage` 为「商品已复制，详情保存失败，请在微店后台补充详情」，WARN 日志不含令牌/密钥。写 `crm_kol_item` 回滚时外层把微店商品 ID 写入明细 `errorMessage` 与 WARN。
3. **专属商品不作原商品**：工人先查 `crm_kol_item` 存活行；本达人 → 不复制不扣额度、明细成功同 ID；`items/resolve` → `already_applied`；其他达人 → failed「该商品是其他达人的专属商品」。
4. **跨模块 SQL**：去掉对 `crm_weidian_shop_auth` 的 JdbcTemplate；`WeidianItemCopyApi.isShopAuthorized` 由 integration 实现。
5. **probe**：仅明确「不存在 / 不属于」返回空；其他微店错误该条 failed「微店接口调用失败」（可附错误码）。
6. **测试**：补 `CopyJobWorkerTest`、`WeidianItemCopyServiceTest`、`ProductLinkRateLimiterTest`、`CopyJobProgressTest`，扩展 `ProductLinkServiceTest` / `ProductLinkIT`（含认证、店铺、复制规则 1–3、额度中途用尽、限流、jobCode、already_applied、linkitem 桶断言）。
