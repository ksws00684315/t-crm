# 1024 更新版后端对接清单

整理日期：2026-10-25。此清单供后续与大白联调；本轮不修改后端、数据库、HTTP 请求或响应契约。

## 订单筛选

1. **平台下单时间范围**：`GET /order/orders` 当前支持付款时间 `payFrom/payTo`，不支持按平台下单时间筛选。请确认并提供基于平台订单 `orderTime` 的起止参数、时区和边界规则。前端日期控件已显示为禁用的“开发中”，不会提交模拟参数。
2. **达人编号/姓名搜索**：当前查询仅支持 `kolCode`。如果同一输入框需要同时匹配达人姓名和编号，请提供明确的后端匹配规则；目前前端只按达人编号查询，并提示姓名查询待支持。
3. **退款状态筛选**：请支持“退款中”以及“退款成功”筛选；“退款成功”须同时匹配部分退款成功和全额退款成功。当前列表只能按订单状态筛选，前端对应选项禁用并标“开发中”。
4. **异常订单组合筛选**：请支持 `orderStatus=UNKNOWN`、归属状态 `UNMATCHED`、归属冲突 `CONFLICT` 的并集语义。若分别筛选会形成交集或只返回一类，无法满足“异常订单”的定义。前端异常筛选暂禁用；行内仍根据已返回的状态标示异常。

## 订单列表与链路数据

5. **商品行字段**：订单列表 `items[]` 目前缺商品图片地址及商品行达人姓名。请在每条商品行返回 `imageUrl` 和 `kolName`，保留现有真实 `kolCode`。多商品订单不能用主单达人姓名代替各行达人姓名。前端保留图片占位并记录缺口，不为每一单单独请求详情。
6. **佣金快照**：链路需要每笔历史订单实际使用的佣金比例及净达人佣金。请从订单/结算快照返回，不能由当前达人佣金比例推算历史佣金。
7. **店铺结算与获利**：请提供订单相关的微店结算净额及结算时间/结算编号，以便按“微店结算净额－净达人佣金”展示店铺获利；不扣商品成本。缺少净额时应保持缺失状态，不以 `0` 代替。
8. **财务流水及提现占用**：链路目前的 `ledger`、`withdrawals` 尚为空/未实现。请提供财务流水金额、发生时间、流水类型、付款关联及结算编号，以及达人提现占用金额、状态、时间和对应提现编号；需要支持订单商品行维度对应。

## 联调约束

- 当前订单详情里的 `orderTime` 是平台下单时间；请勿将系统同步入库时间 `createTime` 混作平台下单时间。
- 退款查询页面本轮不改版。
- 前端已完成的页面布局使用现有响应数据；接口未提供的信息只显示“开发中”或缺省状态。
- 收到接口实现后再依据真实 OpenAPI/DTO 更新前端类型与调用，不预设字段名、参数名或返回值。
