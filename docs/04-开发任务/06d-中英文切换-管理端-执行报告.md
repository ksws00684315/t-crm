- 范围：仅 `admin-ui/`（含锁文件与 `THIRD-PARTY-NOTICES`）及本报告。未改 `backend/`、`kol-portal/`、`redirect/`、`docs/03-设计/`、`docs/05-工程规范/` 与任务索引。

## 1. 设计决定落实情况

照搬达人端执行报告第 2 节。管理端差异：默认与回退语言 `zh-CN`，基准语言包是 `zh-CN.ts`，`localStorage` 键 `tcrm.admin.locale`，Element Plus 默认中文，品牌名为「T-CRM 管理端」/「T-CRM Admin」。

### 4.1 依赖与结构

| 决定 | 落实 |
|---|---|
| 唯一新增依赖 `vue-i18n@11.4.14`，与达人端相同 | `admin-ui/package.json`（`.npmrc` 已有 `save-exact=true`） |
| 不新增其他依赖，不用 `@intlify/unplugin-vue-i18n` | 语言包是 TS 对象 |
| 目录、语言状态、错误码、路由标题、类型约束、测试写法 | 见下表；`createI18n` 不传显式泛型 |
| 默认与回退 `zh-CN` | `src/utils/locale.ts` 的 `DEFAULT_LOCALE`；`src/locales/index.ts` |
| 基准包 `zh-CN.ts` 导出 `MessageSchema`，`en-US.ts` 受该类型约束 | `src/locales/zh-CN.ts`、`src/locales/en-US.ts` |
| `localStorage` 键 `tcrm.admin.locale`；读写失败退回中文 | `src/utils/locale.ts` |
| Element Plus 默认中文 | `App.vue` 的 `ElConfigProvider`；`main.ts` 的 `app.use(ElementPlus)` 不再传 `locale` |
| 品牌名 | `app.title` / `login.title` |
| 登录页与页头（用户名旁）切换，选项为「中文」和「English」 | `src/components/LocaleSwitch.vue`；`views/login/index.vue`、`layout/index.vue` |
| 每个请求带当前语言的 `Accept-Language` | `src/utils/http/index.ts` 拦截器；`src/api/http.ts` 传入 `getLanguage: () => useLocaleStore().locale`（下载走同一拦截器） |

`main.ts` 顺序：注册图标 → Pinia → `useLocaleStore()`（首屏即应用已保存语言）→ `setupHttp` → 路由 → Element Plus（不传语言包）→ i18n → `mount`。

`translate(key, values?)` 比达人端多了一个可选命名插值参数，供确认框、标题使用。键的类型安全仍来自 `MessageSchema` 与运行时展平测试，不来自 `createI18n` 的泛型。

### 4.2 翻译范围

页面、对话框、表格列、按钮、占位符、空状态、`ElMessage` / `ElMessageBox`、菜单与路由标题、角色、数据范围、状态、`utils/validation.ts` 与 `utils/kol-validation.ts`、`utils/rate.ts`、错误码、页面标题后缀，都改为语言包。

| 决定 | 落实位置 |
|---|---|
| 路由 `meta.title` 存键 | `src/router/routes.ts`（`route.login` 等）；类型注释在 `src/types/router.d.ts` |
| 标题翻译 | `src/router/title.ts` 的 `applyDocumentTitle`；`guard.ts` 的 `afterEach`；`App.vue` 在语言变化时用当前路由重设 |
| 菜单 | `buildMenu` 在调用时 `translate(meta.title)`。布局里的菜单 `computed` 读取 `locale`，切换后重算 |
| 页头标题 | 布局 `pageTitle` 用 `translate(route.meta.title)`，避免把键原样显示 |
| 角色名 | 删除 `ROLE_LABELS`，改为 `roleLabel(role)` → `translate(\`role.${role}\`)` |
| 删除未使用的 `ALL_ROLES` | `src/utils/permission.ts`（#27 遗留） |
| 错误码 | `src/api/error-codes.ts` 从基准包 `errors` 的大写键取文案；`ApiError.displayMessage` 在读取时解析；未知码与 `COMMON_INTERNAL_ERROR` 用 `errors.withTrace` 附追踪号。后端 `msg` 不展示 |
| 401 提示 | `src/api/setup.ts` 使用 `messageForErrorCode("AUTH_UNAUTHORIZED")` |
| 通用失败 | `src/utils/notify.ts` 使用 `genericErrorMessage()` |
| 确认框 | 整句键（如 `tenant.confirmDisable`），不拼接动词 |
| 日期时间 | `formatInstant` 未改，两种语言都保持数字格式 |
| 业务数据不翻译 | 达人姓名、商品名、店铺名、公司名、备注、操作日志的模块/动作/结果/URI/IP 原样显示 |

登录页的切换控件在表单之后（样式绝对定位到右上角），避免打乱现有测试对前两个输入框和提交按钮的查找。

### 4.3 顺带处理

`utils/permission.ts` 中未使用的 `ALL_ROLES` 已删除。`SELECTABLE_ROLES` 保留。

## 4. CSP 检查结果

`pnpm build` 之后对 `admin-ui/dist/` 全文搜索 `new Function(` 和 `eval(`，均无匹配。vue-i18n 11 的运行时消息编译器是解释执行，不生成代码。未改 Nginx CSP。

本机没有浏览器自动化工具，没有做达人端那种「生产 CSP 响应头 + 真实浏览器监听 `securitypolicyviolation`」的复测。静态结果与达人端已验证的同一版本一致。

## 8. 偏离与遗留事项

- 店铺页提示仍是「全系统最多 3 个店铺；停用后不可再导入商品或对应关系。」错误码 `SHOP_LIMIT_REACHED` 的中文仍是「店铺数量已达上限（最多 3 个）」。06c 之后上限按公司计算，原文已经过时。本任务只做翻译，没有改产品文案。英文为 “At most 3 shops in the whole system…” 与 “The shop limit has been reached (at most 3).”。
- 字段级校验仍沿用既有做法：只保留字段名，用语言包 `errors.field`（中文「该字段格式不正确」）显示，不展示后端返回的字段文案。这与达人端约定、`serverFieldErrors` 的现有测试一致。提示词写「后端字段提示原样显示」。两边冲突时，没有改已有测试锁住的行为。若要改成原样显示，需要同时改 HTTP 解析和该测试，应单独开任务。
- 原商品页、对应关系页的「批量导入」按钮复用 `kol.import`。中文仍是「批量导入」，英文是 “Bulk Import”，与术语表一致。
- 达人详情里社媒账号一行由全角冒号改为半角 `platform: handle`。平台和账号是业务数据，冒号不是一句可翻译的文案。
- 操作日志列「操作人」的英文暂用 Operator，与角色「运营」相同。见第 2.2 节，等客户确认。
- `LocaleSwitch` 与达人端一样没有声明 `emits`。测试选择选项时 Vue 会警告 `update:model-value` 未声明。lint 与测试通过，没有改组件形状。
- 未改任务索引、设计文档、后端和达人端。
