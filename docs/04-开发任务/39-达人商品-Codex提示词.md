## 3. 要做的事

### 3.1 后端

- `crm_kol_item` 新增 `link_code`：`KPL-` + 12 位大写十六进制随机串，公司内唯一，创建后不变；新建对应关系的所有入口（复制流程、推广表上传、导入）都生成；已有数据回填。
- 列表 `GET /admin-api/product/kol-items` 改造（权限沿用现状，商务只看自己负责的达人）：
  - 参数：`linkCode`（精确）、`kolKeyword`（达人名称模糊、达人编号或邮箱精确）、`shopId`（目标店铺）、`page`、`size`；
  - 每项：`id`、`linkCode`、`itemName`、`imageUrl`（原商品主图，没有为 null）、`kolId`、`kolCode`、`kolName`、`targetShopId`、`targetShopName`、`targetChannel`、`targetItemId`、`targetItemUrl`（`https://weidian.com/item.html?itemID=…`，后端拼接）、`sourceItemId`、`sourceChannel`、`currentRate`（达人当前推广配置的佣金比例，字符串）、`salesQuantity`、`payAmount`、`status`（`ENABLED` / `DISABLED`：对应关系当前是否在有效期内）、`cleanupStatus`（`NONE` 未清理 / `PENDING` 清理中 / `DONE` 已清理 / `FAILED` 清理失败，取该对应关系最近一次清理记录）、`createTime`。
  - **销量与支付金额的口径**（写进设计说明书）：该对应关系下、订单已支付（含已完成，不含待支付和已取消）的商品行的数量之和与实付金额之和，不扣退款；退款在详情和订单页查看。只对当前页的对应关系做一次分组汇总查询，不逐行查询；评估 `crm_order_item(kol_item_id)` 上的索引，用 `EXPLAIN` 结果说明。
- 详情 `GET /admin-api/product/kol-items/{id}`：列表字段 + `sourceItemUrl`、`visitCount`（访问次数：该对应关系的点击记录数，不含机器人和重复点击）、`totalPayAmount`（累计支付金额，口径同上）、`refundAmount`（累计成功退款金额）、`cleanupTime`、`cleanupReason`、`cleanupFailReason`。
- 订单查询（任务 40）会通过本任务的 `link_code` 展示订单链路，`KolItemApi` 中提供按 ID 批量取链接编码的方法。
