## 4. 安全发现

### 4.1 总体结论（修订后有判断）

- **跨公司**：65 处 `TenantScope` 均已填「理由 / 数据去向 / 结论」，**0 处「有风险」**。详见 [跨公司处理清单](./22-阶段性治理审查-附件/跨公司处理清单.md)。重点：`AccountStoreService`、`PlatformService`、`UserService.companyCounts`（`:250`）、`ShopService.java:63`、`ImportTaskService`、`ClickConsumer`（`:193` 显式 `tenant_id`）、`OrderSnapshotCorrection`、`KolSelfRegisterService`；系统作用域写入均显式租户或按主键更新。
- **原生 SQL**：见 [原生 SQL 清单](./22-阶段性治理审查-附件/原生SQL清单.md)。`sys_user` 始终忽略；精确用户名查找 / 成员 JOIN 带 `tenant_id`，**未见枚举全部账号的接口**。
- **鉴权**：117 个映射路径已补全；见 [接口鉴权清单](./22-阶段性治理审查-附件/接口鉴权清单.md)。写操作与权限码总体匹配。`TaskController` 角色偏宽但服务层收紧（`:19-21`）；通知接口声明含 `PLATFORM_ADMIN` 但 `NotificationService.requireCompanyUser`（`:238-242`）拒绝。达人端身份仅来自令牌。
- **P0**：本轮静态审查**仍不抬升**为 P0。隔离 IT 未在本机 Docker 复跑 → 跨公司「无泄露」的最终确认 **defer CI**（标注如下，不夸大）。

| P2-08 | P2 | 各 `*Password*Request`：`@Size(min=10)` + 可打印 ASCII | 无复杂度 | 弱口令 | 按规范 06 补策略 | 文档或源码确认 |
