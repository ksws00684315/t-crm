## 优先修复

1. **06.08 指定店铺生成 Token 报错。** 商务和管理员均返回 500，不指定店铺时可生成。定位：`CopyTokenService.requireEnabledShop` 使用了普通请求中为空的公司上下文。
2. **06.07 Token 默认数量错误。** 页面与后台默认均为 1000，需求为 1。有效分钟 1440 一致；渠道和剩余容量选择未补齐。
3. **04.02 邮箱可修改，审核可回退。** 普通编辑可修改登录邮箱；已通过的达人可改回待审核，与只读、不可再次审核的要求不符。
4. **04.03 推广配置与真实跳转脱节。** 新配置的多选代购平台没有完整供跳转使用；新入口修改邀请码后，跳转仍可使用旧码。普通编辑还能改变佣金而不产生对应配置版本。应统一配置来源、修改入口及刷新机制。
5. **02.01 注册表单不符。** 无邀请链接时不能手填邀请码；通过链接注册也未展示只读商务邀请码。WhatsApp、社媒平台及账号仍必填，需求中为选填。
6. **09.03 CSV 不支持。** Excel 导入和重复导入去重已验证，但 CSV 请求返回 400 `TASK_FILE_INVALID`。

## 其他需求差异

- **04.01** 当前用推广状态表达“待审核、待推广”等，未按需求分开审核状态、登录状态、关系状态。CRM 清理仅关闭映射并逻辑删除达人，尚未实现微店关联商品删除及失败状态。预付入口也未完成。
- **03.01** 当前编号形如 `KOL-FHB001`，需求示例 `ASD001` 没有 `KOL-` 前缀，应统一展示格式。
- **04.03** 多选平台已有，但只有一个通用代购地址字段，平台与地址逐项对应、必填规则及生效时间仍需补齐；不能据此认定 100+ 平台已完成适配。
- **06.01—06.05** 店铺仍为基础资料管理，缺源店、自动池、容量、完整筛选及分接口状态；旧规则还有最多 3 家店的限制，需要与当前店铺池方案统一。
- **07.01—07.05** 支持立即转交和预约转交，但本人离职、预约停用、推广表商务名更新、提现及预付待办交接未完整实现。
- **08.01、10.02** 一个订单包含两位达人的商品时，当前整单进入冲突，人工分配也会把所有商品行给同一达人。需要确认真实代购是否合单，以及是否要按商品行分别归属。
- **08.02、09.04** 退款类型与独立状态、退款查询及完整链路未补齐。订单页缺订单号查询，返回字段缺运费、优惠等需求明细；数据归一化还把缺失运费或优惠写成 0，应区分真实零与未知。
- **11.01—13.05** 收款账户维护和审核已有；佣金余额、预付、提现、冻结占用、支付登记、差额调整及账务流水尚未形成闭环。当前的长期收款账户审核，也不能替代每次提现保存收款快照。
- **06.15 访问次数** 与此前“本版不采集点击”的沟通存在范围差异，应统一最终要求后实施。
