## 3. 订单导入模板与规则

表头键 `import.order.header.*`（中英文）：微店店铺 ID、订单号、子订单号、订单状态、下单时间、支付时间、订单实付（元）、运费（元）、商品 ID、SKU ID、商品名称、型号、数量、明细实付（元）。

处理要点：

1. 逐行按「订单头 + 本行明细」调用 `OrderWriter.save`；同订单多行最终状态与归属以最后一次写完为准。
2. 已存在且 `source = 1`：行失败（`import.order.error.sync-owned`）；`source = 2`：更新；`import_batch_id` 写当前任务 ID。
3. 子订单号为空：稳定键 `line-` + SHA-256(商品 ID + `:` + SKU + `:` + 出现序号)。**偏离提示词**：序号改为「同一订单内同一商品 ID + SKU 的第几次出现」，且只要店铺/订单号/商品 ID 能解析就计数（该行其他校验失败也占序号），避免失败行修正后重导导致键漂移、明细重复。
4. 状态：中文或英文标准名；`raw_status = IMPORT:` + 英文名；时间按北京时间解析存 UTC。
5. 归因与商务快照与任务 13 相同；模板无买家列，`buyer_hash` 为空。
6. 同订单在文件中订单头不一致时，以后出现的行为准。

## 4. 退款导入模板与规则

表头键 `import.refund.header.*`：微店店铺 ID、退款单号、订单号、子订单号、退款金额（元）、发起时间、完成时间。

1. 只写已完成退款：`raw_status = 10`。
2. 退款号已存在：行失败，不覆盖。
3. 订单不存在：行失败。
4. 子订单号能唯一对应明细时写 `order_item_id`，否则为空；写入后重算明细 `refund_amount`。

## 6. 与接口同步的关系

- 导入不覆盖 `source = 1` 的订单。
- 导入订单可被后续接口同步覆盖：`OrderWriter.save` 在已有订单 `source = 2`、本次写入 `source = 1` 时，删除本次载荷中没有的旧明细（接口载荷视为该订单完整明细）；指向被删明细的退款将 `order_item_id` 置空，后续退款同步按任务 13 规则重匹配。
- 退款导入不更新已有退款号。

## 9. 偏离与遗留

- **偏离**：
  1. 任务 ID 用 `CountDownLatch` 传递，避免改 `task` 公共接口（可接受）。
  2. 空子订单号稳定键序号：提示词写「本文件同一订单中的行序号」；实现改为「同一订单内同一商品 ID + SKU 的出现序号」，并在店铺/订单号/商品 ID 可解析时即计数（架构审查同意，更稳）。
- **遗留**：
  1. 管理端导入按钮由 19a 对接 §4.6；微店后台原始导出格式识别与佣金不在本任务。
  2. Excel 若把超长订单号当成数字，超过 15 位会丢精度且仍能通过「全是数字」校验；模板编号列应设为文本格式，需扩展 `ExcelFiles.write`，另开任务。
  3. `crm_refund.weidian_refund_no` 全局唯一（任务 13 约束）：跨公司导入同一退款单号会失败并提示已存在，行为可接受。
- **并行**：尽量只新增导入相关类；`OrderWriter` 在 source 2→1 时增加删明细逻辑，与 19a/19b 查询类无交叉。合并前建议确认 19a/19b 是否同时改过 `OrderWriter`。
