## 1. 背景与负责人决定

**负责人决定（2026-10-29，已确认）：**

1. **收款账户不再需要审核。** 达人添加后直接生效，可以设为默认账户、用于提现。达人可以直接修改未停用的账户：每次提现都会保存当时的收款信息快照，修改不影响已提交的申请。
2. **收款账户信息在管理端的达人列表中查看**：达人在达人端填写后，自动出现在管理端该达人的「资金信息」里。
3. **完整账户的查看范围沿用现有规则**：
   - 持有 `payout-account:review`、且达人在本人数据范围内的账号，能查看完整账户和二维码，例如商务（本人名下）、财务和超管。查看完整账户要写操作日志。
   - 列表一律脱敏显示。
4. **达人列表的行操作改为以下五项：**

   | 现在 | 改成 | 内容 |
   |---|---|---|
   | 资料编辑 | **基础资料** | 不变 |
   | 佣金信息 | **推广信息** | 佣金设置、推广平台、推广表格登记、备注，保留修改记录。现有弹窗已经包含这些内容，只改名称 |
   | 预付金额 | **资金信息** | 新增弹窗，显示该达人的收款账户（见 §3.2 第 2 条） |
   | 清理配置 | 不变 | |
   | 冻结 / 解冻 | 不变 | |

5. **达人列表中删除「预付金额」列和预付申请入口。** 预付相关功能统一在「财务结算 → 达人预付」页处理，申请入口也移过去。
6. 负责人确认现在没有已存在的收款账户，不需要迁移历史数据。

## 3. 要求

### 3.1 后端

1. **新建即生效**：`PayoutAccountService.create` 直接保存为 `APPROVED`，审核人和审核时间为空，不再发布 `PayoutAccountSubmittedEvent`。
   - 删除该事件类和监听里只为它服务的代码，`NotificationService` 中只给它用的方法一并删除。
   - 消息类型 `PAYOUT_ACCOUNT_SUBMITTED` 的展示文案保留，用于显示历史消息。
2. **迁移**：表约束 `ck_crm_payout_account_review` 要求 `APPROVED` 必须有审核人和审核时间。新增一个迁移删除这条约束。`reviewed_by`、`reviewed_time`、`reject_reason` 三列保留不删，字段注释改为「历史字段，2026-10-29 起不再审核」。其他约束不变。
3. **直接修改**：`update` 允许修改所有未停用的账户，修改后仍为 `APPROVED`；停用的账户返回现有的 404 或 409，与现状一致。
   - 原来的「`APPROVED` 不能改」分支和防止并发审核覆盖的条件，改为只防止「已停用」被覆盖。
   - 默认标志不变。
   - 达人操作审计照旧写入，只记录脱敏值。
4. **删除审核**：
   - 删除 `PUT /admin-api/commission/payout-accounts/{id}/review` 和 `GET .../pending-count`，以及只为它们服务的 `ReviewAction`、`ReviewRequest`、`review`、`pendingCount` 和错误码（如 `PAYOUT_ACCOUNT_NOT_PENDING`）。
   - 删除前全仓搜索，还有其他使用方的保留。
5. **管理端列表**：`GET /admin-api/commission/payout-accounts`
   - 不再默认筛选 `PENDING`；
   - 增加 `kolId` 参数，供资金信息弹窗精确查询，数据范围校验与现有一致；
   - 返回结果包含已停用的账户，带状态。
   - 详情接口 `GET .../{id}` 和二维码下载的权限、数据范围和操作日志都不变。
6. **权限码** `payout-account:review` 保留代码不改，岗位模板也不改，只把显示名称改为「查看收款账户 / View payout accounts」，说明改为「查看达人收款账户，含完整账号与二维码」。
7. **商务转交**：检查 `BdTransferService` 和转交结果里有没有统计「待审核收款账户」。如果有，删掉这一项，并在执行报告中说明。

### 3.2 管理端

   - `CommissionDialog` 的标题由「佣金信息」类文案改为「推广信息」；内部页签、字段和修改记录都不变。
2. **资金信息弹窗**：新建 `views/kol/KolFundDialog.vue`。

   - 内容是该达人的收款账户表格，使用 `DataTable`。列为：
     - 类型（PayPal / USDT）；
     - 账户（脱敏）；
     - 收款人或网络；
     - 币种；
     - 默认；
     - 状态（正常 / 已停用）；
     - 最近更新时间（`formatInstant`）；
     - 操作「查看完整」。
   - 「查看完整」打开现有详情：把 `ReviewDrawer.vue` 改为只读的账户详情抽屉，去掉通过和驳回，保留完整账号、二维码和收款人显示，文件改名为 `PayoutAccountDetailDrawer.vue`。

   - 入口可用条件：持有 `payout-account:review`，并且该行在本人数据范围内（沿用 `rowOwned` 的判断方式）。

   - 删除一列后，剩余列宽按规范 13 附录 A 核对，表头不能换行，中英文都要核对。
4. **「财务结算 → 达人提现」**（`views/fund/payout/index.vue`）：
   - 删除「收款账户审核」页签，删除 `views/fund/payout-account/index.vue` 审核页及其测试；
   - 路由 `fund/payout-accounts` 的重定向保留；
   - 页面只剩一个页签时，按页面现有的写法决定保留页签还是去掉页签头，在执行报告里说明选择。
   - 路由 `meta.permission` 中只为审核页添加的 `payout-account:review` 去掉。
5. **待审核角标**：删除 `stores/payout-pending.ts`、layout 中的角标和轮询及其测试。
6. **「达人预付」页增加「申请预付」**：
   - 位置：`ListSearch` 的操作区，与其他列表页的新建按钮位置一致。持有 `prepay:apply` 时显示（`prepayAbilities(me.user).apply`）。
   - 弹窗：`ApplyDialog.vue` 增加「达人」字段，使用远程搜索选择器，写法参照 `CopyTokenCreateDialog.vue` 的 `searchKols`。后端 `listKols` 已按数据范围过滤，商务只能搜到自己名下的达人。
