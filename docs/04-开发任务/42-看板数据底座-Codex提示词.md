## 3. 后端

### 3.1 统计口径（落实「数据统计口径」页）

统一在一处实现并有单元测试，四个模块只调用、不各自重写：

| 指标 | 实现要求 |
|---|---|
| 统计日期 | 北京时间（`Asia/Shanghai`）自然日；销售按**支付时间**，成功退款按**退款成功时间**（`refund_status = SUCCESS` 的 `finish_time`）归入日期 |
| 支付订单数 | 区间内支付成功的订单按订单 ID 去重，一笔订单多个商品算 1 笔 |
| 交易 GMV | 区间内支付商品行实付之和（退款前），运费、优惠按微店回传，不另行分摊 |
| 成功退款金额 / 退款件数 | 只计成功退款，按退款成功时间 |
| 净交易额 | 区间 GMV − 区间成功退款金额（跨期可能为负） |
| 平均订单价 | 交易 GMV ÷ 支付订单数 |
| 金额退款率 | 区间成功退款金额 ÷ 区间 GMV |
| 周期订单退款占比 | 区间成功退款关联的原订单去重数 ÷ 区间支付订单数 |
| 商品退款率 | 商品退款订单数 ÷ 商品订单数（不得平均各商品比例） |
| 成交 SPU | 有支付成交的商品按「店铺 + 商品标识」去重；同一原商品复制到不同店铺分别统计 |
| 邀请人（商务）业绩 | 按订单支付时的所属商务快照 `crm_order.bd_user_id`；快照为空的为「无主业绩」，归管理员 / 公司，不影响达人数据；退款跟随原订单的商务 |
| 有效达人 / 有销售达人 | 有效 = 未冻结；有销售 = 区间内有支付成交 |
| 零分母 | 不产生比例，返回 null，前端显示「-」（GG-07） |
| 金额币种 | 人民币（CNY），按微店回传，不换算（GG-08） |

依赖微店结算数据、当前还拿不到的指标：**达人净佣金、佣金增加 / 扣回、佣金流水、结算净应收、门店应收流水、店铺 UV / PV 与下单人数等经营数据**。接口对这些字段返回 null，并在结果中标明 `unavailable`（含原因代码，例如 `WEIDIAN_SETTLEMENT_PENDING`），前端显示「开发中」。不得用费率自行推算佣金（数据统计口径「达人净佣金」）。

### 3.2 汇总表与任务

- 按日汇总的事实表（命名、字段由你设计，写进设计说明书 §5.3）。至少覆盖四个模块需要的粒度：日 × 店铺、日 × 店铺商品、日 × 店铺商品 × SKU、日 × 达人、日 × 达人 × 店铺商品、日 × 商务（含无主）。可加和的指标进汇总表；**跨日期的去重指标**（支付订单数、成交 SPU、有销售达人、退款关联原订单数）不能把每日数相加，按区间从明细或带去重键的中间表计算，并说明做法。
- 任务（按公司执行、跳过停用公司、分布式锁，GG-11）：
  - 每 5 分钟增量汇总当天有变化的数据（订单同步、导入、人工改归属后）；
  - 每天 02:00（北京时间）重算前一天；每月 1 日 03:00 重算上月；
  - 「脏日期」：迟到的订单、成功退款、人工改归属、映射修正，记录受影响日期并在下一轮重算（设计说明书已有 `crm_agg_dirty` 的设想，可沿用或调整）。
- 汇总结果记录每家公司的「最近更新时间」，供结果说明显示（GG-02）。

### 3.3 公共查询能力

提供给四个模块复用的服务（`stats` 模块内，其他模块经 `api` 包取数）：

- **时间范围**：今日、昨日、近 7 天（默认）、近 30 天、本月、自定义；自定义最长 90 天；边界按北京时间（GG-01）。
- **环比**：上一个等长周期；上期为 0 时比例为 null（GG-03）。
- **权限范围**：`dashboard:shop` / `dashboard:team` / `dashboard:kol` 与数据范围 `ALL` / `OWN`；商务（`OWN`）只看到自己名下达人的数据；汇总、排行、详情、图表、导出使用同一套过滤（GG-04）。
- **排序与分页**：数值列排序；金额相同按「区间内达到该金额的最后一笔支付时间」升序（先达成者在前，GG-05），写进设计说明书；分页 20 / 50 / 100。
- **结果说明**（GG-02、DP-02 等）：每个查询结果附 `meta`：生效的筛选条件、统计起止日期（北京时间）、权限范围（全部 / 本人名下）、最近更新时间。
- **导出当前页**（GG-06）：后端生成 Excel（`.xlsx`），只含当前页记录与当前排序，表头前写筛选条件和导出时间（北京时间）；写操作日志；权限与列表一致。复用现有 Excel 写入工具，不新增依赖；需要新依赖时停下来报告。

### 3.4 示例接口（验证底座用）

实现一个总览接口 `GET /admin-api/stats/overview`（`dashboard:shop` 或 `dashboard:team`，按权限范围过滤），返回区间内的支付订单数、销售件数、交易 GMV、成功退款金额、净交易额、平均订单价、金额退款率、周期订单退款占比及各自环比，附 `meta` 与 `unavailable`。它用于本任务的端到端验证，也给工作台以后使用；四个模块的专用接口由各自任务实现。

### 3.5 一致性与性能（GG-12）

- 指标卡、排行、明细可核对到原订单或退款：集成测试用手算数据（注释写计算过程，规范 05）验证每个口径，包括跨期退款、同单多商品、同单多笔退款、商务转移前后、无主业绩、同一原商品复制到两家店。
