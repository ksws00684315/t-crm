# 任务 157：源商品目录收敛与复制跳过显式化 — 执行报告

## 1. 结论

负责人提出「把之前删除的一个校验加回去：达人 K1 已有关联商品 I1，复制任务里再出现把 I1 复制给 K1，该条跳过、不影响整个任务」。经 git 考古（`git log -L processOne` 全历史 + pickaxe 搜索），**该校验从未被删除**：同达人幂等（条目身份级 `CopyJobWorker` 源 ID 命中本人映射 → 跳过；商品级 `copyFor` 内 `findCurrentByKolProduct` 命中 → 跳过）自任务 17b 初始提交（`63160c76`）起逐字保留至今，单测与集成测试双向钉死。v0.1.16 真正删除的是姊妹规则「**他人**专属商品 → 该条失败」（任务 151 `980e2181` 删除、任务 152 `8a8a37ea` 改为从副本本身复制，删除原因是客户脚本把复制链接写回表格、下一位达人跑同一张表会整批失败）；该口径本期不恢复。

本期实际改动：

1. **同达人幂等跳过显式化**：命中条目由 success 改标新状态 `skipped`（`target_item_id` 仍写已有复制商品 ID），管理端任务明细显示「已跳过」；任务级计数把 skipped 计入成功（脚本以 `successCount + failCount ≥ totalCount` 判完成，语义不变），全 skipped 任务为 completed；对外 `items/resolve` 与任务明细接口对 skipped 一律仍返回 `success` + 已有复制商品 ID，表格脚本零改动（ADR-019 契约冻结条款继续成立）。
2. **软删源商品原位复活**：`ensureProduct` 登记来源商品时若同 `(shop_id, weidian_item_id)` 存在软删行，原位复活（`is_deleted=false` + 刷新名称/价格/图片，P 码不变），不再新插行。配合生产目录收敛操作（软删 2359 条冗余孪生行，发版后执行），转换已收敛 listing 的链接不会再以新 P 码反弹目录。
3. **三入口覆盖核实**（校验在各建关联入口的现状，见 §2）：复制任务为本期改动；对应关系导入与达人推广表上传原本就是跳过/幂等语义，未改。

## 3. 主要改动

### 3.1 后端（`product` 模块）

- `CopyJobItemDO` 新增 `STATUS_SKIPPED="skipped"`。
- `CopyJobWorker`：新增 `markSkipped`（守卫 pending、写 `target_item_id`）；条目身份级与商品级两个幂等命中点改标 skipped；`ensureProduct` 锁后复查增加软删行复活分支（`findDeletedShopItemId` + `reviveDeletedShopItem`，P 码不变、图片仅在有新值时刷新）。
- `ProductMapper`：新增含已删行的查找与原位复活两条原生 SQL（沿用 `existsAliveShopItem` 的租户拦截语义）。
- `CopyJobProgress`：skipped 计入成功桶（不计 failed），任务状态规则不变（fail=0 → completed；skips+fails → partial_failed；全 failed → failed）。
- `ProductLinkService`：`buildResolve` 与 `toJobItemView` 对 skipped 一律按 success 呈现（外部契约不变）；管理端 `CopyJobItemVO` 原样透传原始状态。
- 迁移 `V202611212000__allow_copy_job_item_skipped_status.sql`：`ck_crm_copy_job_item_status` 放行 `skipped` 并更新列注释（约束重建，无数据变更）；新增部分索引 `idx_crm_product_shop_deleted (shop_id, weidian_item_id) WHERE is_deleted = TRUE`——`crm_product` 既有二级索引均为 `is_deleted = FALSE` 部分索引，复活查询需专用索引（审查 P2 修复；仅收敛行入索引，体积极小）。

### 3.2 admin-ui

- `copy-job/index.vue` 明细状态文案加 `skipped`（标签类型沿用 info 灰色）。
- 语言包：`copyJob.itemStatus.skipped` =「已跳过」/「Skipped」（zh/en）。

### 3.3 测试

- `CopyJobWorkerTest`：三个幂等复用用例断言升级（wrapper 参数含 `skipped` 与已有复制商品 ID，首个用例更名 `shouldSkipWithoutCopyOrQuota_whenOwnExclusiveItem`）；新增 `shouldReviveSoftDeletedProduct_whenProbedSourceWasDeleted`（探测路径命中软删行 → 复活不新插、P 码不变、复制继续）；三个 probe 注册用例补 `findDeletedShopItemId → null` 桩（Mockito Long 默认 0L 会误入复活分支）。
- `ProductLinkIT`：新增 `shouldReviveSoftDeletedProduct_whenConvertingItsLink`（端到端：软删行的链接转换 → 原行复活 `is_deleted=false`、P 码不变、全库该 item 仅一行、新映射挂复活行）——两条新原生 SQL 由真实 PostgreSQL 执行验证（审查 P2 修复）。
- `CopyJobProgressTest`：新增全 skipped → completed（success=total）与 skipped+failed → partial_failed 两用例。
- 既有回归：`ProductLinkIT:502`（同达人链接转换不复制不扣额度）、`:444`（二次转换幂等）零改动通过——resolve 契约与完成判定保持原样。
