## 3. 要修复的问题

### 3.1 指定店铺生成复制令牌返回 500（06.08）

- **现象**：在管理端生成复制令牌时指定目标店铺，返回 500；不指定店铺时正常。
- **原因**：
  - `CopyTokenService.requireEnabledShop` 用 `TenantScope.companyId()` 取公司，但管理端的普通请求里这个值是空的；
  - 同时这里用 `JdbcTemplate` 直接查商品模块的表 `crm_shop`，违反规范 01（模块之间只能经由 `api` 包）。
- **修法**：
  - `product` 已经依赖 `kol.api`，`kol` 不能反过来依赖 `product.api`（否则 `ArchitectureTest` 会报循环依赖）。所以在 `kol.api` 定义一个窄接口，例如 `CopyTargetShopApi`，提供「店铺在当前公司存在、未删除且已启用」的判断，由 `product` 模块实现，公司隔离交给租户插件；
  - `CopyTokenService` 改为调用这个接口，删掉直接写的 SQL；
  - 店铺不存在或不属于本公司时，按原来的约定返回 4xx（保持现有错误码）；店铺已停用时返回 `SHOP_DISABLED`。
- **测试**：
  - 先写一个以管理端登录态调用、指定店铺的用例，复现 500；
  - 修复后覆盖：成功；店铺不存在；其他公司的店铺；店铺已停用。

### 3.2 推广配置与跳转数据不一致（04.03）

- **现状**：
  - 达人信息有两个入口可以修改：普通编辑（`KolService#update`）和推广配置（`KolPromotionService#updateConfig`）。两边都能改佣金比例、邀请码、推广表格地址，普通编辑还能改跳转平台模板 `linkTemplateId`；
  - 跳转服务按 `KolDO.linkTemplateId` 和 `inviteCode` 生成目标地址，但推广配置里多选的代购平台（`crm_kol_platform`）完全不参与跳转；
  - 推广配置修改邀请码后，**不会发布** `KolLinkTargetChangedEvent`，跳转仍用旧的邀请码；
  - 普通编辑修改佣金比例时，**不写**推广配置记录。
- **决定**：推广配置是这几个字段**唯一**的修改入口。
  1. 普通编辑的请求和对话框中**去掉**佣金比例、跳转平台模板、邀请码、推广表格地址（邮箱见 3.3）。普通编辑只保留资料类字段：名称、国家、WhatsApp、社媒账号、备注。
  2. 推广配置新增「跳转平台」`jumpTemplateId`，存入已有的 `crm_kol.link_template_id`，**不加迁移**。规则：
     - 必须是本次选中的代购平台之一；
     - 只选了一个平台时自动取它；
     - 选了多个平台但没有指定跳转平台时，返回校验错误。
  3. 改为「推广中」时的配置齐全检查（`missingConfigFields`）增加 `jumpTemplateId`，422 的 `data` 数组加上这个字段名；管理端「缺少：…」提示和「去填写」都要能处理它。
  4. 保存推广配置时，跳转平台或邀请码有变化，就在同一个事务里发布 `KolLinkTargetChangedEvent`（与 `KolService#update` 原来的做法一致）。保存后的配置记录快照中要包含 `jumpTemplateId`。
  5. 25b 的修改记录在显示时会把字段名转成中文，新增字段要有中英文名称。
- **测试**：
  - 修改邀请码后，链接索引登记了刷新（参照现有 `LinkIndexListener` 的测试）；
  - 修改跳转平台后同样登记刷新；
  - 跳转平台不在已选平台中时被拒绝；只选一个平台时自动选中；
  - 普通编辑请求带上佣金比例、邀请码等字段时，这些字段不会被修改；
  - 管理端：编辑对话框不再出现这几个字段；推广配置抽屉中，跳转平台下拉框只列出已选的平台。

### 3.3 邮箱可修改、审核可以回退（04.02）

- **邮箱只读**（R7）：
  - 普通编辑不再修改邮箱：请求里去掉 `email`，对话框中邮箱显示为只读；
  - 管理员是否可以改邮箱还在等确认，本任务对所有角色都只读；
  - 测试：编辑请求带不同的邮箱时，邮箱不变。
- **不可再次审核**：
  - 达人一旦离开「待审核」，`updateStatus` 拒绝再改回 `PENDING_REVIEW`，返回 409，新增错误码 `KOL_REVIEW_ALREADY_DONE`，登记在 `shared.ErrorCode`，管理端中英文语言包都要有；
  - 管理端的状态操作中不再提供「待审核」选项。
  - 测试：待推广 → 待审核被拒；待审核 → 待推广正常。

### 3.4 「我的注册链接」：超管报错、邀请码没有单独展示（01.01）

- **入口**：
  - 只对满足「商务」条件的账号显示：已启用的子账号、数据范围为本人、有 `kol:edit`。条件与后端的 `KolRegisterCodeService.requireBd` 一致；
  - 超管和其他账号不显示这个入口，后端保持现状；
  - 前端判断依据取自 `/me` 的现有字段；如果现有字段不够用，停下来报告，不要新增接口。
- **弹窗**：分两行展示「邀请码」（注册链接里的码）和「注册链接」，各带一个复制按钮。
- **测试**：组件测试覆盖超管看不到入口、商务看得到入口，以及邀请码和链接都能复制。

### 3.5 复制令牌的默认额度改为 1（06.07）

- 把 `crm.copy-token.default-quota` 从 1000 改为 **1**，有效分钟保持 1440。
- 管理端生成令牌对话框里的默认值同步改为 1。如果默认值是从后端取的，确认改后显示正确。
- 更新相关测试和设计说明书 §4.3 中的默认值。

### 3.6 订单与退款导入支持 CSV（09.03）

- 订单明细导入和已完成退款导入（任务 18），在 `.xlsx` 之外，再接受 `.csv`：
  - UTF-8 编码，有无 BOM 都可以；逗号分隔，支持双引号转义；
  - 第一行是表头，表头与 Excel 模板**完全一致**；
  - 文件大小上限与 Excel 相同。
- 读取后复用现有的逐行处理与归因逻辑，不复制一套。
- 编号列（订单号、商品 ID 等）一律按文本读取，避免长数字变成科学计数法。
- **不新增依赖**：CSV 解析用 JDK 自带能力自己写一个小的解析器。如果项目已经有可用的直接依赖（例如 Apache Commons CSV），在报告中说明后可以使用；不得为此新增依赖。
- 管理端导入入口接受 `.xlsx,.csv`，提示文案同步修改。
- **测试**：
  - CSV 与 Excel 导入同一批数据，结果一致；
  - 带 BOM 的文件；
  - 字段中带逗号和引号；
  - 表头不符时返回原有的表头错误码；
  - 长数字编号原样保留。
