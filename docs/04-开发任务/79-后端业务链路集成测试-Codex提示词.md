## 1. 背景与目标

后端已有 42 个集成测试，各段业务都有覆盖，但有两个缺口：

1. **数据是插库造的，不是走接口建的**。`CommissionSettlementIT`、`OrderChainFinanceIT`、`WithdrawalIT` 等用 `jdbc.update` 直接插入达人、订单、商品行、佣金状态。各段单独都对，但「上一段接口产出的数据，下一段能不能正确接上」从没有被验证过。
2. **订单与结算测试在 Java 层替换了微店接口**。`OrderIT`、`OrderQueryIT`、`KolOrderIT`、`OrderSettlementFlowIT` 用 `@MockitoBean WeidianBusinessApi`，真实的 HTTP 客户端、签名与限流、`WeidianBusinessApiParser` 在业务链路里一次都没有走到。任务 65、66 的两次解析缺陷（`itemid` 字段名、重复剥离 `result`），都是到 M0 真实联调才暴露的，就是这个原因。

**目标**：补一组业务链路集成测试，覆盖下面两点：
- **全部业务数据通过 HTTP 接口建立**：管理端 `/admin-api/**`、达人端接口；
- **微店在 HTTP 层模拟**：起一个本地假微店服务，后端用真实的客户端和解析器去调用它。

用 4～6 个测试方法，覆盖主业务链从店铺授权到达人收到打款，以及退款、异常、权限三条支链。

**这些测试证明不了什么**：假微店的返回是按我们对文档和实测的理解写的，测试只能证明「代码与这份理解一致」。结算明细的金额单位、流水类型、订单号格式、`tradeTime` 含义，仍以 M0 第 11 步真实样本为准。执行报告要写明这一点。

## 2. 规则

| 项 | 规则 |
|---|---|
| 建数据 | 公司、账号、店铺、商品、达人、对应关系、订单、提现等**业务数据只通过接口建立**。唯一例外是平台管理员 `bootstrap` 账号，沿用 `CompanySessions` 的方式 |
| 定时任务 | 订单同步、结算拉取、佣金释放、发件箱等按时间触发的环节，在测试里**直接调用该任务的公开入口方法**（照 `OrderSettlementFlowIT` 调 `releaseJob.releaseDue()` 的写法），不等待调度器。有手动触发接口的环节（如订单同步）优先走接口 |
| 直接读库 | 只允许用于断言接口不对外暴露的值，例如未核实原因 `commission_basis_reason`、台账行数。每一处都在执行报告里列出：表、字段、为什么没有接口可读 |
| 直接写库 | **不允许**，只有 `@AfterEach` / `@AfterAll` 清理可以写。如果某一步确实没有接口可走，**停下来报告**，不要用插库绕过 |
| 金额断言 | 每个金额都在注释里写手算过程，断言具体值（`BigDecimal` 比较用 `isEqualByComparingTo`） |
| 测试方法 | 一个测试方法 = 一条链路走通（规范 05「一个方法一个行为」在链路测试中，「行为」指这条链路，`OrderChainFinanceIT` 已有先例）。中间节点的断言写成私有步骤方法，方法之间**不依赖执行顺序**，每个方法自己从开公司开始建数据 |
| 测试数据 | 公司、账号、店铺、达人名称加前缀 `t79_`（只在 Testcontainers 容器内，不进共享库） |
| 外部服务 | 除微店外，汇率（ECB）、Google、邮件沿用现有测试的模拟方式或测试配置，**不访问外网** |

## 3. 范围

### 3.1 假微店服务（测试支持代码）

在 `backend/src/test/java/com/tcrm/admin/` 下新增一个假微店服务，与 `CompanySessions`、`WeidianTestProperties` 放在一起，命名自定，例如 `FakeWeidian`：

- 用 JDK 自带的 `com.sun.net.httpserver.HttpServer`，照 `WeidianIntegrationIT` 的写法。**不新增依赖**（不引入 WireMock、MockWebServer）。
- 路由：`/oauth2/authorize`、`/oauth2/access_token`、`/oauth2/refresh_token`、`/token`、`/api`。`/api` 按请求里的方法名（`vdian.item.list.get`、`vdian.order.list.get`、`vdian.order.get`、`shop.order.trade.detail` 等，以 `WeidianBusinessApiClient` 实际调用的为准）分发。
- 每个测试可以按方法名、参数预置返回。返回体以 `src/test/resources/weidian/` 现有样本为模板，用占位或构造替换订单号、金额、时间。
- **记录每一次请求**（方法名、业务参数，不含签名和令牌），供断言使用：
  - 不传 `ctx`；
  - `pageSize` ≤ 100；
  - 结算窗口 ≤ 89 天；
  - 主链没有调用任何写入型方法（`vdian.item.add`、`vdian.item.delete`、`vdian.item.saveItemDetail` 等）。
- **未预置的方法名返回微店错误结构，并在测试结束时让测试失败**，避免链路悄悄调用了没想到的接口。
- 只给本任务新增的链路测试使用。**不要改造现有测试**去用它（范围外）。

**返回样本的来源，按优先级**：
1. M0「实测记录」和任务 65、66、75 报告中的真实返回形态（字段名、嵌套、单位）；
2. 现有 `src/test/resources/weidian/*.json` 文档样本；
3. 开放平台文档。

新增的样本文件在文件名或同目录的说明中写明来源。结算明细金额按任务 76 的单位常量（分）构造。

### 3.2 链路测试

新增 2～3 个测试类，放在 `com.tcrm.admin` 根包（跨模块，照 `TenantIsolationIT` 的位置），命名 `*ChainIT`，标注 `@Tag("docker")`。方法名照规范 05 的 `should…_when…`。

**链路 A：主链（必做，一个方法）**

按顺序，全部走接口，每一步断言接口返回和关键状态：

1. 平台管理员开公司，公司管理员建商务账号和财务账号（岗位模板：商务 OWN，财务 ALL + 打款权限）。
2. 店铺授权：走 OAuth 发起与回调，令牌来自假微店；店铺检测通过。
3. 商品：同步或导入店铺商品，`vdian.item.list.get` 来自假微店。
4. 达人：按运营实际使用的方式建档并指派给该商务，开通达人账号，达人登录达人端。用哪种方式，报告里说明理由。
5. 对应关系：建立达人与商品的对应关系，并断言推广链接的 Redis 跳转索引已按跳转服务格式写入（格式以 `LinkIT` 为准，**不启动跳转服务进程**）。
6. 设置佣金比例和结算配置（最低提现额等），用接口设置。
7. 订单同步：假微店返回一笔两个商品行、含运费、属于该达人的已付款订单。断言订单入库、金额换算、两行都归因到该达人、商务能在订单列表看到。
8. 结算拉取：假微店返回该订单的结算流水（货款收入、交易手续费、分润，带符号；单位为分）。断言：
   - 两行已核实；
   - 基数按行实付比例分摊，尾差落在实付最大的行；
   - 佣金 = 基数 × 比例，两行合计等于整单可提现金额 × 比例；
   - `release_at` = 货款收入的 `tradeTime`。
9. 释放：货款收入时间设为过去，调用释放任务。断言达人钱包已入账，达人端可提现金额正确。
10. 提现：达人绑定收款账户并申请提现，按现有流程走审核（商务或财务，以现有接口为准），财务打款。断言：
    - 达人钱包和台账正确；
    - 订单链路接口（`/admin-api/order/orders/{id}/chain`）的资金、行级佣金、财务流水正确；
    - 达人端提现记录状态正确；
    - 打款通知已进发件箱。

**链路 B：退款（必做，两个方法）**
- 结算后部分退款：主链走到释放后，假微店在回扫窗口里新增一笔退款流水。断言基数下降、追加修订、已释放部分产生负向 `COMMISSION_ADJUSTMENT`、达人端可提现金额下降。手算每一步。
- 结算前全额退款：订单出现在 `PRE_SETTLE_REFUND`。断言基数为 `0.00`、已核实、无入账、达人端可提现为 0。

**链路 C：微店数据异常（必做，一个方法；场景可以拆成多个方法）**
- 货款收入与订单实付对不上（模拟单位错误：流水按元返回）：两行保持未核实，原因 `INCOME_MISMATCH`，钱包无入账。
- 结算流水的订单号在库里不存在：流水入库、标记未匹配，不影响其他订单。
- 假微店某一轮返回错误码：本轮失败不影响订单同步；下一轮恢复正常后，从已入库流水补算，不重复入账（任务 76 审查返工的行为）。

**链路 D：权限与公司隔离抽查（必做，一个方法）**

在链路 A 建好的数据上（同一方法内自行建立），抽查下列访问，断言 403 或 404，以及列表里看不到：
- 另一公司的管理员访问该订单、订单链路、结算明细、提现单；
- 另一商务（OWN，不负责该达人）访问同样的接口，以及冻结、恢复提现，在公司内打款；
- 没有 `commission:view` 的账号看订单链路时，金额字段为 null（以现有约定为准）；
- 另一名达人在达人端看不到该订单和资金。

各断言以现有接口约定为准，不新增约定。

### 3.4 不做

- 改任何生产代码、迁移、配置。测试中发现缺陷时，**停下来报告**（复现步骤、实际与期望、涉及文件），由架构负责人决定另开任务修复。不要在本任务里修，也不要为了通过测试改断言或加 `@Disabled`。
- 启动跳转服务进程、点击采集链路：跨进程契约已由 `LinkIT`（写索引）与 `redirect` 的 `RedirectIT`（读索引）覆盖，本任务只断言索引内容。
- 商品复制（`vdian.item.add` 写入链路）、预付款、离职交接、看板：不在本任务的链路内。
- 前端、浏览器验收：本任务不涉及界面，不做浏览器验收。
- 改造现有测试、抽取公共基类、重构 `CompanySessions` 等已有支持类。新增的帮助方法放在本任务的测试类或 `FakeWeidian` 中。
