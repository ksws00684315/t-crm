## 主要改动

- `crm_kol_item.link_code`：`KPL-` + 12 位大写十六进制，公司内唯一，创建后不变。复制（`CopyJobWorker`）、上传推广表（`PromoSheetMappingService`）、导入（`MappingImportProcessor`）都经 `KolItemCodes.insertNew`。漏写时数据库默认值补同样格式。已有行按 `KPL-` + `md5(id)` 前 12 位回填。
- 列表 `GET /admin-api/product/kol-items` 与详情 `GET /admin-api/product/kol-items/{id}`，权限 `product:view`。商务 `OWN` 只看自己负责的达人；不存在或越权详情返回 404 `COMMON_NOT_FOUND`。
- 销量与支付金额：当前页一次分组汇总。订单状态 `PAID` / `SHIPPED` / `RECEIVED` / `COMPLETED` 的未删除明细计入 `quantity` 与 `pay_amount`，不扣退款。`UNPAID` / `CLOSED` / `UNKNOWN` 不计入。详情累计退款是该对应关系全部未删除明细的 `refund_amount` 之和。访问次数按 `kol_item_id` 计，排除机器人与重复点击。
- 清理状态取最近一条（`cleanup_time DESC, id DESC`），库内 `SUCCESS` 映射为 `DONE`，无记录为 `NONE`。映射状态按当前是否在有效期内分为 `ENABLED` / `DISABLED`。
- 当前佣金比例读取达人当前 `default_rate`，不是历史快照。
- `KolItemApi.listLinkCodesByIds` 给任务 40 按 ID 取链接编码。销售与访问通过 `product.api` 的查询接口，由 order、link 模块实现，product 不依赖这两个模块的内部包。
- 管理端 `views/product/kol-item/`：筛选、列顺序、复制与打开、详情抽屉、中英文。保留上传推广表、批量导入、佣金信息、链接、重建索引。进入页面即加载。
- 复核发现：再次展开达人远程下拉会清空选项，随后查询丢掉已选达人。已改为选中时记下该达人，空关键字不再清掉已选项。页面测试 `keeps the selected creator after the remote list is cleared`。
