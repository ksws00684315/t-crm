## 6. 疑似脚本问题清单（未改脚本，供正式上线处理）

1. **`refresh-s3-credentials.sh` 不加载 `deploy/.env`**（refresh-s3-credentials.sh:103-108 只读环境变量），与同类主机脚本不一致（`pg-backup.sh:78-84`、`ops-check.sh:240-256`、`renew-public-cert.sh:41-43` 都 source `.env`）。README 原文档化的裸 cron 行在 root crontab 下会因缺少 `TCRM_PGBACKREST_CREDS_DIR` 每次退出 1，凭证永不刷新（后果：pgBackRest 归档/备份失败）。手册与 README 已改为行内变量调用绕开；正式上线时建议让脚本与其它脚本一致地加载 `.env`。
2. **`release.sh` 首发钉库版本取 `.env` 的 `TCRM_VERSION` 原值**（release.sh:608-628）：`.env.example` 占位值 `1.0.0` 非空，首发其他版本时 `crm-postgres` 被钉到占位版本并预拉取不存在的镜像（拉取失败、发布中止）。可运行性无碍（失败发生在任何变更之前），文档已修（§4 修正 3）；脚本侧若要在 `.env` 值未发布过时改用 `TARGET_VERSION`，需要识别占位值，暂无可靠办法，故以文档口径解决。
3. （防护性，非确认缺陷）cron 默认 `PATH` 不保证包含 `/usr/local/bin`（AWS CLI 安装位置）：手册 crontab 显式设置 `PATH` 规避。若正式上线保留手册 crontab 则无需改脚本。
