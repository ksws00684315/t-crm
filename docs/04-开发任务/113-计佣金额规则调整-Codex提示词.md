## 1. 背景与负责人决定

负责人 2026-11-05 确认了《金额名词与口径定义》（下称「定稿」）。其中 §2.1 改变了退款中订单的计佣方式：

| 情况 | 现在 | 定稿 |
|---|---|---|
| 退款中（未完结退款 `PROCESSING` / `UNKNOWN`） | 照常计提，只阻断释放和新的提现占用（`AFTER_SALES`） | **计佣金额暂为 0，不计入**；退款被拒绝或关闭后恢复 |
| 部分退款完成 | 支付金额 − 成功退款 | 不变 |
| 全额退款完成、付款后关闭 | 0 | 不变 |
| 已结算 | 仍按支付金额（结算只作确认） | 改为结算金额，**待 M0 核实流水格式，本任务不做** |

「计佣基数」改名「计佣金额」由任务 112 改页面文案。本任务的代码注释和设计说明书按新名称写，类名、字段名不改。

**业务前提**：一单只对应一个达人，所以「退款中」按整单判断。

## 2. 要求

### 2.1 退款中整单不计佣

1. 订单任一商品行有未完结退款（`PROCESSING` 或 `UNKNOWN`）时，**整单各行**有效计佣金额为 `0.00`，计提为 `0.00`。
   - 释放依据仍为 `AFTER_SALES`，阻断释放和新的提现占用的规则不变；
   - 订单仍算已核实，不进待核实，不写 `commission_basis_reason`。
2. 退款完结后按现有规则重算，不另写恢复逻辑：
   - 被拒绝、撤销、关闭：恢复为支付金额 − 成功退款；
   - 退款成功：按部分退款或全额退款规则计算。
3. 计提变化都经现有快照修订路径（`applyRevision`）写入，订单同步、退款同步、退款导入、结算重算四条路径都要生效，不新增旁路。
4. **已释放的佣金进入退款中**：
   - 先在设计说明书和现有代码里确认：计提降为 0 时，已释放部分是否按 §4.7 第 2 条产生负向台账差额（`COMMISSION_ADJUSTMENT`）、恢复时是否产生正向差额；
   - 占用该行的待付提现申请按 §4.8.6 置为暂停，这条现有联动不变；
   - 在执行报告用一张时间线表写清以下两种情况下，冻结中、可提现、提现中、累计佣金、钱包余额各自怎么变，并保持五层恒等式：
     - 付款 → 释放 → 进入退款中 → 退款被拒；
     - 付款 → 释放 → 进入退款中 → 部分退款成功。
   - 现有修订机制不能产生正确的负向和正向差额时，**停下报告**，不要自行设计新的台账类型。
5. 计佣的订单状态范围不变：已付款、已发货、已签收、交易成功（`PAID` / `SHIPPED` / `RECEIVED` / `COMPLETED`）计入，付款后关闭为 0。`UNKNOWN` 订单状态维持现有处理，在报告里写明现有处理是什么。

### 2.2 展示

1. 退款中的订单，在管理端订单链路、达人收入明细、结算明细，以及达人端我的订单中，预估佣金显示 `0.00`。另加一个提示，说明原因是退款中（例如「退款中，暂不计佣」），文字进两端中英文语言包。不显示成「待核实」。
2. 退款完结、计提恢复后，提示自动消失。
3. 只加这个提示，不改其他文案（改名由任务 112 负责）。若任务 112 已先合并，提示用 112 的新名词；否则沿用现有名词，在报告中说明。

### 2.3 文档

1. 设计说明书 §4.7 第 3 条、§4.8.1「阻断释放」一条：改为「退款中整单计佣金额为 0，阻断释放与新的提现占用；退款完结后按规则恢复」，注明负责人 2026-11-05、定稿 §2.1。
2. §4.8 开头的 2026-11-05 说明中，「退款中订单暂不计入（任务 113）」改为已实现，结算部分仍写待 M0。
3. ADR-032 修订记录追加一条 2026-11-05（任务 113）。
4. 定稿 §8「落地」表中任务 113 的状态改为「已实现（待合并），结算部分待 M0」。

## 4. 验证

1. **单元测试**（`CommissionSettlementRules`、`SettlementBasisCalculator` 及修订服务）：
   - 支付 100、比例 10%，进入退款中：各行计提 0，释放依据为 `AFTER_SALES`；
   - 两行订单只有一行退款中：两行都为 0；
   - 退款被拒绝：恢复为 10.00；
   - 退款中 → 部分退款 30 成功：计提 7.00；
   - 退款中 → 全额退款成功：0；
   - 付款后关闭：仍为 0，与现状一致；
   - 已释放后进入退款中、再恢复：台账差额先负后正，合计为 0，五层恒等式成立。
2. **集成测试**：
   - 退款同步路径：模拟微店退款状态从处理中变为拒绝，断言快照计提先为 0、后恢复；

   - 提现暂停：占用该行的待付申请在退款中时为暂停，恢复后解除暂停（沿用任务 90 的断言写法）。

## 6. 停下来报告

- 现有修订机制不能正确产生已释放部分的负向、正向差额（§2.1 第 4 条）；
- 退款中整单置 0 会让某条路径（同步、导入、结算重算）的结果与其他路径不一致，或者需要绕开 `applyRevision`；
- 「退款被拒绝或关闭」在微店退款状态里没有对应取值，无法判断恢复时机；
- 需要迁移或新增依赖。
