## 4. 接口与表结构变更

无迁移。接口只增字段，另删一个重复字段：

- `GET /admin-api/order/orders/{id}`：新增 `orderAmount`、`discount`、`refundAmount`、`netReceived`、`commission`。**删除 `totalAmount`**：它与 `itemAmount` 同值，前端已改用 `itemAmount`。商品行的 `totalAmount`（商品总价）保留。
- `GET /admin-api/order/orders/{id}/chain`：字段不变。管理端资金区块改读订单详情接口。
- `GET /kol-api/orders`、`/kol-api/analytics/overview`、`/kol-api/analytics/sales-total`：字段不变，金额口径改为订单支付金额。
- `GET /admin-api/product/kol-items`、`/{id}`：字段不变，统计范围变化，见第 3 节。
- `GET /admin-api/commission/incomes/{id}`、`/settlement-details`：`base` 字段名不变，取值改为有效基数。
- 跨模块端口 `OrderChainCommissionApi`：两个 record 各加一个字段。

## 12. 偏离与原因

以下各条都由架构负责人在 2026-11-05 确认。

1. **计佣金额的取数**：commission 模块现有的只读端口（`OrderChainCommissionApi`、`CommissionOrderStateApi`）都取不到计佣基数。按确认，在现有端口 `OrderChainCommissionApi` 的两个 record 上加字段，不新增接口。
2. **计佣金额显示有效基数**：取 `CommissionSettlementRules.effectiveBasis`（已扣成功退款），不显示原始 `basis_cny`。管理端「达人收入明细」「结算明细」的「计佣金额」列（原「计佣基数」）取值，也从原始基数改为有效基数，依据是定稿 §2、§2.1 和负责人答复。这样「预估佣金 = 计佣金额 × 比例」在页面上能对上。计佣计算本身未改。
3. **达人端「我的订单」展开行**：提示词 §2.5.1 的展开行要求不适用，因为桌面端没有展开行（提交 695223df 已移除），窄屏卡片的展开明细也不显示金额。按确认只改表头和取值：「订单金额」改「支付金额」，取订单 `pay_amount`；删除运费说明；「佣金金额」改「预估佣金」。后端不新增 `unitPrice` / `productTotal`，§4.1「明细返回单价」这条测试取消，窄屏卡片不改。
4. **「已申请提现」**：链路的占用合计包含待审核、待付款、已付款三种状态，与定稿 §3 的「提现中」（只算待审核、待付款）不同。以下几处改称「已申请提现 / Applied for Withdrawal」，取值不变：链路行内 `occupiedTotal`、链路节点、页头汇总列、行内提现明细金额列、提现详情关联订单表。定稿 §3、§7 已补说明。
5. **「期间已提现」**：对照表把「佣金付款」（所选期间）和「累计已付佣金」（全期）都映射为「已提现」，同屏会出现两个数值不同的「已提现」。期间口径改称「期间已提现 / Withdrawn in Period」，「已付金额」的说明随之写成「期间已提现＋预付已付」。
6. **达人商品详情的退款金额**：提示词 §2.6.1 要求把详情的「累计退款」改名为「退款金额」。但规范 13 §3.14 写明负责人已确认从详情删除「累计退款」，当前详情不展示它。本任务只改了词条（`mapping.refundAmount`），没有恢复展示；接口仍返回同口径的 `refundAmount`。
7. **人工归属后的链路显示**：人工归属写回 `kol_item_id` 后，订单链路会显示该行的达人商品链接，属于附带的展示变化，已确认可以接受。佣金快照用 `product_id`，清理任务不读这个字段，都不受影响。
8. **链路页头汇总的金额列**：页头汇总的「支付金额」列换成了「商品总价」，因为定稿 §1 规定 SKU 级不显示支付金额，支付金额只在订单级金额区块出现。架构负责人审查 PR #204 时已接受。
