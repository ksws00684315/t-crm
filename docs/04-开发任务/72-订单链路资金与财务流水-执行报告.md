## 契约变更（设计说明书 §6.2 + 机读目录）

`GET /admin-api/order/orders/{id}/chain` 响应由 `{orderId, orderNo, lines[]}` 扩展为 `{orderId, orderNo, funds, lines[], financeFlows[]}`：

- **`funds`（B07 订单级）**：`payAmount` 订单实付、`refundTotal` 成功退款合计（按退款 ID 去重，同一退款跨商品行不重复累加）、`kolCommission` 净达人佣金（Σ 计佣快照累计净计佣；存在未核实行时为 `null` 待核实、不以 0 代替，全部核实才返回合计——架构审查整改后的口径，与行级一致）、`shopProfit` 店铺获利 = 微店结算净额 − 净达人佣金（微店净额待 M0（Q-1017-1/2），接入前恒为 `null`）、`accountStatus` `POSTED`/`UNVERIFIED`。
- **行级 `commission`（B07/B09）**：`rateSnapshot` 支付时刻比例快照（最新修订，不用当前比例反算）、`netCommission`（未核实行 `null`，与真实的 0 区分）、`shopProfit`（`null`）、`releaseBasis`（无快照行 `null`）、`occupiedTotal`（仅 `PENDING_REVIEW`/`PENDING_PAYMENT`/`PAID` 计入，驳回/撤回已释放）、`withdrawals[]`（提现 ID、编号、占用金额、状态机值、`paidAt` 未付为 `null`；含已驳回/已撤回的历史分配，按状态区分）。
- **`financeFlows[]`（B08）**：`flowNo`（`CL{台账ID}` / `WA{分配ID}`，稳定可追溯）、`orderItemId`、`shopName`、`type`（`KOL_COMMISSION`；`SHOP_RECEIVABLE` 保留待 M0，本任务不产生该类型数据）、`direction`（`INCREASE`/`DECREASE`，金额恒为正数、正负由方向表达）、`amount`、`businessAt`（台账 `occurred_at`：释放为释放时间、冲减/修正为业务记账时间；提现分配为申请提交时间）、`transferredAt`（达人佣金取 `crm_commission_withdrawal_payment.paid_at`，未付 `null`；不用冻结到期、入账或申请时间代替）、`withdrawalNo`（提现编号，非提现流水 `null`，前端显示「－」）。按 `businessAt`、`flowNo` 升序。
- **权限**：`funds`、行级 `commission`、`financeFlows` 仅当账号持有 `commission:view` 且（`OWN` 范围时）订单归属行全部为本人名下达人才返回；否则三者均为 `null`（口径同结算明细的混合归属隐藏）。
- 机读目录（api-catalog）同步该行说明；路径与权限（`order:view`）不变，`ApiCatalogConsistencyTest` 校验通过。

## 主要改动

### 后端（backend/）

- 新增 `order/api/OrderChainCommissionApi`（只读端口，order 所有、commission 实现，沿用任务 62 的依赖方向做法）：返回订单级汇总、行级佣金块与流水；权限与 OWN 范围判定留在 order 侧。
- 新增 `commission/service/OrderChainCommissionService`（端口实现）：
  - 行级数据来自 `crm_commission_item_state` + 最新修订比例（`CommissionItemRevisionMapper.listLatestByItemStateIds`）与 `crm_commission_withdrawal_allocation`（新查询 `WithdrawalMapper.listAllocationsByOrderItems`，返回全部状态的分配并左联付款）。
  - 流水来自钱包台账（新查询 `CommissionWalletMapper.listByItemStates`，按 `source_type='COMMISSION'` + `source_id` 关联计佣快照，含归属修正冲抵 `:K{kol}` 变体键的行）与提现分配（`PENDING_REVIEW`/`PENDING_PAYMENT`/`PAID` 逐分配拆行）。
- `order/service/OrderService.chain()`：组装三个财务板块；`commission:view` + OWN 覆盖判定（存在本人行且无他人行，未归属行不阻断，同结算明细 SQL 口径）；订单实付取订单行、成功退款按退款 ID 去重求和、店铺获利恒 `null`；流水补店铺名。
- `order/service/OrderChainDTO`：正式结构取代两个 `Object` 占位。

### 前端（admin-ui/）

- `api/types.ts`：`ChainLineCommissionVO`、`OrderChainFundsVO`、`ChainFinanceFlowVO`、`ChainWithdrawalVO`；`ChainLineVO.commission` 取代 `ledger`/`withdrawals`。
- `views/order/chain/index.vue`（只接线，不改 #122 三板块布局）：
  - 资金卡片：退款合计优先取服务端去重值（无权限回退客户端合计）、净达人佣金与店铺获利接真值；缺失时按「无佣金查看权限 / 当前权限仅展示本人范围商品行；整单金额不可见 / 待核实」区分显示，不以 0 展示。
  - 订单信息每行新增「佣金与提现」块：比例快照（百分比）、净达人佣金、店铺获利（待核实）、释放依据、提现占用合计与提现占用明细表（编号/占用金额/状态/付款时间，状态含已驳回、已撤回）。
  - 财务流水：正式表格（流水编号、店铺名、类型、方向、金额、商品、业务发生时间、金额流转时间、关联结算单号），保留「店铺应收待 M0 接入」说明；无权限/范围受限显示对应警示。
- 中英文语言包同步（新增 ~20 个 key，移除 4 个占位 key）。
