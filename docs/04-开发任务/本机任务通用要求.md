# 本机任务通用要求

> 适用于在负责人本机执行的开发任务（从任务 37 起）。每份任务提示词都会引用本文件，**必须完整阅读**。本文件与任务提示词冲突时，以任务提示词为准；与 `AGENTS.md`、`docs/05-工程规范/` 冲突时，以规范为准。

## 1. 开始之前

1. 完整阅读 `AGENTS.md` 和 `docs/05-工程规范/`，重点：01、02、03、04、05、06、08（第 9 节）、10、11、12。
2. 完整阅读任务提示词列出的进度表行。进度表是 `docs/04-开发任务/CRM系统功能评估与进度跟踪表-1018.xlsx`，**「功能说明」列是唯一需求依据**；「目前进度」列停在 10/18，以代码现状为准。截图只作布局参考（规范 12 第 1 节）。
3. 字体与字号以 `docs/03-设计/网页字体字号规范.xlsx` 为准（规范 10 第 1 节），不得自行增减。

## 2. 工作目录与环境

- **只在任务提示词指定的工作树中读写文件**。启动的每个子代理，输入中都写明工作树的绝对路径，并要求先 `cd` 到该目录。不得在主目录 `/Users/hh-mini/Public/dev/t-crm` 或其他工作树中创建、修改、删除文件，也不得在那里执行格式化、安装依赖、构建等会写文件的命令（规范 08 第 9.1 节）。
- **共享中间件**（规范 08 第 9.2 节）：联调和浏览器验证连接本机共享的 PostgreSQL 与 Redis（Compose 项目 `tcrm-local`，端口 55432 / 46391），连接信息在主目录的 `deploy/.env.local`，**只读，不得修改**。本地运行后端的方法见 `deploy/README.md`「本地共享中间件与开发」一节。
  - 后端、Vite 只用任务提示词分配的端口。负责人在用 18081、8848、8849、8890～8892，不得占用。
  - 测试账号、测试数据统一加前缀 `t{任务编号}_`（例如 `t37_bd01`、`t37_…@example.com`、店铺名 `t37_店铺A`）。
  - 收尾时只删除自己创建的数据，把改过的系统配置恢复默认。
  - **不得停止、删除或重建共享中间件的容器和数据卷，不得 `down -v`，不得另起 `docker-compose.dev.yml` 项目，不得重建负责人的预览 `tcrm-preview`。**
  - 自动化集成测试仍用 Testcontainers 临时容器。
- 分支上的迁移会进入共享库。迁移版本号只用任务提示词分配的区间；**已合并的迁移不得修改**；合并前修改过已在共享库执行的迁移，在 PR 描述中写明，由架构负责人处理校验和。

## 3. 开发要求

- 后端遵守规范 01～06：模块边界、权限码（每个接口声明权限码，商务 `OWN` 只能看自己负责的达人，ADR-018）、公司隔离、统一信封、分页、错误码登记、迁移注释、`Instant` 与 `BigDecimal`。
- 前端遵守规范 10、11：管理端列表用 `ListSearch`、`DataTable`、`RowActions`、`CopyText`；文字进语言包（中英文）；未实现的部分显示「开发中」，不造假数据。
- 依赖微店真实账号才能确认的字段或接口（错误码、状态取值、数量统计接口等）：按设计说明书和现有 `integration` 模块的写法实现，用模拟服务器测试，在执行报告「待 M0 验证」一节逐条列出，不要停下等待。
- 设计说明书 `docs/03-设计/系统详细设计说明书.md` 中受影响的章节同步更新（接口清单、表结构、状态字典）。
- 只做任务范围内的事；发现范围外的问题写进报告，不顺手改。

## 4. 检查与复核：交给子代理

**检查、复核、浏览器验证都交给子代理执行**（使用所在工具的子代理功能，例如 Claude Code 的 Agent / Task 工具）。主代理负责开发、汇总结果和修复问题。每次修改代码后，重新运行完整检查，不能只跑相关测试。

1. **检查子代理**，在工作树中执行：
   - 后端：`mvn -q spotless:check`、`mvn -B verify`、`mvn -B verify -Pdocker-it`（JDK 21：`JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home`）；
   - 跳转服务（如有改动）：同上；
   - 管理端、达人端（如有改动）：`pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm notices:check`；
   - 部署（如有改动）：`docker compose -f deploy/docker-compose.{dev,preview,prod}.yml --env-file deploy/.env.example config -q`、`python3 deploy/scripts/check-healthchecks.py`、`python3 deploy/scripts/check-compose-env.py`。
2. **复核子代理**（只读）：逐条对照任务提示词引用的进度表「功能说明」原文和提示词要求，输出复核表「需求原文（行号）→ 实现位置 → 是否满足（满足 / 部分满足 / 不满足 / 开发中）→ 差异或说明」（规范 12 第 4 节）。部分满足和不满足的必须修复或在报告中说明原因。
3. **浏览器验证子代理**（涉及界面时）：连接共享中间件，按规范 12 第 5 节的矩阵检查——1440×900、1280×800、一个 2560 宽，中英文，任务涉及的全部角色（平台管理员、公司超级管理员、运营、商务），有数据 / 空数据 / 长内容 / 校验失败 / 接口失败，全部弹窗与抽屉。截图放在 `docs/04-开发任务/assets/task-{编号}/`，文件名写明页面、分辨率和语言。
4. 改动了 `application.yml`、`deploy/` 或启动时的初始化逻辑的，按规范 12 第 6 节用预览实际启动验证：`TCRM_PREVIEW_PROJECT=tcrm-p{编号}` 等覆盖变量起一套独立预览（端口用任务分配的），验证后删除；**不要动负责人的 `tcrm-preview`**。

## 5. 交付

- 执行报告 `docs/04-开发任务/{编号}-{名称}-执行报告.md`：结论、版本与环境、主要改动、接口与表结构变更、各项检查命令与结果、复核表、浏览器验证截图清单、待 M0 验证、偏离与原因、遗留、收尾清理命令、PR 链接。
- 提交遵循 Conventional Commits（英文），推送分支，按 PR 模板创建 PR，PR 描述中贴出子代理的检查结果和复核表摘要。GitHub Actions 暂停中，不要等待 `gh pr checks`。
- **不要合并 PR，不要推送 `main`，不要修改 `docs/04-开发任务/README.md`（索引由架构负责人维护）。**

## 6. 停下来报告

- 进度表原文、任务提示词、设计说明书、规范之间存在冲突或歧义；
- 需要新增依赖、修改已合并的迁移、降低测试或覆盖率门槛；
- 合理排查后验证仍然失败。

完成后回复一段总结：PR 链接、主要改动、检查结果、复核表中非「满足」的条目、待 M0 验证、遗留。
