# 任务 38 执行报告：商品任务页

## 结论

管理端「商品管理 / 商品任务」（路由仍是 `/product/tasks`）可以按任务编号、目标渠道、状态查询复制任务，并在弹窗里核对新旧商品。复制流程补写目标渠道、任务级错误、完成时间和来源店铺；不改复制判断本身。

06.12、06.13、06.14 满足。06.11 部分满足：已经落库的任务可以按达人、目标渠道、目标店铺和新商品 ID 查询；令牌在确定目标店铺之前就失败时，仍然不建任务。`targetShopCode` 在店铺编码（任务 37）合并前固定为空。

## 主要改动

- 迁移 `V202610221100`、`V202610221101`：`crm_copy_job.target_channel`、`error_message`、`finish_time`，`crm_copy_job_item.source_shop_id`，以及列表、明细用的两个索引。已有终态行的完成时间用 `update_time` 回填；渠道按令牌回填，没有则写 `WEIDIAN`；来源店铺只在同一公司、未删除原商品恰好属于一个店铺时回填。

- `GET /admin-api/product/copy-jobs`、`GET /admin-api/product/copy-jobs/{id}/items`，权限 `product:view`。商务 `OWN` 只看自己负责的达人；越权或跨公司按 ID 访问返回 404。

## 接口与表结构

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/admin-api/product/copy-jobs` | `product:view` | `jobCode` 精确或前缀，`targetChannel`、`status`、`page`、`size`；`create_time DESC, id DESC` |
| GET | `/admin-api/product/copy-jobs/{id}/items` | `product:view` | 序号按明细 `id` 从 1 连续编号；新商品链接由后端拼 `https://weidian.com/item.html?itemID={新商品ID}` |

`targetShopCode` 有字段，值为 `null`。店铺表还没有 `shop_code`。列表里达人 ID、达人编号、达人名称、目标店铺编码、目标店铺名称默认隐藏。

任务状态：`processing` 处理中、`completed` 已完成、`partial_failed` 部分失败、`failed` 失败。明细：`pending` 待处理、`success` 成功、`failed` 失败。

本仓库控制器不写 OpenAPI 注解，springdoc 按映射生成。接口清单写在设计说明书机器可读目录里。未新增错误码，未改 `error-codes.ts`。未新增依赖。

索引：`idx_crm_copy_job_tenant_channel_status (tenant_id, target_channel, status, create_time DESC, id DESC)`，给带渠道或状态的列表用；不带这两个条件的列表仍走 `idx_crm_copy_job_tenant_time`。明细 `idx_crm_copy_job_item_job_id (job_id, id)`。两张表加列后的索引数仍在规范上限内。迁移在共享库首次启动本分支后端时已执行，脚本此后未再改，不需要修校验和。

## 偏离与原因

- 令牌无效、过期、额度用尽、达人停用，以及没有可落库的目标店铺时，不建任务。这些失败发生在插入之前，没有 `target_shop_id` 就不能满足表约束。
- 指定店铺在库中不存在时，返回给脚本的错误码和文案保持原来的「未配置默认复制店铺，且令牌未指定目标店铺」；任务行另写「指定的目标店铺不存在」。避免改动对外脚本已经在用的 `msg`。
- `targetShopCode` 恒为 `null`。不把微店店铺标识冒充店铺编码。
- 任务编号输入框 `maxlength="64"`，正常打字不会触发超长校验。去掉限制后提交 65 个字符，页面提示「提交的内容不符合要求，请检查后重试」。
- 不实现重试接口，设计说明书标明本任务不做。

## 遗留

- 多家店铺都有同一来源商品时，来源店铺留空。冲突失败不会把已经写下的来源店铺清掉。
- 映射落库失败会回滚该次工人更新；来源店铺仍以建任务时的唯一匹配为准。
- 语言切换展开隐藏列已修复，并用中英文复验截图确认。
