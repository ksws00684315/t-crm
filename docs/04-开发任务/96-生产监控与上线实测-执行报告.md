### 4.2 §2.2 300 MB 推广表实测（全部真实运行）

**样张生成**（脚本 `.tmp/verify/gen_sheet.py`，未提交）：结构按 ADR-024 描述的真实样例——单工作表 `ARCHIVE style`、第 2 行表头 `PHOTO / NAME / CW / PRICE (USD) / LINK`、E 列「LINK」单元格超链接指向 kakobuy 包装的微店商品 URL（shop 1856156775）、每 50 行一个重复商品、每 100 行一个分类行、每 200 行一个 `RETURN` 表内跳转行、每 500 行一个 Discord 外链；每行一张 92×92 随机像素 PNG（约 25.6 KB，可解码、CRC 正确），共 11,880 张。**12,000 行链接、文件 305,746,228 字节（291.6 MiB，低于 Nginx/Spring 的 300 MiB 上限）**，生成用时 4.9 秒。

**路径**：`https://upload.t96.localhost:19680`（生产模板的 `upload.` server：`client_max_body_size 300m`、`proxy_read_timeout 300s`）→ crm-admin（`mem_limit: 2g`）→ 预览 → `https://admin.t96.localhost:19680` 确认（确认接口在生产模板中只存在于 `admin.` 站点，`upload.` 站点对它返回 404，与前端 `promo-sheet.ts`「只有上传走 upload 子域」一致）。

| 测量项 | 结果 |
|---|---|
| 预览（上传 + 解析 + 分类） | HTTP 200，**5.82 s**（首跑未注册店铺时 8.77 s，冷缓存），上传 305,746,452 B，约 52.5 MB/s |
| 预览分类 | linkRows 11,880、duplicates 120、toAdd 11,760、skipCounts 空 |
| 确认写入 | HTTP 200，**11.36 s**，inserted 11,760；数据库 `crm_kol_item` 计数 11,760（UI 确认小样张后 11,800） |
| crm-admin 内存峰值 | cgroup `memory.peak` **997,249,024 B = 951 MiB，为 2 GiB 限制的 46.4%**；其中 JVM 基线（首启、未上传前）668 MiB，300 MB 处理自身贡献约 283 MiB；期间 `docker stats` 稳态约 700 MiB |
| OOM / 重启 | `OOMKilled=false`、`RestartCount=0`、容器持续 running/healthy |
| `proxy_read_timeout 300s` | 两个请求 5.8 s / 11.4 s，远低于阈值；无 502/504 |
| 发现的问题 | 无。未出现提示词 §6 的任何停下来报告情形 |

## 8. 偏离与原因

1. **验证替身（均已在正文标注）**：本机 arm64 与 macOS（GNU/BSD 双路径兼容，target 是 Linux）；`gpg` 经 `postgres:17.11` 容器执行（真实加密）；登录验证码在验证环境关闭（生产默认开启，生产模板未改）；浏览器经明文监听 19681 访问、文件选择器用页面内注入（§5）；容量告警用日志注入（§4.3 末）。
2. **`PGBACKREST_REPO1_S3_BUCKET` 从合并后的验证 Compose 中删除**：posix 仓库 + 空值会被 pgBackRest 拒绝（衔接说明中的同类问题）；生产模板未改。
3. **磁盘检查过滤伪挂载**：排除 macOS `/Library/Developer/...`，以及 Ubuntu snap 的 `/dev/loop*` 与 `/snap/`（只读 squashfs 常年 100%，否则会持续 CRITICAL）；Linux 上优先 `df -x squashfs`，单测用固定 Ubuntu `df` 样例覆盖。
4. **可观测性一行的「结构化日志（JSON）」改为「结构化日志」**：实际日志是 Spring Boot 控制台文本格式（仓库无 JSON encoder），原文与实现不符；ops-check 的解析按实测格式。这是设计文档与代码现状的对齐，不是行为变更。
5. **阈值可通过 `TCRM_OPS_*` 覆盖**：提示词 §4 要求「人为缩短阈值触发」，因此阈值设计为环境变量可覆盖，默认即生产值，`.env.example` 注释写明「只为测试设计」。
6. **确认接口在 `upload.` 站点 404 属生产模板设计**（只有上传放行在该站点），实测与前端实现互相印证，非缺陷。
7. **检查与复核由我本人直接执行**，没有再派发子代理（本任务派发时已是子代理）。

1. **告警与心跳的三个值**（`TCRM_ALERT_WEBHOOK_URL`、`TCRM_HEARTBEAT_URL`、`TCRM_OPS_STATE_DIR`）为空时脚本只打印告警：上线清单需把它们加入 `deploy/.env` 的必填核对项（飞书机器人地址、Healthchecks 类地址、主机目录）。
