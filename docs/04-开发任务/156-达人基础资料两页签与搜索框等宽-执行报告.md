## 4. 解读与排除项

- **只读态的展示方式**（负责人 2026-11-18 反馈修正）：基础资料与推广信息保存后再次打开，不把表单输入框置灰，而是按商品详情页的样式用 `el-descriptions` 展示标签和值，footer 只保留「关闭 / 编辑」；点「编辑」才切回原来的表单。基础资料在创建达人时已带姓名等数据，不存在可判定的「未填写」状态，因此非审核模式一律打开为详情视图；审核（PENDING）场景仍走可编辑表单，覆盖「首次填写」。
- **日期区间控件不纳入等宽**：`el-date-editor` 的 datetimerange（订单筛选约 360px、操作日志约 400px）是区间控件不是下拉框，压到 288px 会截断起止时间，本次未改。若负责人认为区间控件也要等宽，需另行确认可用宽度。
- **邀请人与两个商务账号是两层信息**（负责人 2026-11-18 澄清）：邀请人取当前负责商务名，由达人所属商务自动关联、只读；`bd_discord` / `bd_whatsapp` 按达人单独记录、手工填写，不由商务账号自动带出，同一个商务对不同达人可以使用不同账号。商务转移后邀请人显示新商务名，两个账号仍是该达人上的原值；若客户要求随转移改写，需要另行定义规则。
