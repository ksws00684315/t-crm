# 47 预付流程：2026-10-22 补充确认

本文件记录负责人在本对话中的新决定，覆盖原 47A／47B 提示词中与此冲突的申请字段阶段要求。后端已按负责人后续授权恢复并在独立 `task/47-prepay-backend` 分支实现；两端分别提交 PR，契约以本文件为准。

## 最新界面与流程

1. 达人列表／详情“预付金额”弹窗参考负责人提供的截图：上方达人名称和 ID 分两行；横排人民币申请金额；只读申请状态；底部右侧“取消／提交”。新申请为“待申请”，这是本地未提交状态，不新增服务端状态。不得伪造已审核或已支付。
2. 本次最终确认：入口不保留“是否从佣金抵扣”。入口唯一业务输入是必填 `amountCny`。不要求已有审核收款账户，不查询账户列表，不自动填写原因、期望日期、账户或抵扣默认值。
3. 负责人已确认其余信息在**财务结算 → 达人预付 → 待审核任务中补录，补齐后才能审核通过**。补录项目：明确选择是否佣金抵扣、申请原因、期望支付日期、该达人有效已审核收款账户；附件仍选填、总计最多 5 个。
4. 审核及支付权限保持独立。具有 review 或 pay 权限的公司账号可补录，只有 review 可通过／驳回。未补录的抵扣值为 null，不能默认为“不抵扣”；未补齐不能审批通过，可以驳回／按原规则撤回。终态及已审核任务不再开放申请资料补录。

## 前端请求与 47A 续做契约

- 申请仍走 `POST /admin-api/commission/prepays` multipart，JSON Blob `payload` 仅 `{requestId,kolId,amountCny}`，不含 attachments 或人为默认业务字段；保留 UUID 幂等重试。
- 待审核补录走 `PUT /admin-api/commission/prepays/{id}/application-details` multipart，JSON Blob `payload` 为 `{reason,expectedPayDate,payoutAccountId,deductFromCommission}`，重复 `attachments` 文件 part 为本次新增附件，原附件保留，总计不超过 5 个。保存返回最新管理端详情。
- 新建申请详情允许 `reason`、`expectedPayDate`、`payoutAccountSnapshot`、`deductFromCommission` 为 null；补录后返回选中 `payoutAccountId` 供编辑回填，普通快照仍脱敏。缺项前端不崩溃、不冒充 false。
- 已审账户选项接口应允许本公司 review／pay 账号读取该任务达人的选项，不再仅允许申请商务。必须服务端校验账户同达人、同公司、有效且已审，不按 PayPal／USDT 或币种过滤。
- 因账户改在财务补录，快照改在补录选定账户时创建，审核通过后冻结。完整快照仍只由 pay 权限受审计接口读取，不允许前端提交账号明文。
- 补录及审核都必须服务端校验待审核状态、当前权限与数据隔离；补录操作人／时间／变更写审计和轨迹。审批服务端再次检查补录完整性，不能只依赖前端禁用按钮。付款的 CNY、凭证、幂等、负钱包、FIFO 及达人支付后最小结果投影保持原要求。
