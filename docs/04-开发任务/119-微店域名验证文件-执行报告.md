# 119 微店开放平台域名验证文件：执行报告

- 分支：`task/119-weidian-domain-verify`
- 日期：2026-11-06
- 类型：生产上线阻塞缺陷修复（部署）

## 1. 问题

微店开放平台注册服务型应用时，保存「授权回调链接」会立即校验域名所有权：
平台 GET 的是**根域名**下的 `https://<域名>/weidian_open.json`，而不是回调所在
`admin.<域名>`。正式环境实测报：

```
从 https://sparktrackcrm.com 获取 weidian_open.json 失败
java.net.UnknownHostException: sparktrackcrm.com: 未知的名称或服务
```

两个原因：

1. Cloudflare 只解析了 `t.`、`kol.`、`admin.`、`upload.`，根域名没有 A 记录；
2. 即使解析，Nginx 也没有根域名的 server 块（未知 Host 走 `ssl_reject_handshake`），
   而验证文件此前被临时放在 `releases/<版本>/admin/` 下，下次发布会随软链切换丢失。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `deploy/nginx/templates/default.conf.template` | 新增根域名 server 块：仅提供 `location = /weidian_open.json`（`root /usr/share/nginx/sites`，即主机 `TCRM_STATIC_DIR` 根目录），其余路径 404；使用 Cloudflare 源站证书与 Authenticated Origin Pulls |
| `deploy/RUNBOOK.md` | 第 5 章第 2 条补根域名 A 记录（橙云）；新增第 9 条微店应用注册与验证文件放置步骤；第 16 章第 6 项补验证命令与期望 |
| `deploy/README.md` | 「生产部署」第 1 条补根域名记录、验证文件位置与证书说明 |
| `docs/04-开发任务/README.md` | 任务 119 索引行 |

验证文件放 `TCRM_STATIC_DIR` 根目录（生产为 `/var/lib/tcrm/www/weidian_open.json`），
不在 `releases/`、`current/` 内，发布切换软链不影响。

## 5. 偏离与遗留

- 验证文件内容由微店平台在保存回调链接后生成，不入库（每家公司、每次注册可能不同）。
- 部署时需同时：(1) 主机 `git` 切换到合并后的提交并重建 Nginx；(2) 把
  `weidian_open.json` 放到 `/var/lib/tcrm/www/`；(3) Cloudflare 添加 `@` A 记录（橙云）。
- 临时放在 `releases/0.1.1/admin/` 下的副本可以保留到下次发布自然消失，不影响验证。
