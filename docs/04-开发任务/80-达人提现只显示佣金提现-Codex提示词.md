## 1. 背景与负责人决定

「财务结算 → 达人提现」第一个页签「财务结算任务」调用 `finance-tasks` 时没有传类型，佣金提现和达人预付混在一张表里，申请类型一列会显示「达人预付」。负责人在其他机器造测试数据时发现这个问题，认为容易误解。

预付已经有独立的「财务结算 → 达人预付」页面，列表、详情、运营审核、财务审核、支付登记都在那里完成，4 类预付通知也跳到那里。

**负责人决定（2026-10-29，已确认）**：财务结算按申请类型分两页处理。「达人提现」只显示佣金提现；达人预付只在「达人预付」页处理。

## 3. 要求

### 3.1 「达人提现」页（`views/fund/withdrawal/index.vue`）

1. 列表查询固定传 `type: "COMMISSION"`。重置、移除筛选标签、翻页、刷新、预览角色切换之后都要保留这个参数。`type` 不放进 `filters`，不出现在筛选标签里。
2. 删除「申请类型」列（`type`）。剩余各列按规范 13 附录 A 重新核对列宽，表头不能换行，中英文都要核对。
3. 状态筛选只保留佣金提现的 5 种状态：`PENDING_REVIEW`、`PENDING_PAYMENT`、`PAID`、`REJECTED`、`WITHDRAWN`，与后端 `WITHDRAWAL_STATUSES` 一致。文案用 `finance.*`。
4. 删除页面里只为预付行服务的代码：
   - `prepayAction`；
   - `processLabel` 和 `actions` 里的 `PREPAY` 分支；
   - `openPrepay`、`statusLabel` 里的预付状态分支；
   - `PrepayDetailDrawer` 及其状态变量；
   - 删除后不再使用的 `getPrepay`、`prepayAbilities` 导入。

   佣金提现的查看、审核、付款登记、`?withdrawalId=` 通知跳转、导出，行为都不变。
5. 页签名称从「财务结算任务 / Finance tasks」改为「提现申请 / Withdrawal requests」。页签在 `views/fund/payout/index.vue`，用的是语言包键 `finance.tasks`，目前只有这一处在用，直接改 `locales/finance-zh-CN.ts`、`finance-en-US.ts` 里的值即可。动手前再全仓搜索确认一次，如果别处也在用，就新增键，不改原键。

### 3.2 不做

- 不改后端、接口、权限码、菜单结构和路由，不改「达人预付」页。
- 不改预付「从佣金抵扣」的记账（05.02），达人可提现金额的计算不变。
- 不改达人端。
- 不新增依赖。
