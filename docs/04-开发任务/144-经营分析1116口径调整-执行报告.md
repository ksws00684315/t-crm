## 同店商品链接合并

畅销榜按店铺和已识别的同款商品分组，汇总原链接和复制链接的销量、销售额及可归到商品的退款，并按支付订单去重。SPU ID 取本店原链接 ID。本店没有原链接时，取本店最早确认的关联链接，历史关联记录缺失时可以使用最早有原商品归属的支付记录。尚未识别关联的链接按各自的微店商品 ID 统计。

店铺抽屉的订单商品和成功退款保留原有的明细粒度，使用与排行一致的 SPU ID。商品筛选按同店商品分组应用，店铺成交 SPU 数对同店已关联链接去重。

验收通过 37 项后端测试（含 PostgreSQL 和架构检查）、14 项前端测试及前端生产构建。Edge 验证桌面和移动宽度的商品及退款明细 SPU 显示和悬停口径。PostgreSQL 回归覆盖三条同店链接合计、跨店各自的 SPU ID、同名未关联链接单列及商品筛选。

## 四页术语和达人身份核对

| 核对项 | 现状与统一建议 |
| --- | --- |
| 支付订单数、订单数 | 都是所选支付期间的去重已付款订单数。可统一为「订单数」，悬停说明支付范围。商品排行按分销成交统计，商品订单列表也纳入原链接直接成交和待确认归属，应明确分销榜与明细的范围。 |
| 客单价、平均订单价、商品净销售额 | 客单价与平均订单价都是销售额除以支付订单数。商品净销售额与同页净销售额是同一口径。件均价以销量为分母，独立保留。 |
| 销售额 | 店铺、达人及未筛商品的邀请人聚合使用订单实付，含运费。畅销商品、商品行使用商品行实付。邀请人按商品筛选时也改用匹配商品行。 |
| 退款金额 | 主榜、经营概览及成功退款明细按退款完结期。订单商品明细按同批支付商品行在支付日起 30 个北京时间自然日内完结的成功退款。明细可在确认后统一标作「同批退款金额」。 |
| 有效达人及关联达人 | 达人榜卡片的有效达人按所选期间曾有效统计。邀请人有效达人数取当前有效归属。商品关联达人数取当前有效商品绑定。分别标注时间点和关联对象。 |
| 结算金额 | 店铺按本店入账，达人和邀请人抽屉按可归属订单入账，商品级仍缺少可用流水。各处按范围显示计算和可用性。 |
| 达人总佣金 | 达人主卡和抽屉读取已核实商品行的计提佣金。但主卡说明写的是「未结算取预估、已结算取实际」，这与邀请人业绩的计算方式相符，主卡说明需要对齐实际算法。 |
| 达人名称与编号 | 在订单商品、成功退款及邀请人主榜最佳达人补充可复制的 CRM 达人编号。达人主榜、达人抽屉、商品达人贡献、邀请人抽屉达人排行均检查名称与编号。 |

验证通过 22 项相关后端测试及前端类型检查和生产构建。Edge 使用样例在 1600 和 390 px 验证四页的达人名与编号。
