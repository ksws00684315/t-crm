# 131 复制任务提交后再派发、自动登记商品带首图：执行报告

- 分支：`task/131-copy-job-commit-image`
- 日期：2026-11-08
- 类型：缺陷修复（后端，无迁移）

## 1. 背景

v0.1.6 发布后，负责人在正式环境实测复制商品，第一笔成功，又发现两个问题。

**问题一：复制任务一直「处理中」。** 负责人在正式环境现场查到的情况如下（只记 ID、计数与时间）：

- `crm_copy_job.id = 2119069735597068289`：`status = processing`，`total_count = 1`，`finish_time` 为空。创建于 2026-11-07 14:09:30Z（北京时间 22:09:30），到排查时已过约 2 小时。
- 对应明细 `crm_copy_job_item.id = 2119069735605456898`：`pending`，`update_time` 与创建时间在同一毫秒，`target_item_id` 和 `error_message` 都为空，说明从未被处理。
- nginx 日志：14:09:30Z `POST /admin-api/external/product-links/convert` 返回 200。
- crm-admin 日志：14:09:30Z 前后没有任何记录。`copy-job-*` 线程最后一次活动在 13:45:27Z，处理的是上一笔任务。没有异常栈。

**根因**：`ProductLinkService.convert` 是 `@Transactional` 方法，写入任务和明细后，在事务提交之前就调用了 `worker.submit(jobId)`。工作线程用另一条连接执行 `selectById(jobId)`，如果抢在提交前读，就读不到这一行。`processJob` 读到 `null` 直接返回，不写日志也不重试，任务于是一直停在 `processing`，直到服务重启时 `CopyJobWorker.run` 续跑。这种情况只在线程抢在提交前读取时出现，所以时有时无。这种写法从任务 17b 起就有。

**问题二：系统里的商品图片不显示。** 源商品还没在系统里登记时，复制任务会先用 `vdian.item.get` 查出它，再自动登记（`CopyJobWorker.ensureProduct`）。登记时只写了名称和价格，没写图片，所以 `crm_product.image_url` 为空。另外，微店文档样例中 `imgs` 的地址都是 `http://`，而商品图片规则只接受 https（`ProductRules.isHttpsUrl`）。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `backend/.../product/service/ProductLinkService.java` | `convert` 改用 `submitAfterCommit`，在事务提交后再把任务交给工作线程；没有活动事务时立即提交 |
| `backend/.../product/api/WeidianItemCopyApi.java` | `ProbedItem` 增加 `imageUrl`，取商品第一张图片的 https 地址，没有图片时为 null |
| `backend/.../integration/service/WeidianItemCopyService.java` | `probe` 取 `imgs` 的第一张，`http://` 改为 `https://` |
| `backend/.../product/service/CopyJobWorker.java` | 自动登记源商品时写入 `image_url`，不符合商品图片规则（https、长度不超过 512）的不写 |
| 测试 | `ProductLinkServiceTest.shouldSubmitWorker_onlyAfterCommit_whenTransactionActive`（复现：旧代码在提交前就派发，用例失败）；`WeidianItemCopyServiceTest` 新增两条（多张图取第一张并转为 https；没有图片时为 null）；`CopyJobWorkerTest` 的登记用例断言写入了图片；`ProductLinkIT` 跟随记录增加字段 |

## 3. 影响范围

| 对象 | 影响 |
|---|---|
| 新建复制任务 | 一定在任务写入数据库后才开始执行，不会再卡住不动 |
| 已卡住的任务 2119069735597068289 | 服务启动时会续跑所有 `processing` 任务，发布本版本时 crm-admin 重启，该任务会自动接着执行，无需手工处理 |
| 首次复制、自动登记的源商品 | 带上第一张商品图片 |
| 已经登记、但没有图片的商品 | **不会自动补图**。可以在管理端编辑商品补填图片，或另开任务回填（见第 6 节） |
| 接口、表结构 | 不变，无迁移 |

## 6. 偏离与遗留

- **已有商品不回填图片**：本任务只改新登记的商品。若要给已登记、无图片的商品补图，需要另开任务（例如复制时发现图片为空就补写），由负责人决定。
- **同类写法**：`KolCleanupItemService`（第 80、117 行）也是在调用方事务内直接 `worker.submit`。若调用方在事务中，可能有同样的竞态。本任务未改，留待确认。
- **图片地址未用真实数据核对**：`imgs` 为字符串数组是依据微店文档样例。代码同时兼容 `{url}` 对象数组，发版后以实测为准。
