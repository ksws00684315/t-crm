## 主要改动

- 扩展店铺数据模型和分页接口：系统生成店铺编码，维护渠道、商品容量、源店铺与复制池状态；迁移旧 `copy_target` 数据后删除旧列。
- 合并授权和商品、订单、退款接口探测状态到店铺行；提供源店铺、复制池、容量刷新、接口检查动作。
- 按可用资格和剩余容量计算复制池容量；令牌可指定店铺或渠道，复制任务自动选剩余容量最大的店铺，并通过行锁与并发测试避免超卖。
- 复制成功后递增商品数；订单同步支持只拉订单、只拉退款，省略类型时保持两者都拉。
- 更新设计说明书并新增 ADR-031。

## 契约变更

- 店铺列表改为分页 `{items,total,page,size}`，增加店铺编码、渠道、源店标记、复制池、容量、授权状态、三类接口状态与复制资格字段。
- 新增 `GET /admin-api/product/shops/options`：本公司全部店铺下拉（`id`、`shopCode`、`shopName`、`channel`、`status`；按 `shopCode` 排序；`product:view`），供选择器使用，避免分页接口 `size=100` 截断。
- 新增源店铺、复制池、容量刷新、接口检查动作及复制渠道容量查询接口；移除旧 `copy-target` 动作。
- 令牌创建增加必填 `targetChannel`；令牌列表增加 `targetShopCode` 和 `targetShopName`（自动分配前为 null）。
- 订单同步请求增加可选 `type`（`ORDER` / `REFUND`）。
- 新增错误码 `SHOP_COPY_CAPACITY_EXCEEDED`、`COPY_SHOP_CAPACITY_INSUFFICIENT`。并行前端需同步语言包映射。
- 已在执行报告登记接口契约变化，架构决策记录见 ADR-031；需在 PR 描述中再次显式列出，供架构负责人审阅。

## 偏离、遗留与风险

- 编辑店铺允许将 `maxItems` 调到低于 `currentItems`：剩余容量按 0 处理，不拒绝保存（架构审查建议维持现状）。
- `allocateCopyTarget` 对候选店铺按 `id` 升序加锁，避免死锁。
- ADR 编号：自动复制池决策为 **ADR-031**（main 上 ADR-029 已用于表格行操作；共性规范变更占用 ADR-030）。

- 并发容量 IT 曾发现锁后容量查询命中 MyBatis SqlSession 的本地缓存，导致并发分配复用锁前的预留数。`ShopMapper.countReservedItems` 增加 `flushCache = TRUE` 后，第二个事务会重新查询待处理复制项；并发 IT 稳定通过。
- 已补齐专项回归：HTTP 模拟服务器验证容量刷新成功/失败保留快照及三接口分别失败互不影响；参数化测试验证六种复制资格原因；旧数据两阶段迁移 IT 验证 `copy_target` 回填和公司内编码；并发建店断言编码唯一、跨公司独立编号；令牌 IT 验证源店联动、配额超限、最大容量店选择与不拆分、并发预留只成功一份。
- 并行前端负责页面浏览器验收和新增错误码语言包映射，需在两分支联调时确认。
- 开发时一次早期补丁误写到主目录 `OrderSyncRequest.java`。架构负责人已核对为早期稿、存档并恢复主目录。恢复任务后仅核对指定工作树：新版请求包含 `shopId` 校验和可选 `ORDER` / `REFUND`，Controller → Coordinator → OrderSync 调用链与分流测试完整；后续子代理指令均明确工作目录、先 `cd` 及禁止写主目录。
