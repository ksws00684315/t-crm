# 订单链路调整验收记录

分支 `codex/production-adjustments-1121`。在本地预览使用独立示例数据验收。

| 需求 | 实现与验收 |
| --- | --- |
| 优先展示全链路 | 各节点直接展示，商品创建任务节点支持复制任务编码，成交订单节点展示订单号，佣金与提现节点按状态写明申请笔数。 |
| 商品明细直接显示全部字段 | 前三列为商品图、商品名/SKU、新商品ID/原商品ID，商品 ID 前标明新旧，状态列左对齐。缺少原商品映射显示「—」。 |
| 合并资金变动 | 「资金变动」在同一张表展示货款、佣金。资金类型用胶囊区分，方向为普通文字，正金额绿色、负金额红色。共用结算/付款时间、结算单号/提现单号两列。 |
| 微店订单结算 | 沿用微店订单结算接口的定时同步，按店铺和订单号读取金额及结算时间。当前文档的返回结构没有独立结算单号，缺失时显示「—」。结算金额下方移除「已入账」。 |
| 达人佣金提现 | 按申请合并本订单各商品行的关联金额。进行中的申请状态统一为「提现中」，已付款的为「已提现」。点击提现编号打开详情。 |

微店结算字段以开放平台的订单结算明细为准。支付钱包的收支明细为账户视角，当前文档同样未给出可关联订单的结算单号。[微店订单结算接口](https://open.weidian.com/#/api/10652)

Edge 在 1600、1280、390 像素宽度验证了版面、商品列、已入账与待结算示例、已支付与待支付提现，以及提现详情跳转。示例订单为 991121000001，其中微店货款收入 ¥150.00、退款扣减 ¥20.00，达人已支付的本订单关联金额为 ¥10.00。

前端 36 项和后端 75 项相关测试通过。前端类型检查及构建通过，后端 Spotless 检查与预览镜像构建通过。

## PR #300 审查整改

| 审查项 | 整改与复核 |
| --- | --- |
| 金额单位 | 订单详情和全链路读取微店流水已换算的 `amount_cny`。集成用例模拟微店实付 ¥6.00、货款原值 600 分、标准金额 ¥6.00，并断言两个接口均为 ¥6.00。预览库现有四条流水的 `amount_cny` 均为空，正式环境真实已核实订单的三字段比对待补。 |
| 结算条件 | 恰好一笔货款收入且所有参与计算的货款、退款金额齐全，才汇总结算金额。已有货款或退款流水但无法汇总时，节点显示「待核实」。 |
| 部分退款 | 处理中展示估算的剩余冻结佣金，成功后根据实际扣减和释放结果显示余额。既有提现占用优先判断，已付提现和进行中申请保留各自信息。 |
| 流水发生时间 | 微店退款和佣金支出显示交易发生时间，结算单和提现单沿用相应结算或付款时间。 |
| 下单时间范围 | 查询可不传日期。传日期时必须同时传入起止端点，区间大于零且最多 30 天。 |
| 商品任务索引 | 新建 `idx_crm_copy_job_item_tenant_target`，支持 `tenant_id` 和 `target_item_id` 等值查询。索引并发创建，迁移在事务外执行，Flyway 使用会话级锁。[Flyway PostgreSQL 锁设置](https://documentation.red-gate.com/flyway/reference/configuration/flyway-namespace/flyway-postgresql-namespace/flyway-postgresql-transactional-lock-setting) |
| 上一版 CI 回归 | 补登记 Token 关联任务接口。订单检索测试覆盖下单时间优先于支付时间。订单链路测试覆盖新增的应收和扣减流水，并继续核对既有佣金台账与提现金额。 |

统一预览已通过健康检查。Edge 验证退款处理中和部分退款成功的订单链路。预览库只读查询确认迁移执行成功、索引有效，并用 `EXPLAIN` 验证按租户和目标商品 ID 检索可走 `Index Only Scan`。后端新增不同费率商品的部分退款用例，核对扣减归属和剩余已释放佣金。
