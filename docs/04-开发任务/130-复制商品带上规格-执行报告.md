# 130 复制商品带上规格：执行报告

- 分支：`task/130-copy-item-sku-attrs`
- 日期：2026-11-07
- 类型：缺陷修复（后端，无迁移）

## 1. 背景

微店重新接入后跑 M0 真实验证。v0.1.4（任务 127）发布后，最新一次复制仍然失败。正式环境日志
（2026-11-07T12:52:28Z）：

- `vdian.item.add`（1.5）返回 `200056`，`status_reason` 为「SKU标题不能为空」。任务 128 起日志会带上这个原因。
- 请求参数中 `attrList`、`createTempAttr` 都是 `null`。十余个 SKU 只带了 `price` 和 `stock`，`attrIds` 是 `null`。

根据微店官方文档：

| 接口 | 规格相关字段 |
|---|---|
| `vdian.item.get`（源商品） | 商品级 `attrList[{attrTitle, attrValues[{attrId, attrValue}]}]`；SKU 有 `title`（如 `L ; 蓝色`）和 `attr_ids`（用 `-` 连接的字符串，如 `764651-764647`） |
| `vdian.item.add` 1.5（目标店新增） | SKU **没有** title 字段，规格名由商品级 `attrList` 加 SKU 的 `attrIds` 生成。商品有 SKU 时 `attrList` 必传。`createTempAttr=true` 时规格 ID 可以自定义，否则须是店内已有的规格 |

复制时没有带源商品的规格，微店生成不了 SKU 标题，所以报错。**任务 127 的根因判断有误**：200056
是通用参数错误码，当时没有拿到 `status_reason`，就认定成了「商家编码重复」。不传商家编码这个改动本身
无害，予以保留。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `backend/.../integration/service/WeidianItemCopyService.java` | `buildAdd()` 读源商品的 `attrList`，原样作为 `attrList` 传入，规格 ID 和规格值不变。有规格时 `createTempAttr=true`，因为源规格 ID 属于源店铺，目标店不一定有。`skus()` 把 SKU 的 `attr_ids` 拆成数字列表，填进 `attrIds`。无规格的商品照旧不传这两个字段 |
| `backend/.../integration/api/WeidianBusinessApi.java` | `ItemSku.attrIds` 的类型由 `List<List<Long>>` 改为 `List<Long>`，与官方请求示例 `"attrIds":[452521,460520]` 一致 |
| `backend/.../integration/service/WeidianItemCopyServiceTest.java` | 新增两条用例。`shouldSendSourceAttributes_whenItemHasSkus`：样例按官方文档结构构造，断言 `attrList`、`createTempAttr`、SKU `attrIds` 都传了。`shouldSendNoAttributes_whenItemHasNoSkus`：无规格商品三者都为 `null` |
| `docs/04-开发任务/127-复制商品不传商家编码-执行报告.md` | 第 6 节补一条更正：真实原因见本任务 |

## 6. 偏离与遗留

- **源商品结构依据官方文档**：代码调用的是 `vdian.item.get` 1.1，文档页面是 1.0 的。正式环境日志没有记录
  item.get 的原始返回，所以字段名（`attrList`、`attr_ids`）没能用真实数据核对，要靠发版后的实测确认。
- **SKU 成本价字段名疑似不符（未处理）**：文档中 SKU 级成本价叫 `cost_price`，代码读的是 `costPrice`，
  所以 SKU 成本价复制不过去。这不影响新增成功，不在本任务范围内。
- **规格图片**：源 SKU 的 `img` 没有映射到规格值的 `img`，复制后规格不带图。
