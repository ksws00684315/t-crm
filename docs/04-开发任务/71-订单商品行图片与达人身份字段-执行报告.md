## 9. 偏离与原因

- **主目录误启动**：首次启动联调后端时工作目录落在主仓库 `backend/`（`mvn spring-boot:run` 因此在主目录编译并写入了其 `backend/target/` 构建产物；主目录受控文件无任何改动，已核对 `git status`）。发现后已停止该进程并改用工作树绝对路径重启，接口验证以工作树代码为准。违反了规范 08 §9.1「不得在主目录执行构建等写文件命令」，在此如实记录。
- 占位文案由「开发中/await API support」改为「暂无图片/No image」：图片接口已实现，缺图不再是未完成状态，继续显示「开发中」会与规范 11 §9「未实现才显示开发中」冲突。
- 提现通知（`WITHDRAWAL_*`）后端已写入 `kolName`，但管理端前端尚未支持这四类消息的渲染（无语言键、图标映射，任务 63 的遗留缺口，与本任务无关）；本任务的 `NotificationText` 组件机制对其向前兼容，后续任务补齐类型即可复用。
- 复核子代理指出 `ProductAccessService` 类注释称「软删商品仍可见」与实际行为（`@TableLogic` 过滤）不符——系任务 40 遗留的注释出入，按 AGENTS.md 规则只记录不顺手改。
