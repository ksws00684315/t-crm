# 141 复制任务明细上限放宽：执行报告

- 分支：`task/141-copy-job-total-constraint`
- 日期：2026-11-09
- 类型：缺陷修复（数据库迁移，无业务代码改动）

## 1. 背景

正式环境 2026-11-09：

- 06:03:46 负责人在管理端把系统配置 `product-links.max-convert-items` 由默认 500 改为 5000（任务 138 引入）。
- 06:35:18 表格插件提交 1713 个商品的转换请求（`POST /admin-api/external/product-links/convert`），接口返回 500，运维告警记录：

  ```
  DataIntegrityViolationException:
  ERROR: new row for relation "crm_copy_job" violates check constraint "ck_crm_copy_job_total"
  Failing row contains (..., processing, 1713, 0, 0, ...)
  ```

**根因**：任务 138 只放宽了应用层（请求体 `@Size(max = 5000)` 与系统配置），`V202610181401__create_copy_job.sql` 里的表约束仍是 `CHECK (total_count <= 500)`，且没有配套迁移。应用接受了请求，插入 `crm_copy_job` 时被数据库拒绝，任务无法创建。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `backend/src/main/resources/db/migration/V202611091500__relax_copy_job_total_check.sql` | 新增迁移：删除并重建 `ck_crm_copy_job_total`，上限由 500 放宽到 5000；同步更新 `crm_copy_job.total_count` 列注释 |
| `backend/src/test/java/com/tcrm/admin/product/ProductLinkIT.java` | 新增 `shouldAllowCopyJobTotal_upToTheConfiguredMaximum`：插入 `total_count = 1500` 的任务成功，`5001` 仍被约束拒绝 |

上限 5000 与 `SystemConfigDefinition.PRODUCT_LINKS_MAX_CONVERT_ITEMS` 的允许最大值一致（1～5000）。配置值保持 5000 不变；以后调整配置范围时，需要同步调整该约束。

已合并的 `V202610181401` 未修改。

## 6. 偏离与遗留

- **回滚**：回滚到更早版本不会自动恢复 500 上限（数据库不回滚），旧版本在新库上仍可正常运行，只是不再受 500 限制。
- **大批量任务**：放宽后单任务可达 5000 条，复制逐条执行、耗时较长；worker 队列默认 200，超出部分由提交线程执行（`CallerRunsPolicy`）。是否调整队列属于容量问题，未在本任务处理。
- **任务索引**：`docs/04-开发任务/README.md` 由项目负责人维护，本任务未修改该文件，需要负责人登记 141。
