# 133 前端 CSP 放行外部商品图片：执行报告

- 分支：`task/133-csp-product-images`
- 日期：2026-11-08
- 类型：缺陷修复（部署配置，无迁移，无代码改动）

## 1. 背景

v0.1.8 发布后，负责人重新提交复制，商品上传成功，但系统里商品图片仍然不显示。

任务 131 已在自动登记源商品时保存首图（http 转 https）。这次排查转向前端展示：

- 管理端「达人商品」列表、详情抽屉，订单、退款、提现明细里的商品图，都用 `<el-image :src="imageUrl">` 直接加载 `crm_product.image_url`。
- 商品图片都是外部 https 地址：微店图床，或者负责人手工填写的地址。系统没有自己的图片上传与存储。
- 正式管理端 `https://admin.sparktrackcrm.com/` 的响应头（2026-11-08 用 `curl -I` 读取）：

  ```
  content-security-policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; ...
  ```

**根因**：`deploy/nginx/snippets/security-headers-web.conf` 里两个前端的 CSP 只允许 `img-src 'self' data:`，浏览器会拒绝加载所有外部图片。所以不管 `image_url` 有没有值，图片都显示不出来。

这个问题在 2026-10-27 交付就绪审查中已登记为 D5（「生产 CSP 拦截外部图片」），之后一直没有修复。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `deploy/nginx/snippets/security-headers-web.conf` | `img-src 'self' data:` 改为 `img-src 'self' data: https:`，并加一行注释说明原因 |

放宽范围由负责人选定（2026-11-08）：允许所有 https 图片。这与商品规则「图片须为 https 地址」（`ProductRules.isHttpsUrl`）一致，手工填写的任何 https 图片都能显示。没有只放行微店图床域名，因为那样会拦掉手工填写的其他域名。

规范 06 只要求两个前端设置 CSP，没有限定 `img-src` 的取值。其他指令不变：`script-src` 仍然只允许 `'self'`，`connect-src` 仍然只允许 `'self'`。图片指令放宽不会让外部脚本执行，也不会让页面向外部发请求读取数据。

管理端和达人端共用这个片段，所以两端同时生效。

## 3. 影响范围

| 对象 | 影响 |
|---|---|
| 管理端、达人端的商品图、订单行图、提现占用快照图 | 外部 https 图片可以显示 |
| http 图片 | 仍被拦截（商品规则本来就只接受 https） |
| 其他 CSP 指令、其他响应头 | 不变 |
| 后端、数据库 | 不变 |

## 4. 验证

| 验证项 | 方式 | 结果 |
|---|---|---|
| 正式环境现状 | `curl -I https://admin.sparktrackcrm.com/` | 返回 `img-src 'self' data:`，确认根因 |
| preview 响应头 | `preview.sh up`（项目 `tcrm-p133`，端口 8990～8992，子网 `TCRM_PREVIEW_SUBNET=172.30.133.0/24`，避开常驻 `tcrm-preview` 的默认子网），`curl -I` 管理端 8990、达人端 8991 | 两端都返回 `img-src 'self' data: https:` |
| 浏览器对比 | 内置浏览器分别在 8990（本分支）和 8890（负责人常驻的 `tcrm-preview`，旧配置）的页面里加载同一张外部 https 图片 | 8990 加载成功、无 CSP 违规；8890 加载失败，触发 `img-src` 违规事件 |
| 微店图床 | 在 8990 页面加载 `si.geilicdn.com` 上的两张真实图片（取自微店公开商品页），请求带 localhost 来源域名 | 都加载成功（96 与 550 像素宽），未见防盗链拦截 |
| 正式环境 | 2026-11-08 发布 v0.1.9，部署后执行 `nginx -t` 与 `nginx -s reload`；`curl -I` 管理端与达人端，只读查询 `crm_product.image_url` 并从服务器请求图片外链 | 两端 CSP 均为 `img-src 'self' data: https:`；`image_url` 有 2 条，均为 `https://si.geilicdn.com/...png`，请求返回 `200 image/png`（591 KB、156 KB） |

## 6. 偏离与遗留

- **正式库 `image_url`**：已于 2026-11-08 发版时只读核对，`crm_product` 有 2 条非空 `image_url`，都是 `https://si.geilicdn.com/...png`，长度在 512 以内；从服务器直接请求返回 `200 image/png`。
- **Nginx 配置变更需手动重载**：`release.sh` 按设计不重启、也不重载 Nginx，`git checkout` 只改宿主机上的配置片段，因此本次发版在执行 `release.sh deploy 0.1.9` 之后，又执行了 `docker compose -f docker-compose.prod.yml exec -T nginx nginx -t` 和 `nginx -s reload`，新 CSP 才在正式环境生效（reload 为平滑重载，容器未重启，无 `emerg`/`alert` 日志）。这条已补充到 `deploy/README.md`「发布与回滚」的前提与限制和步骤 6，回滚到旧版本时同样要重载。
- **微店图床防盗链**：用 `si.geilicdn.com` 的真实图片在 localhost 来源下验证可以加载。商品图片如果来自其他微店图片域名，没有逐一验证。
- **preview 默认子网冲突**：`docker-compose.preview.yml` 默认固定子网 `172.30.0.0/24`。常驻 `tcrm-preview` 运行时，另起一套 preview 不设 `TCRM_PREVIEW_SUBNET` 会报「Pool overlaps」。本任务通过设置该变量绕过，没有修改脚本。
- **交付就绪审查 D5**：本任务修复。
