## 4. 对应关系查询 EXPLAIN

### 4.1 验证机实测（审查，约 194 万行，`ANALYZE` 后）

| 查询 | 计划 | 耗时 |
|---|---|---|
| 默认列表（当前有效） | `idx_crm_kol_item_current` | 0.19 ms |
| 按达人 + 当前有效 | `idx_crm_kol_item_kol` | 0.05 ms |
| 按原商品（含历史） | `idx_crm_kol_item_product` | 0.02 ms |
| 店铺 + 专属商品 ID | `idx_crm_kol_item_shop_item_from`（旧列序） | 0.04 ms |
| 只按店铺 + 当前有效 | `idx_crm_kol_item_current` | 0.03 ms |
| 达人 + 原商品（含历史） | `idx_crm_kol_item_product` | 0.04 ms |
| **只按专属商品 ID**（旧） | Parallel Seq Scan | 32 ms |
| 分页总数：当前有效全部 / 按店铺 | Parallel Seq Scan | 57 ms / 84 ms |
| 分页总数：按达人 | `uk_crm_kol_item_kol_product`（Bitmap） | 14 ms |

接口端到端（3 次最快）：`/product/kol-items` 默认 36 ms；按达人 7 ms；按原商品 6 ms；只按专属商品 ID 64 ms；按店铺 37 ms；第 5000 页 64 ms。`/product/products` 默认 7 ms；关键字 30 ms；分类 5 ms。

> 旧索引下列「只按专属商品 ID」走 seq scan 的偏离**已撤回**；改为索引列重排 + 强制精确条件。验证机将在约 **1,000 万行**复核。

### 4.2 索引重排后合成数据 EXPLAIN（本机 PostgreSQL 17，约 22 万行）

环境：无 Docker；本机 `postgresql-17` 库 `tcrm_explain`；`crm_kol_item` 220,000 行（当前有效 200,000）。原文见 `docs/04-开发任务/explain-task05/explain-after-index-reorder.txt`（归档副本 `/workspace/reports/tcrm-pr22-explain-after-index-reorder.txt`）。

| 查询 | 使用的索引 | 执行时间（本机） |
|---|---|---|
| 按达人 + 当前有效 | `idx_crm_kol_item_kol` | ~0.51 ms |
| 按原商品 + 当前有效 | `idx_crm_kol_item_product` | ~0.17 ms |
| 只按专属商品 ID | `idx_crm_kol_item_item_shop_from` | ~0.15 ms |
| 专属商品 ID + 店铺 | `idx_crm_kol_item_item_shop_from` | ~0.24 ms |
| COUNT 按达人 + 当前 | `uk_crm_kol_item_kol_product`（Bitmap） | ~0.32 ms |
| COUNT 按专属商品 ID | `idx_crm_kol_item_item_shop_from`（Index Only） | ~0.03 ms |
| 历史：专属商品 + 店铺 + valid_from | `idx_crm_kol_item_item_shop_from` | ~0.03 ms |

修改后的管理端查询类均能走索引；分页总数规模受精确条件约束（单达人最多约 2 万原商品量级）。
