- 接口依据：[25a 提示词第 5 节](25a-达人编号与推广状态-后端-Codex提示词.md)（25a 已合并进 `main`；接手上号后用真实后端重做了浏览器验证，见 §3.4）

## 1. 页面与交互

### 1.1 达人编号（§3.1）

- `utils/kol-validation.ts` 新增 `KOL_CODE_PATTERN = /^KOL-[A-Z]{3}[0-9]{3,8}$/` 与 `validateKolCode`、`looksLikeKolCode`；示例占位文字改为 `KOL-ASD001`（`bdTransfer.kolCodePlaceholder`、认领对话框占位）。
- 编号由系统生成、创建后不可改，前端原本没有编号录入项；本轮用到编号输入的新场景只有「认领达人」，已按新正则校验（大小写不敏感输入，提交前统一转大写）。达人端没有编号输入场景（只在「我的账户」展示），无代码改动点。
- 既有测试夹具中的旧格式编号（`KOL0001`）已改为新格式。

### 1.2 达人列表（§3.2，`views/kol/index.vue`）

- 新增「状态」列，显示 `displayStatus` 五种状态，五种颜色互不相同（`utils/promotion.ts` 的 `promotionTagType`：待审核 warning、待推广 primary、推广中 success、合作结束 info、待更新 danger）；原启用/停用列更名为「启用状态」，避免两列同名。25a 未返回该字段时显示「-」。
- 「更多筛选」中新增状态筛选（参数 `displayStatus`，五种值），与既有筛选一样走 chips 展示与移除。
- **点击状态跳转**：
  - 待审核 → 打开审核界面（复用编辑对话框的 review 模式）；
  - 待推广 → 打开推广配置抽屉；
  - 推广中 / 合作结束 → 打开达人详情抽屉（详情含推广状态、落地页；有 `kol:edit` 权限时提供「推广配置」按钮，从详情再进配置——见 §2 偏离 3）；
  - 待更新 → 超级管理员打开转移商务对话框（`{kolIds:[id]}`）；其他角色（商务）弹出说明文案 `kol.pendingUpdateHint`。
- 行操作「修改状态」（`kol:edit` 可见）：`PromotionStatusDialog` 选择目标状态（四种存储状态）→ 确认 → `PUT /kol/kols/{id}/promotion-status`；422 `KOL_PROMOTION_CONFIG_INCOMPLETE` 时在对话框内展示缺少的配置项，并提供「去填写」按钮打开**当前达人**的推广配置抽屉。
- 工具栏「认领达人」仅对可用商务显示（前端判定：启用、`STAFF`、`OWN`、有 `kol:edit`，与后端 `BdUserApi` 一致）；「清理配置」仅对数据范围「全部」且有 `kol:edit` 的账号显示（超级管理员或 `STAFF + ALL + kol:edit`）。

### 1.3 审核界面（§3.3，`KolFormDialog.vue` review 模式）

- 新增 `review` prop：标题变为「审核达人 {code}」；达人编号、邮箱只读展示；其他资料可编辑；底部新增「审核通过」。
- 「审核通过」两步执行：保存资料（`PUT /kol/kols/{id}`）→ 改状态为待推广（`PUT …/promotion-status`，`PENDING_PROMOTION`）。第一步失败提示「资料保存失败，状态未修改」并保留对话框与字段错误；第二步失败提示「资料已保存，但修改状态失败」。两步都成功才关闭并刷新列表。
- 普通「保存」按钮在审核模式下保留，可只存资料不改状态。

### 1.4 推广配置界面（§3.4，`PromotionConfigDrawer.vue`）

- 抽屉标题「推广配置 - {code}（{name}）」；字段：佣金比例（百分比输入，沿用 `percentToRate`/`rateToPercent` 与小数存储）、代购平台多选（选项为本公司**已启用**模板）、落地页地址（https、≤512，前端校验）、邀请码、推广表格地址（选填，沿用 Google 表格正则）、本次修改备注（选填，≤255）。
- 「保存」：`PUT /kol/kols/{id}/promotion-config`，成功后刷新配置与修改记录（抽屉保持打开，便于核对新增记录）。
- 「保存并开始推广」：先做客户端完整性预检（佣金比例、至少一个平台、落地页、邀请码，规则镜像 25a §4.2）→ 保存配置 → `PUT …/promotion-status {status:"PROMOTING"}`；后端 422 时在抽屉顶部展示缺少项（从 `data.missingFields` 等多种可能的负载形态解析，解析失败则显示通用文案），抽屉保持打开。
- 下方「修改记录」：`GET …/promotion-records` 分页（10/页），列：时间、操作人、类型（配置/状态）、改动内容、备注。改动内容由 `promotionFieldDiffs` 计算：对 `before/after` 逐字段比较，输出「字段：旧值 → 新值」（佣金比例格式化为百分比、平台列表渲染为模板名、状态渲染为状态文案；未知字段原样展示）。后端快照里的状态键是 `promotionStatus`，计算时归一为 `status` 再套标签与翻译（见 §3.4 修复 1）。

### 1.5 清理配置（§3.5，`CleanupConfigDialog.vue`）

- 入口：达人管理页右上角「清理配置」（数据范围「全部」且有 `kol:edit`）。
- 内容：启用开关、未出单天数（`el-input-number`，7–365 整数，组件钳制 + 代码双重校验）、说明文案（逻辑删除、商品对应关系一并结束、订单与佣金历史保留、不调用微店接口）。
- 「预览」调用 `GET /kol/cleanup-preview` 分页展示下次将被清理的达人（编号、姓名、负责商务、最近订单时间、起算时间）。预览按已保存配置执行（接口无参数，见 §2 偏离 4）。

### 1.6 达人端（§3.6）

- 注册页：WhatsApp 必填——现有实现中空值会被格式校验拒绝（`/^\+[0-9]{8,15}$/`），本轮补充了回归测试固定该行为；未改校验逻辑本身。
- 收款账户：PayPal 新增币种下拉（USD/EUR/GBP/CNY，默认 USD，必选），创建与重新提交均携带 `currency`；USDT 不变。卡片头部类型行显示「PayPal · USD」。管理端收款账户审核详情新增「币种」行（仅 PayPal 显示）。

### 1.7 语言包（§3.7）

- 新增键全部中英文成对（`kol.promotionStatusOption.*`、`promotion.*`、`cleanup.*`、错误码 `KOL_PROMOTION_CONFIG_INCOMPLETE`、`KOL_ALREADY_CLAIMED`、校验文案、`payout.currency`、达人端 `payoutAccounts.form.currency*`）。
- 英文沿用 Creator 术语。既有英文 KOL 用语测试按任务「编号示例除外」的例外放宽了一处：先剥离 `KOL-[A-Z]{3}\d{3,8}` 字面样例再检查 `\bKOLs?\b`（新编号格式含连字符，`KOL-ASD001` 会被单词边界命中）；其余文案仍零容忍。

## 2. 偏离与设计取舍

1. **列表筛选参数名**：25a §5 只约定了列表行新增字段，未约定筛选参数名。前端使用 `displayStatus`（含 `PENDING_UPDATE`，与列上显示一致）。已登记在 PR 描述，25a 合并前需与后端对齐。
2. **422 负载形态**：约定未定义缺项字段的具体结构。`missingPromotionFields` 兼容 `["f"]`、`{missingFields:[…]}`、`{fields:[…]}`、`[{field:"f"}]`，解析不出来时显示通用文案 + 仍提供「去填写」。25a 定稿后如形态不同需回头适配（测试已覆盖解析函数，改动成本小）。
3. **推广中/合作结束的配置入口**：任务只说这两种状态点击状态打开「达人详情的推广数据」。现有详情抽屉没有订单/链接标签页（链接在独立的「链接」抽屉），为满足 ADR-023「推广配置之后可改」，在详情抽屉的推广状态行增加了「推广配置」按钮（`kol:edit` 可见）。
4. **清理预览的口径**：接口无参数，预览按**已保存**配置计算；未保存的天数修改不影响预览结果。界面文案已注明「按已保存的配置」。
5. **英文 KOL 用语测试**：如 §1.7 所述按任务明示的例外调整了样例剥离逻辑，检查强度不降低。
6. **error-codes 测试的 pending 白名单**：两个新错误码的前端文案先行（25a 并行开发），沿用该测试既有的 pending 机制登记，25a 合并后白名单自动收敛。

**本轮修复的问题**（只改 `admin-ui/`）
