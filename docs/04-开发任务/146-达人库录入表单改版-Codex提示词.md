## 1. 背景

任务 143 已上线 B 公司达人库（`com.tcrm.admin.kollibrary`、`admin-ui/src/views/kol-library/`）。负责人 2026-11-10 修订录入交互与必填项：

- 新增 / 编辑表单从「六组卡片」改为**三个二级标签页**：基础信息、建联及寄样、质量及分层。
- 必填项改为七项：达人ID、达人名称、所属平台、粉丝数、国家站点、主页链接、跟进负责人。内容类目、建联状态改为非必填。
- 取消「合作阶段」（与建联状态重复）。
- 「建联及寄样」新增「跟进备注」，与档案「备注」是两个字段。
- 列表表头改为：达人名/ID、平台、粉丝数、国家站点、内容类目、建联状态、负责人、达人分级；筛选为关键词、平台、站点、内容类目、建联状态、跟进负责人（与现状相同）。
- 删除只放在编辑表单里：列表和明细页都去掉「删除」。
- 明细页分组不动，只做跟随性的小改。

## 2. 要求

### 2.1 后端（`kollibrary`）
1. **迁移**（一个脚本）：
   - `crm_library_kol` 增加 `follow_up_remark`（`VARCHAR(1000)`，可空，带注释「跟进备注」）。
   - 放宽内容类目约束：删除 `categories` 至少一项的 CHECK，重建为只校验是数组（允许空数组，列仍 `NOT NULL`，空即 `[]`）。
   - 更新 `cooperation_stage` 的列注释，注明 2026-11-10 起停用、只保留历史数据。**不删列、不清数据。**
   - `followers`、`profile_url` 在库里保持可空（老数据可能为空），必填只在接口校验。
2. **接口校验**（新增、编辑档案）：
   - `followers` 必填，非负整数。
   - `profileUrl` 必填，URL 格式沿用现有校验。
   - `followUpOwner` 仍为必填。
   - `categories` 改为可空或空数组。
   - `outreachStatus` 改为可不传，不传时新增按「未建联」、编辑保持原值。
   - 其余规则不变（达人ID 规范化、判重、计算口径都不改）。
3. **合作阶段停用**：从请求、列表 / 详情返回体、命令对象、DTO 中删除 `cooperationStage`。保存时不读也不写该列，编辑已有记录不会清掉它的历史值。
4. **跟进备注**：
   - 档案新增、编辑接受 `followUpRemark`。
   - 更新跟进接口（`PUT …/kols/{id}/follow-up`）也接受它。
   - 详情返回它；列表不返回。
   - 长度上限 1000，写在注释和校验里。
5. **列表接口**：
   - 筛选不变：关键词、平台、站点、内容类目、建联状态、跟进负责人。
   - 列表项按 §2.2 第 3 条的列返回：增加 `followers`、`grade`，保留 `categories`、`outreachStatus`、`followUpOwner`；列表不需要的字段（如 `updateTime` 只用于排序时）可不返回，排序仍按更新时间倒序。
6. 操作日志、权限、版本声明保持不变。日志不输出联系方式和备注内容。
7. 设计说明书同步更新：达人库表结构（新列、约束、`cooperation_stage` 停用说明）、接口字段、取值字典。

### 2.2 管理端
1. **新增 / 编辑表单**（`views/kol-library/kol-form`），按需求 1.2.5 ④ 的表逐项做：
   - 页面仍以系统内一级标签打开。表单内用**二级标签页**，样式与现有 `views/kol/index.vue` 的「达人列表 / 达人分配」页内页签一致（`el-tabs`，复用同一套样式，不新写一套），默认显示「基础信息」。
   - 「基础信息」分三小块，依次为基础信息、账号类型、受众画像。小块用规范 13 §3.5 的分组卡片，卡内单列。
   - 「建联及寄样」顶部只读显示达人ID、达人名称，随「基础信息」里的输入实时更新；未填时显示「—」。
   - 「质量及分层」只有内容质量、带货潜力、配合度、达人分级。
   - **删除入口**：编辑表单里，超管另有「删除」按钮（新增表单没有）。删除前二次确认，确认文案带达人名称，调用现有删除接口。删除后关闭表单标签和该达人已打开的明细标签，回到并刷新达人列表。非超管看不到这个按钮，后端仍只认 `SUPER_ADMIN`。
   - 整张表单只有一个「保存」，位置与现有表单一致。保存时校验全部三个标签：有错误时切到第一个有错的标签，并滚动到第一个错误字段。必填星号按新的七项显示。
   - 切换标签不丢输入。编辑时三个标签都回填原值。
   - 判重提示、保存后关闭表单标签并打开或刷新明细页的行为，都保持 143 的现状。
   - 已有达人缺粉丝数或主页链接时，编辑页正常打开，保存时提示补齐。
2. **更名**（语言包，中英文都改，明细页同步生效）：
   - 「平均播放量」改为「近期平均播放量」；
   - 「快递单号」改为「寄样单号」；
   - 「WhatsApp/TEL」改为「联系方式」，如现有文案已是这个名称则不动。
3. **达人列表**（`views/kol-library/kol-list`）：
   - 表头依次为（负责人 2026-11-10 定，文字按此）：**达人名/ID**（昵称 + `@用户名`；昵称改为普通文字、**去掉现有的点击跳转**（负责人 2026-11-11），用户名沿用 `CopyText`）、**平台**、**粉丝数**（千分位、右对齐）、**国家站点**、**内容类目**（多项沿用现有标签样式）、**建联状态**、**负责人**（即跟进负责人）、**达人分级**（空显示「—」）。
   - 去掉更新时间列；列表仍按更新时间倒序。不显示主页链接。
   - 筛选保持现有六项：关键词、所属平台、国家站点、内容类目、建联状态、跟进负责人。
   - 行操作（`RowActions`）改为两个，依次为：
     - **编辑**：打开该达人的编辑表单标签（`/kol-library/kols/:id/edit`），与「新增达人」是同一个表单（三个二级标签页），带出该达人现有数据，超管另有「删除」；只对有 `kol-library:edit` 的账号显示；
     - **查看**：打开该达人现有的明细页标签（默认「达人档案」，已打开则切过去），这是列表进入明细页的唯一入口。
   - 列表上去掉「删除」。
   - 跑 `scripts/table-align-audit.js`，问题数为 0。
4. **明细页**（`views/kol-library/kol-detail`）不改分组，只做以下几处：
   - 去掉页头卡片和「质量及分层」组里的合作阶段；
   - 去掉页头的「删除」按钮（删除只在编辑表单里），同时删掉明细页里不再使用的删除相关代码和测试；
   - 「建联与寄样」组末尾加「跟进备注」，长文本占整行；
   - 字段名随第 2 条更名。
5. **更新跟进弹窗**：加「跟进备注」（多行文本）。
6. 删除合作阶段的前端取值、语言包键和类型定义。删除后没有任何引用残留，`pnpm lint` / `typecheck` 能发现残留引用。
