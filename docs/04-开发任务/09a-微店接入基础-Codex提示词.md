## 1. 背景

客户要求新系统通过微店开放平台接口完成订单与退款同步、商品自动复制等功能。这些业务的规则还在等客户确认（第二轮确认清单第 3～10、13～15 题），**本任务只做与业务规则无关、后续模块一定会用到的底层能力**：

1. **按公司加密保存第三方凭证**：设计说明书 §3.4"公司级配置与凭证"已定，本任务首次落地。
2. **微店应用配置**：每家公司一份 appkey / secret。
3. **店铺授权**：对每个店铺发起授权、接收回调、保存令牌、自动续期，并展示授权状态。
4. **接口调用客户端**：统一处理请求格式、令牌、限流、重试与错误分类，并提供店铺连通性检查。

已有调研：`docs/02-调研/微店API风险调研报告.md` 第三节（网关、OAuth2、令牌有效期、QPS）。客户现有系统中，每个店铺都有"去授权"按钮和"授权过期时间"，说明是按店铺授权。

### 4.1 凭证加密（`shared`）

新增一个通用的凭证加密组件，例如 `shared.SecretCipher`：

| 项目 | 规则 |
|---|---|
| 算法 | AES-256-GCM，每次加密使用新的 12 字节随机 nonce，128 位认证标签 |
| 主密钥 | 环境变量 `TCRM_SECRET_KEY`：Base64 编码的 32 字节。**必填**，缺失或长度不对时应用启动失败，提示变量名（规范 06 第 5 节） |
| 密文格式 | `v1:` + Base64(nonce ‖ 密文 ‖ 标签)。解密时遇到未知版本前缀或认证失败，直接抛异常，不返回部分数据 |
| 换密钥 | 本期只实现 `v1`，前缀为以后更换主密钥预留，换密钥功能不实现 |
| 日志与异常 | 明文、密文、主密钥一律不进日志和异常信息 |

同步更新：
- `deploy/.env.example`，写明生成方法，例如 `openssl rand -base64 32`；
- `deploy/docker-compose.prod.yml`：给 crm-admin 传入该变量；
- `deploy/README.md`：必填说明，并写明"丢失主密钥意味着已保存的凭证全部要重新录入"；
- 集成测试在测试配置中提供随机密钥。

### 4.2 数据表（新增迁移）

两张表都带 `tenant_id`，并遵守规范 04：雪花主键、通用字段、表和字段注释、不加外键。

**`crm_weidian_app` 微店应用（每家公司一份）**

| 字段 | 说明 |
|---|---|
| `tenant_id` | 唯一 `uk_crm_weidian_app_tenant` |
| `app_key` | VARCHAR(64)，明文 |
| `app_secret_cipher` | TEXT，`SecretCipher` 密文 |

**`crm_weidian_shop_auth` 店铺授权（每个店铺一行）**

| 字段 | 说明 |
|---|---|
| `tenant_id` | |
| `shop_id` | `crm_shop.id`，唯一 `uk_crm_weidian_shop_auth_shop` |
| `access_token_cipher`、`refresh_token_cipher` | TEXT NULL，密文；未授权时为空 |
| `access_expires_at`、`refresh_expires_at` | TIMESTAMPTZ(3) NULL |
| `status` | VARCHAR(16) + `CHECK`：`UNAUTHORIZED` 未授权、`AUTHORIZED` 已授权、`EXPIRED` 已过期、`FAILED` 续期或校验失败 |
| `authorized_at`、`authorized_by` | 最近一次授权成功的时间与操作人 |
| `last_refresh_at` | 最近一次刷新成功的时间 |
| `last_check_at`、`last_check_ok` | 最近一次连通性检查的时间与结果（BOOLEAN NULL，未检查时为空） |
| `last_error` | VARCHAR(500) NULL，英文摘要，**不得包含令牌** |

如果官方文档中没有刷新令牌，或者有效期字段与此不同，可以相应调整字段，在报告中说明。

### 4.3 店铺授权流程

1. **发起授权**（仅 `SUPER_ADMIN`）：
   - 校验店铺属于本公司（自动过滤）；
   - 生成随机 `state`（至少 32 字节，URL 安全）存入 Redis：键 `weidian:oauth:state:{state}`，10 分钟过期，值为 `{tenantId, shopId, userId}`；
   - 返回微店授权地址。
   - 本公司未配置应用时，返回新错误码 `WEIDIAN_APP_NOT_CONFIGURED`（422）。
2. **回调**（公开接口，标注 `@PublicEndpoint`）：
   - 用 `GETDEL` **一次性**取出 `state`，不存在、过期或已用过一律视为失败；
   - 在 `state` 记录的公司范围内，用授权码换取令牌；
   - **调用连通性检查接口，确认令牌对应的微店店铺 ID 等于 `crm_shop.weidian_shop_id`**，不一致即拒绝，防止把 A 店的授权保存到 B 店；
   - 校验通过后加密保存令牌，状态设为 `AUTHORIZED`，写入授权时间和操作人，记录审计日志；
   - 最后 302 跳转到**相对路径** `/product/shops?weidianAuth=success`，失败时为 `?weidianAuth=failed&reason={原因码}`。原因码为固定的英文枚举，例如 `STATE_INVALID`、`TOKEN_EXCHANGE_FAILED`、`SHOP_MISMATCH`。响应中不带任何令牌或微店返回的原文。
3. **回调地址**：`{TCRM_ADMIN_BASE_URL}/admin-api/integration/weidian/oauth/callback`。
   - `TCRM_ADMIN_BASE_URL` 是新增的**必填**环境变量（https、不带末尾斜杠），校验方式与 `TCRM_LINK_BASE_URL` 相同；
   - 同步写进 `.env.example`、prod compose 和 README，并说明需要在微店开放平台登记这个回调地址。
4. **令牌续期**（定时任务）：
   - 每小时运行一次，系统范围，跳过已停用的公司；
   - 对 `AUTHORIZED` 且访问令牌将在 24 小时内过期的店铺执行刷新（阈值以官方有效期为准，可调整，报告说明）；
   - 每个店铺使用分布式锁 `weidian:token:{shopId}`，与按需刷新共用；
   - 成功后更新密文和时间；
   - 刷新令牌已过期或刷新被拒，状态设为 `EXPIRED`；其他失败设为 `FAILED`，写 `last_error` 并记 `ERROR` 日志；
   - 每家公司的处理互相独立，一家失败不影响其他公司。

### 4.4 接口调用客户端（`integration`）

在 `integration` 模块内实现，供后续订单、复制等模块通过 `integration.api` 调用：

1. **入口**：例如 `WeidianClient.call(shopId, method, version, params)`，返回解析后的业务数据（JSON 节点）。调用方处在公司范围内，客户端按 `shopId` 读取该店铺的令牌。
2. **请求格式、网关地址、成功判断**：严格按官方文档。
   - 网关和授权域名做成配置项 `crm.weidian.api-base-url`、`crm.weidian.oauth-base-url`，默认值取官方地址；
   - 测试中指向本地模拟服务。
3. **限流**：
   - 按应用（appkey）用 Redisson 限流器限制 QPS，默认值按文档（调研为 5/秒），配置项 `crm.weidian.qps`；
   - 拿不到许可时等待，最长 10 秒；超时按"频率超限"处理。
4. **重试**：
   - 网络错误、HTTP 5xx、频率超限：指数退避重试，1 秒、2 秒、4 秒，最多 3 次；
   - 令牌无效：先按需刷新一次，持有店铺锁，再重试一次；仍然失败，状态设为 `EXPIRED`，并抛出明确的异常；
   - 其他业务错误不重试。
5. **超时**：连接超时 5 秒，读取超时 30 秒。
6. **日志**：每次调用记录 `method`、店铺 ID、状态码、耗时、重试次数；**不记录令牌、appSecret、请求参数和返回内容**。
7. **加解密 jar**（订单敏感字段解密）本任务不引入，订单任务需要时另行评估。

### 4.5 接口

全部在 `/admin-api/integration/weidian/**` 下。回调以外的接口都要求本公司登录，平台管理员不可访问。

| 方法与路径 | 角色 | 说明 |
|---|---|---|
| `GET /app` | SUPER_ADMIN | 返回 `{ appKey: string\|null, secretConfigured: boolean, updateTime: string\|null }`，**不返回 secret** |
| `PUT /app` | SUPER_ADMIN | 请求 `{ appKey, appSecret }`，两者都必填；secret 加密保存。审计日志中 `appSecret` 必须脱敏：如果 `AuditSanitizer` 没有覆盖这个字段名，就补上并测试 |
| `GET /shops` | SUPER_ADMIN、OPERATOR、FINANCE | 本公司全部未删除店铺的授权状态：`shopId`、`shopName`、`weidianShopId`、`status`（没有授权记录的店铺返回 `UNAUTHORIZED`）、各时间字段、`lastCheckOk`、`lastError` |
| `POST /shops/{shopId}/authorizations` | SUPER_ADMIN | 返回 `{ authorizeUrl }` |
| `GET /oauth/callback` | 公开 | 第 4.3 节第 2 条 |
| `POST /shops/{shopId}/checks` | SUPER_ADMIN | 立即执行连通性检查，返回该店铺的最新状态行 |

- 其他公司的 `shopId` 一律返回 404。
- 新错误码在 `ErrorCode` 中登记（至少 `WEIDIAN_APP_NOT_CONFIGURED`、`WEIDIAN_SHOP_NOT_AUTHORIZED`），HTTP 状态码按规范 03 选择。前端文案由后续界面任务添加，本任务不改前端。

## 6. 测试要求

| 场景 | 期望 |
|---|---|
| 加密 | 加密后解密得到原文；同一明文两次加密结果不同；篡改密文或使用错误密钥时抛异常；未知版本前缀抛异常；密钥缺失或长度错误时启动失败 |
| 应用配置 | `GET /app` 永不返回 secret；数据库中 secret 为密文；审计日志中 `appSecret` 已脱敏；公司之间互相隔离 |
| 授权：正常流程 | 发起 → 模拟授权码 → 回调 → 令牌加密保存 → 状态为 `AUTHORIZED` → 302 到成功地址 |
| 授权：异常 | `state` 无效、过期、重复使用，均失败；用 A 公司的 `state` 不能写入 B 公司的店铺；连通性检查返回的店铺 ID 与记录不一致时拒绝，不保存令牌 |
| 回调响应 | 不含令牌，也不含微店返回的原文 |
| 客户端 | 请求格式与官方文档一致（模拟服务器断言参数）；频率超限和 5xx 按 1、2、4 秒退避重试（测试中注入可控的等待，不真实 sleep）；令牌无效时刷新一次再重试；业务错误不重试；日志中没有令牌 |
| 限流 | 同一应用的并发调用不超过配置的 QPS |
| 续期 | 即将过期的令牌被刷新；刷新被拒时状态为 `EXPIRED`；一家公司失败不影响另一家；已停用公司被跳过；续期与按需刷新互斥，不会把新令牌覆盖成旧令牌 |
| 权限 | 每个接口的角色限制；平台管理员 403；其他公司的 `shopId` 404 |

现有测试全部通过，不得删除或弱化。覆盖率门槛不降低。
