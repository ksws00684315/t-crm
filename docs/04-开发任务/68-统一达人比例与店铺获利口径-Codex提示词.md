## 1. 负责人决定（2026-10-25）

《1024前端调整内容》D12、D14 中的两条，负责人已确认：

1. **每位达人统一一个佣金比例，不设单商品覆盖。** 取消 ADR-032 第 3 条中「商品级比例（`crm_product.rate`）优先于达人比例」的规则（原 [D7]）。比例只取支付时刻生效的推广配置（`crm_kol_promotion_record` 中 CONFIG 记录的 `defaultRate` 与 `version_no`）。历史商品行已经保存的比例快照不变。
2. **店铺获利 = 微店结算净额 − 净达人佣金，不扣商品成本。** 取代原口径 `retained = 支付 − 退款 − 佣金`。「微店结算净额」是微店侧的结算字段，还没有经过 M0 核实（Q-1017-1/2）。**核实之前，店铺获利一律返回 `null`（待核实），不得用买家实付减佣金代替。**

共享库中目前没有任何商品设置了 `crm_product.rate`，取消商品级比例不涉及历史数据。

## 2. 范围

### 2.1 契约（作为本 PR 的第一个提交）

- ADR-032：在「修订记录」中新增一条 2026-10-25 的修订，写明上面两条决定和理由；同步修改第 3 条正文和附录 A 的 `Settlement.retained` 说明。
- 设计说明书：§6.2 `settlement-details` 行中的店铺获利口径、§8.3 及其他提到 [D7] 商品级比例优先的位置（例如 §9 附近「商品级比例仍优先 [D7]」），改为新口径。

### 2.2 后端

- **比例解析**：`CommissionItemSnapshotService` 不再读取商品级比例。不再使用的 `ProductAccessApi` 比例方法和 `ProductRateDTO`，如果没有其他调用方就删除。比例解析继续写成纯函数，补单元测试：商品设置了比例时也只取推广配置的比例。
- **来源版本指纹**：比例来源变化后，确认已有行的指纹不会因此全部变化，产生大量无意义的修订。如果会，先停下来报告。
- **店铺获利**：`CommissionSettlementDetailService` 计算 `retained` 时改为新口径。数据源中还没有「微店结算净额」字段，所以本任务中 `retained` 恒为 `null`。代码中留出取数位置，注释注明待 M0 核实（Q-1017-1/2）后接入，不新增字段和迁移。补测试：已核实行的 `retained` 也是 `null`；`status` 的 `POSTED`/`UNVERIFIED` 判定不变。
- **商品编辑接口中的 `rate`**：`EditProductRequest` 的 `rate` 字段不再参与计佣。为了不破坏现有调用，本任务不删除这个字段。在设计说明书中把它标为「已废弃，不参与计佣」，并在报告中列为遗留事项。

### 2.3 不做

- 不删除 `crm_product.rate` 列，不写迁移；
- 不实现「微店结算净额」的同步（等 M0）；
- 不改前端（#122 已按新口径显示「待核实」）。

## 3. 测试

- 比例：商品有比例和没有比例两种情况，结果都等于推广配置比例；比例按支付时刻取对应版本；
- 店铺获利：已核实和未核实的行都返回 `null`；
- 集成测试中涉及商品级比例或 `retained` 数值的断言随新口径修改，不得删除或弱化。
