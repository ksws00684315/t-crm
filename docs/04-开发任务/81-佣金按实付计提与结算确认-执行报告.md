## 1. 改动概要

- **计提基数**：付款后按订单实付 `pay_amount`（含运费）分摊到商品行（`SettlementBasisCalculator.compute` → `OrderCommissionSync.sync`），付款即计提，释放依据 `UNSETTLED`（冻结中）。
- **结算确认**：`INCOME_DETAIL` 中恰好一笔「货款收入」、带 `tradeTime`，金额等于实付或实付减 CRM 成功退款，才设结算时间（`CONFIRMED`）并写 `settled_time`；基数仍按实付分摊。
- **不参与计算**：手续费、分润与其他子类型流水只入库、只展示。`UNKNOWN_FLOW_TYPE` 原因码、分支与 `KNOWN_TRADE_TYPES` / `KNOWN_TRADE_SUB_TYPES` 常量已删除。
- **退款（架构师 PR #158 回复，2026-10-30）**：退款三信号（订单关闭、`RefundDO`、结算流水「退款」行）同一笔只计一次。`CLOSED` 且有 `pay_time` 的订单整单基数为 0；流水退款超出 CRM 成功退款的部分按实付比例补扣并记 WARN；只有 `PROCESSING` / `UNKNOWN` 阻断释放，阻断期间该行显示冻结。
- **事件**：`OrderCommissionSync` 对有基数的行发 `basisIncludesRefund = FALSE`，成功退款（含流水补扣）由引擎扣减。
- **未付款（架构师 M2）**：未付款订单的行结算状态为 `UNPAID`（迁移 `V202610301000`，存量行回填），不计入待核实计数，也不阻塞提现；达人端订单级与行级状态为空（「—」）。计数 SQL 不再读取 `crm_order`。
- **零佣金（架构师 M1）**：已核实且计提为零的行（如全额退款）达人端显示「无佣金」（`NO_COMMISSION`），不再显示「待核实」；`INVALID` 只表示未核实。
- **结算明细（L-024）**：「净增减」改为「微店可提现金额」（该单 `INCOME_DETAIL` 流水合计，只展示，无结算流水为 null，前端显示「-」）；「店铺获利」删除（后端 `retained`、前端列与抽屉、文案）；支付金额改为订单实付；行状态为 `UNVERIFIED` / `FROZEN` / `POSTED`。
- **订单链路**：资金卡片与商品行删除「店铺获利」（`OrderChainDTO` 的 `shopProfit` 字段删除）。
- **order.api**：`OrderRefDTO` 增加 `payAmount`；新增 `weidianWithdrawableByOrderIds`。
- **未改**：`CommissionSettlementRules`、快照、释放、提现分配、预付冲抵、钱包台账、结算流水拉取、达人端状态映射（`CommissionOrderStateService` 原映射已覆盖「已核实、计提>0、未释放 → FROZEN」，只补了测试）。**无新迁移，无新依赖。**
