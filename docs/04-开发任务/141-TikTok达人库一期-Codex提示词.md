## 1. 背景

客户 2026-10-31 提出 B 公司（TikTok 店铺场景）：只用一个精简的「达人库」，录入并跟进 TikTok 达人，记录每条带货内容的投入产出；与 A 公司（现有分销系统）完全隔离。负责人 2026-11-08、11-09 确定一期范围、账号方案（需求 1.1.1 方案甲）、字段规则（1.2.6）和交互（1.2.5），并接受 ADR-038。

本任务分两部分，**同一个 PR**，按顺序做：
- **A 部分：公司版本**（ADR-038 的全部决定）。这是 B 部分的前提，也影响 A 公司全部接口，先做、先测通。
- **B 部分：达人库模块**（需求 1.2）。

## 2. A 部分：公司版本（ADR-038）

### 2.1 数据
1. 迁移：`sys_tenant` 增加 `edition`（`varchar`，`NOT NULL`，CHECK 只允许 `DISTRIBUTION`、`KOL_LIBRARY`，带注释），现有公司全部回填 `DISTRIBUTION`。
2. 后端枚举 `Edition`（放在 `security.api` 或 `shared`，以模块边界规则为准），由 `CurrentUserContext` 提供当前公司版本。

### 2.2 平台管理员
1. 新建公司（`POST /admin-api/platform/tenants`，`CreateTenantRequest`）增加必填 `edition`；编辑公司**不能**改版本（`EditTenantRequest` 不加该字段，传了也忽略或拒绝，二选一并写测试）。
2. 平台公司列表、详情返回并显示版本（语言包：分销完整版 / 达人库版）。管理端 `views/platform/tenant` 新建弹窗加「版本」单选，默认分销完整版；列表加「版本」列。

### 2.3 后端：按版本拦截，默认拒绝
1. 控制器声明所属版本（例如类级注解 `@EditionScope({DISTRIBUTION, KOL_LIBRARY})`，命名自定）。**没有声明的控制器只属于 `DISTRIBUTION`**。
2. `KOL_LIBRARY` 只开放以下控制器，其余一律不开放：
   - `AuthController`（登录、`/me`、切换公司、退出、改密码）；
   - `UserController`、`PermissionController`（账号管理）；
   - 本任务新建的达人库控制器。
   - 离职交接（`ResignationController`，虽在 `/admin-api/auth/` 下）、离职计划、岗位模板、通知、商务选择器等都是 A 公司流程，**不开放**。
3. 新增拦截器：当前公司版本不包含该控制器时返回 403，错误码 `AUTH_EDITION_FORBIDDEN`（登记在 `shared.ErrorCode`，中英文提示进语言包）。位置：`SecurityConfiguration` 中公司状态拦截器之后、`CompanyHeaderInterceptor` 之后、`SaInterceptor`（角色与权限码注解）**之前**。平台接口（`/admin-api/platform/**`，平台管理员不在公司会话中）、`/admin-api/external/**`、公开接口不经此判定。CORS 预检照旧放行。
4. 权限码按版本收窄：
   - `Permission` 增加分组 `KOL_LIBRARY` 和两个权限码 `kol-library:view`（查看达人库）、`kol-library:edit`（新增、编辑达人和内容记录、更新跟进）。删除不设权限码，只判 `SUPER_ADMIN`（需求 P1-15）。
   - 每个版本对应一组权限码：`DISTRIBUTION` = 现有全部码；`KOL_LIBRARY` = 上述两个码。
   - 超级管理员的有效权限码 = 当前公司版本的全部码（`CurrentUserContext.permissionNames` 及 `/me` 返回值都按此收窄）。
   - 子账号授权（`PUT /system/users/{id}/permissions`）、建账号时的 `permissions`、`GET /system/permissions` 目录，都只接受 / 返回当前版本的码；传入其他版本的码返回参数错误。
   - B 公司建子账号：岗位模板（`postTemplate`）、数据范围（`dataScope`）是 A 公司概念。B 公司不显示这两项；后端对 `KOL_LIBRARY` 不要求、不保存岗位模板，数据范围按 `ALL` 存（P1-13 账号之间不做区隔）。如果现有校验或岗位模板的预填逻辑让这一点做不到，停下报告。
5. `/me` 与切换公司接口（`POST /auth/company`）返回当前公司 `edition`；登录返回体如已带公司信息，一并加上。
6. 架构测试（`ArchitectureTest`）新增：每个 `/admin-api/**` 控制器的所属版本都能确定（未声明即 `DISTRIBUTION`，测试校验声明了 `KOL_LIBRARY` 的控制器在上面第 2 条的白名单中，新增开放必须改测试，防止误开放）。

### 2.4 管理端
1. 用户 store 保存 `edition`。路由 `meta` 增加版本声明（例如 `editions: ["KOL_LIBRARY"]`），未声明的路由只属于 `DISTRIBUTION`；`canAccessRoute` 改为「版本 ∧ 权限码 / 角色」。菜单与守卫共用这一判断（静态菜单不变，不引入动态菜单）。
2. `KOL_LIBRARY` 公司的菜单：「达人列表」（`kol-library:view`）、「账号管理」（仅超管，复用 `views/system/user`）。不显示经营分析、商品、订单、达人管理、资金、系统设置的其他项，不显示通知铃铛。账号管理页在 B 公司隐藏岗位模板、数据范围，权限勾选只列达人库两个码。
3. B 公司的首页就是达人列表：登录后、点 Logo、访问 `/` 或 `/home` 时进入 `/kol-library/kols`；固定标签（affix）同样换成达人列表。
4. 直接访问不属于当前版本的路由进入 403 页。
5. 页头切换到不同版本的公司后：关闭不属于新版本的标签，回到新版本的首页。已有的本地标签恢复逻辑（`loadStoredTabs` 的 `canAccess`）必须把版本纳入判断。

## 3. B 部分：达人库模块

### 3.1 后端模块
1. 新模块 `com.tcrm.admin.kollibrary`（按规范 01 分 `controller/service/mapper/model/api`），控制器声明只属于 `KOL_LIBRARY`。**不复用 `crm_kol` 及 `kol` 模块的任何表和服务**（ADR-038 §4）。
2. 表（名称可调整，须有表注释、字段注释、`tenant_id`、审计字段，删除方式按规范 04 现有约定）：
   - 达人档案表（如 `crm_library_kol`）：需求 1.2.1、1.2.2 的全部字段，其中「合作阶段」「建联与寄样」字段都在档案上；
   - 内容记录表（如 `crm_library_kol_content`）：需求 1.2.3 的手填字段，外键关联档案。
   - 计算字段（预估佣金、总投入成本、实际 ROI、累计数）**不入库**，查询时在服务层计算。
3. 字段与取值严格按需求 1.2.6 ①：
   - 下拉取值后端存英文常量（例如平台 `TIKTOK`、站点 ISO 代码 `US`），中文名称进语言包；取值集中在一处定义（枚举 + 语言包），方便客户核对后调整（需求第 3 节 Q-2）。
   - 「内容类目」多选、「标签」多个：存储方式自定（不新增依赖），列表能按「内容类目包含某项」筛选。
   - 日期字段（最近沟通时间、寄样日期、发布日期）用 `date` / `LocalDate`；更新时间等时刻用 `Instant`。
   - 金额（带货GMV、样品成本、坑位费）`numeric`、`BigDecimal`，两位小数，非负，序列化为字符串；佣金比例 0～100，两位小数；互动率百分比两位小数。
   - 非负整数（粉丝数、平均播放量、点击量、出单量）用 `bigint`，ID 序列化为字符串。
   - 文本长度上限自定合理值，写在字段注释与校验里。
4. **达人ID 规范化与判重**（需求 1.2.6 ②）：
   - 保存时去首尾空格、去开头的 `@`、转小写；规范化后为空即校验失败。
   - 同一公司内「所属平台 + 规范化达人ID」唯一，由数据库唯一约束兜底（并发提交也只能成功一条；若软删，约束须排除已删记录）。
   - 新增和修改都判重；命中时返回业务错误码（如 `KOL_LIBRARY_DUPLICATE`），`data` 中带已存在记录的 `id` 和「跟进负责人」，前端提示「该达人已由 {跟进负责人} 录入」并给出「查看」链接。
5. **计算口径**（需求 1.2.6 ③），统一在后端一个地方实现并单测：
   - 留空的金额、佣金比例按 0 计；
   - 预估佣金 = 带货GMV × 佣金比例 ÷ 100，保留两位小数（`HALF_UP`）；
   - 总投入成本 = 样品成本 + 坑位费 + 预估佣金；
   - 实际 ROI = 带货GMV ÷ 总投入成本，两位小数；总投入成本为 0 时返回 `null`（前端显示「—」）；
   - 累计：内容条数、Σ点击量、Σ出单量、Σ带货GMV、Σ总投入成本；累计 ROI = Σ带货GMV ÷ Σ总投入成本（**不是**各条 ROI 的平均），Σ总投入为 0 时为 `null`。
6. 接口（路径复数 kebab-case，统一信封、分页，规范 03）。参考：

   | 接口 | 权限 |
   |---|---|
   | `GET /admin-api/kol-library/kols` 分页列表，筛选：关键词（达人ID / 达人名称，包含）、平台、站点、内容类目、建联状态、跟进负责人（包含） | `kol-library:view` |
   | `GET /admin-api/kol-library/kols/{id}` 档案详情（含累计数） | `kol-library:view` |
   | `POST /admin-api/kol-library/kols`、`PUT /admin-api/kol-library/kols/{id}` 新增 / 编辑档案 | `kol-library:edit` |
   | `PUT /admin-api/kol-library/kols/{id}/follow-up` 更新跟进（只改建联状态、最近沟通时间、寄样状态、快递单号、寄样日期） | `kol-library:edit` |
   | `DELETE /admin-api/kol-library/kols/{id}`（连同其内容记录） | `SUPER_ADMIN` |
   | `GET /admin-api/kol-library/kols/{id}/contents` 内容记录列表（含每条计算字段，按发布日期倒序；数量通常不多，可不分页，如分页按规范 03） | `kol-library:view` |
   | `POST …/kols/{id}/contents`、`PUT …/kols/{id}/contents/{contentId}` | `kol-library:edit` |
   | `DELETE …/kols/{id}/contents/{contentId}` | `SUPER_ADMIN` |

   - 列表项只返回列表页需要的字段（需求 1.2.5 ②）。
   - 内容记录的 `contentId` 必须属于路径上的达人，否则 404；跨公司访问按多租户插件照常过滤为 404。
   - 新增、编辑、删除、更新跟进写操作日志（沿用现有操作日志机制；日志不输出联系方式）。
7. 设计说明书同步：§3.4 公司表版本字段（已写，核对）、接口清单、新增两张表的表结构与取值字典。

### 3.2 管理端页面（需求 1.2.5 全文，逐条实现）
页面放 `admin-ui/src/views/kol-library/`，路由在 `/kol-library` 下，全部声明只属于 `KOL_LIBRARY`。

1. **达人列表** `/kol-library/kols`（菜单「达人列表」）：`ListSearch` + `DataTable` + `RowActions` + `CopyText`。
   - 筛选与列严格按 1.2.5 ②，**不加**内容条数、GMV 等其他列。
   - 「达人」列：昵称（链接，打开明细页）+ `@用户名`（`CopyText`）。内容类目多项时按现有标签样式展示。
   - 页头「新增达人」（`kol-library:edit`）；行操作「查看」、「删除」（仅超管，二次确认，确认文案带达人名称）。
2. **达人明细页** `/kol-library/kols/:id`（`hideInMenu`）：
   - 以**系统内标签页**打开（顶部 `TabBar` 的一个标签，不是浏览器新标签）；同一达人再次点击切换到已打开的标签；不同达人各开一个标签，标签标题显示达人昵称（取不到时用语言包里的「达人详情」）。现有 `TabBar` / `stores/tabs` / KeepAlive 以路径区分标签、以组件名缓存；**多个明细标签同时打开时各自内容必须正确、互不串数据**，若现有机制做不到，在本任务内最小改动修好并写测试。
   - 页头卡片、两个页内页签「达人档案」（默认）/「带货数据」，内容严格按 1.2.5 ③。
   - 「达人档案」六组只读，短字段两列（规范 13 §3.4），空值显示「—」。
   - 「带货数据」：六个指标卡 + 内容记录表（列按 1.2.5 ③ 的顺序）；内容表的金额右对齐、带千分位、`¥` 前缀；「发布内容链接」可点击（浏览器新窗口打开）且可复制；表尾或指标卡体现累计数，两者数值一致。
   - 「编辑档案」打开编辑表单标签；「更新跟进」打开弹窗（1.2.5 ⑤）；超管另有「删除」，删除后关闭本标签并回到列表、刷新列表。
   - 达人已被删除或不存在：显示空状态，提供返回列表，不报错弹窗堆叠。
3. **新增 / 编辑档案**：`/kol-library/kols/new`、`/kol-library/kols/:id/edit`（`hideInMenu`），全页表单，以系统内标签打开；六个分组卡片，卡内单列（规范 13 §3.5）；必填与校验按 1.2.6 ①；达人ID 输入框提示可粘贴 `@用户名`；判重命中时表单顶部提示并给「查看」链接（打开已有达人的明细标签）。保存后关闭表单标签，打开或刷新该达人明细标签，列表标签如已打开也要刷新。未保存离开按现有页面的做法处理（没有现成做法就不加）。
4. **内容记录弹窗**（1.2.5 ⑥）：手填字段按 1.2.6 ①；预估佣金、总投入成本、实际 ROI 随输入实时显示、只读。前端实时值只作展示，保存后以后端返回为准，两边口径一致（同一组用例前后端各测一次）。弹窗较长时按规范 13 §3.7 固定操作区。
5. 按钮权限：无 `kol-library:edit` 的账号看不到新增、编辑、更新跟进、新增内容记录；非超管看不到删除。
6. 界面文字全部进语言包（中英文都写，项目规则）；B 公司按需求 P1-16 只做中文验收。金额显示人民币。

## 5. 验证

1. **单元测试**：
   - 版本拦截：两个版本 × 开放 / 未开放 / 未声明（默认拒绝）的控制器；平台接口不受影响；预检放行。
   - 权限码收窄：`KOL_LIBRARY` 超管有效码只有两个；子账号授权传入 A 公司码被拒；`DISTRIBUTION` 超管码与改动前一致。
   - 新建公司必须带版本；编辑不能改版本。
   - 达人ID 规范化（`@Abc `、`ABC`、`abc` 判为同一个；只有 `@` 判为空）；判重（新增、修改改成已有用户名、不同平台同用户名可以共存、不同公司同用户名可以共存）。
   - 计算口径：留空按 0、佣金比例小数、四舍五入、总投入为 0 时 ROI 为空、累计 ROI 与平均 ROI 不同的例子。
   - 前端：路由与菜单按版本显隐、B 公司首页与 affix 标签、切换公司关标签、明细标签复用与多标签不串数据、计算字段实时显示、判重提示、按钮按权限显隐。
2. **集成测试**（`*IT`，`@Tag("docker")`）：
   - `KOL_LIBRARY` 超管调用 A 公司接口（至少：达人列表、商品、订单、资金、岗位模板、离职交接、通知各一个）返回 403 `AUTH_EDITION_FORBIDDEN`；
