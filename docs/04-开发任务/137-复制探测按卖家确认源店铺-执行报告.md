# 137 复制探测按卖家确认源店铺：执行报告

- 分支：`task/137-copy-probe-seller`
- 日期：2026-11-08
- 类型：缺陷修复（后端，无迁移）

## 1. 背景

2026-11-08 07:37Z，客户通过表格脚本提交一条复制任务，共 411 个商品，结果全部失败，`error_message` 都是「多个店铺都有该商品」。经负责人同意，在正式环境做了只读查询和日志查看：

- 该公司原来只有一个店铺；约 46 分钟前新接入了第二个店铺。这条任务是第二个店铺接入后的第一条任务。
- 两个店铺都是服务型授权，状态都是 `AUTHORIZED`，`openid` 不同，且各自等于店铺的 `weidian_shop_id`。所以这是两个不同的微店，不是同一个微店授权了两次。
- 411 个源商品都没有登记在 `crm_product` 里，因此冲突不是来自已登记商品，而是来自探测。
- crm-admin 日志（任务提交后）：每个商品都依次对两个店铺调用 `vdian.item.get`，两次都是 `statusCode=0`。

**根因**：源商品没有登记时，`CopyJobWorker.findSource` 会用 `probe`（`vdian.item.get`）逐个探测启用店铺，「返回了商品」就算命中。但服务型授权下，微店 `item.get` 不校验商品归属，用任何一个店铺的令牌都能查到其他卖家的商品。只有一个店铺时这个问题看不出来；第二个店铺接入后，每个商品都同时命中两个店铺，于是被判为冲突。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `backend/.../product/api/WeidianItemCopyApi.java` | `ProbedItem` 增加 `sellerConfirmed`：微店返回的 `seller_id` 等于被探测店铺的微店店铺 ID 时为 true |
| `backend/.../integration/service/WeidianItemCopyService.java` | `probe` 经 `ShopAccessApi.findShop` 取店铺的 `weidianShopId`，与 `item.get` 返回的 `seller_id` 比对，填写 `sellerConfirmed`；任一方为空时为 false。不再新增微店调用 |
| `backend/.../product/service/CopyJobWorker.java` | 探测命中后，优先采用卖家已确认的店铺；没有任何确认时，所有命中都作为候选，与修改前相同。候选只有 1 个才登记，多于 1 个仍报冲突 |
| 测试 | `WeidianItemCopyServiceTest`：只有所属店铺 `sellerConfirmed` 为 true；`seller_id` 缺失时为 false。`CopyJobWorkerTest`：两店都命中、其中一店确认时，登记并从确认的店铺复制（复现用例）；两店都命中、都未确认时仍报冲突。`ProductLinkIT` 只是适配 `ProbedItem` 的新字段 |

**为什么不直接把未确认的命中丢掉**：`item.get` 返回的 `seller_id` 和 `weidian_shop_id`（也就是授权 `openid`）是不是同一套编号，至今没有用真实数据核对过（09a 执行报告把它列为 M0 待确认项）。如果两者不一致，直接丢掉会让所有店铺都「查不到」，现在单店铺能成功的复制也会失败。退回原逻辑可以保证：编号一致时修好多店铺；编号不一致时，行为与现在完全一样。

## 3. 影响范围

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 单店铺、商品未登记 | 命中即登记 | 不变 |
| 多店铺、商品未登记，`seller_id` 与店铺 ID 一致 | 全部判为冲突 | 登记到所属店铺并复制 |
| 多店铺、`seller_id` 缺失或编号不一致 | 冲突 | 不变（仍为冲突） |
| 商品已登记在多个店铺 | 冲突 | 不变 |
| 接口、表结构 | — | 不变，无迁移 |

## 6. 偏离与遗留

- **`seller_id` 编号未用真实数据核对**：正式环境日志不记录 `item.get` 的原始返回。发版后，如果多店铺任务仍然报「多个店铺都有该商品」，说明两套编号不一致，要改用别的归属判断（例如按店铺商品列表核对）。重新提交后看结果即可判断。
- **失败的任务不会自动重跑**：这条任务已是终态 `failed`，发版后需要客户通过表格脚本重新提交。
- 每个未登记的商品仍会探测所有启用店铺（每店一次 `item.get`）。411 个商品、两个店铺约 4 分钟，本任务不做优化。
