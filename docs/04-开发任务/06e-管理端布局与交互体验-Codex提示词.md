## 1. 背景

客户要求新系统**完整替换**现有系统。现有系统有多标签页、侧边栏折叠、表格工具栏（刷新、密度、列设置）、编号旁的复制按钮、搜索区展开等功能，而我们的管理端在任务 03 中为通过严格类型检查重写成了最简布局，这些都没有。

项目负责人调研了主流后台模板（vue-pure-admin、Vben Admin、Ant Design Pro / ProTable、vue-element-admin、Soybean Admin）和 NN/g 的数据表格研究，确定本期做"P0 + P1"两档功能，并确认了视觉稿：

- 视觉稿：<https://claude.ai/artifact/LWAtseCTYB5cn4NcKyknAj>
  - 第一块是可点击原型（工作台、达人列表、订单查询）；
  - 第二块是交互状态与设计规范（配色、字号、间距、右键菜单、列设置、登录过期弹窗、新版本提示、水印、空状态）。
- 能打开时以视觉稿为准；打不开时以本提示词第 4 节为准，两者一致。

**本任务不增加任何业务功能**，只改造布局、交互和视觉，让现有页面都用上同一套能力。

## 4. 已定的设计决定（不要自行改变）

### 4.1 设计规范与主题

1. **设计变量**：在一个文件中集中定义 CSS 变量（例如 `src/style/tokens.css`）。浅色、深色各一组，取值以视觉稿第二块"颜色"为准：

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| 主色 | `#2457D6` | 同左（文字用的主色在深色下适当提亮） | 主按钮、选中项、链接 |
| 页面底色 | `#F5F6F8` | `#0D0F12` | |
| 卡片 | `#FFFFFF` | `#15181D` | |
| 次级底色 | `#F0F2F5` | `#1D2128` | 表头、悬停、分段控件 |
| 边框 | `#E2E5EA` | `#2A2F38` | |
| 正文 | `#15181D` | `#E7E9EC` | |
| 次要文字 | `#5C6470` | `#A3AAB5` | |
| 成功 / 警告 / 危险 | `#1E7A4C` / `#94570A` / `#B42318`，各配浅底 | `#5CC98E` / `#F0B35A` / `#F2877D`，各配深底 | 状态标签 |

   - 用这组变量覆盖 Element Plus 的主题变量（`--el-color-primary` 等）；
   - 深色模式使用 Element Plus 自带的深色变量，并在 `<html>` 上切换 `dark` 类；
   - 页面和组件里不再写死颜色。
2. **形状与间距**：4 / 8 px 网格；控件高 32 px；卡片圆角 12 px、控件 8 px、标签 6 px。分隔用 1 px 细边框，阴影只用于浮层（下拉菜单、弹窗、通知）。
3. **字体**：
   - 视觉稿用了 IBM Plex，**实现时不引入网页字体**。原因有三：许可证（OFL）不在规范 07 的白名单内；Google Fonts 在国内无法稳定访问；CSP 只允许同源字体。
   - 用系统字体栈：中文优先 `PingFang SC`、`Microsoft YaHei`；等宽字体用 `SFMono-Regular`、`Consolas`、`Menlo` 等。
   - **编号、订单号、时间用等宽字体；金额列右对齐，并使用 `font-variant-numeric: tabular-nums`。**
4. **主题切换**：浅色 / 深色 / 跟随系统，默认浅色。页头一个按钮循环切换，选择保存在 `localStorage`（键 `tcrm.admin.theme`，读写都包 `try/catch`）。
5. **对比度**：正文、次要文字、标签与背景的对比度在浅色和深色下都 ≥ 4.5:1。状态色同时在明度上区分，不只靠色相。

### 4.2 页面框架

1. **侧边栏**：
   - 展开 224 px，折叠 64 px（折叠后只显示图标，悬停显示名称）；
   - 折叠状态保存在 `localStorage`（`tcrm.admin.sidebar`）；
   - 视口宽度 < 992 px 时自动折叠为抽屉。
   - 菜单分组标题、图标、选中样式以视觉稿为准。
   - 视觉稿中的待办数量徽标**本任务不做**：后端还没有对应数据，随后续功能一起做。
2. **页头**（从左到右）：
   - 折叠按钮；
   - 面包屑；
   - "搜索菜单"按钮，旁边标出 `Ctrl K`，Mac 上显示 `⌘ K`；
   - 刷新当前页；
   - 全屏（Fullscreen API，浏览器不支持时隐藏）；
   - 主题切换；
   - 语言切换（沿用现有）；
   - 用户菜单：昵称、公司名、修改密码、退出登录。
   - 视觉稿中的通知铃铛本任务不做。
3. **工作台页面**：只按新的设计规范调整样式，**不增加**视觉稿里的指标卡、待办和排行。那些需要后端接口，留给后续任务。

### 4.3 多标签页

| 项目 | 规则 |
|---|---|
| 打开 | 通过菜单、链接或地址栏进入任一需要登录的页面，都会打开或切换到对应标签。同一路由路径只有一个标签，查询参数变化不新开标签。登录页、403、404 不进标签栏 |
| 固定标签 | "首页"（平台管理员为"公司管理"）固定在最左，不能关闭 |
| 关闭 | 标签上的 ×；鼠标中键点击；关闭当前标签时切换到右侧相邻的标签，没有右侧则切到左侧 |
| 右键菜单 | 右键任一标签，或点标签栏右侧的"⋯"按钮（作用于当前标签）：刷新当前页、关闭其他、关闭左侧、关闭右侧、关闭全部。固定标签不受影响 |
| 页面状态 | 用 `KeepAlive` 缓存已打开的页面：切换标签后再回来，筛选条件、分页、滚动位置、展开状态都保持。关闭标签即释放缓存。"刷新当前页"会重新挂载该页面 |
| 数量上限 | 最多 12 个标签。超出时，自动关闭最早打开的、不是当前也不是固定的标签 |
| 刷新浏览器 | 已打开的标签列表和当前标签保存在 `sessionStorage`（`tcrm.admin.tabs`），刷新后恢复；恢复时去掉当前用户已无权访问的标签 |
| 退出登录、切换账号 | 清空标签 |
| 标题 | 用路由的语言键，切换语言时立即更新 |
| 溢出 | 标签栏可以横向滚动，支持鼠标滚轮横向滚动；当前标签自动滚动到可见位置 |

**`KeepAlive` 的组件名**：现有页面组件名（例如 `KolListPage`）与路由名（`KolList`）不一致。请在路由元数据中显式登记组件名，或者统一命名，二选一并在报告中说明。同时加一个测试，保证每个可缓存路由登记的组件名与实际组件的 `name` 一致，避免缓存静默失效。

### 4.4 表格

做成一组可复用的组件和组合式函数，**所有现有列表页都要改用**：

- 达人列表、店铺、原商品、对应关系
- 用户管理、操作日志、公司管理

抽屉和对话框中的小表格可以不加工具栏，但要遵守第 4 条的基础规则。

1. **工具栏**（表格卡片顶部）：
   - 左侧：总数；
   - 右侧：密度分段控件（默认 / 紧凑 / 宽松，对应 Element Plus 表格的 `default` / `small` / `large`）、刷新、列设置、表格全屏（在页面内铺满，不是浏览器全屏）。
2. **列设置**：
   - 勾选显示或隐藏；用"上移 / 下移"按钮调整顺序，不用拖拽（NN/g 建议提供非拖拽方式，同时避免新增依赖）；"重置"恢复默认；
   - **第一列（编号或名称）固定在左、始终显示；操作列固定在右、始终显示**，这两列在面板里置灰；
   - 有列被隐藏时，按钮上显示"已隐藏 N 列"。
3. **每张表单独保存设置**：可见列、顺序、密度、每页条数，存在 `localStorage`，键形如 `tcrm.admin.table.<表格标识>`。
   - 值带版本号；
   - 读取时丢弃已不存在的列，补上新增的列（按默认显示）；
   - 解析失败时回到默认，不报错。
4. **基础规则**：
   - 表头吸顶，表格区域在页面内滚动；
   - 首列、操作列固定；
   - 行悬停高亮；
   - 金额列右对齐、等宽数字；
   - 编号、订单号、时间用等宽字体；
   - 状态统一用视觉稿中的浅底标签。
5. **分页**：显示"第 1–10 条 / 共 N 条"（中英文各一份），以及每页条数、页码。每页条数按第 3 条保存。
6. **空状态**：有筛选时显示"没有符合条件的数据 · 已应用 N 个筛选条件"，并提供"清除筛选"按钮；没有筛选时显示普通的空状态。

### 4.5 搜索区

做成可复用组件，所有列表页统一使用：

1. **常显与展开**：每页指定"常显条件"（第一行），其余放在"展开"里。展开状态随页面缓存，但不保存到下次登录。
2. **操作**：在任一输入框中按 Enter 即查询；"重置"清空条件并查询。
3. **已筛选提示**：只要有条件生效，搜索区下方就逐个列出（"国家：美国 ×"），可以单独移除（移除后立即重新查询），也可以"清除全部"。标签文字用"字段名：显示值"，下拉框显示选项文字，而不是代码。

### 4.6 菜单搜索（Ctrl / ⌘ + K）

1. **打开**：`Ctrl+K` 或 `⌘+K` 打开，在任何页面都可用；输入框聚焦时同样生效。也可以点页头的按钮。
2. **范围**：只搜索当前用户有权访问的菜单。匹配菜单名称（当前语言）和所属分组，不区分大小写。
3. **最近访问**：输入为空时显示最近访问的菜单，最多 6 个，保存在 `localStorage`（`tcrm.admin.recent`，按用户 ID 区分）。
4. **键盘**：`↑` `↓` 选择，`Enter` 打开（打开或切换到对应标签），`Esc` 关闭。焦点在弹窗内循环，关闭后回到原来的位置。

### 4.7 复制

做成复制组件：

- 用在编号、订单号、邮箱、链接旁；
- 用 Clipboard API，不可用时退回 `document.execCommand('copy')`；
- 成功后提示"已复制 xxx"（内容过长时截断）；失败时提示手动复制。

现有页面中所有编号、邮箱、链接、微店商品 ID 列都要加上。

### 4.8 登录过期：弹窗重新登录

1. **触发**：已登录用户的请求返回 401 且错误码为 `AUTH_UNAUTHORIZED`（会话过期或空闲超时）时，**不跳转到登录页**，而是在当前页面弹出登录框：
   - 用户名显示当前账号，不可修改；
   - 输入密码后调用现有登录接口。
2. **成功**：关闭弹窗，留在原页面，页面上正在填写的表单不丢失。失败的那次请求不自动重发，用户再点一次即可。
3. **其他选择**：弹窗提供"切换账号"，点击后清空会话，进入登录页。
4. **仍然直接回登录页的情况**：
   - 错误码为 `AUTH_ACCOUNT_DISABLED`（账号或公司被停用）；
   - 登录接口本身失败到被锁定（`AUTH_ACCOUNT_LOCKED`）；
   - 当前不是已登录状态。
5. **并发**：多个请求同时返回 401 时，只弹一个框。
6. **校验**：弹窗中登录返回的账号必须与原账号相同；不同时视为切换账号（清空标签和会话，进入首页）。

### 4.9 新版本提示

1. **生成版本文件**：构建时在产物根目录生成 `version.json`，内容为 `{"version": "<构建标识>"}`。构建标识可以用构建时间加内容哈希，在 Vite 配置中用一个很小的内联插件生成，不新增依赖。
2. **检查**：应用每 5 分钟检查一次，页面从后台切回前台时也检查一次。请求 `/version.json?t=<时间戳>`，并带 `cache: "no-store"`。
3. **提示**：版本与启动时不同，就在右上角显示通知卡片："系统已更新，刷新页面以使用新版本。已打开的标签会保留。"，提供"立即刷新"和"稍后"。选"稍后"后，30 分钟内不再提示。
4. **开发环境**：不检查。

### 4.10 水印

1. **范围**：已登录后，主内容区（不含侧边栏和页头）铺一层水印，用 Element Plus 的 `ElWatermark`。
2. **内容**：`昵称 · 用户名 · 日期（YYYY-MM-DD）`。
3. **样式**：颜色取正文色，深色模式下自动适配；透明度很低，以不影响阅读为准，参照视觉稿；旋转约 −20°。
4. **行为**：不拦截点击。**用户不能关闭水印**：它是防止截图外传的安全措施。

### 4.11 其他

1. **刷新当前页**：页头按钮和标签右键菜单都可以触发，只重新挂载当前页面组件，不刷新整个应用。
2. **页面切换**：保留现有的顶部进度条。可以加轻微的淡入过渡（≤ 150 ms），系统设置为"减少动态效果"时关闭。
3. **偏好保存**：主题、侧边栏、语言、表格设置都只保存在浏览器本地，不存服务端。
4. **新增文字**：全部按 06d 的约定写进中英两份语言包，现有的"残留中文"测试必须继续通过。

## 6. 测试要求

用 Vitest 测试，至少覆盖以下场景：

| 场景 | 期望 |
|---|---|
| 标签：打开 | 同一路径只有一个标签；查询参数变化不新开 |
| 标签：关闭 | 关闭当前标签后切到正确的相邻标签；固定标签不能关闭；中键关闭 |
| 标签：右键菜单 | 关闭其他、左侧、右侧、全部的结果正确，固定标签保留 |
| 标签：上限 | 超过 12 个时关闭最早的非当前、非固定标签 |
| 标签：恢复 | 从 `sessionStorage` 恢复并过滤无权访问的标签；存储不可用时不报错；退出登录后清空 |
| `KeepAlive` | 每个可缓存路由登记的组件名与组件实际的 `name` 一致；关闭标签后缓存被移除；"刷新当前页"会重新挂载 |
| 列设置 | 隐藏、排序、重置；固定列不能隐藏；按表格标识分别保存；遇到已删除或新增的列、版本不符、内容损坏时，都能正确处理 |
| 密度与每页条数 | 保存后，刷新页面仍然生效 |
| 搜索区 | Enter 查询；已筛选标签显示选项文字；移除单个条件、清除全部后都会重新查询 |
| 菜单搜索 | `Ctrl+K` 和 `⌘+K` 都能打开；只显示有权限的菜单；最近访问按用户区分、最多 6 个；键盘选择与 `Esc` |
| 复制 | Clipboard API 可用和不可用两种情况；成功与失败的提示 |
| 登录过期 | `AUTH_UNAUTHORIZED` 弹出登录框；多个 401 同时出现只弹一个；登录成功后表单内容仍在；`AUTH_ACCOUNT_DISABLED` 直接回登录页；换成另一个账号登录时清空标签 |

## 8. 禁止事项与停止条件

**禁止**：

- 修改 `admin-ui/` 以外的文件，或修改任务索引；
- 新增依赖，或引入网页字体；
- 改变后端接口的调用方式或参数；
- 删除或弱化测试；
- 推送 `main` 或合并 PR；使用 `push --force`、`reset --hard`。

**遇到以下情况停下来**：推送已完成的提交，以 `[WIP]` 标题创建 PR，在执行报告中说明后结束。

- 某项功能不新增依赖就无法实现；
- `KeepAlive` 与现有路由守卫、权限或国际化冲突，无法在不改变既定行为的前提下解决；
- 设计说明书、本提示词、规范之间存在冲突；
- 验证在合理排查后仍然失败。
