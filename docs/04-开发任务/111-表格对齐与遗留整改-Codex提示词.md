## 1. 背景

负责人 2026-11-04 发现：达人提现列表「状态」列的内容是左对齐的。前端已经审过多轮，样式问题仍然漏网。

原因是单元格插槽外面包了一层 `<div class="status">`，样式是 `display: flex`，又没设水平居中。`DataTable` 的居中只给单元格加了 `text-align: center`，对撑满整格宽度的 flex 或 grid 容器不起作用（见 `admin-ui/src/views/fund/withdrawal/index.vue` 第 261、306 行）。

规范 13 附录 A.2 早有规定：对齐看「实际可见内容」，不能只看外层单元格。但审查核对的是列定义里的 `align`，截图靠人眼看，执行方的验收脚本也从没测量过内容的实际位置，所以一直漏掉。

## 2. 要求

### 2.1 表格对齐：组件兜底（两端）

1. 在两端的 `DataTable` 里，让**居中列**中的自定义内容按实际内容居中：
   - 插槽里只有一个块级根元素（`div`，或 `display` 为 flex / grid 的元素）时，这个元素按内容宽度收缩，水平居中；
   - 长度不能超过单元格，过长时仍能换行或省略。

   建议做法：在组件样式里，对居中列单元格中唯一的块级子元素设 `width: fit-content; max-width: 100%; margin-inline: auto`。动手前先在三四个页面上实际试一下，确认不会把多个行内元素拆开、不会丢空格，也不影响左对齐列、操作列和选择列，再决定用哪种写法。把选择的写法和原因写进报告。
2. 左对齐列不动。左对齐列外层的 `AccessibleCell` 也不动。
3. 组件单测覆盖：
   - 居中列中的 flex 根元素；
   - 居中列中的多个行内元素（空格保留）；
   - 左对齐列不受影响。

### 2.2 表格对齐：浏览器实测脚本

1. 新增一个**不依赖任何包**的浏览器测量脚本 `scripts/table-align-audit.js`：一个可以直接在页面里执行的纯 DOM 函数，在浏览器自动化工具的 `evaluate` 或开发者工具控制台里都能运行。仓库里没有 Playwright 一类的依赖，也不要新增。打开页面、登录这些驱动步骤用执行方自己的验证工具完成，不进仓库。函数对当前页面每张表的每个数据格和表头格做测量：
   - **居中列**（`td` / `th` 带 `is-center`）：计算可见内容的外接框，取文字节点和可见子元素的并集。内容中心与单元格内容区中心相差超过 **2px**，记为问题。
   - **左对齐列**：内容起点与单元格内容区左边界相差超过 2px，记为问题。
   - 同一列里，表头和数据格方向不一致，也记为问题。
   - 返回一个问题数组，每项包含页面地址、表格、列名、行号、偏差像素；空数组表示没有问题。
   - 抽屉、弹窗里的表格同样能测，只要它们当时在页面上可见。
   - 补一个最小单测：用 jsdom 加手动设置的尺寸，或者把计算部分拆成纯函数来测，覆盖居中偏差、左对齐偏差、表头方向不一致三种判定。
2. 用这个脚本跑两端的全部列表页，以及抽屉、弹窗里的表格（订单详情、提现详情、佣金弹窗、达人资金抽屉等）。每页都要有数据：没有数据的页面先造 `t111_` 测试数据。管理端用超管登录，达人端用一个测试达人登录。中英文各跑一次，宽度 1440。
3. 实测发现的每处问题都要修掉。优先依靠 §2.1 的组件兜底；兜底覆盖不到的，在页面上改。改完重跑，问题数为 0。
4. 修复前后各截一张对比图，至少包括达人提现列表、达人收入、订单列表三页。截图放 `docs/04-开发任务/assets/task-111/`。

1. **L-096**：平台管理员在「公司管理」点「成员」时，请求变成 `/tenants/undefined/admins`。

   - 不改发布流程本身。
   - 在 `deploy/scripts/test-release-lock.sh` 或新的测试脚本里补用例：人为制造一个未定义变量的错误，断言退出码非零。分别在本机 bash 3.2 和 Linux 容器（bash 5）里各跑一次。
