## 3. 主要改动

- `CommissionIncomeController`：删除嵌套 `PageVO`。`IncomeResultVO` 为 `{items,total,page,size,summary}`。`total` 与 `orderCount`/`quantity`/`unverified`、汇总计数用 `int`（`Math.toIntExact`），避免全站 `long`→字符串序列化。`summary` 增加 `commissionPaid`、`prepayPaid`。详情 `CommissionLineVO` 增加 `product`、`sku`。
- `CommissionIncomeService`：`occupied` 读取在途提现（`PENDING_REVIEW`、`PENDING_PAYMENT`），`available` = 钱包余额 − 占用，可为负。`paid`、`commissionPaid`、`prepayPaid`、`lastPaidAt` 按付款时间 `start`/`end`（含头不含尾），`paymentType` 对行和 `summary` 同一效果；`cumulativePaid` 仍是提现台账 `withdrawalPaidSums` 加全期预付，不受时间段和 `paymentType` 影响。详情 `payments[]` 合并窗口内已付提现（`type=COMMISSION`，`sourceNo` 为提现编号，`deduct` 为 false，`deducted`/`pending` 为 `0.00`）与预付，按 `paidAt`、`id` 倒序。`product`/`sku` 取 `order.api.OrderSettlementApi.ItemRefDTO` 的 `itemName`/`skuName`，空白视为 null。未扩展该 API，未改提现写入。
- `SettlementDetailController` / `CommissionSettlementDetailService`：分页改为 `SettlementPageVO`（`total` 为 `int`）；`lines[]` 同样增加 `product`、`sku`。查询参数仍是设计 §6.2 的 `shopId`。
- `KolCommissionController`：`fund-records` 改为 `FundPageVO`，`total` 为 `int`。概览十项金额未改。
- 设计说明书 §6.2 收入列表/详情/结算明细、§6.3 `fund-records` 同步上述形状与类型。
- 测试：四个管理端控制器切片用 JSON 路径锁字段与类型；`product`/`sku` 单元测试覆盖有 SKU、空白 SKU、订单行缺失；`CommissionSettlementIT` 的收入列表与结算明细断言随结构更新，并加上分列金额与 `product`/`sku`。未核实结算行的 `retained` 断言仍是 `doesNotExist()`：jsonPath 把 JSON null 和缺字段看成同一结果，该用例在单元 `verify` 中通过；实现按契约写出 null。

## 9. 偏离与原因

1. **分页 `total` 为数字，与规范 03 示例字符串不一致。** ADR-032 附录 A 写明 `Page.total: string` → 契约 `total: number`（「全站为数字」），任务提示词同样要求数字。规范 03 的示例仍是 `"1024"`。本任务只把收入列表、结算明细、资金流水这三个响应的 `total` 写成 `int`，不改全站 Jackson、不改 `PageResult`、不改规范 03。达人订单列表分页仍是字符串。#112 的 `Page.total` 目前仍是 `string`，ADR 已要求前端改为 `number`，本任务不改前端。
2. **`rateVersion` 与结算配置 `version` 是 JSON 数字。** #112 写成 `string | null` / `string`。ADR 与设计只要求字段名和乐观锁语义，任务提示词只把 ID 与金额定为字符串。保存配置时 Jackson 仍可把数字或数字字符串绑到 `Integer`。不改成字符串，也不改 #112。
3. **结算明细查询参数是 `shopId`，不是附录 A / #112 的 `shop`。** ADR §14：契约正文以设计说明书为准，§6.2 写的是 `shopId`（店铺 ID）。#112 页面把 `shop` 当作文本框。按设计保留 `shopId`，不改契约、不改前端。#112 若只传 `shop`，后端不会按店铺过滤。
4. **行与汇总的付款口径（已在审查修订中消除）。** 首次交付时行上两列不随 `paymentType` 变化，提现合计也没有付款时间窗口。任务 63 合并后，行与 `summary` 都按付款时间窗口和 `paymentType` 计算；`cumulativePaid` 仍用全期台账。
5. **`lines[].kolId`、结算行 `kolIds` 保留。** 附录 A 未列，任务 62 已返回，前端会忽略多余字段。未删。
6. **#112 把 `product`/`sku`/`image` 写成不可空 `string`。** 设计与任务要求没有 SKU 时 `sku` 为 null，图片取不到为 null。以后端契约为准。
