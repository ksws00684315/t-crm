## 2. 解析与安全措施

- **防 XXE**：StAX 工厂关闭 `SUPPORT_DTD` 与 `IS_SUPPORTING_EXTERNAL_ENTITIES`；含 DOCTYPE/实体的 worksheet 被拒（单元测试覆盖）。
- **防 ZIP 炸弹**：每个条目经计数流解压，超过 64 MB 即拒绝（单元测试构造 64MB+1 条目覆盖）。
- **不读媒体**：仅打开白名单条目；含 16MB 随机图片的样本与无图片样本解析耗时差 < 3s（测试断言，实际差远小于该上限）；真实 241MB（646 张图）样例上传→预览仅 2.0s。
- **文件不留存**：临时文件在成功/失败路径都删除；预览只存解析行 JSON 于 Redis（30 分钟 TTL，绑定公司+达人+上传人）；不走会保存文件的导入任务框架。
- **权限**：接口 `kol:edit`；OWN 范围只能传名下达人；确认时三重绑定校验；冲突对方信息按角色裁剪。

## 4. 偏离与说明

1. **模块位置**：任务建议解析类放 `kol` 模块。`product` 模块已依赖 `kol.api`（`KolApi`），`kol` 再依赖 `product.api` 会被 `ArchitectureTest` 的模块无环规则拒绝（实测报 cycle）。因此 `PromoSheetReader` / `PromoSheetService` / `PromoSheetUploadController` / `PromoSheetItemApi` 全部放在 `product` 模块（控制器路径仍是 `/admin-api/kol/...`，权限与行为不变）。`SheetLinkParser` 按任务许可移到 `product.api` 供双方复用，规则未改。
2. **读取范围**：任务列举的读取清单未含 `xl/_rels/workbook.xml.rels`，但不读它无法把工作表名映射到 `sheet*.xml`（跳过样例的「工作表」列需要正确的表名）。它与 sheet rels 同属关系文件、体积极小，已一并读取并在类注释说明；`xl/media` 及其它条目仍不打开。
3. **超限错误码**：超过 Spring multipart 上限（300 MB）的请求由 `GlobalExceptionHandler` 统一映射为 `TASK_FILE_TOO_LARGE`（消息仍写「Import file exceeds 20 MB」）。该映射是全局的，改动会影响其它接口的既有行为，故未动；推广表接口自身在进入控制器前就把 >300 MB 拒为 `KOL_PROMO_SHEET_TOO_LARGE`，实际用户几乎不会看到旧消息（仅在 Spring 层被拦时出现），遗留见 §5。
4. **浏览器上传方式**：ZCode 内置浏览器不支持文件选择器（capability 上限），因此浏览器内上传用「同结构生成样本」注入完成全流程；真实 241 MB 样例经 `curl -F` 走同一 HTTP 接口完成上传→预览→确认，DB/Redis 结果一致。两种方式覆盖的是同一条服务端链路（multipart → 临时文件 → 解析 → Redis → 确认）。
5. **既有测试语义更新**：`KolItemLookupServiceTest.shouldTreatMissingStatusAsUnusable` 更新为「缺失商品状态 = 无原商品（可售），缺失店铺状态 = 不可用」。这是 `product_id` 可空后的必然语义（旧行为下该行根本不会出现），非弱化。
6. **确认响应**：确认接口除计数外也返回 `conflictsDetail`（确认时重新校验后可能出现的冲突），便于前端展示「哪些没写、为什么」；任务 §3.3 只要求预览含冲突清单，此为超集。

## 5. 遗留

- 超 300 MB 且被 Spring 层拦截时错误消息仍是导入上限文案（§4.3）；如需精确文案，可给 `MaxUploadSizeExceededException` 处理器按请求路径区分，涉及全局处理器行为，留给审查决定。
- Cloudflare 免费计划请求体上限约 100 MB，生产若经 Cloudflare 代理上传 300 MB 文件需升级计划或让该路径绕过代理（已写进 `deploy/README.md`）。
- 任务 17b 的脚本复制上线后，`source = COPY` 由该任务写入（枚举与 CHECK 已预留）。
- 与 25a 合并时：`PromoSheetIT` 使用旧达人编号格式（`KOL100001`），25a（`KOL-XXX###` 新格式）合入后需同步该测试的编号与断言（届时冲突双方语言包已约定保留双方）。
