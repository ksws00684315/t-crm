## 1. 需要的样例（由负责人提供）

| 编号 | 样例 | 用于 |
|---|---|---|
| S1 | 一个**多规格**商品的 `vdian.item.get` 原始返回（至少两个 SKU、带规格图、带 SKU 成本价） | L-124、L-125 |
| S2 | 同一商品分别用**所属店铺**和**另一家已授权店铺**调用 `vdian.item.get` 的返回，以及两家店铺各自的微店店铺 ID | L-126 |
| S3 | 退款接口原始返回，尽量覆盖：退款成功、商家拒绝、买家取消、处理中 | L-034 |
| S4 | 一笔**交易已完成**订单的订单详情原始返回 | L-052 |

样例只保留结构和与本任务相关的字段值。买家姓名、电话、地址、令牌、签名等必须删除或替换为占位值。

## 2. 要求

每一条都先用样例确认现有代码的行为（写成失败的单元测试），再改。样例显示现有代码已经正确的，不改代码，只补测试，在报告里写明。

1. **L-124 SKU 成本价**：按 S1 的真实字段名读取商品级和 SKU 级成本价（现在读 `costPrice`，文档写 `cost_price`）。如果两种写法都可能出现，两种都兼容。
2. **L-125 规格图片**：S1 里有规格图的，复制时带到目标商品对应的规格值上。字段对应关系以 S1 和微店文档为准，写进报告。
3. **L-126 源店铺确认**：用 S2 核对 `seller_id` 与店铺微店 ID 是否同一套编号：
   - 一致：现有逻辑正确，补用真实样例的测试；
   - 不一致：**停下来报告**，写明两套编号的样子，并给出替代判断方法（例如按店铺商品列表核对）的方案和调用次数估算，由负责人决定。
4. **L-034 退款状态映射**：按 S3 补齐 `RefundDictionary` 的状态值映射（成功、拒绝、取消、处理中等），未知值仍映射为 `UNKNOWN`。L-037 已在任务 83 处理，前置约束已满足。被拒绝、取消的退款不再让该行永久冻结，确认任务 81、113 的售后阻断规则在新映射下行为正确，补测试。
5. **L-052 交易完成时间**：用 S4 确认订单详情里有没有明确的交易完成时间字段：
   - 有：解析并写入（字段与写入位置按设计 §4.8.2 和 ADR-032 的「接口明确返回才写，不推断」），让「完成时间＋冻结天数」这条释放依据生效，补测试；
   - 没有：不改代码，报告里写明样例中所有时间类字段及其含义，L-052 保持现状。
6. 设计说明书中受影响的状态字典、字段说明同步更新，文末修订记录加一条。
