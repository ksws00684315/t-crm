## 第二轮：与预览图逐项对齐（负责人复审"两模两样"后）

负责人指出实测页面与讨论中的生成预览图差异过大。逐项比对后，确认差异集中在列表卡片的密度而非字体层级，本轮据此重做布局层：

| 差异点         | 此前                                                | 现在                                                                        |
| -------------- | --------------------------------------------------- | --------------------------------------------------------------------------- |
| 卡片高度       | 撑满视口剩余高度，7 行数据下方留下约 290px 空白     | 内容高度，行数少时卡片收缩、分页紧跟最后一行；行数多时才在表体内滚动        |
| 行高           | 73px（六个操作换行，每行两行文字）                  | 49px，与预览图一致                                                          |
| 列宽           | 合计 2,236px，1844 宽度下横向裁掉 5 列，看不出滚动  | 中文合计 1,558px，恰好放进 1,562px 卡片：13 列同屏、表头不换行、无横向滚动  |
| 被裁列观感     | 固定操作列直接压在半列文字上，像渲染错误            | 溢出时固定操作列加左侧投影，横向滚动条常显（不再等悬停）                    |

| 英文界面       | 与中文同宽，操作列折成三行、行高 91px               | 按更长的英文标签单独给宽，行高仍 49px；英文总宽超出时在卡片内横向滚动       |

- `DataTable` 不再固定 `height: 100%`，改为测量容器可用高度后作为 `max-height` 上界（`ResizeObserver` + `requestAnimationFrame` 合并重算），并扣除筛选区等同级元素的高度，兼顾"行少不空、行多分页仍在视口内"。
- 达人列表列宽按 14px 实测文字重排：`达人ID 108 / 名称 76 / 电话 112 / 邮箱 120 / 社媒 160 / 佣金 80 / 预付 80 / 邀请时间 158 / 邀请人 80 / 审核 80 / 登录 80 / 关系 80 / 操作 344`；英文字典单独给出更宽取值。
- 长邮箱、电话、社媒 ID 保持省略号 + 悬停全文，符合视觉规范中"长值省略、可查看全文"的约定；表头一律完整显示。

## 第三轮：侧栏子菜单箭头压在文字上

负责人反馈左侧菜单的下拉箭头与文字完全重叠。实测原因不在箭头定位，而在宽度继承：

- Element Plus 自带 `.el-sub-menu__icon-arrow { width: inherit }`。标题宽度为默认 `auto` 时该值等价于收缩宽度，箭头正常；第一轮为菜单项设了显式 `width: calc(100% - 16px)` 之后，箭头继承了 191px 的行宽，被拉成一条透明横条，14px 图标在其中居中，于是画在标签文字上。实测箭头 rect `[4, 480, 191, 14]`，文字 rect `[57, 475, 56, 22]`，完全重叠。
- 修复：箭头显式定宽高 14px、`right: 16px`、`margin-top: -7px`，颜色继承标题；标题标签加 `min-width: 0` 与省略号，长词条不再挤向箭头。修复后箭头 rect `[185, 687, 14, 14]`，与文字间距 72px；注入 10 字超长词条时标签在 114px 内省略（scrollWidth 154），箭头位置不变，间距 14px。
- 折叠态沿用 Element Plus 的隐藏规则，仅图标导航，未受影响。
