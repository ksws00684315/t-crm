# 退款中状态与计佣修复

| 需求 | 实现与回归用例 |
| --- | --- |
| 退款中可查且可识别 | 订单级状态、订单查询筛选和订单链路使用未确认完结口径。微店未知原值仍保留。历史退款未匹配商品行时，在整单展示申请金额。 |
| 退款中保留净销售额和佣金 | 退款申请金额与成功退款金额分开。订单链路用例覆盖实付 105 元、退款申请 105 元、净销售额 105 元和冻结佣金 21 元。 |
| 成功后同时扣减 | 只有成功退款计入退款合计。已关联商品行按成功退款额扣减销售额及计佣金额，整单无其他阻断且微店确认结算时释放佣金。 |
| 恢复旧规则计成零的佣金 | 迁移标记具备可信来源和费率的旧快照，经现有结算重算队列重新计提。集成用例覆盖排队、恢复及成功退款后扣减，单元用例覆盖相同来源重复同步。 |
| 佣金与提现提示 | 改为「退款中佣金冻结，退款完成后扣减」，自动化用例覆盖退款中提示和退款结束后的隐藏。 |
| 订单链路商品明细的商品 ID | 在商品名/SKU 后展示可复制的原商品ID、新商品ID。原商品ID取已关联来源的微店商品ID。新商品ID优先取该行实际成交商品ID。无法确认原商品时显示「—」。 |

生产订单需在发布且完成店铺结算重算后核对。微店未识别的状态码保留原值。
