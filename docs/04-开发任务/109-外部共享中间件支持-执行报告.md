## 6. 专项结论

1. **postgres:17.11 客户端向 16 导入时实际需要过滤的语句**：只有 `SET transaction_timeout = 0;` 一行（5.1 的 17 备份中确认存在该行；过滤后导入 16.8 无任何其他语句失败）。备份头部另有一条 psql 元命令 `\restrict <token>`，由 17.11 客户端本地处理、不会发给服务器，无需过滤——与提示词预判一致。
2. **外部模式下 DROP SCHEMA public 的权限情况**：PG 16 中 `public` schema 属主是 `pg_database_owner`，因此**应用角色只要是数据库属主即可**执行 `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`，不需要超级用户。已在模拟实例上用非超户库主角色（`t109_nonsu` 拥有独立库）实测成功；本任务模拟主库的角色（镜像 POSTGRES_USER，超级用户）同样成功。云端 tcrm 专用角色只要拥有 tcrm 库即可；若角色不拥有该库（public 属主为其他角色）才会失败，属 §6 停下报告的情形，本次未触发。
3. **host.docker.internal 在预览容器中的解析方式**：`extra_hosts: host.docker.internal:host-gateway` 在容器 `/etc/hosts` 写入 `192.168.65.254 host.docker.internal`（Docker Desktop 的 host-gateway 地址）及 IPv6 条目；Docker Desktop 自身也内建解析该名称。后端经 `host.docker.internal:19932` 成功连上 16.8（Flyway 日志为证），与现有网络配置（预览 default 网络 + 外部 `tcrm-t109-net`）无冲突。
4. **凭证搜索结果**：0 命中（见 §5.7）。
