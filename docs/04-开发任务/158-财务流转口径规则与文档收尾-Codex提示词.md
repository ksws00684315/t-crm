## 2. 已确认的业务规则（负责人 2026-11-22 会话）

财务流水按事件记科目。原口径中「微店提现」即达人提现，最后两段是同一提现付款事件的两笔记账：

| 事件 | 记入科目 |
|---|---|
| 订单同步登记为未支付（下单未支付） | 预收入（订单级） |
| 订单支付 | 冻结中收入（订单级）、冻结中佣金支出（商品行级） |
| 订单退款成功 | 支出（订单级）、佣金扣回（商品行级） |
| 订单结算确认 | 可提现收入（订单级）、可结算佣金（商品行级） |
| 达人提现付款成功 | 订单已提现（按分配明细记到商品行/订单）、佣金已提现（达人级） |
| 未支付订单关闭 | 预收入核销 |

- **订单已提现**：该订单佣金被有效提现申请占用并完成付款（负责人确认），金额按分配明细到行；行级展示「已提现 X、可提现 Y」。
- **多商品行**：收入侧科目挂订单级；佣金计算与退款呈现以商品行为主；售后冻结维持整单判定（现行行为）。
- **提现分配**：复用现有机制（`crm_commission_withdrawal_allocation` 行级分配、`crm_commission_withdrawal_order` 订单快照、按 `release_at` FIFO），不新建分配模型。
- **结算周期**：维持现行规则（微店结算确认后释放）；「收货满 15 天、次月 20 日付款」建议稿不采用。
- **计佣基数**：维持现行实现（订单实付 `pay_amount` 含运费、按商品行实付分摊、付款即计提），A-006 就此定案。
- **术语基准**：`/Users/hh-mini/Downloads/名词口径.xlsx`（负责人 2026-11-22 指定，两个页签：「1116新」「Sheet1」）。两页签矛盾处按「1116新 优先、Sheet1 独有条目保留」起草定稿对照表；表内自带的「待核验 / 待确认」标注照录为「待 M0 验证」，不阻塞后续开发。
