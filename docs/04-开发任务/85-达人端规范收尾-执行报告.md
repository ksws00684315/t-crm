## 本轮解决的问题

### 1. 依赖安全审计：移交 PR #161，不在本分支重复修复

任务 60 起一直记为「不满足」的项是 `pnpm audit --prod` 各命中 1 个高危：`axios → follow-redirects 1.16.1`，`GHSA-mrwp-f3q8-3g9p`，补丁版 `>=1.16.2`。

本轮最初在两端把传递依赖提升到 `1.16.2`，两端审计归零。收尾时发现 `main` 的 OSV 扫描已因四条新公告失败，负责人已用 PR #161 统一修复 follow-redirects 1.16.2、glob 14.0.2、minimatch 11.0.1，并同步了 `pnpm-workspace.yaml` overrides、`THIRD-PARTY-NOTICES` 与 `osv-scanner.toml` 许可证白名单。该口径是本项的严格超集。

处置：撤回本分支的锁文件与许可证清单改动，恢复到 `main` 原状。理由：

- 保留会与 #161 在两端 `pnpm-lock.yaml`、`THIRD-PARTY-NOTICES` 上重复冲突；
- 本分支只改前端样式，不该夹带依赖升级；
- 单项 follow-redirects 修复不能通过 OSV 工作流（glob、minimatch 仍在），留下也只是把失败从「4 项」降到「2 项」。

#161 已于 2026-10-31 合并，本分支已合入 `main`，当前 `pnpm audit --prod` 为 No known vulnerabilities，OSV 工作流通过，本项关闭。

### 2. 表格行操作字重（规范 10 第 1 节「表格操作链接 400」）

`#app .el-button { font-weight: 600 }` 是全局规则，把表格行内的操作链接也抬到 600。管理端 `admin-ui/src/style/index.css` 早有一条对冲规则 `#app .actions-cell .el-button { font-weight: 400 }`，达人端移植组件时漏了这条。

处理：`kol-portal/src/style/index.css` 补同一条规则，与管理端写法一致。

### 3. 手机端触控目标不足 44px（规范 10 第 2 节「小于 768px 时交互目标至少 44px」）

| 位置 | 原值 | 现值 |
|---|---|---|
| 页头账户菜单 `summary` | `min-height: 32px` | 767px 以下 `44px` |
| 账户菜单面板内链接 | `min-height: 32px` | 767px 以下 `44px` |
| 我的商品卡片「复制链接」 | 无最小高度（实际约 40px） | 767px 以下 `44px`，并改为 `inline-flex` 垂直居中 |

统一取 `--tcrm-control-height-mobile`（44px），不新增数值。

### 4. 我的商品手机卡片列表缺空态（规范 10 第 3 节「空态在卡片内居中」）

桌面表格的 `#empty` 插槽随表格在 767px 以下一起 `display: none`，而卡片列表 `v-for` 在无数据时不渲染任何内容，手机上整页空白。

处理：卡片列表改为 `v-if="items.length"`，无数据、不在加载中且未加载失败时渲染独立空态（`data-test="items-empty-mobile"`），仅在手机断点显示；文案复用 `items.empty` / `items.emptyHint`，不新增语言键。

审查返工修正两点：

- 判断加上 `!error`。原实现在接口失败时同时显示报错和「还没有商品」，违反规范 13 第 4.3 节。
- 空态改为白底卡片（`--tcrm-color-card`，边框和圆角与手机商品卡相同）。手机商品卡本身没有背景色，只照搬它的底色仍会铺在页面底纹上，所以这里用卡片白底。

补单元测试 2 条：空态存在且卡片列表不渲染；接口失败时不显示手机空态（修改前确认失败）。
