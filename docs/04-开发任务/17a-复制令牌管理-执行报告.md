## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin-api/kol/copy-tokens` | 分页列表，只返回脱敏值；按 hint/kolId/channel/显示状态筛选 |
| POST | `/admin-api/kol/copy-tokens` | 生成；响应含一次明文 `token` |
| POST | `/admin-api/kol/copy-tokens/{id}/reveal` | 取回明文 |
| DELETE | `/admin-api/kol/copy-tokens/{id}` | 作废；已作废再作废 409 |

权限均为 `kol:copy-token`。OWN 范围只能操作名下达人令牌，否则 404。

内部 API（`kol.api.CopyTokenApi`）：

- `authenticate(plaintext)`：系统作用域按 hash 查找，再在令牌所属公司作用域校验；错误码 `COPY_TOKEN_INVALID` / `EXPIRED` / `QUOTA_EXCEEDED`、`KOL_DISABLED`。
- `consume(tokenId, count)`：条件 UPDATE，并发不超额。

设计 §6.2 `api-catalog:admin` 已登记上述四个接口；区间外原说明行已删除。

## 安全

- 明文格式 `TKN-` + 26 位大写 Base32（128 bit SecureRandom）。
- 库中仅 `token_hash`（SHA-256 hex）与 `token_cipher`（SecretCipher）；列表只返 `tokenHint`。
- 操作日志经 `@AuditLog`；`AuditSanitizer` 对字段名含 `token` 的内容脱敏。集成测试断言 oper_log 不含明文。
- 店铺校验用 `JdbcTemplate` 读 `crm_shop`（避免 kol → product.api 与已有 product → kol.api 形成环）。
