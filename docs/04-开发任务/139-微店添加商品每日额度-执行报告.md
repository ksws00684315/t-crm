# 139 微店添加商品每日额度：执行报告

- 分支：`task/139-daily-copy-quota`
- 日期：2026-11-08
- 类型：功能调整（后端 + 管理端，无迁移）

## 1. 背景

负责人 2026-11-08 提出：微店添加商品接口（`vdian.item.add`）每天最多调用 5000 次。要求如下：

1. 统计已调用的添加商品接口次数；
2. 本次要复制的商品数加上当日已调用次数超过上限时，拦截新任务，并告知用户当日剩余量；
3. 在系统中显示已用量和总量，文字要友好，例如「本日已复制商品 xxx条/本日最多复制商品 xxx条」；
4. 上限支持配置。

负责人确认的口径：

- 上限按**每家公司合计**计算，不按店铺分别计算；
- 用量显示在「商品任务列表」，即管理端的复制任务列表页。

## 3. 口径说明

- **计日**：按北京时间计算，每天 0 点切换到新的计数。微店是国内平台，按北京时间计日是推断，没有找到官方文档说明它的重置时刻。如果实际按其他时区重置，只需修改 `CopyDailyQuota.DAY_ZONE`。
- **计数对象**：只统计 `vdian.item.add` 的实际调用次数。探测（`vdian.item.get`）、保存详情等其他接口不计入。调用失败（例如微店返回错误）也计入，因为微店同样会计这次调用。
- **预检从严**：预检时把去重后的每个商品都按会调用一次 add 来估算。实际执行时，探测不到的商品不会调用 add，所以实际用量可能少于预检估算。
- **并发兜底**：同一时间可能有多个任务在跑。每次调用 add 之前都会原子地「检查并 +1」，所以总调用次数不会超过上限。超出部分的明细会失败，可以在明细里看到原因。
- **不变的行为**：令牌额度的扣减方式不变。
- **存储**：计数只存在 Redis，没有建表、没有迁移。如果 Redis 数据被清空，当日计数会从 0 重新开始。
