## 3. D1：达人登录清空字段

### 3.1 根因（复核确认）

`KolAccountStoreService.updateLastLoginTime` 原实现：

```java
KolDO change = new KolDO();
change.setId(id);
change.setLastLoginTime(time);
kols.updateById(change);
```

`KolDO` 有 9 个字段标注 `@TableField(updateStrategy = FieldStrategy.ALWAYS)`：`defaultRate`、`remark`、`whatsapp`、`linkTemplateId`、`inviteCode`、`sheetUrl`、`phone`、`promotionRemark`、`autoCleanupDays`。MyBatis-Plus 按实体生成 `UPDATE` 时会把这 9 列一并写成 `NULL`。5 条登录路径（`login`、`select`、`changePassword`、`activate`、`KolSelfRegisterService.register` → `loginEstablished`）都经由同一个私有方法 `KolAuthService.logIn` 调用它。

**复核中补充发现**：`KolDO.lastLoginTime` 标注的是 `FieldStrategy.NEVER`，所以原 `updateById` 生成的 `SET` 子句根本不含 `last_login_time`——即登录时间从来就没有写入过（复现测试的失败输出也印证了这一点：改密用例在登录后立即读取 `last_login_time` 得到 `NULL`）。修复改为按列更新后，这一功能同时恢复。

### 3.2 复现测试与修复前失败输出

新增集成测试（`@Tag("docker")`，Testcontainers 真库）：

### 3.3 修复

`KolAccountStoreService.updateLastLoginTime` 改为按列更新，与同文件 `activate`/`updatePassword` 及管理员侧 `system/service/AccountStoreService.recordLogin` 的写法一致：

```java
kols.update(
    null,
    new LambdaUpdateWrapper<KolDO>()
        .eq(KolDO::getId, id)
        .set(KolDO::getLastLoginTime, time));
```

- 未改 `KolDO` 的 `ALWAYS` 策略（资料编辑清空字段依赖它）。
- 登录不算资料变更，未写 `update_time`（与 `activate`/`updatePassword` 写 `update_time` 形成对照——那两个是真正的账号资料变更）。若审查人认为登录也应刷新 `update_time`，请指出，再统一调整。
- `KolAuthServiceTest` 中对 `updateLastLoginTime` 的调用校验原样保留（17/17 通过）。

## 4. S1：冻结和恢复提现越权

`WithdrawalService.freeze`/`resume` 只调用了 `requireKol(kolId)`（仅判断达人存在），未调用同文件已有的 `requireKolScope(user, kol)`（OWN 范围校验，越权抛 `COMMON_NOT_FOUND`）。`commission:freeze` 是 `Permission` 注册表中的权限码，可通过「用户管理 → 权限替换」授予任意范围账号（审查实测 OWN 商务 `trev_bd_a` 授予后冻结/恢复他人达人均返回 200）。
