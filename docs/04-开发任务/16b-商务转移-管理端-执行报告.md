## 4. 管理端

### 4.1 转移对话框（`views/kol/BdTransferDialog.vue`，三处入口共用）

- **转移对象**：只读。`kolIds` 入口显示「已选 N 位达人」；按商务入口显示「商务 X 名下全部达人（当前 N 位）」。
- **新商务**：下拉选项来自 `GET /admin-api/system/bd-users`（对话框打开时自取，失败提示不中断），外加「未分配（归公司）」（哨兵值提交时转 `toBdUserId: null`）；按商务转移时排除来源商务本人。
- **生效时间**：「立即 / 指定时间」单选。指定时间用 `el-date-picker type="datetime"`，按浏览器本地时区选择，旁注动态时区（如「时区：Asia/Shanghai（UTC+8）」，取自 `Intl.DateTimeFormat().resolvedOptions().timeZone` 与本地偏移），提交时 `toISOString()` 转 UTC；过去日期在选板上禁用，提交前再校验「必须晚于当前时间」「一年以内」，未选时间提示。
- **原因**：可选，≤ 255 字，带字数统计。
- **结果与错误**：成功提示「立即完成 X 位，预约 Y 位，跳过 Z 位（已属于新商务）」并关闭；409 `KOL_TRANSFER_EXISTS` 在对话框内以 `el-alert` 显示「以下达人已有预约转移，请先取消：」并列出 `data` 中的达人编号（顿号分隔），对话框保持打开；422 `KOL_INVALID_BD_USER` 等其余错误走 `notifyError` 按 `errorCode` 映射文案。为拿到 409 的 `data`，`ApiError` 增加了通用只读字段 `payload`（错误信封的 `data`），`utils/http` 构造时透传。
- **500 上限**：提交前校验 `kolIds` 数量，超过 500 提示「一次最多转移 500 位达人」且不发起请求（当前页面选择只覆盖当前页，实际上限 100，仍保留防线）。

**三处入口**（均只对超管显示）：

1. 达人列表工具栏「转移商务」（`ListSearch` 的 `#actions`，`data-test="transfer-bd"`）：勾选达人后可用，提交 `kolIds`。
2. 达人行「更换商务」（`data-test="change-bd"`）：打开同一对话框，仅这一位达人，`kolIds: [id]`，**不再调用 `PUT /bd-user`**；前端 `changeKolBd` API 函数与旧 `ChangeBdDialog.vue` 已无引用，随之删除（后端旧接口保留不动）。行按钮增加 `asKol(row).id` 渲染守卫，避免 Element Plus 操作列空行探测触发空对话框（沿用任务 06e 在公司管理页的做法）。
3. 用户管理中商务账号行（仅子账号且数据范围「本人」）「转移名下达人」：人数通过 `GET /kol/kols?bdUserId=…&size=1` 的 `total` 取得（页面加载后按行批量取），为 0 时按钮置灰并以 tooltip 提示「名下没有达人」；点击以 `fromBdUserId` 打开对话框。

### 4.2 停用商务确认

用户管理行停用（超级管理员确认框）在原有「确定要停用用户 X 吗？」之后追加一行：「停用后，其名下 N 位达人将立即转为未分配（归公司），转给他的预约转移将被取消。」N 为 0 时不显示这句话；非商务账号与其他确认不变。换行通过 `customStyle: { whiteSpace: "pre-line" }` 呈现。批量停用未改（不在本任务范围）。

### 4.3 转移记录页（`views/kol/bd-transfers/index.vue`）

- 路由 `/kol/bd-transfers`，`meta.superAdmin: true`，`componentName: KolBdTransferPage`（进 KeepAlive 与标签），菜单位于「达人管理」之后，图标 `Switch`。
- 使用 `ListSearch` + `DataTable`（`table-id="kol-bd-transfers"`）+ `CopyText`（达人编号）。
- 筛选：状态（预约中/已完成/已取消）、达人编号（提交前大写化，与后端口径一致）、来源商务、目标商务（选项来自 `listBdUsers`，芯片文本用「昵称（用户名）」，未知 ID 回退原值）。
- 列：达人（编号可复制 + 姓名）、来源商务、目标商务（空显示「未分配」）、约定生效时间、状态（标签：预约中=warning / 已完成=success / 已取消=info）、实际执行时间、原因、取消原因、创建时间、操作。时间 `formatInstant` 按浏览器本地时区。
- 操作：`SCHEDULED` 行显示「取消预约」，`ElMessageBox` 二次确认后 `DELETE /admin-api/kol/bd-transfers/{id}`；409 `KOL_TRANSFER_NOT_SCHEDULED` 提示对应文案并刷新列表。
- 查询参数（4.5 节）：打开页面时读取 `?status=` 与 `?kolCode=` 作为初始筛选（非法状态值忽略）；页面被 KeepAlive 缓存时监听路由查询变化重新应用，供任务 20 的站内消息链接跳转。
- 权限：仅超管可见（路由 `superAdmin` + 菜单过滤），子账号即使拥有全部权限码也无法进入（后端同限，BdTransferControllerTest/IT 已覆盖）。
