## 2. 账户规则（实现于 `commission` 模块）

- **类型校验**：PAYPAL 须 `account`（3～128）+ `holderName`（1～64）；USDT 须 `account`（3～128，仅字母数字）+ `network`（五选一）+ 可选 `qrFileId`。字段级错误在 `KolPayoutAccountRequest` 的 `@AssertTrue` 中给出（消息键 `tcrm.payout.paypal-fields` / `tcrm.payout.usdt-fields`，中英文已入 `ValidationMessages*.properties`）。账号最小长度 3 是为保证脱敏后至少隐藏一位（提示词只给了上限，见第 7 节偏离）。
- **数量**：非停用账户 ≥ 5 时新建返回 422 `PAYOUT_ACCOUNT_LIMIT`。
- **状态流转**：新建/修改后 `PENDING`；审核通过 `APPROVED`（锁定，修改返回 409 `PAYOUT_ACCOUNT_LOCKED`）；驳回 `REJECTED`（原因必填，缺省为字段错误 400）；停用 `DISABLED`（不可恢复；对达人的列表与修改不可见 → 404）。审核非 `PENDING` 返回 409 `PAYOUT_ACCOUNT_NOT_PENDING`。
- **修改**：`PENDING`/`REJECTED` 可改，改后回 `PENDING` 并清空审核信息（`reject_reason`、`reviewed_by/time`）、刷新 `last_submitted_at`、重新加密与脱敏。
- **默认账户**：仅 `APPROVED`（否则 422 `PAYOUT_ACCOUNT_NOT_APPROVED`）；同一事务内先取消原默认再设置新的；停用时自动取消默认并清空驳回原因（数据库 CHECK 要求）。
- **停用检查点**：`PayoutAccountService.disable` 中留有注释检查点——提现任务（16）实现后须校验「被处理中的提现单引用的账户不能停用」，本任务不检查（提示词 §4.2.6）。
- **加密与脱敏**（`AccountMasker`，规则集中一处）：
  - 邮箱：前 2 位 + `***` + `@域名`（本地部分 ≤ 2 位时整个本地部分换成 `***`，`ab@gmail.com` → `***@gmail.com`）；
  - 其他字符串：前 4 位 + `…` + 后 4 位；≤ 8 位只保留首尾各 1 位（`TQ5x…L9aZ`、`1…8`）；
  - 列表（达人自己的除外）、审计参数一律只有脱敏值；明文只出现在达人本人列表与管理端详情接口的响应里，日志中无完整账号（有测试断言）。
- **二维码**：`POST /kol-api/files`（multipart `file`，参数 `bizType=PAYOUT_QR`）按文件头识别 PNG/JPEG（不信任扩展名与 Content-Type），≤ 2MB，返回 `{fileId}`；保存账户时 `claimQrFile` 校验「本人上传 + 未被使用」后回填 `biz_id`（同一事务）；编辑保持原文件不需重新认领，换新文件则认领新的，被替换的旧文件保留归属（只追加表，历史可查）。

## 3. 接口与示例

### 3.1 达人端（达人令牌，`X-Kol-Token`）

| 方法与路径 | 说明 |
|---|---|
| `GET /kol-api/payout-accounts` | 本人账户（不含停用），完整账号仅本人可见，按最近提交倒序 |
| `POST /kol-api/payout-accounts` | 新建。请求体：`{"accountType":"USDT","account":"TQ5x…","network":"TRC20","qrFileId":"66"}` 或 `{"accountType":"PAYPAL","account":"a@example.com","holderName":"Alice D"}` |
| `PUT /kol-api/payout-accounts/{id}` | 修改 `PENDING`/`REJECTED` 的账户，请求体同上 |
| `PUT /kol-api/payout-accounts/{id}/default` | 设为默认（仅 `APPROVED`） |
| `PUT /kol-api/payout-accounts/{id}/disable` | 停用 |
| `POST /kol-api/files` | 上传二维码，multipart `file` + `bizType=PAYOUT_QR`，返回 `{"fileId":"66"}` |
| `GET /kol-api/files/{id}` | 下载本人上传的文件（附件） |

响应字段（`KolPayoutAccountVO`）：`id`、`accountType`、`account`（完整值）、`holderName`、`network`、`qrFileId`、`status`、`defaultAccount`、`rejectReason`、`lastSubmittedAt`、`reviewedTime`。别人的账户或文件一律 404。达人的新建/修改/设默认/停用写入达人操作审计（`sys_oper_log`，`module=PayoutAccount`，参数只含脱敏账号）。

### 3.2 管理端

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /admin-api/commission/payout-accounts` | `payout-account:review` 或 `commission:view` | 分页 `{status?, type?, kolCode?, page, size}`；`status` 默认 `PENDING`，`ALL` 看全部；按 `lastSubmittedAt` 倒序；只返回脱敏值 |
| `GET /admin-api/commission/payout-accounts/pending-count` | 同上 | `{"count":"3"}`，当前账号能审核的待审数量 |
| `GET /admin-api/commission/payout-accounts/{id}` | `payout-account:review` | 完整账号 + `qrFileId`；**每次查看写操作日志** |
| `PUT /admin-api/commission/payout-accounts/{id}/review` | `payout-account:review` | `{"action":"APPROVE"}` 或 `{"action":"REJECT","reason":"…"}`（≤255，必填） |
| `GET /admin-api/files/{id}` | `payout-account:review` | 下载已挂到账户的二维码（附件，记操作日志）；未挂载或其他类型 404 |

列表行（`AdminPayoutAccountVO`）：`id`、`kolId`、`kolCode`、`kolName`、`accountType`、`accountMasked`、`holderName`、`network`、`qrFileId`、`status`、`defaultAccount`、`rejectReason`、`lastSubmittedAt`、`reviewedTime`。详情额外以完整 `account` 替换 `accountMasked`。

数据范围：`OWN` 的子账号只能看/审**当前**归属本人的达人的账户（经 `KolApi.listByBdUserId`，商务转移后立即生效，原商务 404）；跨公司 ID 一律 404；超管全公司。二维码下载要求 review 权限（二维码编码了钱包地址，等同完整账号），`commission:view` 只有脱敏列表。

## 4. 新错误码与前端映射

| errorCode | HTTP | 说明 |
|---|---|---|
| `PAYOUT_ACCOUNT_LIMIT` | 422 | 非停用账户超过 5 个 |
| `PAYOUT_ACCOUNT_LOCKED` | 409 | 已通过的账户不能修改 |
| `PAYOUT_ACCOUNT_NOT_PENDING` | 409 | 只能审核待审核的账户 |
| `PAYOUT_ACCOUNT_NOT_APPROVED` | 422 | 只有已通过的账户能设为默认 |
| `FILE_INVALID` | 400 | 文件必须是 PNG 或 JPEG |
| `FILE_TOO_LARGE` | 400 | 文件超过 2MB |
| `FILE_IN_USE` | 422 | 文件已被其他业务记录使用 |

按提示词 §3 与规范 03 §4，七个错误码的中英文文案已写入 `admin-ui/src/locales/{zh-CN,en-US}.ts` 与 `kol-portal/src/locales/{zh-CN,en-US}.ts` 的 `errors` 段（`error-codes.ts` 的映射从语言包键自动派生，无需改其他前端文件）；admin-ui 有 7 条（含只面向管理端的 `NOT_PENDING`），kol-portal 有 6 条（达人不会触发 `NOT_PENDING`）。两前端 `pnpm lint && pnpm test` 全部通过（admin-ui 269、kol-portal 118）。

## 7. 偏离与遗留

1. **站内通知（遗留）**：`crm_notification` 未实现，客户要求的「通知所属商务和超管」由待审核列表默认 `PENDING` + `pending-count` 接口承担（提示词 §4.5 明确本任务不做通知）。
2. **停用时的提现检查（检查点）**：`PayoutAccountService.disable` 留有注释检查点，任务 16 实现提现后补充「处理中的提现单引用的账户不能停用」。
3. **账号最小长度 3**：提示词只给上限（≤128），为保证脱敏后至少隐藏一位字符而设（`@Size(min=3)`）；钱包地址同为 3～128。已在 §4.11 写明。
4. **`crm_file` 的 PDF**：设计 §5.2 提到 PDF，但本任务只接受 PNG/JPEG（二维码场景足够，提示词 §4.2.8 只要求 PNG/JPEG）；`WITHDRAWAL_VOUCHER` 等类型与 PDF 随提现/预付任务再放开（`biz_type` CHECK 已含全部四种）。
5. **达人操作审计的 method 列**：`ExternalAuditApi.recordKolOperation`（12a 的接口）固定写 `POST`，本任务的 PUT 操作也记为 `POST`（接口未暴露 method 参数，未改 12a 的代码以免越界）；`requestUri` 与 `action` 准确。如需精确 method，后续给 `system.api` 加参数。
6. **管理端文件下载权限**：设计 §6.2 写「能查看该文件所属业务记录的账号」，本任务实现为 `payout-account:review` + 账户在数据范围内（二维码等同完整账号）；未挂载的文件对管理端 404。已在 §6.2 注明。
