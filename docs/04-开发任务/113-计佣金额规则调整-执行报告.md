# 任务 113：计佣金额规则调整（退款中暂不计佣，退款成功时才扣）— 执行报告

## 1. 结论

已完成，待审查与合并。结算金额部分（定稿 §6 P1）按提示词不做，仍待 M0。

- 订单任一商品行有未完结退款（`PROCESSING` / `UNKNOWN`）时，整单按售后中处理：
  - 各行释放依据为 `AFTER_SALES`，包括没有退款的行；
  - 每行计提 = min(原计提, 该行已释放)。未释放的行为 0.00，已释放的保持不变；
  - 不产生任何台账记录；订单仍算已核实，不写 `commission_basis_reason`。
- 退款被拒绝或关闭（`CLOSED`）后，按现有规则重算恢复。暂停的待付申请由 `applyRevision` 中现有的 `resumeForItem` 自动解除。
- 退款成功后，按支付金额 − 成功退款重算；低于已释放的部分写 `COMMISSION_ADJUSTMENT`，余额可为负。这是现有行为，未改。
- 展示：
  - 管理端订单详情、订单链路的订单级金额区块：预估佣金下方显示完整提示；
  - 达人收入明细、结算明细的佣金明细表：金额旁显示「售后处理中」标签，悬停显示完整提示；
  - 达人端我的订单：金额旁显示标签，窄屏卡片显示完整提示；
  - 退款完结后提示自动消失。
- 无迁移，无新增依赖。

### 执行中的停止报告与决定

- **第一次停止**（旧版提示词）：「已释放后进入退款中先扣回、被拒后补发」的路径有两个问题：
  - 补发要等释放任务，暂停的申请不会自动解除；
  - 负向扣回不撤回预付冲抵记录，补发后同一笔佣金会被记成冲抵两次（已只读核实，登记为 L-118）。

  负责人 2026-11-05 改为「退款成功时才扣」：已释放的不扣回，只冻结。新版提示词经 PR #205 合并。
- **第二次停止**（新版提示词 §6 第 4 条）：`RefundDictionary` 只把微店原值 10 映射为 `SUCCESS`，拒绝、关闭没有对应原值。派发方 2026-11-05 决定：

  - 代码只依赖标准状态：`PROCESSING`、`UNKNOWN` 阻断，`SUCCESS`、`CLOSED` 不阻断；
  - 提示文案改用不下结论的「售后处理中…」（见第 12 节）。

## 6. 时间线（§2.1 第 5 条）

数据与 `BusinessChainIT` 新增用例一致：订单支付 65.00，A 行 43.33、B 行 21.67，比例 10%，计提 4.33 / 2.17，已结算确认，无预付。

恒等式：累计佣金 = 冻结中 + 可提现 + 提现中 + 已提现（设计 §4.8.2）。可提现 = min(钱包余额 − 提现中, 已释放未占用且不在售后的行合计)。冻结中 = 计提 − 已释放，加上被阻断行的已释放未占用金额。

## 7. 订单状态范围（§2.1 第 6 条）

范围未改。现有处理（`SettlementBasisCalculator.compute`）：
- 无支付时间：未核实（`NO_SETTLEMENT`），行结算状态 `UNPAID`，不计佣。
- 有支付时间且订单状态为 `CLOSED`（付款后关闭）：整单基数 0.00，计提 0。
- 有支付时间的其他状态，包括 `PAID` / `SHIPPED` / `RECEIVED` / `COMPLETED` 和 **`UNKNOWN`**：按支付金额分摊计佣。`UNKNOWN` 订单状态和已付款订单处理相同，本任务未改。
- 售后中的判定只看退款记录，与订单状态无关。

## 12. 偏离与原因

1. **提示文案**：提示词 §2.2 的示例是「退款中，暂不计佣；…」，实际用「售后处理中，暂不计佣；已释放部分冻结，退款成功后按退款金额扣减」（英文同义）。
   - 原因：M0 前真实数据只会出现 `UNKNOWN`，它可能是退款中，也可能是已经被拒绝或关闭、只是还没登记映射，不能下结论。
   - 派发方 2026-11-05 决定。
2. **集成测试「退款被拒」**：用把 `refund_status` 改为 `CLOSED` 的方式模拟，沿用 `OrderSettlementFlowIT` 的写法。原因是微店的拒绝原值尚未映射（派发方 2026-11-05 决定）。
3. **售后判定范围**：整单判定也包括 `order_item_id` 为空（无法唯一对应到单行）的未完结退款。原实现按行判定，这类退款不阻断任何行。

4. 以下几项由架构负责人 2026-11-05 审查 PR #206 时确认，接受：
   - 达人端售后中行状态冻结优先：必要。
   - 佣金列加宽：可以。1280 宽英文需横向滚动、「Release basis」列溢出两项，由架构负责人登记为 L 项。
   - `order_item_id` 为空的未完结退款也阻断整单：符合「一单一达人、整单判断」的口径。
   - 已释放大于 0 但小于原计提时，计佣金额 × 比例 ≠ 预估佣金：少见，由架构负责人登记为 L 项。
   - 「退款被拒」用 `closeRefund` 改库模拟：按 E2，可以。
   - 「钱包余额不变」用台账间接证明：可以。第二轮已在 `BusinessChainIT` 补直接断言余额。
