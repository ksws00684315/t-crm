## 1. 背景

负责人 2026-10-16 决定做「多公司账号与切换」：

- 一个管理员账号可以属于多家公司，在每家公司有各自的角色与权限码；
- 登录后在页头切换当前公司；
- 当前公司由服务端会话决定，前端只负责显示和核对（任务 21a，ADR-022）。

现状：

- 页头只显示所属公司的名称；
- 用户管理页假设一个账号只属于一家公司；
- 平台管理员的公司管理页只能为公司创建超管。

## 4. 已定的设计决定（不要自行改变）

### 4.1 页头切换公司

1. `companies` 不止一家时，页头的公司名改为下拉菜单，列出本人的公司（当前公司打勾，并显示该公司中的角色：超级管理员 / 子账号）。只有一家时保持现在的纯文字显示。平台管理员不显示。
2. 选择另一家公司时：
   - 调用 `POST /admin-api/auth/company`；
   - 用返回的数据更新用户状态：公司、角色、权限码、菜单；
   - 关闭除首页外的所有标签页，清空 keep-alive 缓存，跳到首页；
   - 提示「已切换到 {公司}」。
3. 切换成功后，通过 `BroadcastChannel`（名称 `tcrm-admin-company`）通知同一浏览器的其他标签页。其他标签页收到后重新获取 `/me`，并按第 2 步刷新。浏览器不支持 `BroadcastChannel` 时，依靠第 4.2 节兜底。
4. 切换失败（403 `AUTH_COMPANY_NOT_MEMBER`）：显示对应文案，并重新获取 `/me` 刷新公司列表。

### 4.2 请求头核对

1. 已登录的公司账号，每个请求都带 `X-Company-Id: {当前显示的公司 ID}`。平台管理员和未登录时不带。
2. 收到 409 `AUTH_COMPANY_SWITCHED` 时：
   - 不按普通错误弹出提示；
   - 改为提示「当前公司已在其他标签页切换，页面将刷新」，然后重新获取 `/me` 并按 4.1 第 2 步刷新；
   - 同时触发的多个 409 只处理一次。
3. 这个头只用来核对，前端任何地方都**不得**用它或其他参数来选择公司。

### 4.3 与公司相关的本地状态

1. 切换公司时清空：
   - 标签页与 keep-alive 缓存；
   - 各列表的筛选条件（如果有保存在内存里的）；
   - 锁屏状态以外的会话级缓存（如消息铃铛的未读数，切换后立即重新获取）。
2. 按用户保存的个人偏好（表格列设置、每页条数、主题、语言）**不清空**。
3. 水印、锁屏显示的公司名随当前公司变化。

### 4.4 用户管理页（公司超管）

1. 列表新增「多公司」标签：`companyCount > 1` 时显示，悬停提示「该账号还属于其他公司；姓名、邮箱、密码只能由平台管理员修改」。
2. 对多公司账号：
   - 编辑对话框中姓名、邮箱只读；
   - 「重置密码」按钮禁用，并给出同样的提示；
   - 后端如果仍返回 422 `USER_MULTI_COMPANY_LOCKED`，显示对应文案。
3. 角色、岗位模板、数据范围、权限码、启停，以及 16b 的转移、停用确认都保持不变，作用于本公司。
4. 新建账号时用户名已存在（409 `USER_USERNAME_EXISTS`），在现有文案后补一句「如需让其他公司的账号加入本公司，请联系平台管理员」。

### 4.5 平台管理员：公司成员

1. 公司管理页每行的「超管」对话框（`TenantAdminsDialog`）改名为「成员」。保留现有的创建超管、重置超管密码，另外新增「加入已有账号」：
   - 输入用户名（精确匹配），调用 `GET /platform/users?username=`；
   - 显示找到的账号及其已加入的公司；
   - 选择角色：超级管理员，或子账号（选岗位模板与数据范围）；
   - 调用 `POST /platform/tenants/{id}/members`；
   - 已是成员时提示 409 文案。
2. 找到账号后可以进行账号级操作：
   - 修改姓名和邮箱（`PUT /platform/users/{id}`）；
   - 重置密码（`PUT .../password`，确认框说明「该账号在所有公司的登录都会失效」）；
   - 启用或停用整个账号（`PUT .../status`，确认框说明影响所有公司）。
3. 平台管理员界面仍然不出现任何业务数据。

### 4.6 接口约定（与 21a 共用，不得改动）

```text
GET  /admin-api/auth/me                → 现有字段（当前公司身份）+ companies: [{ tenantId, tenantName, role }]
POST /admin-api/auth/login             → 现有字段 + companies
POST /admin-api/auth/company           → 请求 { tenantId }；响应同 /me；403 AUTH_COMPANY_NOT_MEMBER
请求头 X-Company-Id                     → 与会话当前公司不一致时 409 AUTH_COMPANY_SWITCHED
GET  /admin-api/system/users           → 每行增加 companyCount
PUT  /admin-api/system/users/{id}、/{id}/password → companyCount > 1 时，改姓名、邮箱、密码返回 422 USER_MULTI_COMPANY_LOCKED
GET  /admin-api/platform/users?username=
     → { id, username, nickname, status, companies: [{ tenantId, tenantName, role, status }] } 或 null
POST /admin-api/platform/tenants/{id}/members  → { userId, role, postTemplate?, dataScope? }；409 USER_ALREADY_MEMBER
PUT  /admin-api/platform/users/{userId}、/{userId}/password、/{userId}/status
```
