## 0. 前提

1. **一单只对应一个达人。** 多达人订单不是业务场景，只按数据异常处理（保留现有的 `CONFLICT` 人工池兜底），金额不按达人拆分订单。
2. 金额单位为元（CNY），两位小数；后端用 `BigDecimal`，接口序列化为字符串。
3. 命名按钱的流向区分：买家付给店铺的叫「支付」；公司付给达人的叫「付款」（单笔）或「支出」（统计）。
4. 名词分三级：**SKU 级**（订单里的一行商品）、**订单级**、**统计级**（多笔订单按时间段或维度汇总）。同一个名词在不同级别含义一致，只是汇总范围不同。

## 1. SKU 级

| 名词 | 定义 | 说明 |
|---|---|---|
| SKU | 商品规格 | — |
| 单价 | 链接设置的 SKU 售价（下单时的一口价） | 取 `historical_unit_price`；缺失时显示「缺失历史售价」 |
| 件数 | 该 SKU 的购买件数 | 不合并：买红色×2 + 绿色×1，分别显示 2 件和 1 件 |
| 商品总价 | 单价 × 件数 | 单价缺失则为空 |

SKU 级**不显示**支付金额（支付金额只在订单级出现）。

## 2. 订单级

| 名词 | 定义 | 说明 |
|---|---|---|
| 商品总价 | Σ 各 SKU 商品总价 | 任一 SKU 单价缺失则为空 |
| 商品数量 | Σ 各 SKU 件数 | 合并：红色×2 + 绿色×1 显示 3 |
| 运费 | 订单运费 | 取 `freight` |
| 订单金额 | 商品总价 + 运费（买家应付） | 取代原「订单总额」 |
| 优惠 | 订单金额 − 支付金额 | 推算值，不另取微店字段；商品总价缺失时为空 |
| 支付金额 | 买家实际支付金额 = 订单金额 − 优惠 | 取订单实付 `pay_amount`（微店 `total`，含运费）；只要付款就计入，不考虑退款 |
| 退款金额 | 订单成功退款合计 | 按退款单去重；取代「退款合计」 |
| 订单实收 | 支付金额 − 退款金额 | — |
| 计佣金额 | 预计可结算金额，见 §2.1 | 取代「计佣基数」 |
| 佣金比例 | 给达人设定的佣金比例 | 付款时快照 |
| 预估佣金 | 计佣金额 × 佣金比例 | 订单**未结算**时显示 |
| 结算金额 | 订单在店铺**已结算**后，店铺结算流水的整单金额；未结算时为 0 | **待确认**（§6）；取代「微店可提现金额」，名称不带「微店」 |
| 实际佣金 | 结算金额 × 佣金比例 | 订单**已结算**时显示；**待确认**（依赖结算金额） |

订单详情和订单链路都要有订单级金额区块，显示上表各项；商品表只显示 SKU 级各项。

### 2.1 计佣金额规则

- 计入的订单状态：已付款（待发货）、已发货、已签收、交易成功。
- **退款中**：暂不计入（计佣金额为 0）；退款被拒绝或关闭后恢复。
- **部分退款完成**：计佣金额 = 支付金额 − 退款金额。
- **全额退款完成**：计佣金额为 0。
- **已结算**：计佣金额 = 结算金额（**待确认**，见 §6）。
- 含运费（因为支付金额含运费）。

## 3. 达人佣金五层

| 名词 | 定义 | 取代的旧名 |
|---|---|---|
| 累计佣金 | Σ 该达人全部已核实订单的佣金（未结算按预估佣金，已结算按实际佣金） | 预估总佣金、预估佣金（五层顶层） |
| 冻结中 | 已计入、尚未释放的佣金 | 冻结佣金 |
| 可提现 | 已释放、未被提现占用、未被预付抵扣的佣金；算法不变（`availableCny`） | 可提现金额 |
| 提现中 | 待审核、待付款提现申请的占用合计 | 申请占用、占用金额、提现占用 |
| 已提现 | 已完成付款的佣金提现合计 | 佣金付款、累计已付佣金 |

- **已申请提现**：待审核、待付款、已付款提现申请的占用合计，用于订单链路和提现详情的按单占用；与五层的「提现中」不同（架构负责人 2026-11-05）。
- **期间已提现**：所选期间内已完成付款的佣金提现合计，用于管理端达人收入的期间付款拆分；全期累计仍叫「已提现」（架构负责人 2026-11-05）。

恒等关系不变（设计说明书 §4.8.1），只把顶层名字由「预估总佣金」改为「累计佣金」。
达人端工作台第一板块的「预估总收入」「预估总佣金收入」（任务 92 负责人原文）保持现状。

## 4. 预付与付款

| 名词 | 定义 | 取代的旧名 |
|---|---|---|
| 预付款 | 公司预先付给达人的款项 | — |
| 已抵扣 | 约定从佣金抵扣的预付中，已抵扣部分 | 已扣回、预付抵扣 |
| 待抵扣 | 约定从佣金抵扣的预付中，尚未抵扣部分 | 待扣回 |
| 付款金额 | 单笔付款登记金额（佣金提现付款、预付付款都用此名） | 登记支付金额、实际支付金额 |

## 5. 统计级（供后续经营分析看板使用，本期只定义不实现）

「所选范围」指统计时间段和所选维度（店铺、达人、商务等）。

| 名词 | 定义 | 说明 |
|---|---|---|
| 销售额 | 所选范围内订单支付金额合计 | 按付款时间统计；含运费、含退款（售中、售后退款都含，付款后秒退也计入）；取代 GMV |
| 商品销售额 | 按商品（达人商品）统计时，该商品各商品行实付之和（已扣优惠、**不含运费**，不分摊运费） | 范围：已付款且已归属达人的订单，含付款后关闭、已退款订单，含人工改归属订单；不含冲突、未匹配订单；退款按同一范围统计（负责人 2026-11-05）。本期在管理端达人商品页实现（任务 112） |
| 净销售额 | 所选范围内付款的订单，支付金额剔除这些订单后续的退款 | 按付款时间归期；退款会持续发生，指标持续刷新，最长 30 天。例：7 月 1 日成交 1000 元，其中 200 元后来退款，则净销售额 800 元 |
| 退款金额（完结时间） | 所选范围内成功完成的退款合计 | 按退款完成时间归期；含售中、售后的仅退款和退货退款，含退差价、退定金。因此 净销售额 ≠ 销售额 − 退款金额（完结时间） |
| 退款中 | 所选范围内退款中订单的支付金额合计 | — |
| 订单数量 | 订单笔数 | 一单多件也只计 1 |
| 商品数量 | 订单商品件数合计 | 一单 3 件计 3 |
| 计佣金额 | Σ 订单计佣金额 | — |
| 结算金额 | Σ 订单结算金额 | 待确认 |
| 预估佣金 | Σ 订单预估佣金 | — |
| 实际佣金 | Σ 订单实际佣金 | 待确认 |
| 预估实收金额 | 计佣金额合计 − 预估佣金合计 | — |
| 实收金额 | 结算金额合计 − 实际佣金合计 | 待确认 |
| 佣金支出 | 已完成付款的佣金提现合计 | — |
| 预付支出 | 已完成付款的预付合计 | — |
| 总支出 | 佣金支出 + 预付支出 | — |
| 待支出佣金 | 累计佣金合计 − 佣金支出 | 用累计佣金，不用预估佣金 |
