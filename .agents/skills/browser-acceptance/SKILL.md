# 浏览器验收

依据：规范 12 第 5 节、规范 08 第 9.2 节、`本机任务通用要求.md` 第 2、4 节。由浏览器验证子代理执行；派发时在子代理输入里写明工作树绝对路径，要求先 `cd` 进去。

## 1. 启动

- 中间件：连接本机共享的 PostgreSQL / Redis（Compose 项目 `tcrm-local`，端口 55432 / 46391）。连接信息在**主目录**的 `deploy/.env.local`，只读，不复制进工作树、不修改。
- 后台：在工作树的 `backend/` 下，导出 `deploy/.env.local` 的变量后用 dev profile 启动（命令见 `deploy/README.md`「本地共享中间件与开发」），`TCRM_ADMIN_PORT` 用任务分配的端口。
- 前端：`admin-ui/`、`kol-portal/` 用各自的 Vite 命令，端口用任务分配的。负责人在用 18081、8848、8849、8890～8892，不得占用。
- **不得**停止、删除、重建共享中间件，不得 `down -v`，不得另起 `docker-compose.dev.yml` 项目，不得动 `tcrm-preview`。

## 2. 测试数据

- 账号、达人、店铺等一律加前缀 `t{任务编号}_`，例如 `t78_bd01`、`t78_…@example.com`。
- 收尾时只删除自己创建的数据，把改过的系统配置恢复默认，并在执行报告中列出清理命令。

## 3. 验收矩阵（只查任务涉及的部分，但涉及的每一格都要查）

| 维度 | 必查项 |
|---|---|
| 分辨率 | 1440×900、1280×800；涉及达人端时加 390×844、375×812；涉及列表时加一个 2560 宽 |
| 语言 | 中文、英文 |
| 角色 | 任务涉及的全部角色：平台管理员、公司超级管理员、运营、商务（只看自己负责的数据）、达人 |
| 数据状态 | 有数据、空数据、长内容（长邮箱、长名称）、校验失败、接口失败 |
| 浮层 | 任务涉及的全部弹窗、抽屉、下拉菜单 |

同时对照规范 10（字体字号以 `docs/03-设计/网页字体字号规范.xlsx` 为准）和规范 11（列表用 `ListSearch`、`DataTable`、`RowActions`、`CopyText`；未实现的显示「开发中」）检查。

## 4. 截图与记录

- 放在 `docs/04-开发任务/assets/task-{编号}/`，文件名写明页面、分辨率和语言，例如 `kol-list-1440-zh.png`。
- 执行报告列出每张截图对应的检查项；发现的问题写清复现步骤，修复后重新截图。
